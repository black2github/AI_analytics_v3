## Правило на будущее

1. **Конфликт в `_meta/tools/*.py` при слиянии — не разрешать самостоятельно.** Любая правка
   прибора делается в репозитории прибора (с тестами), оттуда копируется в канон; владелец
   прибора — Алексей Сень. Если ваша ветка трогает `_meta/tools/`, перед MR: `git fetch`,
   `git log --oneline master..origin/master -- _meta/tools/` — при непустом выводе отправьте
   перечень своих правок прибора владельцу, он сольёт и прогонит тесты. Пока это не прибор, а
   только `_meta/skills`, `_meta/templates`, `_meta/migration` — сливайте сами.
2. **Правки прибора в ветке — с тестами в репозитории прибора.** Код без тестов в каноне
   поддерживать нельзя: следующее слияние его так же молча потеряет. Если доступа к репозиторию
   прибора нет, приложите к MR сценарии проверки (вход → ожидаемые строки отчёта), тесты напишет
   владелец.
3. **Сторож структурных фактов перед MR:** `python _meta/tools/structural_facts.py --repo .`
   должен быть чист; новые файлы с сигнатурами реестра вносятся в потребители.

Правило будет записано в канон (`_meta/tools/README.md`, раздел о порядке правок прибора) отдельным
срезом.

## Модель НФТ: нужна записка владельцу пилота

Содержательно изменения, скорее всего, полезны: НФТ отдельным каталогом `output/<service>/nfr/`,
одна страница на тип, пробелы — долгами матрицы. Но это изменение модели комплекта, и оно прошло
без обсуждения с владельцем пилота. Вместе с каталогом убраны: раздел «Нефункциональные
требования» и префикс `NFR-NN` из шаблона фичи, `NFR` из строки условных обозначений README и из
паспорта (`passport_sync.py`), изменён шаг 5 скилла `create-brd`. У комплекта lk-mp README уже
содержит строку `US / FR / NFR / RR`, и паспорт теперь покажет расхождение.

Просьба прислать владельцу пилота короткую записку (полстраницы), чтобы подтвердить модель и
закрыть вопрос переноса на существующие комплекты:

1. Что убрано и куда перенесено (фича → страница типа; как теперь ссылаться на НФТ из фичи и
   из функции).
2. Что делать с уже мигрированными комплектами, у которых НФТ записаны внутри фич или README
   содержит `NFR`: оставить как есть до следующей миграции, перенести заходом `create-nfr`, или
   иное. Для lk-mp это нужно до переноса комплекта в `docs-lk-mp`.
3. Что скилл делает с НФТ, которые не укладываются в 18 кодов типов каталога.
4. Какие страницы Confluence считать входом НФТ при планировании (признаки из
   `prompt-plan.md`) — чтобы планировщик миграции не отправлял их в «неизвестный тип».

До записки существующие комплекты не трогаем; новые миграции идут по текущему `master`.
