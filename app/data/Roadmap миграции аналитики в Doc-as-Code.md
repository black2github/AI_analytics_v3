# Этап 1: Выгрузка аналитики из Confluence в markdown формат

**Цель**: выгрузка требований аналитики в markdown формат в привязке к задачам Jira

**Контур**: внутренний (VDI)

**Инструмент**: confluence-tree-exporter
> Видео о том, как установить и использовать: https://disk.yandex.ru/i/4vZvS0dJiukLKw. 
> Рекомендуется до просмотра попробовать сразу по инструкции внутри пакета, скорей всего сразу получится. 

**DoD**: 

- каталог выгруженных требований в виде markdown файлов и связанных файлов (например, картинок) на файловой системе.
- в случае привязки требований к задачам - отсутствие UNKNOWN-#XXXXXX отметок в отчете по цветовой привязке требований.

# Этап 3: Сохранение аналитики в архив

**Цель**: сохранение в Git репозиторий сервиса архива аналитики в markdown+ формате (с разметкой привязки к задачам, если требуется) для возможности восстановления в любое время (точка отсчета).

**Контур**: внешний

**Инструмент**: Git, GitLab

**DoD**: 

- каталог файлов требований влит в GitLab репозиторий сервиса на внешнем контуре. Путь в репозитории сервиса: \sources\raw\.

> **Важно:** в каталоге \sources\raw\ должен оказаться каталог с требованиями сервиса в markdown формате. 
> Не стоит сохранять в ZIP или любом ином формате, кроме оригинального, так как все эти файлы потребуются на следующем этапе.

# Этап 4: Восстановление истории изменения аналитики

**Цель:** воссоздание в Git репозитории сервиса истории изменения требований в markdown формате в их оригинальном составе.
Формальное начало Doc-as-Code фазы. Возможность переключения на любую ветку требований из репозитория.

**Контур**: внешний

**Инструменты:** confluence-tree-exporter бандл, Git, GitLab

**DoD**: 

- в Git репозитории сервиса созданы ветки с идентификаторами под каждую бизнесовую задачу, по которой еще не завершена реализация. Путь в репозитории сервиса: \sources\confluence\)
- все нереализованные на ПРОМе изменения аналитики (в markdown формате) связаны с веткой репозитория, относящейся к бизнесовой (или ее эквиваленту) задаче.

**Шаги**:
> Ниже по процессу предполагается, что для каждой Jira задачи с ID (например, GBO-123456) создается ветка репозитория. 
В том случае, если вы создаете ветку на каждый эпик, то используйте тот же подход, рассматривая эпик просто как набор задач.
> Все действия выполнять ТОЛЬКО над каталогом ...\sources\confluence\, каталог ...\sources\raw\ - ТОЛЬКО ЧТЕНИЕ.

1. Создать новую ветку репозитория "PROM" для ПРОМ среза требований.
2. Скопировать весь набор требований (файлов) из \sources\raw\ в \sources\confluence\
3. Получить ПРОМ срез требований: перейти в \sources\confluence\ и выполнить "run-critic.bat reject-all --path ."
4. Влить в репозиторий ПРОМ срез: закоммитить изменения и создать MR.
5. Создать новую ветку под очередную задачу в привязке к ее Jira ID.
6. Скопировать архив требований из \sources\raw\ в \sources\confluence\ (да, заново)
7. Обновить список всех "реализованных" задач, добавив ID задачи к текущему списку задач (например: GBO-ID1, GBO-ID2, TEAM-ID3, ...). На каждом шаге список будет расти, это нормально.
8. Принять ВСЕ задачи списка (а не только новые) в качестве “реализованных” (выполнить "run-critic.bat apply <ID> --path ." по всем задачам списка)
9. Исключить весь “хвост” нереализованных задач (выполнить "run-critic.bat reject-all --path .") из среза аналитики
10. Влить весь получившийся набор требований в ветку репозитория (по факту вольется только diff от предыдущей итерации, что и обеспечит версионность).
11. Если “хвост” (задачи, по которым еще не происходил apply и вливание) остался, что проверяется командой "run-critic.bat list --path .", то перейти к шагу 5. 

# Этап 5: Миграция аналитики в AI-aware формат

**Цель**: переход на полу/автоматизированное создание и сопровождение аналитики, при котором AI-агент и человек-аналитик работают совместно. 

**Контур**: внешний

**Инструменты**: Cursor / VS Code, Git

**DoD:** 

- в Git репозитории созданы ветки под каждую бизнесовую задачу, по которой действительно еще не завершена реализация.
- Идентификаторы веток отличны от веток Этапа 4 (как минимум, отметка, что другой формат аналитики).
- с веткой репозитория связаны все изменения аналитики оформленные в AI-aware формате и относящиеся к бизнесовой задаче.
- Подтверждение команды сервиса о готовности сопровождения аналитики в выбранном формате.

**Шаги**:

1. Пилот по переходу части сервисов на AI-aware формат
2. Тиражирование принятых подходов, шаблонов и инструментов на все сервисы Экосистемы.
3. Переход на этап развития аналитики совместно AI-агентами
