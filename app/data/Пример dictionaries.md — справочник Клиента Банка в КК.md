# Пример `dictionaries.md`: обращение к справочнику Клиента Банка из комплекта «Корпоративные карты»

Иллюстрация к обсуждению справочников. Скилл, создающий файл, —
`_meta/skills/create-data-model.md` (базовый поток `create-artifact` с типом
`data-model`); структура и правила — `_meta/templates/data-model.md`, раздел
«Шаблон dictionaries.md».

За основу взят живой файл референс-стенда КК
(`docs/srs/data-model/dictionaries.md`, реестр EXT-001…EXT-013). Пример сокращён
до трёх зависимостей и одного перечисления и показывает три состояния владельца
по каталогу сервисов `_meta/services.json` (срез 02.10.2026):

| Зависимость | Владелец в каталоге | Поле `repo` | Что в колонке «Адрес у владельца» |
|---|---|---|---|
| Клиент Банка | `client-dictionary` | корень репозитория `EAS/src-bank-client` | ссылка на файл сущности у владельца |
| Справочник Стран | `countryDirectory` | каталог в общем репозитории справочников | ссылка на файл справочника у владельца |
| Сотрудник клиента | `employees` | не заполнено, сервис ещё в Confluence | долг «у владельца» |

Отличия от нынешнего файла стенда — три уточнения, предложенные в правила:

1. колонка «Где ведётся» заменена на «Владелец» с `code` сервиса из каталога, а
   не свободным текстом «Экосистема»/«платформа»;
2. колонка «Внешний репозиторий» заменена на «Адрес у владельца» — абсолютная
   ссылка на файл в комплекте владельца: корень берётся из поля `repo` каталога,
   файл адресуется через `/-/blob/HEAD/…`;
3. если у владельца комплекта нет (`repo` в каталоге отсутствует) — в колонке
   адреса стоит долг «у владельца» по форме `create-artifact` с `page_id`
   страницы Confluence как временным источником.

Значения чужих справочников не копируются. Снимки реквизитов клиента в заявке
(ИНН, КПП, наименования) — атрибуты собственной сущности, каждый со ссылкой на
атрибут владельца по имени; на стенде это уже так.

# Справочники и параметры модели данных

## Общие справочники модели данных

Справочные значения и перечисления, на которые ссылаются атрибуты сущностей.
Собственные перечисления сервиса; EXT-идентификаторы не выдаются, набор значений
полный.

### Типы пользователей

Где используется: [ENT-006 История изменений 2FA операции](ent-006-2fa-operation-history.md).«Тип пользователя»; [ENT-014 История изменений Заявки на выпуск карты](../cc-card-issue/data-model/ent-014-card-request-history.md).«Тип пользователя».

Реализация: способ хранения набора не зафиксирован.

| Код | Название |
|---|---|
| `CLIENT` | Пользователь Клиента |
| `BANK` | Пользователь Банка |
| `TECHNICAL` | Автомат |

## Справочники и сущности платформы

Данные, которыми владеют другие сервисы; «Корпоративные карты» их только читает
и хранит ссылки или снимки реквизитов. Владелец — `code` сервиса из каталога
`_meta/services.json`; адрес — файл в комплекте владельца (корень — поле `repo`
каталога). Значения справочников здесь не дублируются.

### Как читать строку

- **Адрес у владельца** собирается из каталога: поле `repo` владельца даёт корень
  комплекта, дальше путь к файлу. Комплект в корне репозитория
  (`client-dictionary`): `<репозиторий>/-/blob/HEAD/docs/srs/…`. Комплект в
  каталоге общего репозитория (`countryDirectory`):
  `<репозиторий>/-/blob/HEAD/<каталог комплекта>/srs/…`. Имя ветки в адресе не
  пишется.
- **Ссылка на запись владельца** хранится в атрибуте сервиса как идентификатор
  (`[ENT-016](…).«Ссылка на сущность Клиент Банка»` — GUID клиента в Экосистеме);
  в описании атрибута — ссылка на строку реестра:
  `[EXT-002 Клиент Банка](../../data-model/dictionaries.md#реестр)`.
- **Снимок реквизитов** — собственные атрибуты сервиса с указанием, чей атрибут
  скопирован: `ИНН клиента = [EXT-002 Клиент Банка](../../data-model/dictionaries.md#реестр).«ИНН/КИО»`,
  «на дату сохранения заявки». Имя атрибута — как в модели данных владельца.
- **Коды значений** чужого справочника в требованиях и контролях указываются
  конкретными кодами со ссылкой на реестр (`… только для «Код страны» = RUS по
  [EXT-003](../../data-model/dictionaries.md#реестр)`), таблица значений в
  комплекте потребителя не заводится.
- **Долг «у владельца»** (EXT-011) снимается заменой текста в колонке «Адрес у
  владельца» на ссылку, когда у владельца появится комплект и поле `repo` в
  каталоге. Согласование владельца для этого не требуется. Тот же долг
  учитывается сводкой по владельцам инструмента проверки долгов.

## Настраиваемые параметры

Во входных страницах упомянуты параметры хешей текстов согласий, но их значения
не зафиксированы. До получения значений параметры в реестр не включены.

## Что в примере условно

- Имена файлов внутри комплектов владельцев (`ent-001-bank-client.md`,
  `srs/data-model/dictionaries.md` у справочника стран) — предположение о
  раскладке; реальные пути нужно сверить с репозиториями `src-bank-client` и
  `src-common-dictionary`.
- Адрес `repo` у `countryDirectory` в каталоге сейчас записан через имя ветки
  `master`; в примере использована правильная форма с `HEAD`.
- `service: business-cards` — `code` из каталога; на референс-стенде КК во
  frontmatter пока стоит прежний ключ `CC`.
- У EXT-011 идентификатор страницы-источника не подставлен: его берут из
  выгрузки Confluence при оформлении долга.
