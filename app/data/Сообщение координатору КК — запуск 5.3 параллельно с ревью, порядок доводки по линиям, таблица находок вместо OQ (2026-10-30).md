# Сообщение координатору КК — запуск 5.3 параллельно с ревью 5.2: порядок доводки по линиям, таблица находок вместо OQ на каждое замечание (2026-10-30)

Передаёт владелец канона. Исполнители названы в каждом пункте. Основание — отчёты ревью `sandbox/review-5.2-G1-r01…r05.md`, `G2-r01.md`, `G3-r01…r03.md` (master 828c803) и журнал координации.

---

Коллеги, прочитал отчёты 5.2 по G1, G2 и первым трём волнам G3. Отчёты держат протокол 5.1, опоры до строки, фильтр реестров работает, верификация координатором подтверждена — как список для доводки они пригодны без доработки. Числа: 66 карточек, ~186 замечаний, плотность от 1.0 до 3.6 на 100 строк против 0.46 в калибровке. По оставшимся ~300 карточкам выйдет ещё несколько сотен. Поэтому доводку 5.3 организуем сейчас, не дожидаясь конца ревью. Решения владельца канона 30.10:

**1. 5.3 стартует параллельно с 5.2, по закрытым группам.** Ревьюер продолжает очередь (остаток G1 — 20 файлов вложенных групп, G3 — bc-status 28–39 и bc-pin, затем G4–G11). Исполнитель КК начинает доводку с закрытых: G2 (20/20) и закрытая часть G1 (bc-домен 11 + scr-cl-19…28/32). Постановку на каждую группу готовит координатор (`prompts/_task-PROM-5.3-G<n>.md`), владелец канона её не пишет.

**2. Кто правит.** Почти все замечания — дефекты миграции (потеря, приписка, искажение, недословность, ложная ремарка). Они лечатся дословностью по срезу силами исполнителя, аналитики для этого не нужны. Аналитикам уходят только содержательные вопросы (ревьюер их помечает отдельно; пока таких единицы). Правило «аналитика не лечится» в силе: дефект самого источника остаётся в карточке дословно, с долгом, а не исправляется. Строку 5.3 плана (исполнитель «аналитики КК») владелец канона поправляет: исполнитель — по дефектам миграции, аналитики — по содержательным, координатор — реестры и списки находок.

**3. Дом находок — таблица на группу, а не OQ на каждое замечание.** Очередь 5.2 говорит «OQ заводятся координатором по факту подтверждения». Так делать не нужно: сотни OQ вернут CORE-20 в красную зону, которую только что закрыли. Вместо этого координатор ведёт `sandbox/fixlist-5.3-G<n>.md` — таблица «карточка | № замечания и волна отчёта | класс | решение (править / долг / снято с обоснованием) | статус | коммит», по одной строке на замечание; исполнитель заполняет статус и коммит. Это и есть доказательство для 5.5. OQ заводятся только на системные линии, по одному на линию (ниже их шесть), и закрываются первой строкой «Статус» по завершении линии.

**4. Порядок внутри группы — по линиям, от опасного к мелкому.**

- **Линия 1 — содержимое невведённых задач в ПРОМ-карточках.** Самое серьёзное: нарушает решение 0.1 о замороженном срезе. По отчётам это GBO-50272, GBO-127678, GBO-127395 (зарегистрирован только под SCR-CL-02), GBO-91555 (frozen, долг L1738 без ID карточек), GBO-81575, TEAMTB-3961, TEAMTB-3672/3673, TEAMTB-3210/3212, TEAMTB-3217, TEAMZSTCO2-15256, плюс оставшееся del-содержимое введённой TEAMTB-3633 в scr-cl-22. Причина общая: карточки собирались с копий, где разметка задач читалась как текст (серия z05 и ей подобные). Исполнитель: снять чужое содержимое по диффу raw↔срез (приём ревьюера: `git diff 717b11f 0e32b01 -- "<страница>"` плюс span-разметка raw), вернуть del-содержимое 3633. Координатор: каждую задачу из списка зарегистрировать в `sandbox/confluence-unapproved-jira-pages.md` и долг-строкой матрицы с ID карточек-держателей (долг без ID не действует — прецедент 5.1).
- **Линия 2 — потеря содержимого, блокёры.** scr-cl-22 п.3 (поле 6.1 «Подтверждения»), scr-cl-23 п.1 (кнопки B-1/B-2), fun-cl-55 строки 12–13 маппинга, остальные «потеря контента» по отчётам. Исполнитель, по срезу дословно.
- **Линия 3 — карточки с промежуточных копий.** SCR-CL-26/27 собраны с `sandbox/normalized/PIN-03/z02`, scr-bnk-05/07/13 — с norm-копии LMT-03 с вырезанными спанами; OQ-275/277/278 фиксируют состояние, которого в срезе нет. Исполнитель: переиздать со среза. Координатор: первую строку OQ-275/277/278 дополнить («зафиксированное состояние недействительно против среза 0e32b01, переиздание в 5.3»).

Исполнитель — тела карточек, координатор — матрица.
