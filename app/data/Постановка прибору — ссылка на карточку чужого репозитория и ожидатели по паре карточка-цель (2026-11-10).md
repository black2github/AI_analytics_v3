## 1. Ложное срабатывание «ссылка на ENT-NNN названием без ID» на абсолютном адресе

**Что есть.** `check_named_entity_links` (`app/scripts/CI/kitcheck/checks/links.py`) берёт
имя файла из цели любой ссылки и сверяет с образцом `ent-NNN-…`. Абсолютный адрес
карточки другого сервиса тоже попадает под образец.

**Случай.** FUN-CL-46 КК, ссылка по норме `create-artifact` («внешняя цель: карточка у
владельца существует — абсолютный GitLab URL»):

```
[Заявка на открытие доп счета и заключение ДБС](https://gitlab.gboteam.ru/EAN/docs-account-opening-request/-/blob/HEAD/srs/data-model/ent-001-request.md)
```

Прибор пишет: «ссылка на ENT-001 названием без ID … полной ссылки `[ENT-001 <название>]`
в документе нет». ENT-001 здесь — номер чужого комплекта, пространство ID у каждого
сервиса своё; текст ссылки по норме дословный.

**Что нужно.** Цель с `://` в эту проверку не входит — как уже сделано в
`check_relative_links` того же файла. Тест на срабатывание (относительная ссылка
названием без ID — ⚠ остаётся) и на НЕсрабатывание (абсолютный адрес с `ent-001-….md`).

## 2. Ожидатель долга — по паре «карточка, цель», а не по карточке

**Что есть.** `awaiters_without_debt` (`app/scripts/CI/link_debts.py`) пропускает
карточку, если её ID стоит в FROM любой строки раздела долгов. Ограничение объявлено
в комментарии к сторожу.

**Случай.** КК после снятия 40 ожидателей: сторож показывает 0, а в карточках остаются
формулы по целям без своей строки. Пять карточек (FUN-CL-27, 33, 37, 44, 49) несут
формулу по «[ЦРМ] Ролевая модель клиента» при существующей RBAC-001: у каждой есть
строка долга по другой цели. Замер по паре на `7b26035c`: 144 формулы, до 37 вхождений
в 23 карточках без пары (верхняя оценка). Перечень —
`app/data/координатор/Замер — формулы-ожидатели по паре карточка-цель, ветка exec-ozhidateli-40 7b26035c (2026-11-10).md`.

**Что нужно (к обсуждению до кода).** Признак по форме, без словаря: строка карточки с
формулой из объявленного перечня `AWAITER_FORMS`, в которой нет дословного имени ни
одной строки долга с этой карточкой в FROM, — ⚠ «формула без строки долга по этой
цели». Уровень ⚠, вердикт не меняет. Прежняя строка сторожа по карточке сохраняется
как частный случай.

Развилки на слово владельца до реализации:

- окно поиска имени — строка карточки целиком или ограниченное число знаков вокруг формулы;
- закрытая строка долга с этой карточкой в FROM при оставшейся формуле — отдельная
  строка отчёта («долг закрыт, формула осталась») или тот же ⚠;
- формулы без имени цели в окне (короткая форма после имени в кавычках иного вида) —
  считать ⚠ или информацией.

**Замер перед включением.** На КК (`7b26035c` и master) и на эталонном комплекте: число
новых ⚠ и доля ложных на выборке. Рассылка командам — по правилу «обновление утилит
канона», если сторож меняет вывод на их комплектах.

**Решение владельца 10.11 по трём развилкам п. 2 — рекомендации приняты, пункт в работу.**

- Окно поиска имени цели — строка карточки целиком.
- Закрытая строка долга при оставшейся формуле — отдельный класс «долг закрыт, формула осталась».
- Формула без дословного имени цели в строке — ⚠ «формула без дословного имени цели», не информация.

Что нужно в `app/scripts/CI/link_debts.py`: одна строка ⚠ на формулу из перечня
`AWAITER_FORMS`, у которой в строке карточки нет имени строки долга с этой карточкой в
FROM; в тексте строки — класс лечения: «дописать карточку в FROM строки долга» (цель в
открытой строке), «долг закрыт, формула осталась — заменить ссылкой», «строки долга по
цели нет — завести строку или поставить ссылку», «формула без дословного имени цели».
Уровень ⚠, вердикт не меняется. Прежняя строка сторожа по карточке сохраняется. Признак —
по форме, без словаря имён. Тесты на срабатывание каждого класса и на НЕсрабатывание
(пара есть; формула в блоке кода и в HTML-комментарии; README-реестр).

Замер: КК master `3f9abb3a` — ожидание по отчёту исполнителя 27 формул в 16 карточках
(12 / 6 / 1 / 5 / 3 по классам), расхождение объяснить; эталоны канона `e5771df` — 0.
Полный набор тестов, упавшие — против базлайна. Не коммитить; копия в канон — после
приёмки постановщиком и слова владельца.

## 3. Развилка нормы (не задача прибору до решения владельца): «ID + название» и дословная ссылка

`check_link_anchors_and_ids` считает ⚠ каждую ссылку на карточку вызова, контроля,
платформенной функции или экранной формы без ID в тексте. Основание — конвенции §5
(техбук, `standards/analytics/conventions.md`, строки 402–406): «всегда ID + название».
Норма закрытия входящих долгов (`create-artifact`) требует иного для дословных
упоминаний источника: текст ссылки = упоминание, ID-префикс не добавляется.

Что уже есть в нормах в пользу дословности: тот же §5 для ENT («дословное наименование
источника с тегом сервиса считается полноценным упоминанием и идентификатором не
дополняется — дословность, §4»); прибор пропускает подпись экранной формы с тегом
источника. Для CALL, CTL, PLT такой оговорки нет ни в конвенциях, ни в приборе.

Замер КК, master `3f9abb3a` (перепроверка 10.11, логикой прибора без усечения): 93 ссылки,
79 на карточки вызова и 14 на экранные формы. Подавляющая часть — дословные имена
источника («РКО Ф1_…», «ПЦ SVFE_СИП_…», «ТЕССА_…», «[КК_Виджет_РЕКВ] …»). Авторских или
дефектных подписей около десяти: имя файла вместо названия (`[call-ext-027]`,
`[scr-cl-14.1-limits.md]`), ID в конце подписи, подписи-вкладки («Карты», «Детали заявки»).

Варианты:

- (а) дословная ссылка остаётся без ID — оговорка §5 распространяется с ENT на CALL, CTL,
  PLT и экранные формы; прибор перестаёт считать подписи, дословность которых
  подтверждена источником, и оставляет ⚠ на авторских и дефектных. Сложившаяся практика
  КК, правок комплекта почти нет; правка конвенций в техбуке и прибора;
- (б) форма «[ID <дословное имя>]» — правка нормы закрытия долгов, переписывание около
  85 ссылок КК и такая же работа у других команд.

Рекомендация постановщика, третья редакция (10.11 ночь, по замеру со знаменателем):
вариант (б) — оговорку дословности на карточки вызова НЕ распространять. Основания: в КК
ссылок на карточки вызова 385, из них с ID 306 и без ID 79 — форма «ID + название» уже
преобладает; три дословные подписи без ID ведут на разные карточки (17 ссылок: «ТЕССА_Исходящие
параметры» → CALL-EXT-010, 018, 019; «ТЕССА_Получение карточки объекта/файла документа» →
CALL-EXT-043…046; «ПЦ SVFE_СИП_Получение детальной информации по карте» → CALL-EXT-049…051),
то есть без ID читатель не знает, какая карточка имеется в виду; у сущностей такого нет —
имя и сущность соответствуют один к одному. Конвенции и прибор при варианте (б) не меняются;
правится одна фраза правила закрытия долгов в `create-artifact` (для карточек вызова, контролей
и платформенных функций подпись — «ID + дословное имя источника») и 79 ссылок КК в строке 2.12.
Редакция «вариант (а)» была ошибкой: смотрел только на 93 срабатывания без общего числа ссылок.
До решения владельца прибор не менять; решение задаёт работу строки 2.12 плана довозки КК.

## 4. Короткая ссылка `[ENT-NNN]` без полной ссылки выше (замечание владельца 10.11; норма ПРИНЯТА владельцем 10.11)

**Что есть.** Конвенции §5: первое упоминание сущности — полная ссылка `[ENT-NNN <название>]`,
далее допустима короткая `[ENT-NNN]`, в том числе в записи атрибута `[ENT-NNN](…).«Атрибут»`.
Там же: дословное имя источника с тегом (`[[КК_ВК] Заявка на выпуск карты](…)`) считается
полноценным упоминанием и идентификатором не дополняется. Вместе эти два правила допускают
документ, где ID сущности впервые появляется уже в короткой ссылке, без названия рядом.
Прибор (`check_named_entity_links`) следует той же логике: имя с тегом засчитывается как
полная ссылка; короткая ссылка раньше полной не проверяется вовсе.

**Замер КК, master `3f9abb3a` (скрипт приёмки, не прибор):**

- пар «документ, сущность» с дословным именем с тегом — 57; в 54 короткой ссылки нет,
  в 3 есть, и во всех трёх в документе стоит и полная ссылка с ID. Сценарий замечания
  в КК сегодня не встречается, но правилом разрешён;
- короткая `[ENT-NNN]` без полной ссылки выше — 25 пар в 21 документе, 179 ссылок.
  Прибор их не показывает.

**Норма (принята).** Дословное имя с тегом остаётся допустимым упоминанием без ID, но
полную ссылку не заменяет: короткая `[ENT-NNN]` и запись атрибута `[ENT-NNN](…).«Атрибут»`
требуют более ранней полной ссылки `[ENT-NNN <название>]` в том же документе. Правку
конвенций §5 в техбуке готовит постановщик (worktree, команды владельцу) — не исполнитель.

**Что нужно в приборе.** В `app/scripts/CI/kitcheck/checks/links.py`, рядом с
`check_named_entity_links`:

- новая строка ⚠ «короткая ссылка на ENT-NNN раньше полной `[ENT-NNN <название>]`» —
  ссылка, подпись которой равна ID цели, а полной ссылки (ID и название не короче трёх
  знаков — тот же признак, что уже есть в функции) выше по документу нет; одна строка на
  пару «документ, сущность» со счётчиком вхождений;
- имя с тегом основанием для короткой ссылки не считается; для ссылки-названия без ID
  прежняя логика сохраняется без изменений (имя с тегом её по-прежнему обосновывает);
- вне проверки — то же, что у соседней функции: `README.md`, `dictionaries.md`, служебные
  файлы, блоки кода, ссылка документа на самого себя, абсолютные адреса (п. 1);
- уровень ⚠, вердикт не меняет; строка в таблице проверок `_meta/tools/README.md` канона —
  при копии в канон.

**Замер перед включением.** КК, master `3f9abb3a`: ожидание по скрипту приёмки — 25 пар
в 21 документе, 179 ссылок; расхождение с этим числом объяснить. Эталонный комплект —
число новых ⚠. Рассылка командам — по правилу обновления утилит канона, тексты готовит
постановщик после замера.

**Сдача и развилка (10.11 вечер).** Код п. 1 и п. 4 принят постановщиком, не закоммичен.
Замер эталонов канона (fac80b7): open-add-account — 14 пар в 11 документах, 103 ссылки;
inquiry — 10 пар в 5 документах, 120 ссылок. Основная масса — файлы карточек контролей:
полная ссылка стоит в головном файле документа (`controls/README.md`), части несут только
короткие, как велит шаблон `controls`. Развилка на слово владельца: (А) правило считается

ссылка головного файла засчитывается частям — прибору нужен признак части по форме
