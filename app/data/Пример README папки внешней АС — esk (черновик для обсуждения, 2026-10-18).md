# Пример README папки внешней АС: `esk/README.md` (черновик для обсуждения)

Принцип: README папки АС строится по образцу реестра `INTC-000` каталога `internal-contract/`
(шапка-указатель «что здесь / чего здесь нет» + таблица реестра), потому что внешняя АС для
Экосистемы играет ту же роль, что сервис-владелец контрактов, только снаружи. Отличие одно:
у внешней АС нет своего комплекта с концепцией, поэтому README несёт короткий ручной раздел
о системе (транспорты, адаптеры, среда), которого у `INTC-000` нет — там это в комплекте
сервиса.

Пометки `[ручной]` / `[собирает утилита]` — для обсуждения, в файл репозитория не попадают.

---

---
id: EXTINT-ESK-000
title: 'ЕСК — базовые контракты внешней АС'
type: external-integration-registry
---

# EXTINT-ESK-000. ЕСК — базовые контракты внешней АС

Здесь — базовые контракты АС ЕСК (ЦФТ ГО): описания точек обмена и форматов сообщений с
параметрами, кодами результата и примерами, одно описание на всю Экосистему.
Чего здесь нет: как сервис вызывает контракт (карточки `CALL-EXT-NNN` в комплекте
сервиса-потребителя, `srs/contract-call/external/`), маппинг на сущности сервисов, открытые
вопросы сервисов. Потребители каждого контракта — в разделе «Потребители» его карточки.

## Что откуда берётся

| Элемент | Источник | Кто ведёт |
|---|---|---|
| `id` реестра `EXTINT-<AS>-000` | по аналогии с `INTC-000` и `CALL-EXT-000` | шаблон |
| Шапка-указатель | шаблон, текст фиксированный, подставляется имя АС | шаблон |
| «О системе» | только факты из карточек папки (паспортные строки «Внешняя система», «Протокол взаимодействия») и из существующих README (gpb-smev: URL и тестовая среда); чего нет — «в источниках не задано» | аналитик |
| «Реестр точек обмена» | `id` и `title` шапки карточки (без `title` — H1 без ID, как в матрице), имя файла | утилита `--write`, аналитик руками не правит |
| «Форматы сообщений» | то же; признак формата — решение, см. вопрос 3 | утилита |
| «Примеры обмена» | ссылка на каталог; перечень файлов не дублируется | шаблон |

Чего в README нет и почему: потребителей (они в разделе «Потребители» карточки — один дом),
протокола и синхронности по строкам (они в паспорте карточки; дублировать таблицей — вторая
копия, которая разойдётся; при нужде утилита может показать сводку, не записывая её).
