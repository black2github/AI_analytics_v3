## 0. Контекст

Гейт покрытия `source_coverage.py` делит непокрытые страницы выгрузки на классы по двум последним колонкам описи `inventory.md` (целевой тип, основание): заморожено, контейнер, справочный вход, вне плана, бинарное, не в описи; остальное — пробел миграции (функция `classify`, константы `CLASS_ORDER`, регулярные выражения `_FROZEN_RE`, `_CONTAINER_RE`, `_REFERENCE_RE`). Словарь слов для описи — `prompt-plan.md`, абзац «Опись — дом классов непокрытия». Третий проход по дайджесту КК (30.10, OQ-294) показал два пробела словаря и один дефект selfcheck на глоссарии.

## 1. Класс «снято с миграции» (DELETE, [DRAFT], черновик)

Сейчас страницы, помеченные в выгрузке `DELETE`, `[DRAFT]` или «черновик», классифицируются только словом `reference-only` в основании — то есть маскируются под справочный вход (КК: индекс «DELETE РКО Ф1», пять его «Представлений», «[DRAFT] Копия 18.13.Х», «DELETE(?) Справочник кодов параметров лимитов»). Смысл другой: страница снята с миграции, её преемник или актуальная страница покрыта карточкой.

Сделать:

- новый класс `СНЯТО = "снято с миграции"` в `CLASS_ORDER` после справочных; признак — в основании или целевом типе слова `снято с миграции` либо `DELETE`/`[DRAFT]`/`черновик` в title или основании (с тем же отрицанием `_NOT`, что у остальных классов: «не DELETE» признаком не считается);
- в сводной строке отчёта и в группах — отдельный счётчик; в `--strict` класс не блокирует (как контейнеры и справочные);
- словарь в `prompt-plan.md` дополнить словами класса (одной фразой в существующем абзаце), чтобы планировщик называл снятое этими словами;
- тест: строка описи с `reference-only` и `DELETE` в title → класс «снято», не «справочные»; строка с «не DELETE» → пробел; существующие тесты классов не меняются.

## 2. Каталоги без парной страницы — отдельный класс, не «нарушение инварианта»

Отчёт печатает «каталогов без парной страницы fileN.md (нарушение инварианта имён выгрузки): N» (хвост функции сборки отчёта, переменная `orphan_dirs`). В КК таких каталогов 49, у всех есть только дочерние файлы, 44 значатся в описи родителем своих страниц; владелец канона 30.10 принял их как узлы дерева выгрузки, выгрузку не переснимать. Формулировка «нарушение инварианта» заставляет каждый раз разбираться заново.

Сделать:

- печатать как класс «каталоги-узлы без собственной страницы: N» с пояснением в одну строку: «у каталога есть дочерние страницы, собственной страницы в выгрузке нет; текста среза не несёт; возможная причина — страница не выгружена экспортёром (пустая или без доступа)»; список оставить;
- отдельно (если таких нет — не печатать) — каталоги без страницы и без дочерних `.md` (пустые) — вот это дефект выгрузки, оставить прежнюю формулировку только для них;
- `--strict`: как сейчас (не блокирует);
- тест: каталог с детьми и без страницы → класс «узел»; пустой каталог → «дефект выгрузки».

## 3. `selfcheck.py`: исключения для документа типа `glossary`

При заходе глоссария КК (29.10) selfcheck метил `docs/glossary.md` двумя сторожами, и карточку пришлось подгонять:

- сторож полноты кавычечных литералов источника (область около строк 813–835, `quoted_literals`): требовал дословного присутствия 17 цитат со страницы «[КК] Глоссарий» в тексте глоссария. Глоссарий — документ определений, а не дословный перенос страницы; шаблон канона `_meta/templates/glossary.md` требует атомарных определений и делегирования реестров, то есть сокращения источника;
- сторож выносок `>` (blockquote) метил строку делегирования «> Полный справочник … — в …», которую сам шаблон глоссария предписывает (раздел «Шаблон glossary.md», строка после таблицы).

Решение владельца канона 30.10: для документов `type: glossary` (и `domain-vision.md`/`glossary.md` домена, где применимо) оба сторожа не применяются: литералы — не проверять (информационная строка «i glossary.md: сторож литералов не применяется к глоссарию»), выноска-делегирование по шаблону — допустима. Остальные проверки глоссария (ссылки, frontmatter без `status`, H1, отсутствие `OQ-`/`sources/`) остаются.

Сделать: исключение по `type` из frontmatter, не по имени файла; тест на глоссарий с выноской и неполными литералами → ✓; тест на обычную карточку с теми же признаками → прежние ✗/⚠. Эталонный глоссарий канона (комплект-эталон) после правки должен проходить ✓.
