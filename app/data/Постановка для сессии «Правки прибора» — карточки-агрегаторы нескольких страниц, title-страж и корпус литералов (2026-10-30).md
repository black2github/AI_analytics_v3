## Задача 1. Title-страж для карточек-агрегаторов

Дом: `_meta/tools/kitcheck/checks/card_source.py`, `check_title` (строка ~552); вызов — `kitcheck/checks/card_run.py` (~442). Сейчас: дословное равенство title карточки title главной страницы; единственное исключение — базовый контракт `external-integration` без маркера контура.

Правило (решение владельца 30.10, рекомендация 1 в уточнённой форме):

- карточка считается **агрегатором**, если во frontmatter больше одной `confluence_page_ids` **или** файл называется `dictionaries.md` (шаблон data-model, одна или несколько страниц);
- для агрегатора title принимается, если **наименование каждой страницы-источника присутствует в карточке дословно заголовком раздела** (`##`/`###`; сравнение той же нормализацией, что и у title: без учёта кавычек-обёрток frontmatter, пробелов по краям). Корпус поиска — объединение файлов группы (`combined`), как у литералов;
- равенство title главной странице по-прежнему проходит первым (glossary.md с тремя страницами сегодня ✓ именно так — поведение не менять);
- не-агрегатор (одна страница, имя файла не `dictionaries.md`) — без изменений: расхождение title остаётся ✗ (тест на НЕсрабатывание обязателен);
- строки отчёта: `title: карточка-агрегатор N страниц — наименования источников заголовками разделов ✓` / `title: карточка-агрегатор N страниц — нет заголовков по страницам: '<title 1>'; '<title 2>' ✗ ПОТЕРЯ НАИМЕНОВАНИЯ`.

Где взять title дополнительных страниц: сегодня selfcheck сверяет только главную (строка отчёта «доп. страницы-источники (N) механически не сверяются»); индекс page_id → файл источника в selfcheck есть (`idx`). Нужен способ передать в `check_title` перечень title всех страниц группы — сигнатуру расширить необязательным аргументом, CLI `normalize_tables.py --check` (один источник) должен работать как раньше.

Норма: `_meta/templates/data-model.md`, строка ~30 (`title: '<дословное наименование из title главной страницы-источника>'`) — дополнить одной строкой: для `dictionaries.md` title — собственное наименование файла («Справочники …»), наименования страниц-источников — дословно заголовками разделов. Та же фраза — в docstring `check_title`.

Ожидание на КК 1402d3d: четыре ✗ title **остаются** до захода команды (в словарях и CALL-INT заголовков по страницам сегодня нет), но текст ✗ меняется на «нет заголовков по страницам: …» с перечнем — это и есть задание команде. В сдаче привести этот перечень по четырём файлам.

## Задача 2. Корпус литералов — все артефакты той же страницы

Дом: `kitcheck/checks/card_run.py`, ~506–522: `sib_txt` = соседние `*.md` каталога карточки (только в selfcheck-режиме, `docs_root` задан); `check_quoted_literals(..., sibling_text=sib_txt)` в `card_source.py` (~455); строка отчёта «i кавычечные литералы ×N найдены в соседних карточках каталога, не в группе сверки».

Правило (рекомендация 2): в корпус поиска литералов добавить **все карточки комплекта, у которых главная страница группы есть в `confluence_page_ids` (в любой позиции)**, не только каталог. Пример: группа PROC-047 (главная 2166861145) — GLO-001 `docs/glossary.md` имеет 2166861145 третьим id → литералы «запомнить», «исчезновению», «исчезновения», «подписание пакета» найдены там. Группы selfcheck строятся по `pids[0]` (`selfcheck.py` ~440), поэтому нужен отдельный полный индекс page_id → файлы по всем позициям; строить один раз в контексте selfcheck, не на каждую карточку (392 файла × 392 чтений — недопустимо).

Отчёт: отдельная строка `i кавычечные литералы ×N найдены в артефактах той же страницы (<файлы>), не в группе сверки` — отличать от «соседних карточек каталога», чтобы приёмка видела разложение по решению, а не по соседству.

Ограничитель и тест на НЕсрабатывание: литерал, которого нет ни в группе, ни в каталоге, ни в артефактах страницы, — ✗ как сегодня; артефакт с той же страницей, но без литерала, ничего не меняет. `_NO_LITERALS_TYPES` (glossary, domain-vision) — без изменений: освобождён сам глоссарий, а не карточки, чьи литералы в нём лежат.

Ожидание на КК 1402d3d: ✗ PROC-047 → ✓ (или ⚠, если останутся другие причины — перечислить); итог ✗ 9 → 8.
