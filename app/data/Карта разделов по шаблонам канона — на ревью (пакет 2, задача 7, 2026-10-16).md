## Что видно из карты и что нужно решить

1. **Только шесть шаблонов дают пометку обязательности** (агент, контроли, функция,
   нотификация, экранная форма, платформенные функции — у последней без пометок). Для
   остальных обязательность можно вывести только из H2 образца, а образец показывает
   полный вид, а не минимум. Вопрос: считать ли все H2 образца обязательными или сторож
   ограничить шестью шаблонами с явной пометкой?
2. **Процесс, печатная форма и НФТ** не дают ни пометок, ни образца карточки. Сторож для
   них невозможен без правки шаблонов. Вопрос: добавлять ли в эти шаблоны раздел
   «Структура документа» с пометками (дом — шаблон, волна 6)?
3. **Шаблон статусной модели** использует тот же `type: process`, что и процесс, а разделы
   у них разные. Сторож по типу смешает их. Вопрос: различать по имени файла
   (`status-model.md`) или вводить свой тип?
4. **Экранная форма — группа файлов** (README-оглавление, главная карточка, части): по
   решению 30.08 разделы распределены между главной карточкой и частями. Проверка
   «у каждого файла все обязательные разделы» даст ложные сигналы у частей. Вопрос:
   проверять обязательные разделы по объединению файлов группы? Строки
   «FLD-1, FLD-5…» и «FLD-4…» в разделе «Структура» шаблона — заголовки примеров, не
   разделы; в карте их надо исключить.
5. **«Обязательный» и «неприменимый раздел опускается целиком».** Скилл `create-artifact`
   велит опускать неприменимый раздел целиком; с нормой §6 п.5 стандарта
   «обязательный» означает «обязательный в структуре, при отсутствии данных — формула».
   Вопрос: отсутствие обязательного раздела — ⚠ «нет раздела», а раздел с одной формулой
   «в постановке не задано» — законный?
6. **Нумерация разделов** («1. Назначение» в шаблоне, «Назначение» в карточке):
   сравнение заголовков — без номеров и регистра, как в пакете.

Предложение до решения: сторож только для шести шаблонов с явной пометкой «(обязательный)»,
экранная форма — по объединению группы, частям без собственных обязательных разделов
сигнал не выдаётся; раздел «вне шаблона» — к сведению (i), не ⚠.

## Решения владельца канона (2026-10-16) и как они исполнены

Карта остаётся основанием сторожа `check_required_sections` (selfcheck, пакет 2, задача 7).

1. **Решено:** сторож работает только по шаблонам с явной пометкой «(обязательный)». Это
   агент, контроли, функция, нотификация и экранная форма. Платформенные функции без
   пометок в карту не входят. H2 образцов обязательными не считаются.
2. **Процесс, печатная форма и НФТ** в этот заход не входят. Карта для них расширяется
   после правки шаблонов.
3. **Решено:** статусная модель различается по имени файла `status-model.md` (ID `SM-*`).
   Сторож её не проверяет.
4. **Решено:** экранная форма проверяется по объединению файлов группы. Группа — ID без
   суб-номера: README группы без шапки, главная карточка и части. Частям отдельного
   сигнала нет. Строки «FLD-1, FLD-5…» и «FLD-4…» исключены как заголовки примеров.
   README-реестры каталогов с ID на «-00» и «-000» не проверяются.
5. **Решено:** отсутствие обязательного раздела даёт ⚠ «нет раздела». Раздел, где только
   формула «в постановке не задано», законен: сторож проверяет заголовок, не содержимое.
6. **Решено:** заголовки сравниваются без номеров, регистра и ё/е. Раздел вне шаблона даёт
   строку «i», не ⚠.

Уточнения при исполнении, по тексту шаблонов:

- **Условные разделы экранной формы** не требуются: «Видимость блоков» (если блоков больше
  одного), «События», «Кнопки», «Сообщения», «Функции формы». Условие по тексту не
  проверяется. Безусловно обязательны «Назначение», «Реестр полей» и «Правила полей».
- **Заглушка экранной формы** по шаблону несёт только «Назначение» и строку
  «Документ-заглушка: …». Для неё сторож требует только «Назначение».
- **Перед именем раздела снимается ID**, например «NTF-AGR-01. Сообщения нотификации».
- **Раздел «вне шаблона» у функции не выводится:** шаблон разрешает дополнительные H2.
  У экранной формы к известным разделам добавлены разделы README и главной карточки из
  описания ролей файлов шаблона: «Части», «Макеты ЭФ», «Как перейти», «Структура
  экрана», шаги открытия и закрытия, «Группы контролей уровня формы», «Определения».
- **Документ контролей** проверяется по каталогу: README `CTL-000` и файлы карточек.
