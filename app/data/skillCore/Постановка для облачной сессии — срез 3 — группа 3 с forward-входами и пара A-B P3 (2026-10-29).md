### 1. Переворот пяти скиллов группы 3 — дополнений к `create-artifact`

Файлы: `create-data-model.md`, `create-contract-call.md`, `create-controls.md`, `create-rbac.md`, `create-print-form.md`.
Отличие от групп 1–2: у этих скиллов нет своего «Порядка» — общие шаги исполняет диспетчер (`create-artifact` с типом),
скилл несёт «Вход» и «Специфику типа (дополнение к create-artifact)» с подразделами «Reverse — …», а forward-входа в них
нет вовсе (строка «Режим: reverse или forward (как в create-artifact)»). Каркас применяется так:

- **`## Вход`** — как есть; строка режима дополняется `change` там, где в скилле есть раздел «Режим C — change»
  (`create-data-model`, `create-contract-call`, `create-controls`, `create-print-form`; у `create-rbac` режима C нет —
  строку не трогать); пункт чтения шаблона типа — по каркасу («Прочитай шаблон `_meta/templates/<тип>.md` целиком,
  включая чек-лист»): это новый пункт, которого в дополнениях не было, — связка, в таблицу с объяснением «предусловие
  любого режима по каркасу `create-skill.md`».
- **`### Вход reverse (режим A)`** — подразделы специфики, названные «Reverse — …», переезжают сюда целиком и дословно,
  с сохранением своих заголовков уровнем ниже (`####`): `create-data-model` — «Reverse — порядок сборки (с логического
  уровня)»; `create-rbac` — «Reverse — где искать в коде» и «Reverse БЕЗ кода (клонов в контуре нет)»; `create-controls`,
  `create-print-form` — «Reverse — источник»; `create-contract-call` — пункты «Reverse base», «Сырые HTML-таблицы источника
  (проход 1 …)» со всеми шестью шагами и «Reverse call» из раздела «Reverse / forward». Это то же правило, что в срезе 2:
  сбор, нормализация и адаптация источника — вход режима A. Остальные подразделы специфики (объём и согласованность,
  группы контролей, макеты, данные, связанные документы, структура и таблицы, glossary, scope, контуры и пути
  `create-contract-call`) — на месте: они не зависят от режима.
- **`### Вход forward (режим B)`** — новый текст по SC-04, строка в строку из колонки «Предложение» таблицы SC-04 для
  своего типа (все пять приняты владельцем 2026-10-29), оформленный пунктами списка; последний пункт — «Правила
  проектирования — шаблон `_meta/templates/<тип>.md`, раздел „Проектирование с нуля“; далее — „Порядок“ `create-artifact`
  целиком». У `create-contract-call` строка «**Forward:** base → call → потребители» из «Reverse / forward» переезжает
  сюда первым пунктом (дословно). Текст SC-04 не редактировать и не дополнять; если формулировка SC-04 противоречит
  тексту скилла или шаблона — вопрос в `questions.md`, срез для этого файла стоит.
- **`## Порядок`** (решение владельца Р-1: вариант (а)) — раздел из одного абзаца, дословно: «Общие шаги — „Порядок“
  скилла `create-artifact` (тип `<тип>`): документ по шаблону, матрица, спорные места, чек-лист, selfcheck, отчёт, коммит.
  Специфика типа — разделы ниже.» (`<тип>` — значение типа диспетчера для этого скилла). Это новый абзац — связка, в
  таблицу.
- После подразделов «Вход» и «Порядка» — «Специфика … (дополнение к create-artifact)» без подразделов
  «Reverse — …», затем «Режим C — change», «Самопроверка», «Выход аналитику» — на месте. У `create-contract-call` раздел
  «Reverse / forward» после переноса пунктов пуст — заголовок снимается (связка, в таблицу); «Пути», «Gate», «Внешний
  репо недоступен…», «Контур base/call/both» — на месте, порядок разделов не менять.
- Правила переноса те же: текст дословно, связки — таблицей «было → стало» с объяснением, ничего не сокращать и не
  добавлять сверх пункта чтения шаблона и текста SC-04. Внешние ссылки: grep по `canon/` без `output/` и `sources/`
  (`режим\S* [AB]`, `шаг\S* \d`, имена снятых подразделов «Reverse — …», «Reverse / forward») — таблицей в сдаче; ссылка
  снаружи на раздел одного из пяти файлов — вопрос, не правка (SC-03). `create-contract-call` — потребитель реестра
  структурных фактов (три строки реестра): если сторож SF даёт ⚠ по сигнатуре из-за перемещения строк — реестр точечно
  в том же коммите, с объяснением.

Проверки как в README против baseline шага 0: SF код 0, оба selfcheck байт в байт, pytest 0 failed. Остановки по SC-07.
