# Два слоя канона: что остаётся сервису после переноса в репозиторий документации и как теперь читать отчёт selfcheck

Дата: 2026-10-31. Адресат — аналитики команд, работающие по канону Doc-as-Code; в первую очередь команды, чей комплект
уже перенесён или готовится к переносу из рабочего репозитория `src-<service-id>` в репозиторий документации
`docs-<service-id>`.

## Проблема

Канон вырос из миграции: рядом с шаблонами, скиллами и правилами, которые нужны сервису всегда, лежат инструменты
выгрузки и сверки с Confluence, гид миграции и сторожа дословности. После переноса комплекта в `docs-<service-id>`
выгрузки рядом нет, но до сих пор ни документы, ни прибор не говорили, что из этого больше не применимо. В отчёте
`selfcheck.py` на каждой карточке стоял хвост «без источника (page_ids нет — forward/реестр)», а на каждой карточке,
перенесённой из Confluence, — «источник page_id … не сверялся — `--sources` не задан»; эти строки читались как брак,
хотя браком не были, и приучали пропускать отчёт целиком.

## Что изменилось

1. **Правило двух слоёв записано в канон.** Гид миграции `_meta/migration/reference.md`, раздел «Два слоя канона:
   ядро и миграционный конвейер»: что такое ядро (шаблоны, скиллы с режимами forward и change, правила, реестры,
   общие инструменты прибора), что такое миграционный конвейер (каталог `_meta/migration/`, инструменты выгрузки и
   сверки, ветвь прибора с `--sources`), по какому признаку слой на сервисе считается выключенным и что это значит.
   Признак вычисляется по раскладке репозитория, заводить ничего не нужно: в `docs-<service-id>` матрица
   трассировки лежит в корне, каталога `docs/` нет — этого достаточно, так же этот режим распознаёт гейт переноса.
2. **Таблица «Слои прибора»** в README прибора `_meta/tools/README.md`: по каждой утилите — слой, когда она
   запускается и как ведёт себя без выгрузки. Утилиты миграционного слоя несут в шапке файла строку
   `Слой: миграция`; на комплекте без выгрузки их не запускают.
3. **Отчёт `selfcheck.py` без `--sources` больше не говорит об источнике в строках карточек.** Хвосты «без
   источника (page_ids нет…)» и «источник page_id … не сверялся» сняты, строка о сверке сообщений карточек контролей
   без выгрузки не печатается. Вместо них одна строка на комплект: сколько карточек имеют происхождение из
   Confluence (`confluence_page_ids`) и команда включения сверки по архиву; перечень этих карточек — в файле
   `--out`. Вердикт и число ✓/✗/⚠ от этого не меняются. С ключом `--sources` отчёт прежний.
4. Две формулировки стали нейтральными: ✗ «`confluence_page_ids` задан, но id не распознаны» теперь объясняет, что
   не читается ключ сопоставления по странице (он нужен и после переноса — по нему изменения на страницах, которые
   ещё дорабатываются в Confluence, находят свои карточки); предупреждение о маркере сокращения без выгрузки просит
   проверить полноту перечня, а не перенос из источника.

## Что делать командам

- **Комплект ещё в `src-<service-id>`, выгрузка есть.** Ничего не меняется: `selfcheck.py` с `--sources`, гейт
  переноса, сканы — как прежде.
- **Комплект в `docs-<service-id>`.** Прогон самопроверки — из корня клона репозитория документации, без
  `--sources`:

  ```
  python <клон docs-o2new>\_meta\tools\selfcheck.py --docs . --out reports\selfcheck.txt
  ```

  Ожидание: строки карточек без хвостов об источнике; перед итогом одна строка «карточек с происхождением из
  Confluence: N» — это справка, не замечание; вердикт складывается только из внутренних сторожей. Миграционные
  утилиты (`scan_*`, `source_coverage.py`, `source_inventory.py`) на таком комплекте не запускать — они ищут
  дефекты переноса, которого здесь уже нет.
- **Пришла новая выгрузка страницы, которая дорабатывалась в Confluence после переноса.** Это не повторный перенос,
  а точечное включение сверки: reverse-скилл по карточке с ключом `--sources` на архив рабочего репозитория, правка
  — в `docs-<service-id>`:

  ```
  python <клон docs-o2new>\_meta\tools\selfcheck.py --docs . --sources <клон src-<service-id>>\sources\confluence --out reports\selfcheck.txt
  ```

  Карточка-адресат находится по `confluence_page_ids` — поэтому поле из шапок перенесённых карточек не снимается.
- **Новая постановка на уже перенесённый комплект** — режим C (change) диспетчера `create-artifact`, как и раньше;
  слой здесь ни при чём.
