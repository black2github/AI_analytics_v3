### 1. Переворот шести скиллов группы 2 по образцу `create-function`

Файлы: `create-screen-form.md`, `create-internal-contracts.md`, `create-notification.md`, `create-nfr.md`,
`create-agent.md`, `create-lib-contract.md` (седьмой скилл группы, `create-function`, сделан в срезе 0). Каркас — из
`create-skill.md` (`## Вход` с пунктом чтения шаблона → `### Вход reverse (режим A)` → `### Вход forward (режим B)` →
`## Порядок` 1…N → остальные разделы как были). Правила переноса те же: текст шагов дословно, связки — в таблицу
«было → стало» с объяснением, нумерация «Порядка» сквозная, ничего не добавлять и не сокращать.

Особенности файлов, которые видно по заголовкам (реши по каркасу, решения — в сдачу; где каркас не даёт ответа —
вопрос в `questions.md`, срез стоит):

- **`## Gate`** (`create-screen-form`, `create-notification`, `create-nfr`, `create-agent`): это проверка
  предусловий до работы. Если условия Gate не зависят от режима — раздел остаётся отдельным `## Gate` сразу после
  подразделов «Вход» и перед `## Порядок`; если внутри Gate есть пункты только для reverse или только для forward —
  вопрос.
- **Разделы `## Forward`** (`create-internal-contracts`, `create-notification`, `create-agent`, `create-lib-contract`)
  с отсылками «далее шаги N–M reverse», «Гейт шага N»: содержание уходит в «Вход forward (режим B)», отсылки
  становятся «далее — „Порядок“ целиком» или «„Порядок“, шаг N» с новым номером (связки).
- **`create-nfr`**: разделы называются «Шаги `ingress: reverse` и `ingress: update` по переносу» и «Шаги `ingress:
  forward`». Значения `ingress` — поле шапки NFR, их не переименовывать. Каркас применяется так: сбор источников для
  `reverse`/`update` → «Вход reverse (режим A)» (оговорки про `update` остаются внутри подраздела, это вариант
  переноса), подготовка входа для `forward` → «Вход forward (режим B)», общие шаги → «Порядок». В заголовках
  подразделов сохрани упоминание значений `ingress` в скобках, чтобы связь с полем шапки не потерялась:
  «### Вход reverse (режим A; `ingress: reverse`, `update`)», «### Вход forward (режим B; `ingress: forward`)».
  Если шаги `update` не отделяются от общих без переписывания — вопрос.
- **`create-screen-form`** содержит `## Режим C — change`: переносится как в диспетчере (на месте, связки «правила
  режима A» → «„Порядок“ и правила всех режимов»; «далее шаги 4–10 режима reverse» → «„Порядок“ целиком»).
- Разделы «Самопроверка», «Выход аналитику», «Границы скоупа», «Правила всех режимов» — на месте.
- Внешние ссылки: после правок grep по `canon/` без `output/` и `sources/` (`режим\S* [AB]`, `шаг\S* \d`,
  `Порядок \(reverse\)`, `Порядок \(forward\)`, `## Forward`) — таблицей в сдаче; ссылка снаружи на номер шага или
  раздел одного из шести файлов — вопрос, не правка (SC-03).

Проверки как в README: SF (код 0, `cmp` с baseline; ⚠ по сигнатуре в файлах объёма — реестр точечно в том же
коммите, с объяснением), оба selfcheck байт в байт, pytest 230 passed. Остановки по SC-07.
