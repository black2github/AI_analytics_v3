# Командам и координаторам комплектов: режим change в диспетчере скиллов — тот же «Порядок», другой вход

Дата: 2026-11-01. От владельца методологии. Адресаты: все команды и координаторы. Практически касается тех,
кто ведёт комплект в репозитории документации `docs-<service-id>` и работает скиллом `/change`
(Cursor или Claude Code); остальным — к сведению, порядок заходов reverse/forward не меняется.

## Проблема

В диспетчере скиллов `_meta/skills/create-artifact.md` режим change (изменение комплекта по постановке
аналитика) был описан отдельным разделом из восьми шагов. Он повторял общий «Порядок» захода со своими
отличиями, а другие части канона ссылались на него номерами шагов («режим C, шаг 6»). Результат захода
по постановке при этом тот же, что у forward: документ по шаблону, матрица, самопроверка. Различается
только вход — аналитик даёт ЧТО ИМЕННО править, а не общую цель. Два описания одной процедуры
расходились при каждой правке, а ссылки по номерам ломались при любой перестановке.

## Что изменилось (срез канона `2b0f93e` от 01.11)

- Во «Входе» `create-artifact.md` теперь три подраздела: «Вход reverse (режим A)», «Вход forward (режим B)»
  и «Вход change (режим C)». Вход change — прежние шаги постановки, разбора по домам («Факты по домам»
  в `tasks/<JIRA-ID>.md`) и вопросов до правок, текст дословно прежний.
- «Порядок» один для всех входов. Правила захода по постановке стоят внутри шага документа под ярлыком
  «есть `tasks/<JIRA-ID>.md`». Самопроверка и сдача ветвятся по состоянию комплекта, а не по режиму:
  в новом комплекте (`src-<service-id>`, миграция идёт) — резюме, вердикт `NOT READY` допустим;
  в принятом комплекте (`docs-<service-id>`, матрица в корне) — гейт переноса обязателен, сдача —
  отчёт дельты с происхождением, `NOT READY` не сдаётся.
- Раздел «Режим C — change (изменение по постановке)» остался под тем же заголовком как точка входа,
  но стал коротким: когда применяется, состав захода («Вход change» → «Порядок» целиком → надстройка
  скилла типа), запреты режима, ссылка на гид переноса.
- Ссылки по номерам шагов заменены именами шагов: в 13 скиллах типов, шаблоне постановки `task.md`,
  правилах вопросов `questions.md`, гиде `reference.md`, шаблоне `.cursor/` и подсказках прибора
  `delta_report.py` (подсказки прибора идут следующим MR; поведение прибора не меняется).

Что не меняется: результат захода, форма отчёта дельты и матрицы, долги, гейт, команды `/change`
и `/delta-report`.

## Что сделать команде

1. Принять срез канона обычным порядком (`accept_canon`, baseline): master `2b0f93e` или новее.

2. Обновить локальную обёртку `.cursor/` (и `.claude/skills`, если есть) из шаблона канона. Старая копия
   `skills/change/SKILL.md` ведёт агента к шагам 1–8 режима C, которых в скилле больше нет. Из корня
   клона `docs-<service-id>` в PowerShell, канон лежит рядом как `..\docs-o2new`:

   ```powershell
   git -C ..\docs-o2new switch master; git -C ..\docs-o2new pull
   ```

   ```powershell
   Copy-Item -Recurse -Force ..\docs-o2new\_meta\templates\cursor\skills .cursor\skills; Copy-Item -Recurse -Force ..\docs-o2new\_meta\templates\cursor\commands .cursor\commands; Copy-Item -Recurse -Force ..\docs-o2new\_meta\templates\cursor\rules .cursor\rules
   ```

   Ожидание: в `.cursor\skills\change\SKILL.md` ссылки ведут на разделы «Вход change (режим C)» и «Порядок»
   `create-artifact.md`. Каталог `.cursor/` в git не добавляется (локальное исключение, как при установке).

3. В своих постановках и заметках ссылки вида «режим C, шаг N» заменить именами: шаги 1–3 → «Вход change»
   (постановка, разбор постановки, вопросы до правок); шаги 4–8 → «Порядок» (документ по шаблону, матрица
   трассировки, чек-лист шаблона, самопроверка перед сдачей, сдача).

Вопросы и расхождения — записью в `feedback.md` сервиса обычным порядком.
