# Постановка для сессии прибора: сторож имён параметров HTML-таблиц принимает значение таблицы-паспорта за имя параметра

Дата: 2026-10-29. Источник: пара A/B P2 трека skillCore (четыре независимых захода `create-function` reverse по карточке
FUN-CL-02 эталонного комплекта `open-add-account`). Передаёт владелец в сессию прибора; трек skillCore прибор не правит.

## Проблема

`selfcheck --sources` по карточке функции даёт ✗ «HTML-таблицы источника: в карточке отсутствуют 1 имён параметров ✗
НИЖЕ ПОРОГА — пример потери: 'CLIENT_CONTRACT_VIEW'». На странице источника
(`sources/confluence/o2plus/Функции-системы/Функции-Клиента/Клиент-Функция-просмотра-заявки.md`) единственная
таблица — паспорт функции: две колонки, слева жирные лейблы с двоеточием («Доступность функции:», «Как вызывается
функция:», «Входящие параметры функции:», «Что делает функция:», «Код привилегии:»), справа значения. Строки
«Код привилегии: `CLIENT_CONTRACT_VIEW`» достаточно, чтобы `html_param_names()` (`app/scripts/CI/normalize_tables.py`)
записала значение в обязательные имена параметров: функция берёт первые две ячейки каждой строки со второй у каждой
верхней HTML-таблицы и проверяет токен только регулярным выражением имени.

Канон при этом требует обратного: шаблон `function.md` («Роль и привилегия») — код привилегии **из `rbac.md`
комплекта, не со страницы источника**, расхождение — в open-questions; OQ-023 эталона решён: `CLIENT_CONTRACT_VIEW` —
имя Java-константы, не код привилегии. Правило диспетчера `create-artifact` («Правила всех режимов») запрещает
вписывать имя источника в чужую строку ради гейта полноты. Итог: честно сделанная по шаблону карточка не проходит
сторож, а проходит только карточка с вписанной константой (так и сделали два захода из четырёх — маскировка потери
по определению канона). Эталонная карточка FUN-CL-02 ✗ не ловила, потому что у неё нет `confluence_page_ids`.

## Воспроизведение

В клоне канона: в шапку `output/open-add-account/docs/srs/functions/client/fun-cl-02-view-request.md` добавить
`confluence_page_ids: [2166863992]` и прогнать
`python _meta/tools/selfcheck.py --docs output/open-add-account/docs --sources sources/confluence/o2plus` — строка ✗ по
карточке с примером потери `'CLIENT_CONTRACT_VIEW'`. Готовые комплекты четырёх заходов с `selfcheck.txt` — зеркало
`black2github/skill-core-cloud`, ветка `skill-core/2-group2`, `skillCore/ab/P2/<до|после>-<1|2>/`.

## Что сделать

1. Исключить таблицы-паспорта из сбора имён параметров: таблица без строки заголовка, две колонки, в первой — лейблы
   (жирный текст и/или двоеточие на конце) — это «лейбл | значение», а не сетка параметров. В том же модуле паспорт
   уже распознаётся для проверки значений (`plain_passport`, сообщение «таблица-паспорт … значения проверены») —
   использовать тот же признак, не вводить второй.
2. Ограничитель и тест на НЕсрабатывание (асимметрия ошибок): настоящая двухколоночная сетка параметров с заголовком
   («Параметр | Описание», «Имя | Тип»…) ловиться должна по-прежнему; кейс инцидента 2026-08-12 (MFlash «Подготовка к
   загрузке», потеря `file_id`/`upload_token`) — обязательный регрессионный тест, если его нет в `tests/`.
3. Прогон: релевантные тесты `tests/test_selfcheck*.py`, `tests/test_normalize*.py`; сверка с эталоном `C:/tmp/tool-golden`
   (0 отличий, кроме строк этого сторожа по карточкам с паспортом — перечислить); selfcheck эталона `open-add-account`
   и КК до/после — дельта только по этому классу.
4. Дома: прибор analyzer → копия в `_meta/tools` канона (сверить все общие файлы с origin/master перед копией) → бандл.
   Сообщение коммита канона — для всех команд: проблема (паспорт функции принимался за сетку параметров, карточки с
   кодом привилегии по `rbac.md` получали ложный ✗) → что меняется.

## Не делать

- Не менять шаблон `function.md` и правило диспетчера под сторож (вариант «разрешить пометку написания источника» —
  это узаконить маскировку).
- Не добавлять стоп-слово `CLIENT_CONTRACT_VIEW` или строку «Код привилегии» точечно: дефект — в признаке таблицы, а
  не в токене.
