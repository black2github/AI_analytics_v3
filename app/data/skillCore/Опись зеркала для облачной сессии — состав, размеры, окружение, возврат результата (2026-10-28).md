# Опись зеркала для облачной сессии: состав, размеры, окружение, возврат результата

Дата: 2026-10-28. Трек skillCore (переворот структуры скиллов канона, п. 1 предложения от 28.10). Канон на момент
описи — master `a1190f2`; analyzer `febc6347`.

## Принцип

Облачная сессия работает в одном частном репозитории GitHub `skill-core-cloud`, собранном из плоских копий (без
вложенных `.git`), с манифестом исходных коммитов. В нём есть всё, что нужно для правки скиллов, проверки сторожами и
прогона плеч A/B; нет ничего, что требует доступа в контур (GitLab, Confluence, бандл экспортёра). Analyzer уже лежит
на GitHub (`black2github/AI_analytics_v3`), но в зеркало берётся только прибор и нужные тесты — чтобы сессия
работала в одном репозитории и не трогала код прибора.

## Окружение сессии

- Python 3.12, `pip install -r requirements.txt` (только `beautifulsoup4` и `pytest`; сети прибору не нужно).
- Переменная `PYTHONIOENCODING=utf-8` на все запуски (кириллица в выводе).
- Команды, которые сессия гоняет после каждого среза (из корня зеркала):

```
python -m app.scripts.CI.structural_facts --repo canon --strict
python -m app.scripts.CI.selfcheck --docs canon/output/open-add-account/docs --sources canon/sources/confluence/o2plus --out skillCore/selfcheck-etalon-<срез>.txt
python -m app.scripts.CI.selfcheck --docs polygon --out skillCore/selfcheck-polygon-<срез>.txt
python -m pytest tests -q -o addopts=""
```

  Ожидание по двум selfcheck: вывод байт в байт как до среза (прибор скиллы не читает) — это контроль, что сессия не
  задела комплекты. Сторож SF: ⚠ только по сигнатурам, которые переформулированы намеренно, с правкой реестра в том
  же коммите.

- Исполнители плеч A/B — отдельные подагенты с чистым контекстом (см. файл решений, SC-05). Им доступен только
  `canon/` (скиллы, шаблоны, правила) и вход плеча; каталог `skillCore/` им не показывается.

## Возврат результата в контур

1. В зеркале на каждый срез — ветка `skill-core/<N>-<имя>`; коммиты только по путям `canon/…` (правки канона) либо
   только по `skillCore/…` (сдачи), не вперемешку. Сообщения коммитов — для всех команд (сначала проблема, потом что
   меняется), без AI-трейлеров: они поедут в канон как есть.
2. Владелец: `git fetch` зеркала → `git format-patch <база>..skill-core/<N> -o <каталог>` → в клоне канона на ветке
   `meta/skill-core-<N>`: `git am -p2 <каталог>/*.patch` (срезается префикс `canon/`). Переводы строк: в зеркале блобы
   CRLF (собрано из рабочей копии с autocrlf), поэтому там патч ложится только с `--keep-cr`; в клоне канона владельца
   индекс LF при `core.autocrlf=true`, и ложится обычный `git am -p2` (проверено 29.10 на срезах 0+1: с `--keep-cr`
   там отказ «No changes»). Затем снять авторство сессии: `git rebase --exec 'git commit --amend --reset-author
   --no-edit' origin/master` (автор патча — учётная запись сессии, в контур не едет); сверка дерева `_meta` с зеркалом
   `diff -r --strip-trailing-cr`; сторож `_meta/tools/structural_facts.py --repo . --strict` → push в GitLab
   (владелец) → MR → master.
   Перед `git am` — сверка общих файлов `_meta` с `origin/master` канона (урок 14.10 и 28.10: коллеги правят `_meta`
   в обход).
3. Сдачи и A/B-материалы из `skillCore/` зеркала копируются в analyzer `app/data/skillCore/` и коммитятся там.
4. Стенд принимает срез обычным `accept_canon`; команды — при своём очередном приёме среза (в их журнале — «не
   применимо»: структура карточек не меняется).

## Что нужно от владельца до сборки

- Решение о размещении копии канона и полигона во внешнем частном репозитории (вопрос политики, не данных: в
  выгрузках только требования).
- Заполненный файл решений (SC-01…SC-12), хотя бы SC-01, SC-02, SC-05, SC-06, SC-07 для среза 0 и 1.
- Имя репозитория GitHub и права сессии на push.

Сборку зеркала делает скрипт `build_mirror.py` (следующий файл трека, пишется после решения): копирует перечисленное,
пишет `MANIFEST.md`, проверяет, что `structural_facts`, оба `selfcheck` и тесты проходят в собранном каталоге до пуша.
