## Решения, которые записываются в файл решений

- **SC-02, уточнение (2026-10-29):** чтение шаблона типа — пункт общего раздела `## Вход` (предусловие всех режимов),
  не шаг «Порядка». «Порядок»: документ → матрица → спорные места → чек-лист → selfcheck → отчёт → коммит (1…7).
- **SC-03, уточнение для среза 1:** ссылки снаружи объёма на номер шага `create-artifact` («шаг 6» в
  `_meta/templates/traceability-matrix.md:33`, `_meta/tools/README.md:336`, `_meta/migration/reference.md:250`,

  матрицы трассировки») — только эти строки, файлы в объём не входят; любая другая правка в них — вопрос.
- **SC-07, проверка selfcheck (ответ на Q-01):** условие «комплекты не задеты» = байтовое совпадение `--out` и
  консоли двух прогонов в среде сессии: на базе среза (состояние `main`, от которого ветка) и после правок. Baseline
  в `skillCore/baseline/` пересобирается сессией в Linux в ветке среза 0 (те же четыре команды, коммит по
  `skillCore/`), после этого сравнение с baseline — байт в байт, строка о корне полигона входит в baseline. Строки,
  зависящие от даты, перечисляются в сдаче отдельно.
- **Зеркало:** принятая ветка среза вливается в `main` зеркала сессией analyzer (fast-forward), следующий срез
  ветвится от `main`. В канон (контур) переносится по SC-06: срез 0 — вместе со срезом 1.
- **SC-09:** «Срез 0: принят с доработкой (2026-10-29)» ставится после повторной сдачи доработки; постановка среза 1
