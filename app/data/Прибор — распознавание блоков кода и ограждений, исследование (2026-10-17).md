## 1. Откуда берутся блоки: что решает выгрузка

Код бандла `confluence-tree-exporter` собирается из analyzer (`app/scripts/build_bundle.py`):
`app/content_extractor.py`, `app/scripts/CI/critic.py`, `app/scripts/repair_export.py`,
`app/scripts/migrate_*.py` и др. — побайтно те же файлы.

| Что в Confluence | Что пишет выгрузка | Где и когда решено |
| --- | --- | --- |
| Макрос `code` / `noformat`, `<pre>`, многострочный `<code>` | блок ```` ``` ```` с переводом строки до и после; в ячейке таблицы — `<pre>…</pre>` | `content_extractor._code_block`, `_process_code_block`; ячейки — `26190326` (2026-09-06) |
| Однострочный `<code>` | `` `…` `` | `_process_code_block` |
| Абзац обычного текста, который после обрезки пробелов начинается на `{` и кончается на `}` | блок ```` ``` ```` без языка; в ячейке — `<pre>` | `_process_paragraph`, `b2a64f2b` (2026-06-06); в режиме CriticMarkup решение по исходному тексту абзаца, не по обёрнутому — `867c1339` (2026-07-29) |
| Ограждение внутри HTML-острова старой выгрузки | `<pre>…</pre>` вместо пары ```` ``` ```` | `repair_export --unfence-html` (`26190326`) |
| Строка вида ```` ```"filter"``: { ```` (склеенный инлайн-код) | не ограждение: по CommonMark инфо-строка backtick-ограждения не содержит «`» | `critic._FENCE_RE` (`26190326`) |

Ограждение у выгрузки всегда ровно ```` ``` ````: `~~~` она не пишет, длину под содержимое не
подбирает.

Почему распознавание зависит от переводов строк. Правило «абзац `{…}`» срабатывает, только если весь
JSON набран одним абзацем: строки разделены Shift+Enter, то есть `<br>` внутри одного `<p>`. Если
аналитик набирал пример через Enter (каждая строка — свой `<p>`), приклеил его к подписи без
перевода строки или набрал кусками инлайн-кода, правило не срабатывает. Пример уходит в выгрузку
голым текстом или склейкой обратных кавычек. Примеры со снимка:

- голый текст, приклеенный к подписи — `kk/sources/…/ЭКО_Авторизация-операции-по-корпоративной-карте.md:136`:
  `Пример запроса{` и дальше по строке на абзац;
- склейка инлайн-кода в HTML-острове — `…/ЭКО_Получение-числа-карт-на-счете.md:191-196`:
  строки ```` ```"params"``: {` ```` и ```` ```}` ````;
- ```` ``` ```` внутри строки pipe-таблицы (старая выгрузка ячейки, переводы строк склеены) —
  `…/ЭКО_Получение-списка-счетов-клиента.md:151`: нечётное число ```` ``` ```` в строке.

## 3. Где прибор определяет границы

Общие свойства построчных переключателей (Т): любое подходящее начало строки и открывает, и
закрывает блок. Вид и длина не учитываются (```` ``` ```` закрывает `~~~`, ```` ```` ```` закрывается
```` ``` ````), инфо-строка любая (строка ```` ```"params"`` ```` открывает блок), отступ любой.
Незакрытый блок — код до конца файла; в GFM так же.

Как ведут себя регулярки:

- **Р1–Р4** спаривают ```` ``` ```` где угодно. Пара в одной строке — это строчный кодовый спан, и
  здесь поведение совпадает с GFM. При нечётном числе ```` ``` ```` в строке (форма 6b) регулярка
  спаривает остаток со следующим ограждением и вырезает весь текст между ними: ссылки и теги в нём
  не проверяются — **молчаливый пропуск**.
- **Р5** на паре в одной строке (форма 6) захватывает текст до следующей ```` ``` ```` через строки.
  Кроме того, `<pre>{…}</pre>` из ячейки новой выгрузки не может стать кандидатом-JSON: теги не
  снимаются.
- **Р6–Р8** не видят ограждений с отступом. Записи журналов (`^## OQ-`, `^## FB-`) тоже ищутся с
  первой колонки, так что поведение согласовано.
