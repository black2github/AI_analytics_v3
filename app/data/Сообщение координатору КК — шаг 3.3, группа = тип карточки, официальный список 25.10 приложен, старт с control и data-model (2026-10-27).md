# Координатору КК: шаг 3.3 — стартовать по вашей раскладке, но группа = тип карточки, а не тип страницы; официальный список — файл 25.10

«Списки дозаходов по дельте 0e32b01 по типам карточек (2026-10-25)» (шаг 1.5 плана); прикладываю его ещё раз.

## Почему единица — карточка

1. Ваша раскладка по страницам не совпадает с раскладкой по карточкам, и расхождение не в счёте, а в
   единице: по приложению 24.10 страниц с текстовой дельтой и карточкой — 102, они дают 115 карточек
   (18 + 97). Ваши 117 страниц и «сходится с 115» — совпадение чисел разных сущностей. Карточка одна, а
   страниц-источников у неё может быть несколько (DM-002 собирается из нескольких страниц модели данных,
   CTL-078 и cards-ef-* — из одной страницы контролей), и наоборот.
2. Приёмка 3.4 задана по типу карточки: контроли и модели данных акцептующий читает целиком. В вашей раскладке
   «control — 5 страниц», а карточек контролей с изменённым текстом 16: остальные получают изменения через
   страницы ЭФ и сущностей. Если группы — по страницам, карточки контролей окажутся размазаны по четырём
   промптам, и окно приёмки акцептующего «контроли целиком» собрать не из чего.
3. Карточек типов internal-contract (8) и module-interface (4) в вашей раскладке нет вовсе — их страницы у
   вас, видимо, попали в contract-call и function. Исполнитель промпта «contract-call» должен знать, что
   правит карточки INTC, а не CALL: шаблоны и ревью у них разные.

## Что сделать перед первым промптом

1. Переложить derivation-3.3.md на карточки: группа = `type` карточки, список карточек группы — из файла 25.10;
   к каждой карточке — её страницы-источники с текстовой дельтой (карта страница→карточки — приложение 24.10,
   колонка «Карточки»). Страница попадает в промпт каждой карточки, которую питает.
2. Сумма по группам должна дать 97 (3.3) и 18 (3.2). Страницы с текстовой дельтой, у которых карточки нет
   (по приложению их 36), — не в 3.3, это шаг 3.5 (опись, новые страницы, OQ); перечислите их отдельно,
   чтобы разница с вашими 117 была объяснена, а не потеряна.
3. Пометка «не повторять» для страниц закрытых DELTA/ISS-заходов — правильно, это «минус карточки фазы 2» из
   строки 3.3 плана.

## Порядок заходов

Согласен начать с control (16 карточек) и data-model (11): их 3.4 принимает целиком, и раньше сделанные —
раньше в окне приёмки акцептующего. Дальше — параллельно по остальным группам, один промпт на группу; группы
print-form (2) и module-interface (4) можно объединить в один промпт, если исполнитель один, но ревью и
приёмка — по типу. Вход каждого захода — только дифф ПРОМ-среза по страницам карточек (недоснятий вне
фазы 2 нет, отчёт 1.2). После каждого захода — ревьюер.
