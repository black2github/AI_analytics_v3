## Зачем

«артефакт в вопросе называется наименованием, ID в скобках», но не применил его — в вопросах

теперь один — канон `_meta/rules/questions.md` (клон `C:\doc-as-code\ext-sandbox\docs-o2new`,
незакоммиченный срез этой же даты). Механический сторож — единственная защита, которая не
зависит от того, прочитал ли агент правило. Он проверяет только таблицу вопросов файла
`tasks/<JIRA-ID>.md`, не карточки, поэтому шума по комплекту не даёт.

## Что сделать

Файл: `app/scripts/CI/delta_report.py` (прибор), тесты `tests/test_delta_report.py`, копия в

### 1. Функция `check_questions(task_text: str) -> List[str]`

Разбирает таблицу раздела `## Вопросы и ответы` (как `task_questions`, но ВСЕ строки, не только
с ответом «—»); для каждой строки берёт ячейку «Вопрос агента» и возвращает замечания вида
`вопрос N: <что не так>` (строки, без вложенных структур). Проверки:

| № | Замечание | Правило обнаружения |
|---|---|---|
| a | `голый идентификатор «<ID>» — рядом нет наименования` | Сначала markdown-ссылки `[label](target)` заменяются на `label`. Идентификатор — токен `[A-Z]{2,6}(?:-[A-Z]{1,6})*-\d+(?:\.\d+)*` либо `[A-Z]{2,6}-GRP-\d+` (в обратных кавычках или без). Он «назван», если в тех же 60 символах ячейки ДО него есть закрывающая кавычка `»` (образец: «Пользователь» (`EXT-007`)). Исключение: токены `T-<КЛЮЧ>-NN` (ссылки на строки постановки) не считаются. Одно замечание на уникальный ID в строке. |
| b | `префикс типа «<X>» вместо наименования типа требований (словами: уведомления, печатные формы…)` | Токен из списка `NTF, PRN, CTL, SM, CALL, ENT, EXT, FUN, PROC, SCR, RBAC, INTC, LIBC, EXTINT, PLT, FLD, MSG, EV` как отдельное слово (границы слова; за ним НЕ следует `-`), в обратных кавычках или без. Одно замечание на уникальный префикс в строке. |
| c | `вопрос реализации («<фраза>») — физическое имя, тип и ограничения БД в forward не задаются` | Регистронезависимый поиск фраз: `физ. имя`, `физическое имя`, `varchar`, `NOT NULL`, `ограничения БД`, `ограничений БД`, `имя колонки`, `тип БД`. Одно замечание на строку с перечнем найденных фраз. |
| d | `нет рекомендации агента («Рекомендую …»)` | В ячейке нет подстроки `рекоменду` (регистронезависимо). |
| e | `в одной строке несколько вопросов (N знаков «?») — один вопрос — один факт` | В ячейке больше одного символа `?`. |

Порядок замечаний — по номеру строки, внутри строки a → b → c → d → e. Если раздела или таблицы
нет — пустой список (замечание об отсутствии таблицы не нужно: шаблон допускает заход без
вопросов).

### 2. Встраивание в отчёт дельты

В `build()` после `check_task_file`: если текст постановки есть — `notes.extend(check_questions(task_text))`.
Замечания попадают в существующий блок «Замечания прибора» (код выхода не меняется — 0).

### 3. Режим `--questions <JIRA-ID>`

Как `--affected`: ДО правок, git не нужен. `kit_root(--repo)` → `tasks/<JIRA-ID>.md`; файла
нет — `✗ постановка не найдена: tasks/<JIRA-ID>.md`, код 2. Иначе печатает:

```
# Вопросы постановки <JIRA-ID> — проверка формы

- вопрос 1: …
- вопрос 3: …

i замечаний: N — переформулируй по правилам опроса (_meta/rules/questions.md) до показа аналитику
```

или `OK: замечаний по вопросам нет`. Код выхода 0 в обоих случаях (замечание, не гейт). `--out`
пишет тот же текст в файл (UTF-8, `\n`), `--json` — `{"questions": [...], "notes": [...]}`.
Комментарий-шапка файла (список ключей, пункт 6) и `--help` — дополнить.

### 4. Тесты (`tests/test_delta_report.py`, стиль файла)

- НЕсрабатывание (асимметрия ошибок): таблица из трёх правильных вопросов — ровно `[]`. Образец
  правильной строки:
  `| 1 | **Поле «Контактный телефон для уведомлений» на вкладке «Открываемый счёт» (`SCR-CL-03.1`) — блок размещения.** Варианты: «Дополнительно», «Информация о счёте», новый блок. Рекомендую «Дополнительно» — там остальные необязательные реквизиты для уведомлений. | T-ECO-123-02 |`
  плюс строка с именем через markdown-ссылку `[Форма «Заявка» (`SCR-CL-02`)](../srs/…)` и строка с
  `T-ECO-123-02` в тексте вопроса — ни одна не даёт замечания.
- По одному тесту на каждое правило a–e (ровно одно ожидаемое замечание, дословный текст).
- Порядок: строка с a и d даёт два замечания в порядке a, d.
- Отчёт дельты: замечания вопросов видны в «Замечания прибора» (через `build` на `make_repo`).
- CLI `--questions`: код 0 и `OK` на чистой таблице; код 0 и `i замечаний: N` на грязной; код 2
  без файла; `--json` содержит ключ `notes`.

## Ограничители

- Не коммитить, не делать `git add`/`git stash`/`git restore` ни в analyzer, ни в каноне: в
  общей копии analyzer могут быть застейдженные изменения других сессий — их не трогать.
- Правки только в трёх файлах выше. Комментарии в коде — по-русски, как вокруг; слово
  «провенанс» не употреблять («происхождение»).
- Отчёт исполнителя: что сделано, дословные числа прогона (passed/failed), diff --stat по трём
  файлам, предсуществующие падения (если есть) с подтверждением на чистом `HEAD`.
