## Общие правила (обязательны для каждой задачи)

1. **Рабочие деревья общие** с сессией «КК и хвосты»: analyzer `C:\Users\alexe\PycharmProjects\requirements-analyzer-v3`,
   клон канона `C:\doc-as-code\ext-sandbox\docs-o2new`, стенд `C:\doc-as-code\ext-sandbox\src-business-cards`.
   Перед правкой канона — `git status` клона чист и ветка `master`; одна ветка канона за раз;
   если клон не на `master` или грязный — остановиться и сообщить владельцу, не трогать.
2. **Прибор правится только в analyzer** (`app/scripts/CI/*.py`), с тестами в `tests/`, затем
   копия в канон `_meta/tools/` с CRLF. Сверка копий — без учёта переносов с ОБЕИХ сторон:
   `diff <(tr -d '\r' < канон) <(tr -d '\r' < analyzer)`; рабочая копия analyzer бывает CRLF.
3. **Тесты** гоняются системным Python:
   `PYTHONPATH="$PWD;$PWD/.venv/Lib/site-packages" PYTHONIOENCODING=utf-8 /c/Python312/python.exe -m pytest tests/<файлы> -q -o addopts=""`.
   Полный `tests/` падает на предсуществующем `ImportError app.services.context_builder` —
   это не прибор; гонять релевантный набор: `test_normalize_tables.py test_selfcheck*.py
   test_link_debts.py test_transfer_gate.py test_source_coverage.py test_passport_sync.py
   test_structural_facts.py test_canon_delta.py test_accept_canon.py test_kk_feedback_batch.py`.
4. **Каждый новый сторож — с тестом на НЕсрабатывание** (асимметрия ошибок: молчаливая потеря
   хуже шума, но ложный ✗ останавливает команду). Новые сторожа — только ⚠, вердикт не меняют,
   пока владелец не переведёт в ✗.
5. **Коммиты analyzer** — только по слову владельца «коммить»; `git add -- <перечень файлов>`,
   никогда `git add .`; трейлер `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`
   в analyzer допустим, в контурных репозиториях gboteam — запрещён (там коммитит владелец).
6. **Канон**: ветка `meta/<тема>`, перед push — владелец делает `git fetch` и
   `git log --oneline master..origin/master -- _meta/tools/`; непустой вывод — стоп. После
   вливания MR владельцем: `git switch master; git pull --ff-only; git branch -d <ветка>`;
   сторож `python _meta/tools/structural_facts.py --repo .` чист; accept стенда:
   `cd стенд; python ../docs-o2new/_meta/tools/accept_canon.py --profile README.md`
   (стенд без remote, push не нужен).
7. **Сдача** каждой задачи: строка ИТОГО тестов (число passed), дельта живого прогона на
   комплекте (было → стало, ✗/⚠), перечень изменённых файлов, что НЕ сделано. Статус в
   `app/data/onb-v-review/registry.md` (колонка «Решение / коммит») обновляется после коммита.
8. Команды владельцу — в PowerShell, по одной, с ожиданием под каждым шагом; сетевые команды
   (`fetch`, `pull`, `push`) выполняет владелец.

## Задача 1. Сторож формулы «в постановке не задано» (волна 2, ПР-12, ЗК-01/15)

Норма: техбук `conventions.md` §6 п.5 (влит 16.10) — обязательное поле без данных заполняется
ровно формулой «в постановке не задано»; иные пометки о пробеле — нарушение.

- Где: `app/scripts/CI/selfcheck.py`, новая проверка уровня комплекта (рядом с
  `check_readme_legend` / `check_nfr_catalog`), подключить в `run()` как остальные.
- Что: по всем `*.md` комплекта (кроме `README.md` каталогов? — нет, включая) считать
  вхождения формулы `в постановке не задано` (регистр любой); печатать одну строку
  `⚠ формула «в постановке не задано» ×N — перечень пробелов постановки:` и под ней
  `   <файл>:<строка>: <первые 80 знаков строки>` (до 30 строк, далее «… и ещё K»).
  Вердикт не меняется. Отдельно: любые иные пометки о пробеле — слова `не задано`, `вне
  выгрузки`, `в срезе`, `уточняется`, `TBD` ВНЕ формулы и вне frontmatter — ⚠ «пометка о
  пробеле не по формуле» с адресом (не ✗).

  перечислена; пометка не по формуле даёт ⚠; комплект без формулы и пометок — ни одной
  строки; слово «не задано» внутри формулы не считается второй раз (НЕсрабатывание).
- Живой прогон: `selfcheck.py --docs C:/doc-as-code/EAS/src-business-cards/docs --sources
  C:/doc-as-code/EAS/src-business-cards/sources/confluence` — ожидание: ИТОГО без изменения
