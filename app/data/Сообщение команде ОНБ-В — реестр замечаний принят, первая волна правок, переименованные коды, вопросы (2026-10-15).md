# Команде ОНБ-В: реестр замечаний принят в работу, первая волна правок, вопросы

Дата: 2026-10-15. Передаёт владелец канона. В ответ на документ «Причины дефектов реверса ОНБ-В и
предложения по доработке методологии» (29.09.2026).

## Что сделано с реестром

Все 42 класса и 39 предложений разобраны: по каждому классу — локализация на срезе 29.09,
состояние на текущем срезе канона, оценка причины, критичность и сложность исправления,
рекомендация. Итог: принять — 17 классов, принять частично — 20, уже исправлено — 1, не
замечание к методологии — 1, требуют уточнения — 3. Предложений принято 15, частично 20,
отклонено 3 (ПР-01, ПР-10, ПР-31 — с аргументацией), одно уже реализовано. Исправления идут
восемью волнами по критичности; судьба каждого замечания ведётся в реестре с идентификаторами
ЗК-NN и ПР-NN, итоговый отчёт «замечание → исправление → коммит» будет передан по завершении.

Терминология в разборе: «техбук» — стандарт ЭКО (`ED/eco-techbook`), «канон» — `EAS/docs-o2new`
(`_meta/`), «прибор» — утилиты `_meta/tools`.

## Первая волна — срез канона `fbda77a` (15.10)

- **ЗК-29 / ПР-11.** Прибор `link_debts.py` читает раздел «Долги по ссылкам» по заголовку и
  сторожит каждую строку: строка не по формуле — предупреждение в самопроверке и блокер CORE-20 в
  гейте переноса (раньше молча пропускалась). Формула «параметр <ключ> не зафиксирован»
  распознаётся, просрочка — по `dictionaries.md`. Закрытые долги (во второй колонке ID цели, как
  в матрице ОНБ-В) распознаются и не шумят. На комплекте ОНБ-В нераспознанных строк нет.
- **ЗК-11 / ПР-33.** Правило разбора адреса комплекта уточнено: без `/-/tree/` адрес читается
  по имени репозитория (`src-*` — комплект в `docs/`, `docs-*` — в корне). Код владельца в
  строке долга сверяется с каталогом сервисов. Переименование кода в каталоге — только с
  уведомлением команд (документ адресации §4.2).
- **ЗК-12 / ПР-01.** ПР-01 «перестать браковать карточку, чья страница вне выгрузки» —
  отклонено: ✗ «источник не найден» остаётся единственным сигналом, что reverse-карточка
  сверке не подлежит. Причина девяти постоянных ✗ у CALL-INT-002…008 — во frontmatter первой
  стояла страница метода владельца (вне выгрузки). Шаблон `contract-call.md` и скилл теперь
  говорят прямо: `confluence_page_ids` карточки вызова — страницы этого сервиса, где описан
  вызов; страница владельца — не источник, её `page_id` живёт в открытом вопросе или долге.
  Прибор при таком ✗ печатает подсказку. Поправка в карточках ОНБ-В — поменять порядок
  `page_id` местами, тогда ✗ исчезают сами.

## Переименованные коды сервисов (сопровождение каталога)

После 29.09 каталог `_meta/services.json` переименовал два кода: `shortLinkDirectory` →
`short-link`, `gpbBolLocalization` → `gpb-bol-localization`. Уведомление командам тогда не
рассылалось — это дефект сопровождения каталога, правило теперь записано. В матрице ОНБ-В строка
долга «у владельца shortLinkDirectory» ссылается на несуществующий код; прибор на срезе
`fbda77a` показывает это предупреждением. Просьба заменить код в строке на `short-link`.
