# Обновление утилит канона: новая строка проверки ссылок на сущности

Кому: командам, которые ведут комплекты требований по канону docs-o2new.
Срочных действий не требуется: вердикт проверки комплекта не меняется.

## Что изменилось

В проверку комплекта (`selfcheck`) добавлено предупреждение о ссылках на сущности модели
данных. Правило конвенций (§5): первое упоминание сущности в файле — полная ссылка с
идентификатором и названием, `[ENT-NNN <название>](…)`. Короткая ссылка `[ENT-NNN](…)`, в том
числе в записи атрибута `[ENT-NNN](…).«Атрибут»`, ставится только после полной ссылки выше
в том же файле. Правило действует в каждом файле отдельно: если документ состоит из
нескольких файлов (например, контроли: головной файл и файлы с карточками), каждый файл
несёт свою полную ссылку.

Раньше прибор этого не проверял. Заодно исправлена ошибка: ссылка на карточку другого
сервиса по полному адресу GitLab больше не принимается за сущность своего комплекта.

Шаблоны контролей, экранной формы и процесса и эталонные комплекты приведены к правилу.

## Как получить обновление

1. Обновить клон канона:

   ```powershell
   git -C <клоны>\docs-o2new pull --ff-only
   ```

   Ожидаемый результат: строка `Fast-forward` со списком файлов либо `Already up to date.`

2. Убедиться, что обновление на месте:

   ```powershell
   git -C <клоны>\docs-o2new merge-base --is-ancestor 89e3d0f HEAD; $?
   ```

   Ожидаемый результат: `True`.

Здесь `<клоны>` — каталог, где у вас лежит клон docs-o2new.

## Что вы увидите в отчёте

При следующем запуске проверки комплекта в разделе общих проверок могут появиться строки вида:

```text
⚠ srs\controls\cards-request.md: короткая ссылка на ENT-001 раньше полной `[ENT-001 <название>]` ×32 — дословное имя с тегом полную ссылку с ID не заменяет; короткая `[ENT-NNN]` допустима после полной
```

Одна строка — один файл и одна сущность; `×32` — сколько коротких ссылок стоит выше первой
полной. Слова «полная ссылка стоит ниже» в строке означают, что полная ссылка в файле есть,
но не первой.

Итоговая строка отчёта и вердикт от этих предупреждений не меняются.

## Как исправить

В каждом файле из отчёта первую ссылку на сущность сделать полной. Остальные ссылки не
меняются. Название — как в карточке сущности.

Было:

```text
- **Проверяемый атрибут:** [ENT-001](../data-model/ent-001-request.md).«Клиент (ссылка)».
```

Стало:

```text
- **Проверяемый атрибут:** [ENT-001 Заявка на открытие доп счета и заключение ДБС](../data-model/ent-001-request.md).«Клиент (ссылка)».
```

Когда вносить правки — при ближайшем изменении файла или одним заходом по всему комплекту —
решает лид аналитиков команды.
