# Сообщение всем командам: раздел «Процессы» карточки вызова — только точка вызова; колонка «Вызовы» у функций в матрице (2026-11-16)

Передаёт владелец канона. Дополнение к сообщению «Карточка вызова — одна вызывающая функция» от 16.11.2026. Правки влиты в master канона 16.11.2026 (`6177598`).

---

Коллеги, в каноне уточнено, что стоит в разделе «Процессы» карточки вызова, и обновлены матрица трассировки и две проверки утилит. После обновления канона в отчётах появятся новые строки предупреждений. Вердикт `selfcheck.py` и гейт переноса они не меняют.

## 1. Правило: в «Процессах» карточки вызова — только точка вызова

**В чём была проблема.** Раздел «Процессы» отвечает на один вопрос: кто и в каком месте выполняет вызов с правилами заполнения этой карточки. В первом сообщении было сказано, что в той же таблице допустимы процесс или экранная форма, из которых вызывающая функция запускается. На практике раздел смешивал два факта — точку вызова и места запуска функции. У двух карточек разных вызовов одного метода он получался почти одинаковым, и по нему нельзя было понять, к какому месту привязана карточка.

**Что теперь.**

- В «Процессах» стоит только точка вызова этой карточки: функция (процесс, экранная форма или контроль, если вызов записан в них), шаг и вариант, если в шаге их несколько. Обычно это одна строка.
- Дополнительная строка допустима в двух случаях:
  - вызов выполняет общая функция с параметрами от заявки подсервиса — указывается ещё место в подсервисе заявки, где заданы параметры этого вызова;
  - обмен асинхронный — указывается ещё шаг, на котором сервис принимает ответ на этот вызов: там применяется раздел карточки «Сопоставление входящего сообщения».
- Места, откуда вызывающая функция запускается, в карточке вызова не перечисляются. Это сведение о функции: оно стоит в карточке самой функции и в процессах и экранных формах, которые её запускают.
- Таблица раздела — две колонки, «Процесс / функция» и «Шаг / место», без описания шага. Это правило прежнее.

Фраза первого сообщения «процесс или экранная форма в той же таблице — место, откуда эта функция запускается, а не второй вызов» больше не действует.

**Как отличить точку вызова от места запуска.** Точка вызова — документ, в шаге которого выполняется вызов метода и стоит ссылка на эту карточку. Место запуска — документ, который вызывает функцию, а не метод. Признак лишней строки: она слово в слово повторяется в карточке другого вызова того же метода.

## 2. Матрица: колонка «Вызовы» в покрытии функций

**Зачем.** Когда из «Процессов» карточки уходят места запуска, в матрице из колонки «Вызовы» процесса уходят вызовы, которые выполняет не сам процесс, а запущенная им функция. У функций колонки вызовов не было, и цепочка «процесс → функция → вызов» по матрице не читалась.

**Что теперь.** В разделе «Покрытие: функции → артефакты» появилась колонка «Вызовы» — третьей, после «Название». Утилита выводит её сама по ссылкам между документами, как колонку «Вызовы» у процессов. Собственный внутренний контракт функции метода в колонку не входит: функция его реализует, а не вызывает.

**Что вы увидите.** В отчёте `matrix_sync.py --check` и в `selfcheck.py`:

```
⚠ «Покрытие: функции → артефакты»: нет колонки «Вызовы» — --write добавит (новая колонка шаблона)
```

## 3. Проверка «шаг процесса ↔ карточка вызова»

**Что изменилось.**

- Шаг процесса проверка берёт только из разделов шагов («Шаги процесса», «Детали шагов»). Ссылка на карточку вызова из таблицы заполнения атрибутов парой больше не считается. У процесса без раздела «Шаги процесса» поведение прежнее.
- Указатель в «Процессах» карточки вызова читается и из списка («- [PROC-…](…) — шаг N»), а не только из таблицы.

**Что вы увидите.** Строк «нет обратной» станет меньше или столько же. Могут появиться строки «нет прямой», если «Процессы» карточки записаны списком и перечисляют места запуска:

```
нет прямой: CALL-… → PROC-… «шаг N»: строка «Процессов» карточки называет процесс, а шаги PROC-… на CALL-… не ссылаются — если строка не точка вызова, убрать её из «Процессов»; если шаг процесса выполняет вызов, добавить в шаг ссылку на карточку
```

Заодно исправлено ложное предупреждение «раздел „Процессы“ не указатель»: место вызова вида «Шаг C4. Проверка статуса карты» больше не считается текстом из двух предложений.

## Что сделать у себя

Исполнитель каждого шага — аналитик команды.

1. Обновить канон обычным порядком.
2. Пересобрать матрицу, один запуск из корня комплекта:

   ```
   python <канон>/_meta/tools/matrix_sync.py --docs <корень комплекта> --write
   ```

   Ожидание: колонка «Вызовы» добавлена и заполнена, остальные колонки и разделы матрицы не изменились; повторный `--check` печатает ✓. Ручных правок матрицы не требуется. Матрица не по шаблону канона: `--write` по-прежнему отказывает, `selfcheck.py` по-прежнему пропускает её сверку.
3. Если у функции метода в «Вызовах» оказался её собственный внутренний контракт — в функции нет строки шаблона «Входные и исходящие параметры — по контракту …». Добавить строку в функцию и пересобрать матрицу.
4. Новые карточки вызова писать по правилу раздела 1.
5. В существующих карточках привести «Процессы» к точке вызова при ближайшей правке карточки, но не позже, чем сервис начнёт привязку операций API к требованиям. Строка убирается после проверки, что сведение о запуске функции стоит в запускающем документе; если его там нет — сначала перенести, потом убрать, одним изменением. Строки «нет прямой» из раздела 3 показывают, с каких карточек начать.
6. Если документ из строки сам вызывает метод со своими правилами заполнения — это вторая вызывающая точка: строку не убирать, карточку делить по первому сообщению.
