# Матрица трассировки — запись решения и нарезка шага 2 — на подтверждение

Дата: 2026-10-16. Пакет 2, задача 10, шаг 2. Основание — решения владельца по шагу 1 (файл
«Матрица трассировки — разделы комплектов и их природа (2026-10-16)», раздел «Решения
владельца») и правило Д-26: запись решения со сценариями жизненного цикла до кода. Кода нет.
Ждёт подтверждения нарезки и ответа на вопрос о снятых и плановых ID (отдельный файл
«Вопрос владельцу канона — снятые и плановые ID в реестре матрицы»).

## Решение

1. **Утверждение.** Матрица трассировки состоит из выводимых и ручных разделов. Выводимые
   собирает утилита `matrix_sync.py` из тел документов. Ручные ведёт аналитик, утилита их не
   меняет ни на байт. Генерации матрицы целиком нет.
2. **Маркер.** Решение владельца канона 2026-10-16 (задача 10, шаг 1, рекомендации 1–7).
3. **Обоснование.** Техбук, conventions §5.3 п.2: «источник связей — тела документов; матрица …
   производна от тел. Расхождение — дефект матрицы». Замер 16.10: в КК 20 строк покрытия
   функций и 2 строки покрытия процессов называют ID, на которые нет ссылки ни в одном теле.
   Пересборка без проверки молча стёрла бы эти связи.
4. **Операционное следствие.**
   - `--check` (по умолчанию) печатает расхождения и ничего не пишет.
   - `--write` пересобирает только выводимые разделы. Он отказывает и не трогает файл, если
     структура матрицы не по шаблону, если есть связи только в матрице или если из комплекта
     исчез ID, у которого была выводимая строка реестра.
   - Перевод действующих комплектов на шаблон — отдельный заход по каждому комплекту.
5. **Согласованность мест.** Шаблон канона `_meta/templates/traceability-matrix.md` (новый),
   утилита в analyzer и её копия в `_meta/tools/`, ссылка на шаблон из `create-artifact` шаг 6.
   Норма о матрице остаётся в техбуке, conventions §5.3. Шаблон на неё ссылается и не
   повторяет её.

## Шаблон: разделы, порядок, колонки

| № | Раздел | Ведёт | Колонки |
| --- | --- | --- | --- |
| 1 | Реестр ID | утилита + ручные строки с файлом «—» (снятые — с пометкой «снят …», плановые — без неё) | ID · Название · Файл |
| 2 | Покрытие: функции → артефакты | утилита | Функция · Название · Экраны · Данные · Контроли · Печатные формы |
| 3 | Покрытие: процессы → артефакты | утилита | Процесс · Название · Вызывает · Функции · Вызовы · Экраны · Контроли · Данные · Печатные формы |
| 4 | Покрытие: API ↔ SRS | аналитик | по conventions §5.3 п.7 |
| 5 | Источники миграции | утилита + ручная колонка «Основание» | Page ID · Целевые артефакты · Основание |
| 6 | Долги по ссылкам | аналитик | по `link_debts.py` |
| — | BRD-1…BRD-5 | аналитик, только при слое `brd/` | по conventions §5.3 п.8–9 |

Разделы узнаются по имени без номера. Своих пометок в матрице комплекта нет: что выводимое,
говорит шаблон.

## Правила вывода

- **Реестр ID.** Строка — ID из шапки документа или ID в начале заголовка тела (внутренние
  `CTL-NNN`, `CTL-GRP-NN`, `FLD-N` и т. п.). Название — `title` шапки или текст заголовка после
  ID. Файл — путь от корня комплекта. Упоминание ID в тексте строку не создаёт: в `--check` это ⚠.
- **Покрытие.** Связь — markdown-ссылка в любую сторону: из тела строки или из другого
  документа на неё. Ссылка с якорем на заголовок с ID даёт этот ID. Колонка выбирается по
  префиксу ID: SCR — Экраны; ENT, EXT, DM — Данные; CTL, CTL-GRP — Контроли; PRN — Печатные
  формы; FUN — Функции; CALL, PLT, EXTINT — Вызовы; другой PROC — Вызывает, только по ссылке из
  тела процесса.
- **Источники.** Page ID из `confluence_page_ids` шапок, целевые артефакты — ID этих документов.
  С ключом `--sources` добавляются страницы выгрузки без артефакта. Колонка «Основание»
  переносится из старой строки той же страницы без правки.
- **Порядок строк** — по ID, номера сравниваются как числа. Переносы строк и кодировка файла
  сохраняются.

## Сценарии жизненного цикла

1. **Первый запуск на комплекте не по шаблону** (сейчас таковы все пять). `--check` печатает
   отклонения структуры и расхождения разделов, которые узнал. `--write` отказывает с кодом 2,
   файл не тронут.
2. **Первый `--write` на комплекте по шаблону.** Выводимые разделы пересобраны, ручные
   совпадают байт в байт. Утилита печатает сводку: сколько строк и ячеек изменено в каждом
   разделе. Человек смотрит `git diff`.
3. **Повторный запуск без изменений в телах.** Файл не перезаписывается, код 0.
4. **Отказ и повтор.** Запись атомарная: временный файл и замена. Прерванный запуск оставляет
   старый файл. Повтор начинается с нуля, промежуточного состояния нет. Откат — `git restore`
   файла матрицы.
5. **Новая порция данных.**
   - Новая карточка или ссылка: `--check` показывает недостающую строку или ячейку, `--write`
     её добавляет.
   - Ссылку из тела убрали: ячейка теряет ID. Это производность по §5.3 п.2.
   - Документ удалён или сменил ID: `--write` отказывает. Его строку реестра надо оформить
     снятием вручную, по conventions §5, иначе ID откроется для повторной выдачи.
6. **Просмотр результата человеком.** Изменения только в выводимых разделах. Ручные разделы и
   ручные строки в `git diff` не меняются.

## Что подтвердить

1. **Нарезка С1–С5** и порядок.
2. **Колонка «Вызовы»** в покрытии процессов собирает CALL, PLT и EXTINT, то есть все исходящие

## Решения владельца (2026-10-16)

- **Реестр — вариант А.** Одна таблица, как в conventions §5 и §5.3 п.4–5. Строки с файлом «—»
  ручные: снятые с пометкой «снят <дата>: …», плановые без неё. Утилита переносит их без правки
  и сортирует реестр по ID. Снятый ID снова в шапке документа — ⚠ «ID переиспользован». Плановый
  ID появился в шапке — строка становится выводимой.
- **Нарезка С1–С5** подтверждена.
- **Колонка «Вызовы»** — одна на CALL, PLT и EXTINT (вариант 1).
- **Подключение к selfcheck** — пояснено 16.10, решение отложено до С5.

Уточнения правил при живом прогоне:
- ID определяется и первой ячейкой строки таблицы без ссылки: так заданы справочники EXT и группы
  CTL-GRP. Строка с таким ID — источник своих ссылок.
- Определения в экранных формах локальны (FLD, B, EV, точки вызова CALL-N) и в реестр не входят.
- ID ссылки берётся из её текста, если он определён в целевом файле: `[EXT-001](dictionaries.md#реестр)`
  даёт EXT-001, а не ID файла.
- Ссылки на README-реестры связей не дают. README контролей (`CTL-000`) — документ, не реестр.
- Раздел «Источники (вне SRS)» КК — не «Источники миграции»: это перечень страниц вне SRS по
  категориям, ручной.
