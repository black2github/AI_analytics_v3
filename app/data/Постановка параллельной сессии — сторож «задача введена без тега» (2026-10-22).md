## Правило сторожа (selfcheck, уровень комплекта, только ⚠, `affects_verdict=False`)

Вход: корень репозитория сервиса (`--docs` родитель) с git; `coordination-log.md`,
`coordination-state.md`, `sandbox/confluence-unapproved-jira-pages.md` (если есть).

1. **Объявлена, но не введена.** Множество A — JIRA-ID, о которых в `coordination-state.md` или
   `coordination-log.md` сказано «введена в (промышленную )?эксплуатацию», «в эксплуатации»,
   «введённые задачи …: X, Y» (регулярка по ID `[A-Z]+-\d+` рядом с этими словами в одной строке
   записи). Множество B — теги `src/<ID>` на текущей ветке (`git tag --merged HEAD 'src/*'`).
   A \ B → `⚠ задача объявлена введённой, тега src/<ID> нет: TEAMTB-NNN (журнал/состояние: <файл>,
   строка N) — ввод делается run-history (гид, «Ветки и теги»)`.
2. **Введена, но числится замороженной.** Строки `sandbox/confluence-unapproved-jira-pages.md` с
   задачей из B → `⚠ страница <page_id> «<title>» числится замороженной по задаче <ID>, а задача
   введена тегом src/<ID> — список устарел, пересчитать (run-history)`; то же для строк описи
   `inventory.md`, где основание содержит «заморожено <ID>» при `<ID>` из B.
3. Git недоступен или каталог без `.git` — одна строка «i теги задач не проверены (нет git)», без ⚠.
   Репозиторий без тегов `src/*` и без журнала — молчание.
