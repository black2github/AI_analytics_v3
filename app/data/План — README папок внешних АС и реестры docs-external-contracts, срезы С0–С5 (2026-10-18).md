## С0. Запись решения (Д-44)

Сценарии жизненного цикла, которые запись обязана покрыть:

1. Новая АС: папка, `README.md` по шаблону (ручной раздел из источника, выводимые пустые),
   строка в корневом реестре систем.
2. Новая карточка в существующей АС: поля шапки `title`, `kind`, `channel`, `sync`; строка в
   README АС добавляется утилитой `--write`, не руками.
3. Карточка-формат (`kind: format`): таблица «Форматы сообщений», без `sync`.
4. Снятие или переименование карточки: строка реестра снимается только человеком (как в
   матрице), утилита отказывает при файле без строки / строке без файла.
5. Репозиторий недоступен (ветвь скилла): черновик в `sandbox/extint-base-draft/<as>/`
   содержит карточку с полями шапки и заготовку строки «О системе»; реестр собирает владелец
   при переносе.
6. Перевод существующих README (gpb-smev, fns-my-signature, crypto-module): факты среды и
   адресов переезжают в «О системе» без потерь; Криптомодуль с подкаталогами каналов —
   исключение: README уровня канала по той же форме, README АС ссылается на каналы.
7. Дубли ID (F1-005, F1-006): утилита показывает обе строки и ⚠; перенумерация — отдельное
   решение владельца с уведомлением потребителей.
8. Канал вне словаря: ⚠, карточка в реестре с каналом «—»; расширение словаря — правка
   шаблона.

## С1. Норма

Канон, `_meta/templates/contract-call.md`, раздел A:

- дерево репозитория: корневой `README.md` — реестр систем (строка на АС: имя, папка, README,
  число карточек); `<as>/README.md` — `EXTINT-<AS>-000`; `<as>/examples/`; `<as>/files/` при
  вложениях; подкаталоги каналов — исключение (Криптомодуль), не норма;
- шапка базовой карточки: `title` обязателен (название операции или формата, как в реестре
  INTC-000, не заголовок страницы Confluence); колонка реестра — «Название», термин «точка
  обмена» в шаблоне не используется (замечание владельца 18.10),
  первая колонка таблиц реестра — «ID», не «EXTINT» (имя колонки не привязано к типу
  идентификатора);
  `kind` (`operation` | `format`), `channel` из словаря, `sync` (`sync` | `async`, у форматов
  нет); словарь каналов с отображением в README (`suv` → «СУВ», `online-adapter` →
  «онлайн-адаптер», `rest`, `mq`, `file`, `kafka` → «Kafka/СИП», `postmessage`); окончательный
  состав — после инвентаризации С4;
- шаблон `README.md` АС: редакция 3 примера дословно с пометками ручных и выводимых
  разделов;
- правило: реестры собирает утилита (`extint_registry.py --write`), связь «карточка ↔
  строка реестра» руками не ведётся; потребители — только в разделе «Потребители» карточки;
- `examples/README.md` — снять из нормы (в шаблоне не упоминается, утилита не проверяет);
  существующие остаются до решения владельца.

Техбук: `repo-topology.md` §9 — уровень папки АС и README, ссылка на шаблон; `conventions.md`
§5.1.1 — поля шапки базового контракта; `git-workflow.md`, раздел docs-external-contracts —
строка таблицы «новая карточка → README АС пересобирается утилитой в том же MR». Один MR
техбука, два апрува ED.

Реестр структурных фактов: SF-06 «реестры docs-external-contracts выводимы» (дом — шаблон
contract-call.md, потребители — скилл, утилита, техбук).

## С3. Утилита

`app/scripts/CI/extint_registry.py` (analyzer), копия `_meta/tools/` канона; запуск
`python <канон>/_meta/tools/extint_registry.py --repo <клон docs-external-contracts>`.

`--check` (⚠, код 1 при расхождениях):

- уникальность `id` по всем файлам репозитория (включая подкаталоги каналов); `id` ↔ имя
  файла (`extint-<as>-NNN-`); папка ↔ `<AS>` в ID;
- обязательные поля шапки: `title`, `kind`, `channel` ∈ словарь, `sync` у операций;
  сломанная шапка (как у payment-hub) — ✗;
- README АС есть; выводимые таблицы ↔ карточки (нет строки / нет файла / title расходится /
  канал расходится); корневой реестр систем ↔ папки;
- раздел «Потребители»: три колонки, адрес абсолютный на `/-/blob/HEAD/`, не `master` и не
  рабочая ветка;
- маркеры конфликта в любом `.md`.

`--write`: пересборка выводимых таблиц README АС и корневого реестра систем; ручные разделы
байт в байт; README папки без README создаётся по шаблону с пустым «О системе» («в
источниках не задано»); отказ при файле без строки, если строка снята руками (как в
matrix_sync); CRLF/LF и BOM файла сохраняются; неизменённый файл не перезаписывается.

Тесты: срабатывание ×8 (дубль ID, id ≠ имя, поле вне словаря, нет README, строка без файла,
адрес на master, маркер конфликта, сломанная шапка), НЕсрабатывание ×4 (чистая папка, формат
без sync, подкаталог канала, ручной раздел не тронут при `--write`). Живой прогон `--check` по
trunk — числа в сдаче (ожидаю: 22 карточки без title, ~100 без kind/channel, 2 дубля, 24+
адресов не на HEAD).

## С4. Проход по репозиторию

Шаг 1 (без правок): инвентаризация каналов по паспортам всех карточек → таблица «строка
паспорта → канал словаря» на решение владельца; спорные (два транспорта) — перечнем.
Шаг 2 (после решения): поля шапки всем карточкам (`channel` по таблице шага 1 — механика;
`kind` — по признаку «нет §2/§3 запроса-ответа» с перечнем на ревью; `sync` — из паспорта
«Синхронность», нет строки — ⚠ и «—»); `title` 22 карточкам — из MR !53 с авторством
Судницына; починка шапки payment-hub.
Шаг 3: `--write` → README 20 папок; ручной раздел «О системе» — из §1 карточек и
существующих README, остальное «в источниках не задано»; перевод gpb-smev, fns-my-signature,
crypto-module (сверка: ни один факт старого README не пропал — перечень в сдаче).
Шаг 4: корневой README → реестр систем; снятие таблицы «потребители по сервисам» (или её
сборка утилитой — решение владельца на шаге 1).
Шаг 5: ветка `extint/as-readme-registry`, один MR; перебазирование после вливания !37, !44,
!57; push и MR — владелец. Сдача с числами до/после.

## Риски и ограничители

- Проход С4 заденет файлы открытых MR !37, !44, !57 — вливать их до С4 или перебазировать
  проход после; порядок за владельцем.
- Классификация `kind` и `channel` — семантика; перечень на ревью владельцу до записи в
  файлы, в сдаче — число спорных.
- Ручной раздел «О системе» агент заполняет только из карточек и старых README; выдуманных
  фактов быть не должно — выборочная проверка пяти АС владельцем.
- Апрувы техбука медленные: канон и утилита не ждут техбук, в техбуке — ссылка на шаблон.
- Пока С2 не влит, команды создают карточки без полей — ⚠ утилиты, не ✗.
