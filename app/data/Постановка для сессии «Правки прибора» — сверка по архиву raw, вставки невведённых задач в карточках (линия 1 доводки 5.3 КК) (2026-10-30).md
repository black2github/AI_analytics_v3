# Постановка для сессии «Правки прибора» — сверка по архиву raw: вставки невведённых задач в карточках комплекта (линия 1 доводки 5.3 КК) (2026-10-30)

От сессии «Точки расширения эталона». Повод — ревью 5.2 КК (G1–G3, master 828c803): самая опасная системная линия — содержимое невведённых задач (GBO-50272/127678/127395/91555/81575, TEAMTB-3961/3672/3673/3210/3212/3217, TEAMZSTCO2-15256) попало в ПРОМ-карточки, ревьюер находил это вручную по маркерам в raw. Нужен механический сторож по всем 362 карточкам. Решение владельца канона о запуске — ожидается; постановка подготовлена заранее по результату пробы.

## Что уже есть и что показала проба

`app/scripts/CI/raw_oracle.py` (FB-32, версия 1.9.14) умеет обратное: del-фрагменты ВВЕДЁННЫХ задач против карточек (`--cards`, отчёт markdown). Модуль уже собирает и вставки (`collect_ins_fragments`), нормализация и маска карточки (`card_mask`, `index_cards`) общие.

Проба зеркального режима (скрипт сессии, read-only, 24 с на КК master a732c39): вставка задачи, которой нет среди тегов `src/*`, после нормализации дословно присутствует в карточке-потребителе страницы чаще, чем в «срезе как должен быть» (raw без del введённых и без ins невведённых) и чем в применённой копии `sources/confluence`.

Поэтому сторож дополняет ревью, а не заменяет.

## Задача

1. В `raw_oracle.py` добавить второй раздел режима карточек: **вставки невведённых задач в карточках**. Невведённая = `data-task` (и ID wiki/status-нотаций) не входит в множество введённых (теги `src/*`, `--introduced`); `PROM` исключён. Логика — зеркало `check_page`: фрагмент из `collect_ins_fragments` с чужой задачей, длиннее порога, считается находкой, если в маскированной карточке встречается чаще, чем `max(count в raw_kept, count в применённой копии страницы)`; `raw_kept` — как сейчас (raw без del введённых и без ins невведённых). Применённая копия берётся по page_id из `sources/confluence` (ключ `--applied`, по умолчанию `<raw>/../confluence`); без копии — считать только по `raw_kept`.
2. Отчёт `--cards`: тот же файл, два раздела — «Удалённое введёнными задачами осталось» (как сейчас) и «Вставки невведённых задач присутствуют»; у второго — сводка по задачам и карточкам и **три таблицы** одного формата «карточка | раздел карточки | страница | задача | фрагмент | строка | ×лишних | регистрация»: (а) **основной список** — находки длиннее порога «проверить» и не покрытые долгом; (б) **«проверить»** — фрагменты из `CHECK_WORDS` слов или короче `CHECK_CHARS` символов (общая фраза могла совпасть случайно, решает человек); (в) **покрытые долгом** — задача упомянута в строке долга `docs/traceability-matrix.md`, где стоит и ID этой карточки (ровно так ревью 5.2 решает, покрыта ли приписка; долг без ID карточки не покрывает — прецедент 5.1). Столбец «регистрация» во всех трёх: есть ли задача в `sandbox/confluence-unapproved-jira-pages.md` (`да`/`нет`) и строка матрицы (`L<n>` или `—`). Счётчики всех трёх — в сводку; в строке результата `main` — число основного списка отдельно (решение владельца 30.10: исполнителю нужен короткий список, около 50 строк на КК, а не 79 вперемешку).
3. Selfcheck не трогать (решение FB-32: режим карточек — отдельный отчёт, на мигрированном комплекте сигналов десятки). Коды возврата прежние.
4. Ограничители и тесты на НЕсрабатывание: вставка введённой задачи — не сигнал; чужая вставка, текст которой есть в применённой копии или в raw вне маркеров — не сигнал («законно в срезе»); короткая — пропуск со счётчиком; совпадение только в исключённых разделах/строках долга — исключено маской; задача `PROM`. Позитивные тесты: критик-span и критик-row чужой задачи, md-строка «+ID», wiki `{++ID: …++}` — по одной находке; повтор фрагмента — одна находка ×N.
5. Проверки: тесты рядом с `tests/test_raw_oracle.py`; полный набор — регресс против базлайна `HEAD`; эталон `C:\tmp\tool-golden` — 0 отличий (режим не входит в selfcheck, отличий быть не должно); прогон на КК master (клон `C:\doc-as-code\EAS\src-business-cards`, если стоит не на master — `git worktree add --detach C:\tmp\kk-check origin/master`, удалить после): ожидание порядка 79 находок в ~35 карточках, числа в сдачу вместе с перечнем карточек.
6. Канон: `_meta/tools/raw_oracle.py` живёт в бандле экспортёра рядом с `critic.py` (`_load_raw_oracle`), в каноне модуля нет — значит **сборка бандла** (`build_bundle.py --check` перед сборкой, версия 1.9.16), README бандла — строка о втором разделе отчёта. Канон: только если README `_meta/tools` описывает режим `--cards` — дополнить. Вливает владелец.
7. Analyzer — коммит по слову владельца, `git add -- <перечень>`.
