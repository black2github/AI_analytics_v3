# Постановка прибору — сторож «контур функции: префикс идентификатора, каталог и раздел источника»

Дата: 2026-11-15. От: сессия «Точки расширения эталона» (канон, нормы, приёмка).
Кому: сессия «Правки прибора, акцепт и рутина». Слово владельца на сверку префикса с каталогом — 15.11.

## Зачем

Владелец 15.11 провёл ревизию признаков контура функции. Прибор сейчас сверяет контур только у пары «функция метода — контракт». Сверки префикса идентификатора функции с её каталогом нет вовсе: в замере 14.11 `docs-sign` FUN-MB-SYS-01 лежит в `function/bank/`, и прибор молчит.

## Норма

- Шаблон `function.md`, «Идентификация и размещение»: `fun-cl-NN-…` в `function/client/`, `fun-bnk-NN-…` в `function/bank/`, `fun-sys-NN-…` в `function/system/`; чек-лист, п. 1–2: `id` соответствует контуру, файл в папке своего контура, имя файла = идентификатор строчными.
- Скилл `create-function`, «Вход» (ветка канона `meta/function-contour-signs`, ждёт коммита владельца): раздел источника — признак контура («Функции Клиента» / «Клиент» → CL; «Функции Банка» / «Банк» → BNK; «Функции Системы» / «Системные функции» / «Система» → SYS); обращение по токену исключает системный контур; библиотечная процедура — системная независимо от раздела.

## Срез 1 — сделать: префикс идентификатора ↔ каталог ↔ имя файла

Проверка уровня комплекта для карточек `type: function`, слой — ядро:

- контур по префиксу идентификатора (FUN-CL / FUN-BNK / FUN-SYS, со слотом сервиса или части) совпадает с подкаталогом `function/<client|bank|system>/`;
- имя файла начинается с идентификатора строчными.

Вне проверки: часть вне контура Экосистемы — если шаблон для неё даёт иное размещение (проверьте по `function.md` и паспорту границы, ответьте в сдаче); README каталога.

Перед кодом — замер по тем же комплектам, что 13–14.11, с перечнем карточек. Строгость выберу после замера; ожидание — ошибка (✗), если наследия вне одного случая `docs-sign` нет: это внутренняя согласованность карточки, а не норма, менявшаяся со временем.

## Срез 2 — только замер и оценка, без кода: раздел источника ↔ контур

Мой замер 15.11 по КК (master `be98cc10`, 133 функции; страница — по `confluence_page_id` в шапке файла выгрузки, признак — имя папки `…-Функции-Клиента`, `…-Функции-Банка`, `…-Функции-Системы`):

- папка совпала с контуром — 81;
- папка контура не называет — 48 (из них 32 системные: папки «Системные-функции», «Управление-фильтрами-ЭФ», «Настройка-скроллера» и др.; 16 клиентских: страницы методов в «ЭКО_Корпоративные-карты» и «Интеграции», скрипты виджетов);
- папка не совпала — 4: FUN-SYS-12, 23, 27, 33 лежат в «Функции-Клиента». Три из них (23, 27, 33 — «Логика формирования текста MyDSS») — библиотечные процедуры, по норме системные; FUN-SYS-12 «Метод показа карты расположения офиса» — под вопросом, вынесен владельцу.

Нужна оценка: стоит ли сторож «раздел источника не совпадает с контуром функции» (слой — выгрузка; ⚠; библиотечная процедура — по пометке в «Назначении» — вне признака), и замер по остальным комплектам, где выгрузка лежит рядом с комплектом. Имена папок источника — слова источника: если делать, то объявленной словарной эвристикой с записью в реестре README прибора.
