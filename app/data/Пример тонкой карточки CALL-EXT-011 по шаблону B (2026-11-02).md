# Пример карточек вызова по шаблону B в подсервисе-потребителе: CALL-EXT-011 и CALL-EXT-036 (bc-issue), полная инициализация без ветвлений

Версия 5 от 02.11 поздно, по решению владельца: **карточка вызова — полная инициализация параметров без ветвлений.** Переключатель 10.1 / 10.2 версии 4 был выбором между двумя разными наборами параметров одного метода (другое имя процесса, другой состав блоков), то есть между двумя вызовами; в API First это два обращения к контракту, каждое с полной инициализацией, а условие выбора живёт у вызывающего (SCR-CL-20 B-2, FUN-SYS-10 шаг 1), где оно и записано в источнике. Поэтому в bc-issue две карточки: CALL-EXT-011 (вариант 10.1) и CALL-EXT-036 (вариант 10.2); строки «Если «Вариант заполнения идентификатора» = «Основной блок», то …, иначе …» при зафиксированном варианте схлопнулись в значения (10.1) или «в постановке не задано» (10.2, третий случай Р-2). Сохраняются решения версии 4: одна карточка на потребителя без «общей части» в bc-component; чужая специфика страницы-копии не переносится (Р-1); «=» для присвоений; «Сопоставление входящего сообщения» по канону 02.11. Пример для обсуждения и как образец волны PROM-5.3-CALL, не карточка комплекта. Форма — `_meta/templates/contract-call.md`, блок «Шаблон карточки вызова». Источники содержания: страница КК 2464250512 (копия метода ЕСК с колонкой «Логика заполнения для проверки полномочий пользователя на подпись документа»), FUN-SYS-10 (2464250492) §3 и §6, SCR-CL-20 (2166860206) кнопка B-2 «Подписать и отправить», базовый контракт EXTINT-ESK-003 (trunk после !74). Примечания составителя — после черты в конце, в карточки не входят.

Разделение фактов:

| Факт | Кто владеет | Где живёт |
|---|---|---|
| Состав метода: теги, типы, кратности, коды продуктов, коды отказов, примеры | АС ЕСК | базовый контракт EXTINT-ESK-003 |
| Какие параметры и с какими значениями сервис подставляет при вызове для конкретной заявки — общие (конверт, реквизиты организации и пользователя, SessionID) и зависящие от заявки (имя процесса, наборы полномочий); куда записываются параметры ответа | подсервис, чья заявка | карточка вызова подсервиса, одна на каждый набор параметров: bc-issue — CALL-EXT-011 (вариант 10.1) и CALL-EXT-036 (вариант 10.2); bc-status — CALL-EXT-037 (10.2); bc-limits — CALL-EXT-038 (10.2) — примечание 3 |
| Какой из вызовов выполнить для данной заявки (условие на ENT-007) | вызывающий: экранная форма и общая функция | SCR-CL-20 B-2 «Видимость», FUN-SYS-10 шаг 1 |

# CALL-EXT-011. ЕСК. Проверка полномочий на подпись заявки на выпуск карты с открытием счёта [КК_ВК]

**Базовый контракт:** [EXTINT-ESK-003. Проверка полномочий пользователя на подпись документа в АС ЕСК](https://gitlab.gboteam.ru/EAN/docs-external-contracts/-/blob/HEAD/esk/extint-esk-003-signing-authority.md) — внешняя АС ЕСК (ЦФТ ГО)
**Примеры обмена:** [esk/examples/](https://gitlab.gboteam.ru/EAN/docs-external-contracts/-/tree/HEAD/esk/examples)

## Назначение

Подсервис выпуска карт сервиса «Корпоративные карты» через онлайн-адаптер ЕСК вызывает процедуру `Repr_Auth_Check(p_request clob) return clob` АС ЕСК (ЦФТ ГО), чтобы проверить наличие у пользователя клиента полномочий на подпись «[КК_ВК] Заявка на выпуск карты» от имени организации по процессу проверки `GPB_CorpCardIssue_Auth_Check` — для заявок с открытием нового счёта. Владелец вызываемого контракта — АС ЕСК. Направление обмена: запрос XML в CLOB → ЕСК; ответ ← ЕСК сообщением типа ИО `Receipt` в CLOB. Вызов выполняет общая функция сервиса FUN-SYS-10; выбор между этим вызовом и [CALL-EXT-036](call-ext-036-esk-signing-authority-issue-comb.md) делает вызывающий по условию на заявке (SCR-CL-20 B-2 «Видимость», FUN-SYS-10 шаг 1). Результат управляет доступностью кнопки «Подписать и отправить».

### Где используется

Данный запрос используется в:

- проверки полномочий пользователя на подпись заявок в [FUN-SYS-10 Функция проверки в ЕСК наличия полномочий пользователя на подпись документа](../../../bc-component/function/system/fun-sys-10-esk-auth-check.md).

Наличие полномочий определяется с помощью Функции проверки в ЕСК наличия полномочий пользователя на подпись документа, вызываемой с параметрами, определяемыми следующим образом (SCR-CL-20, кнопка B-2 «Подписать и отправить», «Видимость»).

## Примечания составителя (в карточки не входят)

1. **Что изменилось против версии 4.** Одна карточка bc-issue с переключателем 10.1/10.2 разделена на две — по одному набору параметров на карточку; в таблицах правил не осталось ни одного «Если»: строки `CL_PRIV_*` и `CL_ORG_RelPersons` в 011 получили значения варианта «Основной блок», в 036 — «в постановке не задано» (у строки 10.2 источника вариант заполнения идентификатора не задан); блок «Выбор варианта» с условием на ENT-007 из карточек убран — условие живёт у вызывающего (SCR-CL-20 B-2, FUN-SYS-10 шаг 1) и в карточках не повторяется (один дом у факта). Скобка про «Обновление сведений» у `SKIP_CONTROL_DUL` снята (Р-1, замечание координатора). Раздел «Сопоставление входящего сообщения» в обеих карточках одинаков — это цена полной инициализации на карточку, в API First исчезает.

3. **Аналоги для bc-status и bc-limits.** У «[КК_БК] Заявка на изменение статуса карты» и «[КК_ЛК] Заявка на управление лимитами по карте» только вариант 10.2 (строка 10.2 FUN-SYS-10, «- новое»): CALL-EXT-037 (bc-status; источники SCR-CL-17 2166860586, PROC-016 шаг 5) и CALL-EXT-038 (bc-limits; FUN-CL-21 2166859675 шаг 1, PROC-007 шаг 5) строятся по форме карточки 2 с главной страницей своего подсервиса; общие строки повторяются дословно.
