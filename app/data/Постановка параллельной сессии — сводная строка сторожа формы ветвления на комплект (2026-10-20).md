# Постановка сессии «Правки прибора, акцепт и рутина»: сторож формы ветвления — одна сводная строка на комплект

Дата: 2026-10-20. От владельца канона и прибора. Отмашка владельца пилота получена (20.10),
можно начинать. База: analyzer `f58013a2`, канон `master c737cdd`.

## Зачем

Сторож «форма ветвления — «то»/«иначе» не в начале строки» (ПР-15, `normalize_tables.py`,
`Check("branch_form", _fc_branch_form, scope="file")`, строка ~5073) пишет строку
«предупреждение: … ×N» плюс два примера на КАЖДЫЙ файл, и файл идёт в ⚠ итога. У комплекта,
мигрированного до волны 5, это сотни файлов с одним и тем же ⚠ (КК до нормализации: 245 файлов,
1376 мест) — шум, за которым не видно прочих предупреждений. Решение владельца пилота 20.10:
в отчёте самопроверки комплекта — одна сводная строка на комплект вместо строки на файл.

## Что сделать

1. **Сводная строка уровня комплекта** (`selfcheck.py`, новая проверка `_kc_branch_form`,
   `affects_verdict=False`, рядом с `_kc_spellings`): по всем файлам комплекта посчитать места
   сторожа (`branch_form_offenders`) и, сухим прогоном `normalize_branch_form` по тексту файла,
   сколько из них закроет нормализатор. Одна строка:
   `⚠ форма ветвления (notation §1): N мест в M файлах; normalize_tables.py --branch-form --write закроет K, вложенных условий вручную V (<файл1> ×a, <файл2> ×b, <файл3> ×c, …)`
   — три файла с наибольшим числом мест, остальное «и ещё F файлов». N = 0 → строки нет.
   Полный перечень по файлам (файл ×мест) — только в файле отчёта `--out`, под сводной строкой с
   отступом, как у сводки написаний (T7).
2. **Строка на файл в отчёте комплекта — убрать.** В режиме самопроверки комплекта
   `_fc_branch_form` не должна давать ни строки, ни ⚠ файлу: файлы, у которых единственное
   предупреждение — форма ветвления, становятся ✓ (это и есть цель: ⚠ итога — про другое).
   Как именно отключить — на усмотрение (флаг контекста `_FileCtx` «сводка на уровне комплекта»,
   либо исключение `branch_form` из набора файловых проверок при вызове из `selfcheck`), лишь бы
   **одиночная проверка файла** (`normalize_tables.py --check <файл>`, гейт переноса по одной
   карточке) по-прежнему показывала строку на файл с примерами — там она и нужна.
3. **Контракт мягких сигналов.** Сводная строка начинается с `⚠` (видна в отчёте комплекта как
   обычное предупреждение уровня комплекта); `SOFT_SIGNAL_RE` не трогать, если не нужно.
   Итог ИТОГО: число ⚠-файлов уменьшается ровно на файлы, у которых других ⚠ не было, —
   проверить на копии КК и записать дельту в сдачу.
4. **Тесты** (`tests/test_branch_form_normalize.py` или новый `tests/test_selfcheck_branch_form.py`):
   сводная строка с верными N/M/K/V на комплекте из трёх файлов (один с двумя местами в ячейках,
   один с вложенным, один чистый); строки на файл в отчёте комплекта нет; одиночная проверка
   файла строку на файл даёт; N = 0 — строки нет; полный перечень в `--out`.
5. **Полигон.** Копия клона КК ДО нормализации (`C:\tmp\kk-branch-form\orig`, если ещё есть;
   иначе снова скопировать `docs` клона `C:\doc-as-code\EAS\src-business-cards`): отчёт
   самопроверки до/после — ИТОГО дословно, сводная строка дословно, число строк отчёта до/после.
   Стенд (`ext-sandbox\src-business-cards`, уже на срезе c737cdd) и эталон: ИТОГО — ожидаемо
   ⚠ файлов меньше, ✗ те же; golden master — отличия только в строках формы ветвления.
6. **Копии в канон**: ветка `meta/branch-form-summary-tool` от `master` (перед веткой
   `git log --oneline master..origin/master -- _meta/tools/` пуст) в отдельном рабочем дереве;
   `normalize_tables.py` и `selfcheck.py` (и `kitcheck/*`, если тронуты); сверка `tr -d '\r'`;
   SF ✓. Шаблоны не трогать.
