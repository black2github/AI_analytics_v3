## (1) К-13 «HTML-коммент в чистовике» срабатывает внутри fenced-блока кода — очередь (23)

- **Где:** `app/scripts/CI/kitcheck/checks/card_form.py` :312–325 (`re.findall(r"<!--.*?-->", text, re.S)` по всему тексту карточки); то же вырезание комментариев до поиска значений в `card_run.py` :236 и `card_clean.py` :376 — проверить, не режут ли они содержимое блоков кода (это потеря литерала при сверке, а не только ложный ✗).
- **Случай:** proc-033 КК (срез 2166860090) — XML-пример бизнес-нотификации ЕСК с шестью комментариями в самом payload («Мнемо-код компоненты-получателя», «GUID процесса – …»). Прежний заход молча убрал их ради чистого гейта — потеря литерала источника; координатор возвращает дословно, ✗ помечает ложным.
- **Правка:** комментарии внутри ``` … ``` (и `~~~`) не считаются служебными пометками чистовика — К-13 смотрит только текст ВНЕ блоков кода. Границы блоков — одним правилом прибора `kitcheck/fence.py` (`fence_of`), как решено треком fence-recognition 17.10; свой разбор fence не заводить. В `card_run.py`/`card_clean.py` — если комментарии вырезаются до сверки значений, внутри блоков кода их оставлять (значения примера должны находиться).
- **Тесты:** карточка с `<!-- … -->` в блоке кода — ✗ нет; тот же комментарий вне блока — ✗ как прежде (НЕсрабатывание ослабления); комментарий в блоке кода участвует в сверке значений с источником (если применимо).

## (2) check_title: маркер «[КК]» и префикс «Копия » страниц-копий — очередь (22)

- **Где:** `kitcheck/checks/card_source.py` :582 — закрытый список маркеров контура-потребителя `^\[(?:O2\+NEW|О2\+NEW|ОНБ_2021|КК_ВК|ББ_РЕГ|ГЭП|РЭП)\]\s*` (contract-call.md :43–46: маркер контура снимается из титула базового контракта).
- **Случай:** страницы-копии КК «Копия [КК] ЕСК_ОА_Проверка полномочий…» (2464250512 и др.) — базовому ставится имя метода без следов копии, сторож даёт ✗ «ПОТЕРЯ НАИМЕНОВАНИЯ» (EXTINT этап 2, ESK-003).
- **Правка:** в список маркеров добавить `КК` (и, для симметрии, прочие теги подсервисов КК, если они встречаются в титулах копий: `КК_ЛК`, `КК_БК` — проверить по выгрузке `sources/confluence` клона КК grep-ом титулов «Копия [»); префикс `Копия ` (с пробелом, в начале титула, регистр как в Confluence) — снимаемый префикс страниц-копий, снимается ДО маркера. Ограничитель: «Копия» внутри титула («Получение копии документа») — не префикс.
- **Тесты:** титул «Копия [КК] ЕСК_ОА_X» ↔ карточка «ЕСК_ОА_X» — ✓; «[КК_ВК] X» ↔ «X» — ✓ (как было); «Получение копии справки» ↔ «Получение справки» — ✗ (НЕсрабатывание).

## (3) Кавычечные литералы из ярлыков ссылок на страницы выгрузки — очередь (20)

- **Где:** `card_source.py` `quoted_literals()` :391–410 (`_QUOTED_RE`), пропуски `_QUOTED_SKIP_RE`/`_QUOTED_MARKUP_RE`.
- **Случай:** intc-007 КК — в источнике ссылка на страницу с титулом «Маппинг статусов карт в ПЦ на статусы карт в сервисе "Корпоративные карты"»; карточка по решению L1923 ссылается на раздел DM-001 — титул страницы ей не нужен; сторож требует литерал "Корпоративные карты".
- **Правка:** кавычечный литерал, целиком лежащий внутри ярлыка гиперссылки источника (`<a …>…</a>` в HTML view; `[…](…)` в markdown-выгрузке) на страницу выгрузки/Confluence, — адрес, не литерал: не требовать. Ограничитель: ссылка на внешний ресурс вида «Нажмите "Отправить"» внутри `<a>` на кнопку — редкость; граница — href на `confluence`/`pageId`/страницу выгрузки (есть `_QUOTED_SKIP_RE` для figma/confluence URL — расширить на ярлык такой ссылки, не только на URL).
- **Тесты:** литерал в ярлыке ссылки на страницу Confluence — не требуется; тот же литерал в обычном тексте рядом — требуется (НЕсрабатывание).
