# Постановка: полнота FB-16 признаёт ячейку-только-URL Confluence отсылкой источника (FB-41 КК)

Дата: 2026-10-28. Для сессии «Правки прибора, акцепт и рутина». Коммит analyzer — по слову владельца; ветка канона —
по его командам. Источник: FB-41 КК (`feedback.md`, 2026-10-28), ответ владельца канона — там же. Очередь — после
FB-39 (в работе), до двух постановок FB-40: FB-41 держит аннотированный ✗ в baseline КК.

## Проблема

`app/scripts/CI/normalize_tables.py` (= канон `_meta/tools/normalize_tables.py`, срез 7f5a6cf), сверка полноты
таблиц источника, исключение FB-16 (строки 3010–3021): ячейка со ссылкой на Confluence не считается потерей, если
после снятия ссылок остаток `rest` короткий и содержит «confluence» либо начинается с «см». Ячейка страницы
2184433380 (CALL-EXT-005, relink 3.5) — `Документация | [https://confluence.gboteam.ru/x/Ngo5Ag](https://confluence.gboteam.ru/x/Ngo5Ag)`:
ссылка целиком, остаток пуст → исключение не срабатывает → «в карточке отсутствуют 1 значений ✗ НИЖЕ ПОРОГА,
пример потери: '[https://confluence.gboteam.ru/x/Ngo5Ag](https://confluence.'». Перенести URL в карточку нельзя:
сторож отсылков `_fc_source_page_refs_and_columns` (строки 5110–5136) верно бракует «confluence» в теле.
Старая страница-двойник 2184433423 проходила исключение текстом «Cм. внутр. Сonfluence [url]».

Воспроизведено владельцем 28.10: `check_source_tables(card, sources/confluence/…)` на клоне КК — единственный ✗
карточки call-ext-005 именно эта ячейка. Координатор временно снял URL (b4b4cab), ✗ аннотирован в baseline
ACCEPT-36-r06 до патча.

## Что сделать

1. **Условие исключения** — расширить, но НЕ буквально по предложению координатора (`rest.strip() == ""`):
   остаток пуст и для `[Название страницы](confluence-url)`, а текст такой ссылки — содержание, которое
   переносится (норма FB-38: ссылка сводится к тексту-названию; `_norm_cell` так и делает). Правильный признак —
   нормализованное значение ячейки `cv` (ссылки уже сведены к тексту) само целиком состоит из URL:
   `re.fullmatch(r"(?:https?://\S+\s*)+", cv)` при уже проверенном `_CONFLUENCE_URL_RE.search(cell)`.
   Проверено на срезе 7f5a6cf: для `[url](url)` и голого `url` `cv = 'https://confluence.gboteam.ru/x/ngo5ag'`,
   для `[Описание представления](url)` `cv = 'описание представления'` — остаётся потерей.
2. **Отчёт** — та же i-строка «ячейки-ссылки на Confluence ×N полнотой не считаются (живые URL не переносятся)»,
   новых строк не вводить.
3. **Комментарий в коде** — к блоку FB-16 дописать «FB-41 КК (2026-10-28): ячейка целиком URL (markdown-ссылка
   с URL в тексте или голый URL) — та же отсылка».

## Ограничители

- Асимметрия: расширение только на ячейки, где переносить буквально нечего (значение = URL). Ячейка-ссылка с
  названием, ссылка на не-Confluence URL (gitlab, figma) — поведение не меняется (вне FB-41, не расширять молча).
- Тесты (`tests/test_kk_feedback_batch.py`, рядом с `test_confluence_url_cell_is_not_a_loss`):
  (а) ячейка `[confluence-url](confluence-url)` без следа в карточке → `ok`, i-строка ×1;
  (б) голый `https://confluence…` без markdown → `ok`;
  (в) НЕсрабатывание: `[Описание представления](confluence-url)` и карточка без «Описание представления» → ✗
  «отсутствуют»; с названием в карточке → `ok` без i-строки;
  (г) НЕсрабатывание: `[https://gitlab…](https://gitlab…)` → по-прежнему ✗.
- Golden (эталон `C:\tmp\tool-golden`, как в предыдущих постановках): отличий нет ни у одного комплекта, кроме
  КК; живой прогон selfcheck на клоне КК владельца (master 5e7be06) командой координатора
  (`--docs docs --sources sources/confluence`): call-ext-005 ✗ → ✓, остальные вердикты без изменений —
  строки в сдачу.
