# Координатору комплекта КК: мини-комплект виджетов переезжает в `docs/modules/`, после заходов добавляется гейт формы

Дата: 2026-10-23. От владельца канона. Решение владельца пилота 23.10 (реестр решений Д-49).

## 1. Что случилось

Пробный прогон гейта переноса (`transfer_gate.py`) на срезе КК показал: мини-комплект зоны
`modules/widgets-rtl/` лежит рядом с `docs/`, а гейт переносит в репозиторий документации только
`docs/`. После переноса все 26 ссылок карточек `CALL-MOD` и README `contract-call/` на
`../../../../../modules/widgets-rtl/…` ушли бы за пределы репозитория назначения. Это дефект
нормы Д-46, не вашего захода: WID-01/WID-02 сделаны по норме.

## 2. Что меняется в норме

Мини-комплект живёт **внутри `docs/`**: `docs/modules/<имя>/` (у КК — `docs/modules/widgets-rtl/`).
Он уезжает переносом вместе с комплектом, глубина относительных ссылок сохраняется сама.
Обновлены: SF-07, `module-kit-readme.md`, `module-interface.md`, `contract-call.md` (дерево),
`create-artifact`, `create-contract-call`, план (шаг 2а), профиль источников. Прибор (отдельный
срез, после приёмки): переходный сторож ⚠ «мини-комплект вне docs/» на старом месте, зона под
`docs/modules/` не считается карточками комплекта (схема типов, реестр ID, матрица — не
применяются; `page_id`, шапка, ссылки — применяются).

## 3. Что сделать команде (один заход-дозаход, механика)

1. Переезд и пересчёт ссылок делает скрипт `kk-zone-move-links.py` (передаём вместе с этим
   сообщением; положите его вне клона). Из корня клона, PowerShell:

   ```
   python <путь>\kk-zone-move-links.py --dry-run
   ```
   Ожидание: план на 41 ссылку в 18 файлах, `git status` пуст. Затем:

   ```
   python <путь>\kk-zone-move-links.py
   ```
   Ожидание в `git status`: 7 переименований, 7 переименований с правкой, 11 правок. Скрипт
   делает `git mv modules/widgets-rtl docs/modules/widgets-rtl` (история сохраняется),
   пересчитывает относительные ссылки по фактической цели и удаляет опустевший `modules/` и
   пустой `widgets-rtl/` в корне. Байты сохраняются: меняется только путь в скобках ссылки.
2. Что именно пересчитывается — 41 ссылка: 26 из `docs/` в зону (`srs/bc-component/contract-call/README.md`,
   `…/module/README.md`, `call-mod-003-pan.md`, `call-mod-004-cvv.md`,
   `srs/bc-pin/contract-call/module/README.md`, `call-mod-001-pin-input.md`,
   `call-mod-002-pin-send.md`), 7 из зоны в `docs/` (паспорт, контракты `interface/`, `spec/`) и
   8 из зоны на служебный `open-questions.md` в корне (5 в паспорте, по одной в `mod-001`,
   `mod-002`, `scr-05`). Последние 8 скрипт пересчитывает, чтобы ссылка в src не сломалась, и
   печатает отдельным перечнем «убрать или заменить»: в репозиторий документации служебный
   файл не переезжает, гейт формы даёт по ним ✗ (см. п. 4). Контроль — `selfcheck.py` после
   переезда: битых ссылок нет.
3. Если скрипт отказывается (каталог `docs/modules/widgets-rtl/` уже есть) — ничего не меняется,
   напишите нам.
4. Прогнать `selfcheck.py --docs docs --sources sources/confluence` — ИТОГО без новых ✗;
   в `inventory.md` и строке «вне Экосистемы» профиля источников путь `modules/widgets-rtl/`
   → `docs/modules/widgets-rtl/`.
5. Сдача по §8; срок — по вашему плану, до следующего захода зоны (OQ-295…298).

## 4. Гейт формы после захода (протокол §8, новый п. 17)

После приёмки среза канона с Д-49 и прибора: координатор при техприёмке каждого захода гоняет
`transfer_gate.py --after-step --report <файл> --baseline <отчёт прошлого захода>` (35–50 с:
сборка в целевой раскладке, корень раскладки, валидатор платформы, ссылки, README, типы;
selfcheck повторно не гоняется).
Вердикт «ФОРМА ПЕРЕНОСИМА / НЕ ПЕРЕНОСИМА: блокеров N (новых M)», строка — в сдачу. Новый ✗
формы — дозаход до приёмки; известные — долги в журнале координации. Полный гейт (READY) —
только перед переносом.

Что гейт формы показал на копии КК с перенесённой зоной — 9 блокеров, это ваши долги формы,
не срочные: `archive/` внутри `docs/` — посторонний каталог корня комплекта (перенести внутрь
раздела или удалить); 8 ссылок на служебные файлы миграции — `../open-questions.md`,
`../inventory.md`, `../migration-plan.md` из `README.md`, `srs/README.md` и четырёх файлов зоны
(паспорт, два контракта, `scr-05`) — служебные файлы в репозиторий документации не переезжают,
такие ссылки перед переносом надо снять или заменить словами. Предупреждения (не блокируют):
30 каталогов карточек без README-реестра, пустой раздел «Покрытие: API ↔ SRS» при 13 описанных
методах, нет `service-vision.md` и `glossary.md`. Открытых вопросов по журналу — 207 (198
«открыт», 9 «частично»), без строки долга в матрице 203: к переносу все они должны стать
долгами матрицы или закрыться. Сообщим, когда `--after-step` доступен в срезе канона.
