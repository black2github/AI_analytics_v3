# Вопрос владельцу канона — кто заполняет CODEOWNERS и gpb-manifest docs-репозитория

Дата: 2026-10-17. От сессии «Правки прибора, акцепт и рутина» для сессии «Точки расширения
эталона». Волна 8 замечаний ОНБ-В (ЗК-34, ЗК-35, ПР-35, ПР-36). Решение нужно до вливания MR
техбука `analytics/onb-v-wave8` (`521b8f0`, ждёт апрувов ED): если ответ расходится с текстом MR,
ветку надо поправить до вливания.

## Расхождение

| Где | Что записано |
| --- | --- |
| Реестр отработки замечаний, ЗК-34 | «нет контакта — null, заполняет **акцептующий** до MR» |
| Реестр, ЗК-35 и ПР-36 | фраза в reference канона «Перенос комплекта»: кто заполняет `gpb-manifest`, `CODEOWNERS`, `.gitignore`, MR — **акцептующий** |
| Пакет задач 2, п. 12.3 | CODEOWNERS: «кто заполняет (**лид команды**, не агент)» |
| MR техбука, `cookbook/analytics/gitlab-settings.md` | «Заполняет **лид команды**, не агент. Команда — поле `teamInfo.team` в `gpb-manifest.json`, её состав — в team-configs; при сомнении логин уточняют у лида» |
| MR техбука, `standards/common/gpb-manifest.md` | «Значения заполняет **лид команды** до MR» |
| reference канона, «Перенос комплекта» | фраза не внесена |

Тексты MR следуют пакету задач; реестр — решению разбора. Одно из двух надо привести к другому.

## Варианты

- **А. Заполняет акцептующий** (аналитик команды, принимающий комплект при переносе): он и так
  ведёт перенос и MR. Правка MR техбука: «лид команды» → «акцептующий»; фраза в reference.
- **Б. Заполняет лид команды**, как в MR. Правка реестра (ЗК-34, ЗК-35, ПР-36); фраза в reference —
  «лид команды».
- **В. Заполняет акцептующий, значения подтверждает лид команды**: акцептующий вносит файлы при
  переносе, логины и контакты берёт у лида (лид — источник, акцептующий — исполнитель); агент
  значения не подбирает. Правка MR техбука в обоих файлах; фраза в reference.

Рекомендация — В: разделяет «кто делает» и «откуда значения», снимает противоречие обоих текстов и
сохраняет главное правило замечания ЗК-35 — логины не подбираются по косвенным признакам.
