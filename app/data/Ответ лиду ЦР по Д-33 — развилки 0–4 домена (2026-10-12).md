## 1. EXTINT домена — почему правило не меняется

Ваш аргумент принимается в части механики: отклонение с записью и обязательством вынести — именно так и оформляем. Но как **отклонение ЦР**, а не как вариант правила для всех. Три причины.

**1.1. Критерий репозитория — контрагент (внешний сервис или система), а не число потребителей.** `docs-external-contracts` — это не «общее», а «внешнее для Экосистемы»: «базовые описания обмена с внешними АС банка вне контура конкретного сервиса», идентификаторы `EXTINT-<AS>-NNN` «независимо от сервиса-потребителя» (README репозитория, `conventions` §5.1.1). Утверждение «ПлЦР использует только этот домен» — про потребителей и поэтому не входит в критерий и не может обосновать исключение из него. Вариант правила «исключение решением лида» разрешил бы каждому следующему домену держать внешние контракты у себя по тому же основанию — и репозиторий перестал бы быть реестром внешних АС.

**1.2. Для криптомодуля основание «только этот домен» неверно уже сегодня.** В общем репозитории есть `crypto-module/http/` с `EXTINT-CRYPTO-MODULE-001…010` и потребителем `signature` (docs-sign, `CALL-DS-EXT-001`). В `shared/srs/integrations/crypto-module/` ЦР ведёт вторую, независимую постановку того же модуля: `EXTINT-KM-002` «Инициализация ключевого контейнера» = `EXTINT-CRYPTO-MODULE-002`, «Подпись данных и шифрование» ≈ `-008`, «Проверка подписи» ≈ `-006`. Два описания одной АС под двумя рядами идентификаторов, и таблица «Потребители» в общем репозитории про ЦР не знает — владелец контракта не сможет уведомить ЦР об изменении. Это ровно тот вред, ради предотвращения которого репозиторий существует. Для ПЦР-Коннект и альбомов ЭС ЦБ «только этот домен» сегодня, вероятно, правда — на правило это не влияет.

**1.3. Канон — целевой; отклонения фиксируются, а не легализуются.** Так уже живёт O2+ (эталон не соответствует ряду правил, и это записано как расхождение); так живут долги ссылок. У отклонения есть штатная форма — запись в README комплекта и долг в матрице со сроком; её и применяем.

**Что требуется от ЦР по этому пункту:**

1. В README `shared` — раздел «Отклонения от канона»: базовые контракты внешних АС ведутся в `shared/srs/integrations/`, перенос в `docs-external-contracts` — долг трека 7, с обязательством вынести при любом внешнем потребителе.
2. Криптомодуль — вне очереди трека 7, потому что внешний потребитель уже есть: карточки `EXTINT-KM-*` заменяются ссылками на `EXTINT-CRYPTO-MODULE-*` (при расхождении постановок — открытый вопрос владельцу контракта, не параллельная карточка), карточки вызова ЦР регистрируются в «Потребителях» общего репозитория по правилу `create-contract-call` (ветка от свежего `trunk` → MR).
3. ПЦР-Коннект / альбомы ЭС ЦБ — в треке 7 по готовности; до переноса — долг.

## 2. Глоссарий — оба режима

Ваш довод принят: при сквозных терминах указатель в каждом комплекте вырождается в пустой файл. Канон получает два режима, объявляемые в корневом README домена строкой «Глоссарий: доменный» либо «Глоссарий: доменный + указатели»:

- **доменный** — один `glossary.md` домена (`GLO-000`), в комплектах файла нет, ссылки ведут в корень; при выносе сервиса из домена указатель создаётся шагом выноса (ваш пункт);
- **доменный + указатели** — в комплекте `glossary.md` с терминами только этого сервиса и отсылкой в корень; для сервиса с собственным словарём.

Прибор и гейт переноса при режиме «доменный» отсутствие `glossary.md` в комплекте считают нормой (ваш критерий 5.6.4). Для ЦР — режим «доменный», ничего менять не нужно; `GLO-001` → `GLO-000` — при ближайшей правке корня.

## 3. Концепция домена — отдельный шаблон

Принято: шаблон `domain-vision.md`, тип `domain-vision`, `id: VIS-000`, обязательный раздел «Карта сервисов домена»; корневые `VIS`/`GLO` без слотов и вне матриц комплектов — в шаблоне и в стандарте §5 явно. Ваш файл уже в этой форме; `VIS-001` → `VIS-000` — косметика при ближайшей правке.

## 4. Терминология

В стандарте и каноне разводим: `service-id` — имя каталога комплекта и `code` записи каталога сервисов (из `team-configs`); **слот сервиса** — 2–4 латинские буквы в идентификаторах, объявленные в таблице сервисов домена. Таблица корневого README: `service-id (каталог) | Слот | Название | Вход` — ваша форма; прибор читает колонки «Каталог»/«service-id» и «Слот»/«Код в ID». В тексте MR !220 и канона формулировки «код сервиса» заменяются на эти два термина.

## 5. Записи каталога и ссылки — подтверждение

- Каталог: по одной записи на комплект `<service-id>/`, включая `shared`; `repo` внутрь `docs-digital-ruble`; поле `domain` — `digital-ruble`; записи домена нет; `ms-*-processing`, `lib-*`, `eco-*` записей не порождают. Сторож каталога несколько `repo` в один репозиторий считает нормой.
- Прямые ссылки из тел документов в соседний комплект — целевой долг; текущее состояние ЦР — объём трека 7, не условие принятия норм; в гейте нет и не планируется проверки «CALL-INT внутри домена». Порядок трека 7 — ваш: прибор домена → новые связи только через `CALL-INT` → `INTC`/`LIBC` → срезы замены ссылок от границ `shared` → перенос EXTINT (криптомодуль — первым, см. §1).

## 6. Прибор — что уже сделано и что меняется

Сделано (analyzer, в канон — срезом B): корень домена по таблице сервисов корневого README (распознаётся и ваша форма `service-id | Код в ID`); второй слот в стороже ID с колонкой «Слот: нет»; зона `сервис <service-id>[, зона части]` в разметке профиля; поле `domain` каталога. Живой прогон на `digital-ruble-registration` и `shared`: ✗ «корень: посторонние файлы ×5» исчез, слот сервиса принимается; ваши критерии 5.6.1–5.6.3, 5.6.5 выполняются. 5.6.4 — выполняется после правки на режим глоссария (срез B).

Что прибор при этом покажет на ЦР и что с этим делать (трек 7, не блокеры):

| Сигнал | Причина | Действие |
| ------ | ------- | -------- |
| `✗ слот сервиса … CALL-EXT-REG-WSCF-001 несёт слот не на месте` | в каноне слот стоит сразу после префикса: `CALL-REG-EXT-001` (как `CALL-DS-EXT-001` у docs-sign) | перенумерация карточек вызова при треке 7 |
| `✗ слот сервиса … PLT-000 без слота сервиса` (и `EXTINT-KM-*` в `shared`) | документы уровня сервиса в комплекте домена несут слот сервиса (`PLT-SHR-000`); `EXTINT-KM-*` — §1 | при треке 7 |
| ✗ внутренних сторожей по карточкам | расхождения с шаблонами канона (snake_case вертикалей, формы таблиц и т. п.) | срезами трека 7 по сервисам, начиная с `shared` |
