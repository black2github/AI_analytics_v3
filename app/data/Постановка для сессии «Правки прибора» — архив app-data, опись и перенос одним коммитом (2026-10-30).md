# Постановка для сессии «Правки прибора» — архив app/data: опись, согласование, перенос одним коммитом (2026-10-30)

От сессии «Точки расширения эталона», по решению владельца 30.10 (трек предложен 31.10 утром, критерии ниже владелец принял передачей этой постановки). Репозиторий — analyzer (`C:\Users\alexe\PycharmProjects\requirements-analyzer-v3`, ветка main). Рутинная задача: аккуратность важнее скорости, потеря адреса файла хуже лишнего оставленного файла.

## Зачем

В корне `app/data/` около 260 файлов (сообщений ~44, сдач ~32, постановок ~24, ответов ~11; ~160 с датой в имени). Неактуальные мешают поиску. Нужно перенести исполненное в `app/data/archive/` без потери информации и адресов.

## Что переносить и что нет

В архив:
- постановки, по которым есть сдача или запись о вливании (в статус-файле `DOC_AS_CODE_PILOT_STATUS.md`, в самой сдаче или в сообщении коммита);
- сдачи (файлы «Сдача — …»);
- сообщения, ответы, письма, рассылки с пометкой «передано/переданы владельцем» или датой передачи в статус-файле;
- разборы, отчёты, сверки и планы закрытых треков (трек закрыт — есть запись «ЗАКРЫТ/ВЛИТ/закрыто» в статус-файле или памяти-пометке в самом файле).

Остаётся в корне:
- реестры (решений, структурных фактов), принципы, правила, протоколы, глоссарии терминов;
- живые планы и чекпоинты открытых треков (план завершения миграции КК, Forward без платформы, AI Factory, rules, архив-план — если встретится);
- справочники `*.json`, `*.yaml`, `*.py`, `*.txt`-данные, которые читает прибор или скрипты (проверить grep по `app/`, `tests/`, `_meta` канона);
- подкаталоги треков целиком (`skillCore/`, `rules/`, `onb-v-review/`, `kk-review/` и прочие папки) — не трогать;
- файлы, которые владелец правит руками и ещё использует (чек-лист DoR, материалы AI Factory, ответы платформе) — при сомнении оставить;
- всё, датированное 2026-10-29 и позже — оставить (текущие треки КК ещё ссылаются);
- два изменённых чужих файла в рабочем дереве («Forward без платформы — … план трека (2026-10-15).md», `skillCore/Сообщение командам — …(2026-10-29).md`) — не стейджить и не трогать.

Спорное — отдельным списком с вопросом, не решать самому.

## Порядок

1. **Опись переноса** — файл `app/data/archive-inventory-2026-10-30.md`: таблица «файл | тип (постановка/сдача/сообщение/ответ/разбор/план) | дата из имени | вердикт (архив/остаётся/спорно) | основание (где зафиксировано исполнение: статус-файл строка/дата, сдача, коммит)». Основание обязательно для каждого «архив». Опись показать владельцу в своей сессии и ждать его слова; до слова ничего не перемещать.
2. **Grep ссылок** по именам переносимых файлов: `DOC_AS_CODE_PILOT_STATUS.md`, другие `*_STATUS.md`, `app/data/**`, память (`C:\Users\alexe\.claude\projects\C--Users-alexe-PycharmProjects-requirements-analyzer-v3\memory\*.md`), канон `C:\doc-as-code\EAN\docs-o2new\_meta` (на всякий случай). Живые упоминания (в текущих планах, памяти, README) — обновить на новый путь; исторические блоки статус-файла не править — их покрывает указатель архива.
3. **Перенос** — `git mv` каждого файла в `app/data/archive/<ГГГГ-ММ>/` по дате из имени (без даты — `app/data/archive/undated/`), имена файлов не менять. Два неотслеживаемых файла (`app/data/kk-ids-transfer-2026-10-23.txt`, «Письмо — схема сквозного бизнес-процесса в JSON, размещение и вопросы (2026-10-22).md») сначала `git add`, потом `git mv` (если попадают в архив по критериям). `app/data/__pycache__` — в `.gitignore`, из индекса убрать, если отслеживается.
4. **Указатель** `app/data/archive/README.md`: таблица «исходное имя | дата | тип | трек | причина/основание | новый путь», отсортирована по дате. Плюс одна строка правила на будущее: при закрытии трека его постановки, сдачи и сообщения уезжают в архив тем же коммитом, что и запись о закрытии.
5. **Один коммит** на весь перенос (опись, указатель, `.gitignore`, обновлённые ссылки, `git mv`): `git add -- <перечень>`, никаких `git add .`/`-A`. Трейлер `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` не нужен — коммит от модели сессии по её правилу. Коммит и push — только по слову владельца в своей сессии.
6. Проверка после коммита: `git status` чистый по `app/data` (кроме двух чужих файлов), `git log --follow` на двух-трёх перенесённых файлах показывает историю, прибор и тесты не читали перенесённые файлы (`pytest tests -q -o addopts=""` по правилам запуска из CLAUDE.md — число падений прежнее).
