# Эдуарду Шеферу: модель НФТ принята, требование к lk-mp снято, один вопрос о ссылках

Дата: 2026-10-14. От владельца пилота Doc-as-Code. В ответ на записку «Модель НФТ (каталог
`nfr/`)» от 2026-10-14.

## Решение

1. **Модель каталога `nfr/` принята** в том виде, как она на `master` (срез `fec9eb5`): одна
   страница на тип, 18 кодов, атомарные `nfr-<код>-<номер>`, пробелы «Не задано» — долгами
   матрицы без просрочки, расширение каталога только через шаблон `nfr.md`. Запись в реестре
   решений пилота — Д-42 со ссылкой на вашу записку.
2. **Существующие комплекты не трогаем до явного захода** — как в записке.
3. **Требование к lk-mp «заход `create-nfr` до переноса в `docs-lk-mp`» снято.** У комплекта нет
   входа НФТ: страниц НФТ в источниках нет (проверка по заголовкам), раздела «Нефункциональные
   требования» в фичах нет, секции BRD-6 в матрице нет. Единственный след старой модели — строка
   легенды `US / FR / NFR / RR` в README комплекта; прибор на неё не реагирует (сторож легенды
   проверяет, что каждый встреченный префикс описан, а паспорт платформы собирается из шаблона
   канона, не из README комплекта). Строка останется до следующей волны миграции lk-mp. Команде
   это сообщено.
4. **Паспорт раскладки ЭКО для платформы** (`docs-kit-layout.yaml`, собран 13.10) после снятия
   `NFR` с внутренних префиксов расходится с каноном — пересоберём и передадим платформе
   со стороны владельца пилота.
5. Правила по прибору (`_meta/tools/README.md`, раздел «Порядок правок инструментов», срез
   `fec9eb5`) — приняты вами, вопрос закрыт. Проверка `link_debts` на PTP (2 пробела, OK) —
   спасибо.

## Вопрос: ссылки из карточек на страницы типа

В записке: из тела фичи и функции на страницы `nfr/` не ссылаются, связь — только в матрице
BRD-6.2. Читатель карточки функции тогда не видит, какие НФТ её ограничивают, пока не откроет
матрицу; для остальных типов комплекта правило обратное — карточка ссылается на карточку,
матрица лишь повторяет связь.

Просьба пояснить, что именно ломает ссылка из карточки на `../nfr/nfr-<код>.md` (или на
атомарный `nfr-<код>-<номер>` как на якорь страницы): сторож ссылок, слой BRD/SRS, обратная
трассировка? Если ничего, предлагаю допустить такую ссылку как необязательную, с матрицей
BRD-6.2 как единственным обязательным местом связи. Решение не блокирует ни модель, ни
миграции — это уточнение на следующий срез шаблона `nfr.md`.
