## Порядок работы

Волна = одна группа или одна постановка = одна сессия Исполнителя: после сдачи волны сессия закрывается, следующая волна — новая сессия с этим же брифом и своей веткой (как у штатного исполнителя по канону: сессия на одну постановку, без переноса контекста). Внутри волны — карточка за карточкой по fixlist, в порядке линий от опасного к мелкому: 1 содержимое невведённых задач → 2 потери содержимого → 3 карточки с промежуточных копий (переиздание со среза целиком) → 4 ссылки и долги → 5 приписки шаблона и тихие починки → 6 ремарки и статусы.

1. **PROM-5.3-G2** — `prompts/_task-PROM-5.3-G2.md`, `sandbox/fixlist-5.3-G2.md` (34–38 строк, 20 файлов screen-form/bank).
2. **PROM-5.3-G1** — `prompts/_task-PROM-5.3-G1.md`, `sandbox/fixlist-5.3-G1.md` (145 строк, 42 файла screen-form/client).
3. **PROM-5.3-G3** — `prompts/_task-PROM-5.3-G3.md`, `sandbox/fixlist-5.3-G3.md` (117 строк, 52 файла function/client).
4. **Линия 1 по всему комплекту (L1)** — основной список отчёта сторожа (53 строки): постановки координатора на него ещё нет; работаешь прямо по таблице отчёта: карточка, страница, задача, фрагмент, строка. Строки «проверить» (23) — не трогать без явного решения владельца; «покрыто долгом» (3) — не трогать.

Если группа пересекается с L1 (одна карточка в fixlist и в отчёте сторожа) — правишь карточку один раз, закрываешь обе строки.

## Правила (обязательные)

1. **Только дословность по срезу.** Любая правка карточки — перенос текста из `sources/confluence` как есть. Дефект самого среза (опечатка «применется», «drouwer», «к дочному», битая скобка, обрыв нумерации) остаётся в карточке дословно; молча чинить нельзя (FB-09). Если ты видишь, что срез неверен по смыслу, — это не твоя задача: карточка дословна, вопрос в fixlist строкой «статус: вопрос владельцу» с одной фразой.
2. **Асимметрия ошибок.** Потеря содержимого хуже лишнего. Сомневаешься, переносить ли фрагмент среза, — переноси. Сомневаешься, снимать ли фрагмент как чужой, — не снимай, а пиши «вопрос владельцу».
3. **Содержимое невведённых задач** снимается только по диффу: `git diff 717b11f 0e32b01 -- "<путь страницы в sources/confluence>"` плюс `data-task` в `sources/raw`. Введённые задачи (их вставки законны): теги `git tag -l "src/*"` — на 30.10 это TEAMTB-3633, TEAMTB-3716, TEAMTB-3846, TEAMTB-3969. Всё остальное с маркером `critic-ins` — чужое, если текста нет в срезе. Удалённое введённой задачей (`critic-del` с её ID) в карточке стоять не должно; удалённое невведённой — должно (reject-all).
4. **Переиздание со среза** (scr-bnk-05/07/13, SCR-CL-26/27 и другие строки «переиздать»): карточка собирается заново по шаблону типа из `_meta/templates/` и скиллу `_meta/skills/create-*.md` для этого типа, ID карточки, frontmatter и ссылки на неё сохраняются; старое содержимое не «подправляется».
5. **Реестры и матрицу не трогать** сверх того, что явно велит строка fixlist или постановка: `open-questions.md`, `inventory.md`, `sandbox/confluence-unapproved-jira-pages.md` — только координатор или владелец. В `docs/traceability-matrix.md` — только строки, названные в постановке (ссылки при закрытых долгах, замена фабрикованных ID).
6. **Ремарки карточки** (разделы «Что не переносится из источника», «Происхождение», примечания о переносе) проверяются наравне с телом: ложная ремарка, маскирующая потерю, снимается вместе с устранением потери.
7. **Живые ссылки Confluence** в карточки не переносятся: ссылка на карточку комплекта, если цель есть; иначе название текстом и долг — по строке fixlist.
8. **Байты.** CRLF как в файле, кодировка UTF-8 без BOM (как у соседей), без переформатирования нетронутых строк. Правки — python-скриптом или точечной заменой, не пересохранением файла целиком редактором.
9. **Сторонние карточки** не править «заодно». Нашёл дефект вне fixlist — одна строка в конец fixlist группы со статусом «вне списка, вопрос владельцу», без правки.

## Приёмка волны (перед сдачей, обязательно, числа в сдачу)

Из рабочего каталога, `$env:PYTHONIOENCODING = "utf-8"`; `<meta>` = `C:\doc-as-code\EAN\docs-o2new\_meta\tools`:

```
C:\Python312\python.exe <meta>\selfcheck.py --docs docs --sources sources\confluence --out sandbox\selfcheck-exec-<группа>-r<k>.txt
```
Ожидание: `ИТОГО … ✗ 0`; строки по затронутым карточкам ✓. Любой ✗ по затронутой карточке — чинить до сдачи; ✗ по чужой карточке — в сдачу словами.

```
C:\Python312\python.exe <meta>\normalize_tables.py --check docs\<карточка>.md --source "sources\confluence\<страница>.md"
```
Для каждой карточки с таблицами из волны; ожидание ✗ 0 (это критерий дословности таблиц).

```
C:\Python312\python.exe <meta>\link_debts.py --matrix docs\traceability-matrix.md --docs docs --strict
```
```
C:\Python312\python.exe <meta>\matrix_sync.py --docs docs --check
```
Оба — код возврата 0. Если `matrix_sync --check` расходится из-за твоих правок ссылок — `--write` разрешён только для выводимых разделов, ручные не трогаются; результат в сдачу.

Сверка по протоколу ревьюера: для каждой исправленной карточки — литералы и структура против среза (как в `sandbox/review-5.1-calibration-r01.md`); «починил одно — сломал другое» ловится здесь.

## Коммиты и сдача

- Ветка `exec/5.3-G2` (для следующих групп — `exec/5.3-G1`, `exec/5.3-G3`, `exec/5.3-L1` от актуального master после слияния предыдущей; ветки заводит владелец). Коммит — локально, по одной группе или логической части, `git add -- <перечень файлов>`, никогда `git add .`/`-A`; без AI-трейлеров в сообщении (pre-receive hook контура их отклоняет). Push НЕ делать — push, MR и слияние у владельца.
- Сообщение коммита: первой строкой «PROM-5.3-G2: <что сделано, сколько строк fixlist закрыто>», ниже — по карточкам одной строкой каждая.
- Хеш коммита — в столбец «Коммит» fixlist, статус «исправлено» / «переиздано» / «долг» (если по постановке замечание уходит долгом) / «вопрос владельцу». Строка без статуса — незакрытая.
- Сдача волны — одним сообщением сессии «Координатор КК» (SendMessage по имени сессии; если её нет в списке — владельцу в чат): ветка и хеши, числа приёмки (selfcheck ИТОГО, `--check` по карточкам, link_debts, matrix_sync), сколько строк fixlist закрыто и сколько «вопрос владельцу», перечень карточек. Без пересказа правок.
- Один вопрос владельцу — одно короткое сообщение с номером строки fixlist, вариантами и твоей рекомендацией. Работу над остальными строками не останавливать.

## Экономия контекста (обязательно)

Лимиты тарифа общие на все роли, расход считается по токенам, которые ты читаешь. Правила:

1. **Отчёты прибора не читать целиком.** `selfcheck --out` даёт файл на ~2800 строк (около 100 тысяч токенов). Читать из него только строку `ИТОГО` и строки по своим карточкам: `Select-String -LiteralPath <файл> -Pattern "ИТОГО|<имя карточки>"` (или `grep`). То же для отчётов `--check`, `link_debts`, `matrix_sync`: смотреть итог и строки по затронутым файлам.
2. **Страницы среза и raw читать частями.** Сначала найти нужный фрагмент поиском по строке из fixlist (номер поля, литерал), затем читать окно вокруг него; страницу целиком — только при переиздании карточки.
3. **Карточку читать один раз за волну**, правки вносить скриптом точечно, после правки перечитывать только изменённый участок.
4. **Не перечитывать бриф и постановку** на каждую строку fixlist: правила уже в контексте; возвращаться к постановке только при сомнении по конкретному пункту.
5. **Не выводить в ответ содержимое файлов**, если оно не нужно владельцу для решения: в сдаче — числа и перечни, не тексты правок.
6. После сдачи первой волны (G2) сообщить расход сессии (из приложения: использование за сессию), чтобы владелец оценил остаток по плану.
