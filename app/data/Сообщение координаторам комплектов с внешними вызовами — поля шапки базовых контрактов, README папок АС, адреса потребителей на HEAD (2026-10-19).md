# Командам комплектов с карточками вызова внешних АС (координаторам и аналитикам): базовые контракты получили поля шапки и README папок, адреса потребителей переводятся на HEAD

Дата: 2026-10-19 (редакция 2: добавлены способы исполнения без координатора). Касается всех комплектов, у которых есть карточки `CALL-EXT-NNN`
(`srs/contract-call/external/`): КК, lk-mp, common-dictionary, account-opening-request,
onboarding-fo, docs-sign, digital-ruble, file-service, smev-integration и другие — независимо
от того, ведёт ли комплект координатор-агент, аналитик руками или LLM по постановке.

## Что изменилось в репозитории базовых контрактов `EAN/docs-external-contracts`

Срез канона `94455d0` (шаблон, скилл, утилита extint_registry.py); репозиторий контрактов —
`trunk` после вливания MR !58 (`extint/as-readme-registry`).

1. **У каждой папки АС есть `README.md`** с `id: EXTINT-<AS>-000`: назначение АС, «О системе»
   (каналы, среда, документация, примеры), таблицы «Операции», «Сообщения и файлы», «Общие
   форматы и коды». Корневой README — реестр систем. Таблицы README собирает утилита
   `extint_registry.py`, руками их не правят.
2. **Шапка базовой карточки** получила три поля: `kind` (`operation` — вызов, `message` —
   односторонний обмен, `common` — общий тип или коды), `channel` (канал из словаря шаблона:
   `suv`, `online-adapter`, `rest`, `soap`, `mq`, `otsgds`, `file`, `kafka`, `postmessage`),
   `sync` (`sync` / `async`, у операций). Новая карточка без этих полей — ⚠ утилиты самопроверки.
3. **Скилл `create-contract-call`** (контур base) при новой папке АС создаёт README по шаблону,
   свободный номер ищет по файлам папки, после карточки запускает утилиту: сначала `--check`,
   затем `--write`. Корневой README руками больше не правится.
4. **Раздел «Потребители»** базовой карточки: три колонки «Сервис | Локальный ID | Карточка
   вызова», адрес карточки вызова — абсолютный, через `/-/blob/HEAD/`. Адреса на `master`,
   `trunk` или рабочую ветку утилита помечает ⚠: по прогону 18.10 таких строк 81 (на `trunk`
   67, на `master` 23, причём ветки `master` в репозитории контрактов нет).

## Что нужно от команды

В карточках базовых контрактов есть таблица «Потребители» — перечень сервисов, которые
вызывают этот контракт, со ссылкой на карточку вызова в комплекте сервиса. Команде нужно
привести в порядок только строки, где в колонке «Сервис» стоит код вашего сервиса. Два
действия:

1. **Адрес карточки вызова — через `HEAD`.** В ссылке на вашу карточку вместо имени ветки
   (`master`, `trunk`, рабочая ветка) должно стоять `HEAD`:
   `https://gitlab.gboteam.ru/<группа>/<репозиторий>/-/blob/HEAD/<путь>.md`.
2. **Таблица — в три колонки.** Новая форма таблицы: `Сервис | Локальный ID | Карточка
   вызова`, во второй колонке — ID вашей карточки вызова (`CALL-EXT-NNN`). Если ваша строка
   стоит в таблице старой формы из двух колонок (`Сервис | Карточка`), шапку таблицы и
   строку нужно переписать в три колонки. Таких таблиц немного, у большинства сервисов это
   действие не потребуется.

**Объём по сервисам** (срез `trunk` 4e49c7e). Найдите свой сервис, строки других сервисов вас
не касаются:

| Ваш сервис (код в колонке «Сервис») | Ссылок, где надо поставить `HEAD` | Строк в таблицах старой формы (переписать в три колонки) | Карточек, где есть ваш сервис |
| --- | --- | --- | --- |
| signature | 46 | 1 | 30 |
| file-service | 10 | 0 | 10 |
| open-add-account | 8 | 3 | 8 |
| smev-integration | 5 | 0 | 4 |
| reference-request / referenceRequest | 4 + 3 | 1 | 7 |
| digital-ruble-registration | 4 | 0 | 3 |
| mdm-integration | 2 | 0 | 2 |
| account-reserving | 0 | 4 | 4 |
| cancel-account-reserving, payment-control-and-accept, bankBranchDirectory, countryDirectory, rrko-dictionaries | по 1 | 0 | по 1 |

Код сервиса в колонке «Сервис» должен совпадать с `code` из каталога `_meta/services.json`
канона; где он записан иначе (`referenceRequest`, `bankBranchDirectory`, `countryDirectory`),
поправьте тем же заходом.

Исполнить можно любым из трёх способов, результат предполагается один: ветка и MR в репозитории `docs-external-contracts` в git.

### Способ 1 — координатор-агент

Скилл `create-contract-call`, контур base, шаг 5: после правки строк — `extint_registry.py
--check`; реестры не трогать. Дальше как в способе 2 - шаг 6.

### Способ 2 — руками, без координатора

Нужны: Python 3.8+, клон `docs-external-contracts` и клон канона `docs-o2new` (команда
`git clone https://gitlab.gboteam.ru/EAS/docs-o2new.git`, ветка `master`). Все команды — из
корня клона `docs-external-contracts`; `<код>` — код сервиса, `<канон>` — путь к клону
`docs-o2new`.

1. Свежий `trunk` и ветка под заход:

   ```powershell
   git fetch origin; git switch trunk; git pull --ff-only; git switch -c extint/<код>-consumers-head
   ```

   После команды: вывод `Switched to a new branch`.

2. Найти свои строки:

   ```powershell
   Get-ChildItem -Recurse -Filter extint-*.md | Select-String -Pattern "^\| <код> \|" | Select-Object Path, LineNumber, Line
   ```

   После команды: список файлов и строк. Если код в строках записан иначе, чем в каталоге,
   искать по старому написанию и исправлять его.

3. В каждой найденной строке: адрес карточки вызова — абсолютный, вида
   `https://gitlab.gboteam.ru/<группа>/<репозиторий>/-/blob/HEAD/<путь к файлу>.md`
   (вместо `master`, `trunk` или имени рабочей ветки — `HEAD`); таблица — три колонки с
   шапкой `| Сервис (\`code\` каталога) | Локальный ID | Карточка вызова |`, во второй
   колонке — локальный ID карточки вызова (`CALL-EXT-NNN`). Если таблица была в две колонки
   («Сервис | Карточка usage»), шапку и строку переписать в три колонки. Ничего другого в
   карточке не менять.

4. Проверка утилитой:

   ```powershell
   python <канон>\_meta\tools\extint_registry.py --repo .
   ```

   После команды: в блоках «адрес карточки вызова не на /-/blob/HEAD/» и «таблица
   «Потребители» не в три колонки» нет строк с вашим кодом; остальные ⚠ — чужие, не трогать.
   Если строка с вашим кодом осталась — вернуться к шагу 3.

5. Коммит и ветка на сервер (сообщение коммита — без AI-соавторства):

   ```powershell
   git add -- <перечень изменённых файлов>; git commit -m "Потребитель <код>: адреса карточек вызова через HEAD, таблица в три колонки"; git push -u origin extint/<код>-consumers-head
   ```

   После команды: ссылка на создание MR в выводе.

6. MR в `trunk`; одобряет владелец канона или ответственный сотрудник, вливание после одобрения.

### Способ 3 — постановка LLM-агенту (Cursor, Claude, другой)

Готовый текст постановки, подставить `<код>` и пути:

> В клоне репозитория `docs-external-contracts` (ветка `trunk`, свежий `git pull`) найди во
> всех файлах `extint-*.md` строки таблицы «Потребители», где первая ячейка — `<код>`. В
> каждой такой строке: адрес карточки вызова приведи к виду
> `https://gitlab.gboteam.ru/<группа>/<репозиторий>/-/blob/HEAD/<путь>` (имя ветки в адресе
> заменить на `HEAD`); если таблица в две колонки, переделай её в три:
> `| Сервис (\`code\` каталога) | Локальный ID | Карточка вызова |`, во второй колонке —
> локальный ID карточки вызова из адреса (`CALL-EXT-NNN`). Больше ничего в файлах не меняй,
> переводы строк файлов сохрани. Затем запусти
> `python <канон>\_meta\tools\extint_registry.py --repo .` и убедись, что в блоках «адрес
> карточки вызова не на /-/blob/HEAD/» и «таблица «Потребители» не в три колонки» нет строк с
> `<код>`. Покажи перечень изменённых файлов и дифф; коммит и push не делай.

После ответа агента — проверить дифф глазами (только строки потребителя, только адрес и
колонки), затем шаги 5–6 способа 2.

## Что команде делать не нужно

- Заполнять `title`, `kind`, `channel`, `sync` у существующих карточек: поля проставлены
  по паспортам (110 карточек); у 22 карточек нет `title`, у 6 — канала
  (BSK-002…004, F1-004, F1-007, TESSA-001), у 70 операций — синхронности: это ⚠, их закрывает
  владелец карточки, когда знает источник, вопросы заданы авторам.
- Править таблицы README папок и корневой README: их пересобирает утилита.
