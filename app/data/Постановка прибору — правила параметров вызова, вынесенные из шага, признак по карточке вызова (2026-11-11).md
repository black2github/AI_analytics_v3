# Постановка прибору — правила параметров вызова, вынесенные из шага: признак по карточке вызова (2026-11-11)

**Кому:** сессия «Правки прибора, акцепт и рутина».
**От кого:** сессия «Точки расширения эталона» (постановщик, приёмка). Сдача — этой же сессии.
**Мощность модели:** средняя.
**Порядок:** короткий план (раздел 6) — мне, код после подтверждения. Сдача — по быстрому уровню тестов
(`tests/README.md`). Коммит в analyzer — по слову владельца в вашем чате. Копию в канон готовлю я.
Срочно: стоит тираж постановки 2.17 у КК (методы списка карт и числа карт).

## 1. Что случилось

Срез `0e92c962` извиняет вынос из шага только строк вида «имя = значение». На методе списка карт КК
(функции FUN-SYS-15 шаг 3 и FUN-SYS-35 шаг №4, карточка вызова CALL-INT-023) в шаге источника перечень
параметров вызова записан разными формами, и часть строк прибор присваиваниями не считает:

- «clientId == …», «serviceOfficeCode == …» — в источнике два знака равенства;
- «stateAnsStatus заполняется согласно Таблицы 2 …» — правило без знака равенства;
- вторая строка «clientId …» — без знака равенства;
- блок условия значения: «**Если** секция … присутствует, **то:**», под ним вложенные присваивания
  cardIds и isNotIds, «**Если** … заполнен, **то**», «**Иначе**».

По решению владельца все параметры вызова живут в одном доме — в карточке вызова; условие допустимо как
условие значения. Чтобы не получать ✗, исполнителю пришлось бы оставить часть параметров в функции —
это два дома одного факта.

## 2. Принцип правила

Не расширять определение присваивания словами источника («заполняется», «==» и т. п.): перечень таких
форм не замкнуть. Признак — по отношению между шагом и карточкой вызова:

> Строка шага источника — правило параметра вызова, если она начинается с имени параметра, для которого
> в карточке вызова по ссылке из шага карточки есть строка в разделе «Правила заполнения исходящего
> сообщения».

Имя параметра карточки вызова — последний сегмент пути в левой колонке таблицы раздела
(`data.absClientId` → `absClientId`) либо первое слово ячейки правила (в ней текст источника дословно,
включая опечатку имени: «stateAnsStatus заполняется …» в строке параметра `stateAndStatus`). Если раздел
привязки записан списком, имя — первое слово пункта.

Слов источника в признаке нет: используются положение имени в строке и состав раздела карточки вызова.

## 3. Что сделать

`kitcheck/checks/card_steps.py`, ветка «присваивания шага вынесены в карточки вызова»:

1. Снимаемая строка шага источника — либо присваивание по действующему определению, либо строка
   (пункт списка), начинающаяся с имени параметра карточки вызова по правилу раздела 2. Имена параметров
   берутся из карточек вызова, на которые ссылается шаг карточки (тексты уже приходят в `group_text`;
   если для разбора раздела нужна структура — передать её отдельным параметром).
2. Блок условия значения. Строка-условие нотацией **Если** / **то** / **иначе** (в том числе «**то:**»
   и одиночное «**Иначе**») снимается вместе со своими вложенными строками, если ВСЕ вложенные строки
   блока — снимаемые строки параметров. Блок, в котором есть иное (переход на шаг, ярлык шага,
   формирование ошибки, строка без имени параметра), не снимается целиком и остаётся в сверке.
3. Ограничители прежние и остаются в силе: ярлык шага и переход на шаг не снимаются никогда; в шаге
   карточки обязательна ссылка на карточку вызова; остаток шага сверяется прежней цепочкой; имя каждого
   вынесенного параметра должно быть в карточке вызова — иначе ✗ с перечнем.
4. Строка предупреждения прежняя; счётчик — число снятых строк параметров (блок условия считается по
   вложенным параметрам).
5. Действующее поведение для строк «имя = значение» без карточки-образца (нет раздела привязки в
   карточке вызова, раздел списком) не ухудшить: тесты среза `0e92c962` остаются зелёными.

## 4. Чего не делать

- Не добавлять в прибор слова «заполняется», «равно» и подобные.
- Не снимать строку только потому, что в ней встретилось имя параметра: имя должно стоять в начале
  строки (после маркера списка и разметки).
- Не трогать сторож карточек вызова (`call_algorithms.py`) сверх общего помощника, если он понадобится.

## 5. Тесты и замер

- Срабатывание: «имя == значение»; «имя заполняется согласно …»; строка с именем без знака равенства;
  блок «**Если** …, **то:**» с вложенными присваиваниями и «**Иначе**» с вложенными; имя с опечаткой,
  стоящее первым словом ячейки правила карточки.
- Несрабатывание: строка начинается с имени параметра, но имени нет в карточке вызова — ✗; блок условия
  с переходом на шаг или формированием ошибки внутри — остаётся в сверке; имя параметра в середине
  строки — не снимается; шаг без ссылки на карточку вызова — ✗ как прежде.
- Быстрый уровень тестов, поимённая сверка с базлайном; эталон отчётов — 0 отличий сверх ожидаемых.
- Замер на ветке исполнителя КК `exec/f1-kit` (`C:\doc-as-code\EAS\src-business-cards-exec`, только
  чтение, worktree в `C:\tmp`; хеш состояния с черновиком CALL-INT-023 — у координатора КК): функции
  FUN-SYS-15 и FUN-SYS-35 при всех параметрах в карточке вызова — предупреждение, не ✗; число снятых строк
  назвать. Отчёт замера в analyzer не коммитить.
