## Что сделать

1. Перед приёмом клон канона — на `master` и свежий:

   ```powershell
   git -C <клоны>\docs-o2new switch master
   ```

   ```powershell
   git -C <клоны>\docs-o2new pull --ff-only
   ```

2. Принять срез из корня `src-business-cards`:

   ```powershell
   python <клоны>\docs-o2new\_meta\tools\accept_canon.py --profile README.md
   ```

   Ожидается строка `✓ срез канона: a352a28 → 8c4e073` и пять строк `✓ SF-01` … `✓ SF-05`. Если
   вместо `✓ срез канона` — любая другая первая строка, остановиться и прислать вывод.

3. Контрольный прогон самопроверки без правок комплекта:

   ```powershell
   python <клоны>\docs-o2new\_meta\tools\selfcheck.py --docs docs --sources sources --out sandbox\selfcheck-8c4e073.txt
   ```

   Ожидается в конце отчёта: `ИТОГО: файлов 342 — ✓ 316, ✗ 4, ⚠ 22` (прогон владельца 16.10 на
   срезе комплекта `5b92ada`; три последующих коммита меняют в `docs/` две строки и на эти числа
   не влияют). Если число ✗ другое — прислать отчёт.

4. Новые предупреждения — плановая чистка, а не брак. Текущие этапы ради неё не прерывать.
   Чистка — отдельным заходом после закрытия текущего этапа, по таблице ниже. Запись об этом — в
   `coordination-log.md`.

## Справочный прибор матрицы

В срезе есть `matrix_sync.py` — сверка выводимых разделов матрицы трассировки с документами. В
протокол он не входит, скиллы на него не ссылаются. Матрица КК не по шаблону, поэтому
`matrix_sync.py --write` на ней откажет — это ожидаемо; запускать его не нужно. Перевод матриц
комплектов на шаблон — отдельным решением, о нём будет отдельное сообщение.
