## Часть A — `accept_canon.py`: дельта норм при приёме среза (Д-47 п. 5)

Сейчас утилита меняет строку «Срез канона» профиля и коммитит. Добавить печать **дельты норм**
между принятым и новым срезом: `git -C <канон> diff --stat <старый>..<новый> -- _meta/templates
_meta/skills _meta/tools/step-protocol.md _meta/migration AGENTS.md` плюс по каждому изменённому
файлу шаблонов/скиллов — заголовки разделов (`^#{2,4} `), чьи строки затронуты диффом (по хункам:
заголовок, под которым есть изменённые строки). Вывод — блок «Дельта норм <старый>→<новый>:
файл — разделы …» после строки «✓ срез канона: …»; `_meta/tools/*.py` — одной строкой «прибор:
N файлов» без разделов. Ничего в комплект не пишется; это подсказка координатору для записи
«докатка / не применимо» в журнал (протокол §1, новая строка). Тесты: репозиторий из двух
коммитов — изменён один шаблон (раздел виден), один скилл, один файл прибора; без изменений — «дельта
норм пуста». Канон-копия `accept_canon.py` — в вашу ветку.
