# Сообщение всем командам: гейт переноса проверяет матрицу, слой BRD и внешние вызовы

Дата: 2026-11-19. Канон `master` `cd97a94` (два слияния 19.11: `2b2eec9` — проверки гейта, `cd97a94` —
каталог НФТ). Передаёт владелец канона.

---

Коллеги, в каноне обновлён гейт переноса комплекта в репозиторий документации (`transfer_gate.py`).

**Зачем.** Гейт пропускал комплекты, непригодные к переносу: с матрицей трассировки, которая расходится
с документами, без слоя бизнес-требований и с пустым разделом «Покрытие: API ↔ SRS» при описанных
методах. Теперь это проверяется.

**Что сделать — аналитик команды, один раз.** Обновить клон канона:

```powershell
git -C <клон канона docs-o2new> pull --ff-only
```

Ожидаемо: строка `Updating … cd97a94` либо `Already up to date.`

**Самопроверка (`selfcheck.py`) — вердикт не меняется.** Те же проверки приходят в неё предупреждениями
(строки «⚠ …»). Число ✗ и строка ИТОГО у вашего комплекта остаются прежними.

**Гейт переноса (`transfer_gate.py`, полный режим) — новые отказы.** В режиме после захода
(`--after-step`) эти же строки остаются предупреждениями.

| Что проверяется | Когда отказ | Как исправить — аналитик команды |
|---|---|---|
| Структура матрицы | нет раздела шаблона, раздел повторён или вне шаблона, имя или колонки раздела не по шаблону | привести матрицу к шаблону `_meta/templates/traceability-matrix.md`; сведения, которым нет места в шести разделах, — в приложение `## Приложение. <название>` после них. Порядок шести разделов — только предупреждение |
| Реестр ID | документ есть, строки реестра нет; строка есть, документа нет | команда пересборки ниже |
| Покрытия функций и процессов | связи в матрице не совпадают со ссылками в документах | команда пересборки ниже |
| Раздел «Покрытие: API ↔ SRS» | раздел пуст при описанных собственных методах; карточка метода не названа в разделе | внести строки; если операций действительно нет — записать причину в тексте раздела над таблицей |
| Слой бизнес-требований | у продуктового сервиса нет каталога `brd/` | собрать слой скиллом `create-brd`; либо отсрочка — ключ ниже |
| Гейты достаточности BRD | нет секций `BRD-1…BRD-5` матрицы; счётчик в таблице `BRD-5` не равен нулю | довести слой до нулевых счётчиков |
| Ссылки между слоями | документ `brd/` ссылается на файл `srs/` или наоборот | убрать ссылку: связь требований с реализацией ведётся только в матрице. Файлы `README.md` — навигация, на них правило не действует |
| Типы документов | тип документа вне набора платформы не описан в README комплекта | добавить тип в таблицу «Условные обозначения» README |
| Внешние вызовы | в карточке внешнего вызова нет ссылки на базовый контракт в `docs-external-contracts` и нет строки долга | поставить ссылку; если контракта у владельца ещё нет — строка долга в матрице |
| Версия комплекта | перенос (`--out`) при незакоммиченных изменениях | закоммитить комплект и повторить |

Пересборка выводимых разделов матрицы из документов:

```powershell
python <клон канона>\_meta\tools\matrix_sync.py --docs <корень комплекта> --write
```

Ожидаемо: перечень изменённых разделов либо отказ с причиной. Утилита отказывает, пока структура матрицы
не по шаблону, и когда пересборка потеряла бы факт — причина названа в выводе.

Отсрочка слоя бизнес-требований — решение владельца документации сервиса, записывается в отчёт гейта:

```powershell
python <клон канона>\_meta\tools\transfer_gate.py --src <src> --brd-deferred "<основание>; ответственный: <кто>; срок: <ГГГГ-ММ-ДД>"
```

Ожидаемо: вместо отказа — предупреждение с текстом отсрочки в шапке отчёта. Без ответственного или срока
гейт отказывает и называет недостающее поле.

**Ещё два изменения.**

- Журнал открытых вопросов, `feedback.md` и журналы координации документами комплекта не считаются:
  утилита матрицы не вносит их идентификаторы в реестр, а существующую такую строку снимает при пересборке.
- У сервиса вне каталога сервисов канона гейт не может узнать, платформенный ли он: такой сервис
  считается продуктовым. Каталог задаётся ключом `--catalog <путь к services.json>`.

**Каталог нефункциональных требований (НФТ).** Касается комплектов, у которых есть каталог `nfr/`.

- В репозитории документации каталог `nfr/` лежит в корне комплекта. Раньше сторож каталога искал его
  только рядом с `docs/` и в репозитории документации молчал. Теперь он проверяет каталог и там: все 18
  страниц типов, единая таблица `| ID | Параметр | Допустимое значение | Пояснение |`, строки в секции
  `BRD-6.2` матрицы. Сторож каталога влияет на вердикт самопроверки — это единственное место, где вердикт
  `selfcheck` может измениться: у комплекта с каталогом `nfr/` в корне появятся строки, которых раньше
  не было.
- Гейт переноса переносит каталог `nfr/`, лежащий рядом с `docs/`, в корень целевого репозитория вместе с
  комплектом. Раньше каталог при переносе терялся.
- Строки страниц НФТ в «Реестре ID» (`nfr`, `nfr-avl` и другие) утилита матрицы теперь узнаёт: сверка после
  пересборки сходится.

Вопросы — в `feedback.md` сервиса.
