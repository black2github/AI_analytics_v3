## 2. Проект записи решения (в реестр — после подтверждения развилок)

Номер — **Д-50**. План трека rules (`app/data/rules/`) называет «Д-50» своё будущее решение. Трек не запущен, при его
запуске номер сдвинется на Д-51. Развилка Р-5.

**Д-50. Проверки карточки — в `kitcheck/checks/card_*.py`; `normalize_tables.py` — только нормализатор таблиц и CLI**

- **Контекст и проблема.** См. постановку, раздел 1: адрес проверки по имени файла не угадывается (постановка 30.10
  искала сторожа глоссария в `selfcheck.py`), правка «нормализатора» трогает гейт карточек, ревью диффа смешивает
  грамматику HTML и нормы канона.
- **Решение.** Три дома по назначению:
  - `normalize_tables.py` — нормализатор и CLI, все ключи прежние;
  - `kitcheck/checks/card_*.py` — проверки карточки по темам, реестры `FILE_CHECKS`/`SOURCE_CHECKS` и `run_check`;
  - `selfcheck.py` — оркестратор комплекта.

  Поведение, текст отчёта, ключи и коды возврата не меняются. Старые имена `normalize_tables.<проверка>` доступны один
  релиз через реэкспорт и снимаются отдельным шагом.
- **Сценарии жизненного цикла.**
  1. *Новая проверка карточки.* Функция — в тематический модуль `card_*.py` (тема по таблице `kitcheck/README.md`),
     строка — в `FILE_CHECKS` или `SOURCE_CHECKS` (`card_run.py`), тест на срабатывание и несрабатывание. В канон
     едут `card_<тема>.py` и `card_run.py`; `normalize_tables.py` не трогается.
  2. *Правка нормализатора* (сетка, профиль, форма ветвления, `--cell-to-md`). Меняется `normalize_tables.py`, гейт
     карточек не задевается. Исключение — общие примитивы: они в одном доме, его определяет Р-1. Их правка видна в
     диффе обоих.
  3. *Перенос в канон.* Опись файлов прибора в каноне пополняется модулями `card_*.py` (и `kitcheck/html.py` при
     Р-1 = Б). Сверка общих файлов с `origin/master` перед копией — как прежде.
  4. *Команда вызывает `normalize_tables.py --check` по скиллу* (`reference.md`, `create-artifact.md`,
     `create-contract-call.md`, `prompt-coordinator.md`). Тот же вывод и код возврата: CLI делегирует в `run_check`.
  5. *Старый импорт* `nt.check_*` (тесты, `accept_canon.py`, скрипты коллег в канон-копиях). Работает весь переходный
     релиз через реэкспорт. Снятие — отдельным шагом, по `grep` импортёров analyzer и канона.
  6. *Коллега правит проверку в старом `normalize_tables.py` канона в обход analyzer.* После переноса функции там нет:
     MR даёт конфликт или дубль, а не тихую потерю. Сверка общих файлов перед каждой копией (урок 28.10) это ловит.
  7. *Отказ и откат.* Один коммит на репозиторий (analyzer, канон) — откат одним revert, бандл не затронут
     (`normalize_tables.py` и проверки в поставку не входят).
  8. *Просмотр человеком.* `kitcheck/README.md` — таблица «модуль → тема → реестр» и «как добавить проверку карточки».
     Строки отчёта не меняются, команды разницы не видят.

## 3. Развилки

**Р-1. Где живут общие примитивы**, нужные и нормализатору, и проверкам: `cell_text`, `expand_grid`,
`protect_token_tags`, `find_top_tables`, `parse_md_tables`, `_fm_head`/`_fm_body`, `_plain`, `_norm_cell`,
`_strip_markdown_links`.
- **А — остаются в `normalize_tables.py`** (буква постановки: «`expand_grid` … остаётся»), а `card_*.py`
  импортируют их оттуда. Минусы:
  - пакет `kitcheck` начинает зависеть от утилиты рядом с ним (сейчас зависимость обратная: утилиты зависят от ядра);
  - при запуске `python normalize_tables.py --check` модуль загружается дважды (`__main__` и `normalize_tables`),
    потому что `card_*.py` импортирует его по имени — два экземпляра `Profile` и кэшей;
  - реэкспорт из `normalize_tables` обратно даёт цикл импорта, его придётся разрывать ленивым `__getattr__`.
- **Б — переезжают в новый `kitcheck/html.py`** (примитивы разбора HTML/markdown, как `md.py` и `fence.py`), а
  `normalize_tables.py` импортирует их и сохраняет имена. Направление зависимостей прежнее (утилиты → ядро), цикла и
  двойной загрузки нет, канон копирует `kitcheck` пакетом. Отступление от буквы постановки: `expand_grid` физически в
  `kitcheck/html.py`, но доступен как `normalize_tables.expand_grid`.
- **Рекомендация — Б.**

**Р-2. Реэкспорт старых имён проверок из `normalize_tables.py` на переходный релиз.**
- **А — модульный `__getattr__`** (ленивый: имя ищется в `card_*` при первом обращении). Цикла нет, проверки при
  импорте нормализатора не грузятся.
- **Б — явный `from kitcheck.checks.card_… import *`** в конце файла. При Р-1 = Б цикла нет, но нормализатор при
  каждом импорте тянет весь гейт.
- **Рекомендация — А.**

**Р-3. Нарезка тем.** Модули:

| Модуль | Тема |
| --- | --- |
| `card_source.py` | литералы и источник: `quoted_literals`, сверка таблиц и значений, полнота ячеек, title, имена параметров HTML |
| `card_steps.py` | шаги и поведение: маркеры шагов, вложенность, тела шагов, нумерация |
| `card_passport.py` | паспортные и тяжёлые ячейки, лейбл-секции |
| `card_notification.py` | уведомления |
| `card_branch_form.py` | сторож формы ветвления |
| `card_controls.py` | сообщения контролей (FB-12), файл = сущность, приписанные атрибуты |
| `card_clean.py` | чистовик: ссылки, упоминания, OQ и page_id в теле, ТУЗ |
| `card_form.py` | форма текста: разорванные ячейки, маркеры сокращения, гомоглифы, невидимые символы, выноски, блоки кода, длинные строки, нотация |
| `card_run.py` | контексты, реестры, `_rc_*`, `check_file`, `run_check`, `apply_critic`/`strip_history` |

Восемь тем постановки, «форма текста» добавлена девятой: туда уходит около двадцати `_fc_*`, которые иначе не
лягут ни в одну тему. Правило: тематические модули друг друга не импортируют. Общий помощник двух тем уходит в
`card_common.py`, порядок слоёв: `html → card_common → card_<тема> → card_run`. Ацикличность проверяется скриптом до
переноса, раскладка отдельных помощников может сдвинуться при этой проверке. **Рекомендация — так.**

**Р-4. Тесты на новые адреса тем же коммитом** (буква постановки) или пока оставить на реэкспорте. 17 файлов
переписываются скриптом: импорты по карте «имя → модуль», `nt.X` → алиас модуля. Механически, но это около тысячи
правок в `test_normalize_tables.py`. **Рекомендация — по букве: тем же коммитом.** Тогда реэкспорт держит только
внешних импортёров, и его можно снять следующим релизом без правки тестов.

**Р-5. Номер решения.** Д-50 (rules при запуске — Д-51) **или** оставить Д-50 за rules и взять Д-51. **Рекомендация —
Д-50:** номер по порядку записи, у rules в реестре записи ещё нет.

**Оценка.** Один заход. Перенос — скриптом по AST с сохранением исходного текста: без ручного копирования 4 тыс.
строк. Основное время — эталоны (два golden по ~25 мин, по два selfcheck КК и эталона, два `transfer_gate`, два
полных pytest по ~11 мин) и переписывание тестов. Риск низкий, его держит golden «0 отличий». Дефект переноса
(потерянный комментарий, константа не в том модуле) ловят тесты и golden.
