## Часть A — `transfer_gate.py --after-step` (Д-49 п. 1)

Новый ключ `--after-step` («лёгкий гейт после захода»). Отличия от полного режима — закрытый
список, всё остальное как есть:

| Что | Полный режим | `--after-step` |
| --- | --- | --- |
| Сборка комплекта в целевой раскладке | да | да |
| Прибор selfcheck на собранном комплекте | да (~60 с на КК) | **нет** — команда гоняет его сама, вердикт в сдаче; в отчёте строка «i ПРИБОР: selfcheck не гонялся (режим --after-step), вердикт прибора — в сдаче» |
| Валидатор платформы | да | да |
| CORE-20 (открытые вопросы → долги, журнал) | ✗ | **i** — те же строки, статус «i», текст с пометкой «проверяется полным гейтом» |
| SDLC-05 (service-vision, glossary) | ⚠ | i |
| SDLC-04 раздел «API ↔ SRS» отсутствует | ✗ | ⚠ |
| SDLC-04 раздел пуст при описанных методах | ⚠ | ⚠ |
| `--out` | копирование при READY | **отклоняется** (✗ TRF-01 «--out не применим в режиме --after-step», как в режиме docs-репозитория) |
| Вердикт | `READY` / `NOT READY` | **`ФОРМА ПЕРЕНОСИМА` / `ФОРМА НЕ ПЕРЕНОСИМА: блокеров N (новых M)`** — слово READY не печатается |
| Код возврата | 0 / 1 / 2 | 0 / 1 / 2 |

Ограничители: TRF-01…04, SDLC-08, FMT-01, CORE-06, CORE-09, ВАЛИДАТОР — без изменений, их ✗
остаются ✗ (тест на НЕсрабатывание понижения: битая относительная ссылка в `--after-step` —
блокер). В шапке отчёта `--report` — строка «Режим: после захода (--after-step)».

**`--baseline <прошлый отчёт.md>`** — дельта: гейт читает таблицу прошлого отчёта (свою же
форму «Статус | Критерий | Проверка | Результат»), сопоставляет строки ✗ по паре (критерий,
результат) и печатает под итогом «новых блокеров M: …» (список) и «ушло K». Нет `--baseline`
— «(новых —)». Работает в обоих режимах. Строки с числами внутри (например «битые относительные
ссылки: 30 из 7263») сопоставляются по критерию и проверке без числа — иначе каждый заход даёт
«новый» блокер; тест на это.

## Часть B — строка статуса OQ (Д-49 п. 3)

`_OQ_STATUS_RE` гейта принимает обе формы: `- **Статус:** …` (шаблон канона) и `- Статус: …`
(КК, 331 запись). Один дом регулярного выражения: вынести в `kitcheck/checks/review_guards.py`
(там уже `_OQ_STATUS_RE` сторожа B9) и импортировать в гейт, либо наоборот — на ваш выбор, но
не два копипаста. Тест: журнал с обеими формами — ни одной записи «(без строки «Статус»)».
Ожидание на КК: ✗ CORE-20 «открытые вопросы без долга в матрице: 304» уходит; остаётся честное
число действительно открытых (сторож B9 на КК даёт его — сверьте).

## Часть C — зона «вне Экосистемы» под `docs/modules/<имя>/` (Д-49 п. 4)

Норма меняется в С1: мини-комплект лежит в `docs/modules/<имя>/`, не рядом с `docs/`. Прибор:

| № | Где | Правило |
| --- | --- | --- |
| C1 | `selfcheck.py` | `docs/modules/` — зона: её файлы **не** участвуют в схеме типов (`module-kit`, `module-interface` и карточки `spec/` с ID `MOD-<ИМЯ>-SCR-NN/-FUN-NN`), реестре ID, слотах частей, матрице трассировки и проверках README-реестров; **участвуют** в проверке шапки и `page_id` (покрытие), относительных ссылок, нотации (форма ветвления, литералы) — ровно то, что сегодня обещает `module-kit-readme.md` «Что проверяет прибор». Одна i-строка: «мини-комплектов зоны: N (docs/modules/<имя>, файлов K)»; без зоны строка не печатается |
| C2 | `selfcheck.py`, переходный сторож | каталог `modules/` рядом с `docs/` (старое место) → ⚠ «мини-комплект вне docs/ — переносом не переезжает (Д-49), перенести в docs/modules/<имя>/»; `modules` из `_ok_dirs` корня не убирать (иначе ✗ «посторонний каталог» до переезда — асимметрия) |
| C3 | `selfcheck.py` | `docs/modules/<имя>/` без `README.md` → ⚠ «мини-комплект без паспорта границы (module-kit-readme.md)» |
| C4 | `source_coverage.py` | `_under_modules`: уже смотрит `output / "modules"` — проверить тестом, что класс «вне Экосистемы» считается покрытым файлом под `docs/modules/`; старое место тоже остаётся покрытием (переходный период) |
| C5 | `normalize_tables.py` (порог ссылок, строка ~3340) | ссылки на `docs/modules/…` — цель внутри комплекта, порог «источник, не цель» к ним не применяется; старое `root.parent / "modules"` оставить |
| C6 | `link_debts.py` | ⚠ «цель в зоне» — цель ищется и под `docs/modules/`; ограничитель: карточка `docs/modules/…` с `page_id` цели — цель покрыта, долг формы 1 не заводится |
| C7 | `transfer_gate.py` | режим репозитория документации: `modules/` в корне рядом с `srs/` — штатный каталог (не «посторонний»); TRF-04: типы `module-kit`, `module-interface` печатаются в i-строке «типы вне закрытого набора платформы» (как сейчас для любых нестандартных) — проверить, что карточки `spec/` зоны не дают ⚠ SDLC-08 «каталог без README-реестра» (у `spec/` README нет по шаблону — исключить `docs/modules/**` из этой проверки) |

Карточки `spec/` зоны в целевой раскладке лежат в `modules/<имя>/spec/` — гейт их не считает
карточками комплекта для SDLC-08 и TRF-04 (закрытый список: только исключение каталога
`modules/`, не новая логика).
