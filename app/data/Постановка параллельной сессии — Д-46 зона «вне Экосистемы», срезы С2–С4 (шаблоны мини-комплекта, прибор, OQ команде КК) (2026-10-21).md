## С2 — черновики двух шаблонов мини-комплекта (канон, ветка `meta/d46-module-templates`)

Дом: `_meta/templates/`. Два новых файла, по форме существующих шаблонов (шапка «Идентификация
и размещение», «Frontmatter», «Структура документа», «Чек-лист самопроверки»; образец —
`contract-call.md`, `docs-readme.md`):

1. `module-kit-readme.md` — README мини-комплекта `modules/<имя>/README.md` (паспорт
   мини-комплекта): назначение модуля, **контур исполнения** (где исполняется, кто вызывает),
   **граница** (что не проходит через Экосистему — формулировки для аудита, у КК: PAN/CVV2/ПИН),
   что из правил комплекта не применяется (привилегии и ролевая модель Экосистемы, гейты контура
   Экосистемы), состав мини-комплекта (таблица файлов), чужие эндпоинты, которые вызывает модуль
   (ссылки на базовые контракты в `docs-external-contracts`, абсолютные через `HEAD`), открытые
   вопросы (ссылкой на OQ комплекта). ID — `MOD-<ИМЯ>-000` (по образцу `EXTINT-<AS>-000`).
2. `module-interface.md` — базовый контракт интерфейса модуля `modules/<имя>/interface/
   mod-<имя>-NNN-<слаг>.md`: ID `MOD-<ИМЯ>-NNN`, `kind: operation`, `channel: js-api`, метод
   JS-API (имя, входные параметры таблицей, выходные, коды ошибок дословно из источника),
   «Потребители» (три колонки, как у базовых контрактов), происхождение (страница источника,
   `confluence_page_ids`).

Образец внутри каждого шаблона — по виджетам КК: страницы каталога `[КК]-Виджеты` в выгрузке
клона `C:\doc-as-code\EAS\src-business-cards\sources\confluence` (только чтение): паспорт
границы контуров → образец README; «Клиент: Скрипт ввода ПИН-кода» → образец контракта
интерфейса. Литералы и коды ошибок — дословно, по правилам нотации. Это ЧЕРНОВИК на приёмку
владельцу канона: нормативные формулировки не выдумывать — где норма не задана, писать
«<решение владельца канона>» и перечислить такие места в сдаче. Шаблоны остальных типов не
трогать. SF-сторож ✓.

## С3 — прибор (analyzer, затем копии в канон веткой `meta/d46-tool`)

1. **Белый список `modules/`**: сторож корня репозитория (`selfcheck`, «посторонние файлы
   ×N») принимает каталог `modules/` рядом с `docs/`; сторож относительных ссылок из `docs/`
   принимает ссылки в `../modules/<имя>/…` как законные (цель должна существовать — иначе
   битая ссылка, как сейчас).
2. **`source_coverage`: класс «вне Экосистемы»** отдельно от «вне плана». Признак — зона в
   описи (`inventory.md`: целевой тип / основание содержит «вне Экосистемы» или `modules/`).
   Проверка: страница зоны считается покрытой, если её `page_id` есть во frontmatter файла
   под `modules/` (мини-комплект читается как часть `--output`); нет мини-комплекта или
   `page_id` в нём нет — **пробел миграции**, не структурный класс (это ровно та потеря, о
   которой записка: «ложное спокойствие»). Сводная строка — «вне Экосистемы A (покрыто
   мини-комплектом B)».
3. **`link_debts`**: долг формы 1 («нет целевого артефакта … требуется заход …»), чьё имя
   цели совпадает с title страницы зоны «вне Экосистемы» по описи, → ⚠ «цель в зоне вне
   Экосистемы — долг формы 1 не заводится, цель — `modules/<имя>/`» (только ⚠).
4. Тесты на срабатывание и НЕсрабатывание для каждого из трёх; полигон — клон КК (только
   чтение): до/после по сводной строке покрытия и по ✗/⚠ корня и ссылок (у КК `modules/`
   пока нет — после класса «вне Экосистемы» 14 страниц виджетов должны стать пробелами, не
   «вне плана»; это ожидаемо и так и доложить). Стенд, эталон — ИТОГО без изменений.
5. Копии в канон — отдельное рабочее дерево, перед веткой `git log --oneline
   master..origin/master -- _meta/tools/` пуст; сверка `tr -d '\r'`; SF ✓.
