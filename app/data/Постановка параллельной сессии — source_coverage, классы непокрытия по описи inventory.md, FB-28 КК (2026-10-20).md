начинать. База: analyzer `cafbe39f` или новее, канон `master 45be23d`.

## Факт

FB-28 КК: `source_coverage.py` даёт «страниц 615; покрыто 325; НЕ покрыто 290», и в 290
смешаны пробелы миграции со страницами, которые покрыть нельзя по решению плана: замороженные
(«Заморожено-*», `frozen-B2B` ×80, `frozen-KMS` ×46, «вне SRS: заморожено GBO-…»),
TOC-контейнеры без собственной карточки (`README-реестр`, основание «TOC-контейнер»),
страницы чужих подсервисов вне плана, бинарные и изображения. Каждый промпт и сдача
переписывают внеплановый список руками.

Дом классификации — `inventory.md` комплекта (шаг 2 `prompt-plan.md`): таблица
`| page_id | title | родитель | req_type | строк | целевой тип (гипотеза) | основание |`,
в КК — корень репозитория, 615 строк. Значения «целевого типа» в КК: путь каталога типа
(`srs/bc-issue/process`, `brd`, …), `README-реестр`, `doc-rules`, `frozen-B2B`, `frozen-KMS`,
«вне SRS: заморожено GBO-70412» и т. п.; в «основании» — «TOC-контейнер», «сигналы согласны»,
«frozen KMS (unapproved_jira …)». Пример: 2251367197 «[КК_Виджет_ПИН] ЭФ Клиента» — целевой
тип `srs/bc-widget/screen-form/client` (вне плана КК по подсервису, но в описи — карточка).

## Что сделать

1. **Чтение описи.** `source_coverage.py` ищет `inventory.md` в корне комплекта (`--output`
   или его родитель; для `docs/` — рядом с `docs/`), новый необязательный аргумент
   `--inventory <путь>` переопределяет. Нет описи — поведение прежнее плюс одна строка
   «опись не найдена — классы непокрытия не определены».
2. **Классы непокрытой страницы** (по строке описи, первое совпадение сверху):
   - `заморожено` — целевой тип или основание содержит `frozen` / «заморожено», либо
     `req_type` содержит `frozen`, либо родитель начинается с «Заморожено»;
   - `контейнер` — целевой тип `README-реестр` или основание содержит «TOC» /
     «контейнер» / «навигация», либо роль `navigation`;
   - `справочный вход` — роль `reference-only` / `baseline` / `instruction` или целевой тип
     `doc-rules`;
   - `бинарное` — файл выгрузки не `.md` или страница без тела (только вложения /
     изображения) — определяется по файлу, не по описи;
   - `вне плана` — целевой тип указывает на подсервис, которого нет в `migration-plan.md`
     комплекта (если план не читается — класс не выдаётся);
   - `не в описи` — page_id нет в `inventory.md` (сигнал: опись отстала от выгрузки);
   - иначе — **пробел миграции** (целевой тип — карточка, артефакта нет).
   Границы классов — закрытый перечень, словарь признаков — в одном месте модуля с
   комментарием «FB-28 КК».
3. **Отчёт.** Первая строка как сейчас плюс разбивка:
   `страниц выгрузки: 615; покрыто артефактами: 325; НЕ покрыто: 290 = пробелы миграции P; структурно: заморожено A, контейнеры B, справочные C, вне плана D, бинарные E; не в описи F`.
   Далее перечни по классам, каждый со своим заголовком («пробелы миграции:» первым), строки
   в прежнем формате `  - <title> — <путь>`. `--strict` возвращает 2 только при P > 0 (и при
   F > 0 — опись отстала). Дочерняя единица покрытого родителя — пометка как сейчас.
4. **Тесты** (`tests/test_source_coverage*.py`): синтетический комплект с описью — по одной
   странице каждого класса плюс пробел; без описи — прежний вывод и строка «опись не
   найдена»; `--strict` с нулём пробелов и структурными — код 0; страница вне описи — F = 1.
5. **Полигон:** клон КК `C:\doc-as-code\EAS\src-business-cards` (только чтение; `--sources
   sources/confluence --output docs` + соседние `nfr/`): сводная строка дословно; сверить
   с ручным внеплановым списком координатора из `sandbox/source-coverage-FIN-01.txt` /
   промптов PIN-06 — расхождения по страницам перечислить в сдаче с квалификацией. Стенд и
   эталон — прогон, ИТОГО selfcheck без изменений (покрытие в вердикт не входит, проверить).
6. **Копии в канон:** ветка `meta/source-coverage-classes` от `master` в отдельном рабочем
   дереве (перед веткой `git log --oneline master..origin/master -- _meta/tools/` пуст);
   `source_coverage.py` (+ `selfcheck.py`, если сводка идёт через него); сверка `tr -d '\r'`;
   SF ✓. Шаблоны и скиллы не трогать; строку про классы в `prompt-plan.md` (шаг 2: опись —
   дом классов непокрытия) добавит владелец канона.
