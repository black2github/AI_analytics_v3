# Вопрос владельцу канона — снятые и плановые ID в реестре матрицы — решено 2026-10-16

Дата: 2026-10-16. От сессии «Правки прибора, акцепт и рутина» для сессии «Точки расширения
эталона». Пакет 2, задача 10, шаг 2: шаблон матрицы трассировки и утилита `matrix_sync.py`.
Основание — файл «Матрица трассировки — разделы комплектов и их природа (2026-10-16)», раздел
«Решения владельца»: все семь рекомендаций приняты.

## Суть

Решение 3 выносит снятые ID из реестра в отдельный ручной подраздел «Снятые ID» с колонками
«ID | Причина и дата | Преемник». Стандарт техбука хранит снятые ID иначе, и этот стандарт стоит
выше канона. Владелец канона допускает, что решение 3 ошибочно и что лучше одна таблица: тогда
следующий свободный ID — просто следующий номер в одной таблице.

## Что говорит стандарт техбука

- **conventions §5, политика внутренних идентификаторов.** Снятый ID не удаляется из реестра ID
  матрицы. Строка остаётся с пометкой «снят <дата>: <причина/преемник>» и файлом «—». Только так
  ID занят навсегда и защищён сторожем дублей. Прецедент 2026-08-30: строку SCR-CL-05 удалили,
  следующий заход выдал SCR-CL-05 другой форме.
- **conventions §5.3 п.4.** Реестр ID ведётся в матрице: каждый выданный ID — строка «ID,
  название, файл».
- **conventions §5.3 п.5.** Плановые строки разрешены: ещё не написанный артефакт получает ID и
  строку реестра.

Снятые и плановые строки из тел документов не выводятся: файла с таким ID нет. Это ручная часть
реестра при любом варианте.

## Варианты

**А. Одна таблица, как в стандарте (рекомендую).**
- Реестр — одна таблица «ID | Название | Файл». Строки с ID из шапок и заголовков тел собирает
  утилита. Строки с файлом «—» ручные: снятые с пометкой «снят …», плановые без неё. Утилита
  переносит ручные строки без правки и сортирует всё по ID.
- Следующий свободный ID — следующий номер в одной таблице, как и сейчас.
- Сторож: снятый ID снова появился в шапке документа — предупреждение «ID переиспользован».
  Плановый ID появился в шапке — строка становится выводимой, файл заполняет утилита.
- Техбук не правится. Комплекты не переводятся: lk-mp и стенд уже в этой форме.

**Б. Подраздел «Снятые ID», как в решении 3.**
- Плюс: выводимая таблица целиком машинная, ручное видно отдельно.
- Минусы:
  - следующий номер ищут по двум таблицам, сторож дублей тоже читает обе;
  - плановым строкам нужен свой дом: третья таблица или исключение из правила;
  - нужна правка техбука, conventions §5 и §5.3 п.4–5, через MR и апрувы ED;
  - нужен перевод lk-mp и стенда.
