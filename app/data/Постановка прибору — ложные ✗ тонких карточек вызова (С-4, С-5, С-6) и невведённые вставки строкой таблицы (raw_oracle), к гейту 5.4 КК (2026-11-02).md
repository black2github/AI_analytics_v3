## Задача 1 (С-4). Карточка вызова с главной страницей-функцией: шаги функции в карточке не требуются

Сигнал: `call-ext-038-esk-signing-authority.md` + `fun-cl-21-request-ep-sign.md` ← страница 2166859675 — «поведение: шаг «1»…«4» источника не найден в карточке ✗ ПОТЕРЯ ШАГА» (r4 строки 169–186). Главная страница карточки 038 — функция FUN-CL-21, у которой есть собственная карточка `fun-cl-21-request-ep-sign.md`; шаги источника живут в ней, карточка вызова по норме шаги не несёт.

Целевое поведение: сторож потери шагов для группы файлов страницы проверяет шаги в карточке типа function/process/screen-form той же группы; карточка `contract-call` в группе шаги не обязана содержать и в счёт «не найден в карточке» не идёт. Если в группе нет ни одного держателя шагов (только contract-call) — прежнее ✗ остаётся (реальная потеря).
Тест на НЕсрабатывание: группа «contract-call + function» с шагами в function — ✓; группа «только contract-call» без шагов — ✗ как раньше.

Целевое поведение: при сверке HTML-таблицы шага и структуры тела шага литералы и имена параметров ищутся в группе «карточка функции + карточки contract-call, на которые ссылается тело этого шага» (ссылки вида `[CALL-EXT-NNN](…)` в тексте шага). Найденные в карточке вызова — засчитываются; структура тела шага при вынесенной таблице — ⚠ с пояснением «таблица шага вынесена в карточки вызова: CALL-EXT-…», не ✗.
Тест на НЕсрабатывание: шаг со ссылкой на contract-call, в которой имена есть, — ✓/⚠; шаг без ссылок и без имён — ✗ как раньше.

## Задача 3 (С-6). Кавычечные литералы доп. страницы-функции у карточки вызова и экрана: только литералы таблицы правил, не тексты шагов

Сигнал: группы 011+036+SCR-CL-20 (r4 674–689), 037+SCR-CL-17 ×3 (991–1009), 038 внутри С-4 (190) — «кавычечные литералы доп. страницы 2464250492: в карточке отсутствуют 2 из 6 ✗ НИЖЕ ПОРОГА; примеры: 'Должность пользователя подписавшего заявку', 'Документ на основании которого пользователь подписал заявку'». Это имена выходных параметров из текста шага 6 общей функции FUN-SYS-10; по решению владельца 02.11 (Р-7) карточки вызова пишут имена из §5 функции («Должность пользователя», «Документ полномочий пользователя»), сама FUN-SYS-10 со шагом 6 дословно в группу карточки вызова не входит. Та же природа, что С-4/С-5: сторож требует текст шагов функции в карточке вызова и экране.

Целевое поведение: для доп. страницы типа «функция» у карточки `contract-call` (и у screen-form той же группы) сторож кавычечных литералов проверяет литералы таблиц правил/параметров страницы (значения тегов, коды, имена процессов — как у страницы метода 2464250512) и не требует литералов из текстов шагов; литералы шагов проверяются у карточки самой функции (FUN-SYS-10 ← 2464250492 — как сейчас). Дополняет прежнюю строку очереди «литералы колонки правил заполнения обязательны у тонкой карточки» (`"Active"`, `GPB_…`, `PROD_EXEC_WRNT`, `RKO`, `CORP_CARDS`).
Тест на НЕсрабатывание: карточка вызова без `GPB_…`/`PROD_…` из таблицы правил — ✗; карточка без имён шага 6 функции — ✓.
