# Как передать замечания по комплекту аналитики locks (первый MR по ошибке влит в репозиторий)

Комплект аналитики лежит в docs/ репозитория src-locks. 
Замечания принимаются двумя способами — выбирайте по типу замечания.

1. Замечание к конкретному месту документа — комментарий в MR: {ссылка на MR}

Откройте MR, вкладка Changes — там виден весь комплект.
Наведите курсор на нужную строку → появится иконка комментария → напишите замечание → нажмите «Start a review» (для первого замечания; для следующих — «Add to review»).
Когда закончите проход — нажмите «Submit review»: все замечания уйдут одним пакетом, аналитик получит уведомление.
То, что MR уже влит, не мешает — комментарии в нём работают как обычно.

2. Замечание «вне строк» (общее, архитектурное, к комплекту целиком) — любой из двух вариантов:

проще: общий комментарий в том же MR — вкладка Overview, поле комментария внизу страницы;
через git: запись в файл feedback.md в ветке locks-run1 (формат записи — в шапке самого файла; новая запись дописывается в конец, номер FB-NN — следующий по порядку):
git fetch
git switch locks-run1
git pull
(дописать запись в feedback.md)
git add -- feedback.md
git commit -m "FB-01: <кратко о чём>"
git push

В этой ветке просьба править только feedback.md — сами документы docs/ исправляет аналитик по вашим замечаниям.

3. Когда проход по комплекту закончен — итоговый комментарий в MR: «Ревью завершено: N замечаний в строках, M в feedback.md». Это сигнал аналитику начинать исправления.

4. Что будет дальше. Исправления придут отдельным MR «Аналитика locks: исправления по ревью run1» — в нём аналитик ответит на каждое замечание («исправлено в …» или обоснование, почему нет). За вами — закрытие своих замечаний (кнопка Resolve thread у комментария / подтверждение по записи в feedback.md) и Approve финального MR: его вливание и будет означать, что комплект принят командой.
