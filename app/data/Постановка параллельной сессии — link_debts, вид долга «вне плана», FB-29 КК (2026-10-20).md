## Факт

FB-29 КК: долг по ссылке, цель которого не появится по решению (тип или подсервис вне плана
миграции; прецедент — L1556 матрицы КК, «[КК_Виджет_ПИН] ЭФ Клиента», подсервис `bc-widget`
вне `migration-plan.md`), держит комплект в ✗ навсегда: формой 5 не закрыть, снять открытую
строку неканонично, статуса «снят» прибор не знает.

Решение владельца канона (20.10): снятия открытого долга не вводим — долг остаётся видимым;
вводится **вид долга без цели «вне плана»** (второй формат строки). Канон: таблица
«Условие закрытия по виду долга» (`docs-readme.md`) — новая строка; `create-artifact` —
вид в закрытом перечне и правило записи:

```text
| <FROM-ID> | — | долг вне плана: «<дословное имя>» — причина: подсервис <слаг> вне плана миграции (OQ-NNN); ответственный: владелец комплекта; ограничение: <…>; закрытие: включение подсервиса в план |
```

## Что сделать (`app/scripts/CI/link_debts.py`)

1. `ISSUE_KINDS` — добавить «вне плана». Просрочка и исполнимость к строке не применяются
   (как у остальных видов); обязательные поля — те же (причина, ответственный, ограничение,
   закрытие); источник `OQ-NNN` для этого вида — обязателен (решение владельца комплекта
   должно быть записано), как у «открытого вопроса».
2. **Ограничитель (асимметрия: вид не должен прятать исполнимый долг).** Из поля «причина»
   берётся слаг подсервиса (`подсервис <слаг>` / `зона <слаг>`); если в `migration-plan.md`
   комплекта (корень `--docs` или его родитель; поиск как в `source_coverage.find_kit_file`)
   этот слаг есть среди подсервисов плана — `⚠ долг «вне плана» от <FROM-ID>: подсервис
   «<слаг>» есть в плане миграции — вид не подходит, долг по ссылке формой 1`. Слаг не
   назван или план не найден — `⚠ … причина не называет подсервис / план не найден —
   проверить приёмкой`. Только ⚠, вердикт не меняет (строка остаётся долгом без цели).
3. Отчёт: в сводке долгов — счётчик по видам, как сейчас для остальных (если такой
   есть), «вне плана» отдельной цифрой.
4. Тесты (`tests/test_link_debts.py`): строка вида «вне плана» с полными полями — не ✗, не
   просрочка, не НЕИСПОЛНИМ; без OQ — ✗ неполной строки; подсервис из плана — ⚠; план не
   найден — ⚠ «проверить приёмкой»; прежние виды — без изменений.
5. Полигон: клон КК (только чтение) — прогон `link_debts` на `master`: ✗ по L1556
   остаётся до перевода строки командой (это ожидаемо); затем на копии матрицы перевести
   L1556 во второй формат по образцу выше и показать: ✗ ушёл, ⚠ ограничителя нет
   (`bc-widget` в плане отсутствует). Стенд, эталон — ИТОГО selfcheck без изменений.
6. Копии в канон: ветка `meta/debt-out-of-plan-tool` от `master` после вливания
   `meta/coverage-classes-plan` (перед веткой `git log --oneline master..origin/master --
   _meta/tools/` пуст) в отдельном рабочем дереве; `link_debts.py` (+ `selfcheck.py`, если
   трогали); сверка `tr -d '\r'`; SF ✓. Шаблоны и скиллы не трогать.
