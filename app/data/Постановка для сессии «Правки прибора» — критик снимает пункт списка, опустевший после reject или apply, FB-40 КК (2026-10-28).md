# Постановка для сессии «Правки прибора» — критик снимает пункт списка, опустевший после reject/apply (FB-40 КК) (2026-10-28)

Исполнитель — сессия «Правки прибора, акцепт и рутина». Постановщик — сессия «Точки расширения эталона».
Повод — FB-40 КК: после `reject-all` на странице 2166861010 остались 8 строк `    * ` без текста (пункты списка
целиком из вставок невведённой задачи), карточка FUN-SYS-13 унаследовала их. По срезу КК таких строк 92 на 23
страницах (в raw — 6 предсуществующих). Класс известен (статус 1.9.11/1.9.12: «косметика»), но косметика уходит в
карточки и в ПРОМ-текст, которым пользуются аналитики.

## Что сделать (`app/scripts/CI/critic.py`, `process_text`)

1. После снятия маркеров (все три пути: inline, таблицы, HTML-острова) строка, которая **до обработки содержала
   маркер** и **после обработки состоит только из маркера списка** (`^\s*([*+-]|\d+[.)])\s*$`), удаляется целиком
   вместе со своим переводом строки. Симметрично для apply (пункт целиком из удаления задачи) и для reject.
2. Ограничители (асимметрия ошибок — лишнее не удалять):
   - строки без маркера до обработки не трогать (предсуществующие пустые пункты — свойство источника, в raw КК их 6);
   - строка, где после снятия остался любой текст (включая один символ, пробелы внутри текста, инлайн-код, ссылку), —
     не трогать;
   - fenced-код — байт в байт, как сейчас;
   - вложенный список: если удаляется родительский пункт, а дочерние остаются — родителя НЕ удалять (дети повиснут
     без родителя и сменят уровень); удалять только пункт без непустых потомков;
   - HTML-острова `<li>` — тот же критерий по тексту элемента; пустой `<ul>/<ol>` после удаления всех пунктов —
     удалять целиком (у экспортёра пустые `<ul></ul>` уже есть в архиве — их не трогать: нет маркера).
3. Счётчик правок: удаление пустого пункта считается правкой (видно в сводке «правок N»).
4. Идемпотентность (ТЗ п. 5.3): повторный прогон по уже обработанному файлу — 0 правок.

## Тесты (парами: срабатывание / НЕсрабатывание)

(а) пункт целиком `{++ID: текст++}` → reject удаляет строку, apply оставляет текст; (б) пункт целиком `{--ID: текст--}`
→ apply удаляет, reject оставляет; (в) пункт с чёрным остатком «`* до {++ID: х++}`» — остаётся «`* до`»; (г) пустой
пункт без маркера в источнике — остаётся; (д) вложенность: родитель из вставки с чёрным ребёнком — остаётся; (е)
нумерованный `1.`/`1)`; (ж) HTML-остров `<li><span class="critic-ins">…</span></li>` и пустой `<ul>`; (з)
идемпотентность; (и) CRLF сохраняется.
