# Корпоративные Карты

Документация сервиса **«Корпоративные Карты»** (кодовое имя `CC`) — одного из сервисов АС Экосистема.

**С чего начать.** Концепция сервиса и глоссарий в комплекте ещё не заведены; состав спецификации требований — в [реестре SRS](srs/README.md), выданные идентификаторы и связи между артефактами — в [матрице трассировки](traceability-matrix.md).

## О сервисе (кратко)

Сервис ведёт заявки клиентов на выпуск корпоративных карт с открытием счёта и заявки на изменение статуса карты: клиент создаёт и редактирует заявку, загружает документы держателя; банк принимает заявку, проверяет её и управляет статусами. Данные держателей, карт, документов и заявок хранятся в сервисе; проверки реквизитов описаны контролями.

У сервиса два пользовательских контура:

| Контур | Кто | Что делает |
|--------|-----|------------|
| **Клиентский (CL)** | представитель организации-клиента | создаёт, редактирует и подтверждает заявку на выпуск карты и открытие счёта; подаёт заявку на изменение статуса карты |
| **Банковский (BNK)** | сотрудник банка | просматривает журналы и скроллеры заявок, принимает и проверяет заявки, устанавливает статусы карт и заявок |

Автоматические проверки и переходы статусов (**SYS**) описаны в процессах и контролях; отдельных системных функций в комплекте нет.

## О комплекте

Это чистовой комплект аналитической документации для версии `exp-2026-07`. Он самодостаточен: описывает поведение системы на уровне требований, не ссылаясь на внешние источники.

- **Формат** — Markdown, docs-as-code: документы дробятся на карточки с устойчивыми идентификаторами (`ENT-`, `SCR-`, `FUN-`, `CTL-`, `CALL-`, `PROC-`), связанными сквозными ссылками.
- **Идентификаторы и трассировка.** Каждый артефакт имеет стабильный ID; сквозные связи сведены в [матрицу трассировки](traceability-matrix.md) — она общая для всего комплекта.
- **Подсервисы.** Спецификация разделена по каталогам: общая часть в корне `srs/` (модель данных, контроли запросов, платформенные функции), подсервис `cc-card-issue` — заявка на выпуск карты и открытие счёта, подсервис `cc-card-status-change` — заявка на изменение статуса карты. Код подсервиса в идентификаторы не входит: нумерация сквозная по комплекту.
- **Навигация.** В каждом каталоге с реестром есть `README.md` — обзор раздела и реестр его артефактов.

## Условные обозначения

Самоописание комплекта: контуры, префиксы идентификаторов, статусная модель и поля frontmatter — всё, что нужно читателю, чтобы разобрать любой идентификатор и любую карточку комплекта (полная схема ID — в конвенциях проекта / org-стандартах аналитики). Раздел читают и инструменты, и агенты вне комплекта: имена подразделов не меняются.

### Контуры (суффиксы в ID)

| Код | Значение | Где встречается |
|-----|----------|-----------------|
| **CL** | Клиентский контур | `FUN-CL-*`, `SCR-CL-*`; каталоги `client/` |
| **BNK** | Банковский контур | `SCR-BNK-*`; каталоги `bank/` |
| **SYS** | Системные функции (без пользовательского UI) | в этом комплекте функций `FUN-SYS-*` нет |

### Типы артефактов (префиксы ID)

| Префикс | Что обозначает | Где лежит |
|---------|----------------|-----------|
| **PROC** | Процесс | `srs/cc-card-issue/process/` (реестр `PROC-000`) |
| **SM** | Статусная модель: `SM-000` — статусы заявки на выпуск карты и открытие счёта | `srs/cc-card-issue/process/status-model.md` |
| **ENT** | Сущность модели данных | `srs/data-model/` (общая часть), `srs/cc-card-issue/data-model/`, `srs/cc-card-status-change/data-model/` |
| **EXT** | Справочник / сущность платформы (вне сервиса) | `srs/data-model/dictionaries.md` |
| **DM** | Реестр модели данных (`DM-000`) и общий документ справочников (`DM-001`) — наследие первых заходов, новые `DM` не выдаются | `srs/data-model/README.md`, `srs/data-model/dictionaries.md` |
| **FUN** | Функция системы | `srs/cc-card-issue/function/` |
| **SCR** | Экранная форма; экран с вкладками — папка с `README.md` и файлами вкладок `SCR-…-NN.K` | `srs/cc-card-issue/screen-form/` (реестр `SCR-000`), `srs/cc-card-status-change/screen-form/` |
| **CTL / CTL-GRP** | Контроль / группа контролей; карточки контролей — файлы `cards-*.md` с `partOf: CTL-000` | `srs/control/` (реестр `CTL-000`), `srs/cc-card-issue/control/`, `srs/cc-card-status-change/control/` |
| **CALL** | Вызов чужого контракта: `CALL-EXT-NNN` — внешняя АС, `CALL-INT-NNN` — метод платформы ЭКО со спецификацией | `srs/cc-card-issue/contract-call/` (реестры `CALL-000`, `CALL-EXT-000`, `CALL-INT-000`) |
| **PLT** | Платформенная функция ЭКО — переходный реестр функций платформы Экосистемы без собственной постановки; новые записи не заводятся, при появлении спецификации заменяются на **CALL** | `srs/platform-functions.md` (реестр `PLT-000`) |

Внутри экранных форм дополнительно: **FLD-N** — правило поля, **EV-N** — событие, **B-N** — кнопка, **MSG-N** — сообщение.

### Долги по ссылкам

В матрице трассировки есть раздел «Долги по ссылкам». Каждая его строка — открытое поручение по комплекту, не дефект: в тексте документа оставлено дословное имя цели, которой в комплекте нет. Как читать строку `| FROM-ID | — | нет целевого артефакта <тип> «<имя>» [у владельца <service-id>] — требуется заход <скилл> |`:

| Поле поручения | Откуда берётся |
|----------------|----------------|
| Формулировка (`statement`) | текст строки долга целиком |
| Основание (`basis`) | карточка `FROM-ID` — документ, в котором цель упомянута дословно |
| Адресат (`addressee`) | сервис-владелец из «у владельца <service-id>» (межсервисный долг: закрывается публикацией владельца, в этом комплекте не решается); без владельца — аналитик этого сервиса |
| Приоритет (`priority`) | `IMPORTANT`: работа по сервису продолжается, цель дописывается отдельным заходом |
| Область (`scope`) | комплект: долг действует до появления цели, независимо от задач |

Долг закрывается заменой дословного имени на ссылку, когда цель появляется; строка из матрицы снимается.

## Границы комплекта

- Комплект описывает целевой контур сервиса с меткой версии `exp-2026-07`.
- Устаревшие, тестовые и скопированные материалы не входят в целевой контур.
- Контуры PCI DSS-виджетов не входят в этот комплект.
- Бизнес-требования (BRD), концепция сервиса и глоссарий ещё не заведены.
