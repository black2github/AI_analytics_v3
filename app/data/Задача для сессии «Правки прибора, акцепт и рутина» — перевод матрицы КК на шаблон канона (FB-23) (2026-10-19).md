# Задача для сессии «Правки прибора, акцепт и рутина»: перевод матрицы трассировки КК на шаблон канона (FB-23)

Дата постановки: 2026-10-19. Ставит сессия «КК и хвосты» по решению владельца пилота (вариант 2
по FB-23: заход владельца силами параллельной сессии, а не координатора). Общие правила — как в
прежних пакетах: контурный репозиторий команды, коммит и push — владелец; без AI-трейлеров;
сдача с числами.

## Контекст

- Комплект: `C:\doc-as-code\EAS\src-business-cards` (ветка `master` = серверный `master`,
  b9d6a23 на 19.10; команда активно коммитит — заходы PIN-01 и далее). Матрица
  `docs/traceability-matrix.md`, ~1300 строк, старая структура.
- Норма: шаблон `_meta/templates/traceability-matrix.md` канона (master a9658be+), утилита
  `_meta/tools/matrix_sync.py`; записка координаторам 18.10 («Сообщение координаторам КК, lk-mp,
  common-dictionary — матрица трассировки производна от тел…») — раздел «Порядок перевода»;
  образец — эталон `output/open-add-account/docs/traceability-matrix.md` в каноне (переведён
  тобой 18.10, приложения «## Приложение N. …»).
- FB-23 в `feedback.md` КК (19.10): координатор ждёт решения; владелец решил — заход владельца.
- Состояние по `matrix_sync --check` на 18.10 (из записки): структура — 8 отклонений (раздел
  «Источники (вне SRS)» вне шаблона; нет «Покрытие: API ↔ SRS» и «Источники миграции»; реестр с
  колонкой «Тип»; имена и колонки покрытий); реестр — 11 строк EXT с пояснением вместо файла
  («(вне комплекта; title …; pageId …; алиас …)»), нет строки EXT-004; 23 ячейки покрытия
  процессов с текстом без ID (названия ненайденных целей в CALL/FUN).

## Что сделать

1. Рабочее дерево `C:\tmp\kk-matrix`, ветка `docs/matrix-template` от свежего `origin/master`
   (`git fetch` перед началом; клон команды не переключать).
2. **Структура — руками, без потери фактов:**
   - порядок, имена и колонки шести разделов по шаблону; колонка «Тип» реестра снимается
     (тип виден по ID и шапке);
   - «Источники (вне SRS)» → `## Приложение 1. Источники вне SRS` (содержимое построчно как
     было); если раздел по смыслу равен «Источники миграции» шаблона (page_id → артефакты) —
     решить по содержимому и написать в сдаче, что выбрано и почему;
   - пояснения в 11 строках EXT (title, pageId, алиас, OQ) — в `## Приложение 2. Внешние
     справочники: источники и алиасы` таблицей `ID | Пояснение` построчно дословно; в реестре
     файл EXT — `srs/…/dictionaries.md`, как найдёт утилита;
   - 23 ячейки покрытия процессов с текстом: каждая — либо строка «Долги по ссылкам» (нет
     целевого артефакта «<название дословно>» — форма 1), либо `## Приложение 3. Цели без
     карточек` таблицей `Процесс | Колонка | Текст ячейки`; выбор — по правилу: если цель
     должна существовать в комплекте (CALL/FUN этого сервиса) — долг, если это внешняя или
     чужая цель — приложение; в сдаче перечень всех 23 с решением;
   - пустые разделы шаблона («Покрытие: API ↔ SRS», «Источники миграции», если пусто) — с
     заголовком, поясняющей строкой и шапкой таблицы, как в эталоне.
3. `matrix_sync --check` до чистой структуры; отказы по «ID ячеек, которые пересборка
   потеряет» и «строка реестра без документа» разбирать по записке (ссылка в тело, если связь
   настоящая; снятие ID — только по решению владельца, перечислить в сдаче, самому не снимать).
4. `matrix_sync --write`; затем `--check` ✓; `selfcheck.py --docs docs --sources
   sources/confluence` — строка `✓/⚠ выводимые разделы матрицы … (matrix_sync)`, строки `i …
   пропущена` нет; baseline команды (`sandbox/selfcheck-PIN-01-r05.txt`) сравнить — новые ✗
   недопустимы, число ⚠ до/после в сдаче.
5. **Инварианты (в сдаче числами):** ни один ID прежнего реестра не исчез (множество ID до ⊆
   после; снятые — только строками «снят …»); связи покрытия — только добавились или совпали
   (дифф по ячейкам: удалённых ID 0, кроме перенесённых в долги/приложения — перечень);
   ручные разделы и приложения — построчно прежние; долги по ссылкам — число строк до/после,
   `link_debts.py` без новых «не распознана».
6. Запись в `feedback.md` к FB-23: «Решение владельца канона (2026-10-19): заход владельца;
   ветка `docs/matrix-template`, срез канона <хеш>; что перенесено в приложения и долги —
   числами» (текст в сдаче, в файл — владелец после push).
7. Сообщение коммита — файлом `C:\tmp\kk-matrix-commit.txt`; push, MR и запись FB — владелец.
   Перед push — `git fetch` и перебазирование на свежий `origin/master` (матрицу могли
   тронуть): конфликт разрешается повтором шагов 3–4 на новой базе, не ручным слиянием ячеек.
