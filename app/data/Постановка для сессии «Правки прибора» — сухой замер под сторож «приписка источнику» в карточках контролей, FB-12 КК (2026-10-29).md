# Постановка: сухой замер под сторож «приписка источнику» в карточках контролей (FB-12 КК)

Дата: 2026-10-29. Для сессии «Правки прибора, акцепт и рутина». Прибор в этом заходе НЕ меняется — только замер и
отчёт; коммит analyzer — по слову владельца. Источник: FB-12 КК (`feedback.md`, 2026-10-05), решение владельца канона
06.10 и дополнение 29.10 — там же.

## Проблема

Десять карточек контролей КК утверждали «в постановке текст сообщения дословно совпадает с текстом логики проверки»
при пустой ячейке «Сообщение об ошибке» в строке источника. Это приписка источнику: утверждение о содержании ячейки,
которой нет. Односторонняя сверка прибора («всё ли из источника перенесено») такое не видит, следующая карточка с
той же припиской пройдёт ✓. Правило с 06.10 действует (шаблон `controls.md`, поле «Сообщение об ошибке», чек-лист
п. 6; скилл `review-artifact`): пустая ячейка переносится ровно формулой «в постановке не задано», утверждения о
содержании источника не-цитатой запрещены. Сторож отложен решением 06.10 до замера: надёжная проверка должна
разобрать таблицу источника, найти строки с пустой ячейкой сообщения и сопоставить их с карточками по тексту
логики; объединённые ячейки и разные названия колонки могут дать ложные срабатывания. Замер не делался —
координатор КК 29.10 числит это неисполненным обязательством владельца канона. Этот заход его закрывает.

## Что сделать

1. **Инвентаризация колонок сообщения.** По всем страницам источников найти таблицы с колонкой сообщения:
   варианты заголовка — «Сообщение об ошибке», «Текст сообщения», «Сообщение», «Текст ошибки», «Сообщение
   пользователю» (список дополнить по факту, перечислить в отчёте). Посчитать: страниц, таблиц, строк данных,
   строк с пустой ячейкой сообщения. Отдельно посчитать таблицы, где надёжный разбор невозможен или сомнителен:
   объединённые ячейки (`rowspan`/`colspan`), заголовок не в первой строке, несколько колонок-кандидатов, таблица
   без заголовка. По FB-12 в КК таких страниц ожидается около 71 — число проверить, не переносить.
2. **Сопоставление карточка ↔ строка источника.** Для каждой карточки `control` взять текст логики проверки (поле
   карточки по шаблону `controls.md`) и найти строку источника: сначала точное совпадение после нормализации
   (пробелы, регистр, кавычки «»/"", неразрывные пробелы, точечная нотация), затем подобие (порог назвать, например
   `difflib.SequenceMatcher` не ниже 0.9). Отчитать долю сопоставленных карточек по комплектам; несопоставленные —
   списком с причиной (страница не в источниках, текст переформулирован, карточка собрана из нескольких строк).
3. **Поиск приписок.** Два детектора, числа по каждому отдельно:
   - текстовый: в карточках фразы-признаки не-цитаты о сообщении — «дословно совпада», «как в постановке»,
     «в постановке текст», «совпадает с текстом логики», «аналогично постановке», «см. логику» в поле
     сообщения (список дополнить и перечислить);
   - обратный: поле «Сообщение об ошибке» карточки заполнено содержательно (не «в постановке не задано»), а
     ячейка сопоставленной строки источника пуста.
   Каждое срабатывание классифицировать вручную по трём классам: истинная приписка; корректный перенос
   (например, текст взят из другой колонки или соседней строки по объединённой ячейке — указать, откуда); ложное
   срабатывание разбора (объединённая ячейка, неверная колонка, неверно сопоставленная строка).
4. **Отчёт** — файл `app/data/Замер FB-12 — приписка источнику в карточках контролей, два комплекта (2026-MM-DD).md`:
   таблица по комплектам (страниц с колонкой / таблиц / строк / пустых ячеек / карточек control / сопоставлено /
   срабатываний текстового и обратного детекторов / истинных / корректных / ложных); список истинных приписок с
   путём карточки и строкой источника; перечень классов ложных срабатываний с примерами; оценка: при каком
   проценте ложных сторож имеет смысл как ⚠, как i (информационная строка), или не имеет; рекомендация с
   обоснованием. Числа — только из прогона. Скрипт замера — одноразовый, положить рядом с отчётом как
   `app/data/Замер FB-12 — скрипт (2026-MM-DD).py.txt` (не часть прибора, в бандл не входит), в отчёте — команда
   запуска.

## Ограничители

- Прибор (`app/scripts/CI`), шаблоны и скиллы канона, карточки комплектов не править. Найденные истинные приписки
  в КК — только в отчёт, исправляет команда по решению владельца.
- Контурные репозитории не коммитить; analyzer — коммит по слову владельца, `git add -- <перечень>`.
- Кодировка `utf-8` явно, пути через `pathlib`; Python системный с `PYTHONPATH` по правилу репозитория.
