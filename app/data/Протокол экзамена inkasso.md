# Протокол экзамена: src-inkasso-outgoing (exam-run1)

Правила (подтверждены 2026-08-16): канон ЗАМОРОЖЕН (методология
75aecb9; поздние коммиты — только данные/прибор); заходы по разделам
минимальными промптами; находки методологии КОПЯТСЯ здесь (волны —
пакетом после экзамена); дефекты измерительного прибора (гейтов)
чинятся сразу с пометкой — их шум кумулятивен и портит все следующие
измерения; приёмка заходов — коммитами на exam-run1, допускается
«принят с задокументированным остатком» решением аналитика.
Продукт экзамена — этот список, не документация.

## Стратегия сэмплирования (решение аналитика 2026-08-16, после захода 5)

Метрика экзамена — находки на страницу, не страницы на комплект.
Принцип: сэмплирование по осям разнообразия «тип × команда × стиль
вёрстки»; сплошное покрытие оси — только пока она даёт находки
(функции насытились к заходу 5: К-2…К-5/Э-4/Э-5 пришли с первых
партий, дальше — случайные особенности страниц). Интеграционные
классы (дозакрытия, межтиповые связи, покрытие) сохраняются финальным
заходом vision+README на СОЗНАТЕЛЬНО неполном покрытии («отложено
экзаменом» — документированная судьба страниц, сам по себе новый
класс проверки). Пересобранный план: микро-дозаход fun-bnk-04 →
ЭФ партия 1 (1–2 формы из 38 стр.) → контроли (2) → интеграция+методы
(6+2) → агенты-сэмпл (1 из 12) → ПФ-сэмпл (2) → vision+README.
ОТЛОЖЕНО: функции партия 3б (27 стр.), хвосты ЭФ/агентов/ПФ (~50 стр.)
— возврат только если пакет волн изменит соответствующий канон.
Межкомандное разнообразие — принцип отбора сервисов для фазы тиража
после пилота. Уточнение (аналитик, 2026-08-16): ось «команда» — это не
только вёрстка, а ИНТЕРПРЕТАЦИЯ шаблонов при формально одинаковых
шаблонах типов: стиль изложения и структурирования, варианты выноса
служебного в дочерние страницы, имена колонок, оформление заголовков.
Подтверждено пилотом: file-storage → locks → inkasso — каждый сервис
дал свою порцию калибровок. Норма процесса тиража: первый сервис
каждой новой команды — калибровочный (ожидаемые К-находки и шаблонные
дыры — свойство процесса, не дефект канона); словари и профили
сторожей держать расширяемыми данными, не кодом.

## Инструментальные калибровки (прибор, не методология)

- **К-1** (заход 1): сторож маркеров шагов сделан тип-зависимым
  (process/agent/function/notification; тип не распознан — применяется)
  — на страницах сущностей МД составные номера 1.1… — нумерация секций,
  не шаги; ложные «отсутствуют 72 из 72» (ent-001/007/008). Analyzer +
  синк; тесты (162).
- **К-2** (заход 3): обрезки ТЕКСТОВОГО CriticMarkup («++}», «{++») в
  ячейках таблиц источника исключены из требуемых значений — разметка
  правок, не содержимое (fun-bnk-04: пайп внутри `{++…++}` породил
  ячейку-обрезок «++}»); содержимое внутри правок сторожится как
  прежде (тест на НЕсрабатывание).
- **К-3** (заход 3): `_title_suspicious` бракует «чистый тип» только
  по словарю типов — одиночный латинский идентификатор (TraceID,
  SessionID) — легитимное имя параметра, generic-латиница ложно
  бракавала имена (fun-bnk-04). Тесты (166).
- **К-4** (заход 4): колонные роли параметрических таблиц не
  применяются к README-реестрам (навигационные таблицы) — колонка
  «Краткое название формы (элемент…)» реестра ЭФ ложно распознана
  ролью «путь» (75% → брак трёх названий форм). Полноту реестра
  держит сверка значений источника. Тесты (168).
- **К-5** (заход 5): гейты сверяют ЦЕЛЕВОЙ текст источника —
  `apply_critic` применяет правки CriticMarkup обеих форм (добавления —
  содержимым без маркеров и префикса задачи, удаления выпадают,
  замены — новым текстом) до всех сверок. Двусторонний инцидент:
  старый гейт ПРОВОЦИРОВАЛ перенос разметки в чистовик (fun-sys-08:
  «markup сохранён для прохождения гейта») и ПРОЩАЛ выброс содержимого
  вставок (fun-bnk-04: вставка «Доступность функции проверяется в
  соответствии с [ЦРМ]…» выброшена целиком — вскрыто сразу после
  К-5). Тесты (172, включая НЕсрабатывание: целевое содержимое
  добавлений обязано присутствовать).

## Находки методологии (копятся до конца экзамена)

- **Э-1. Lifecycle-паспорт сущности** (ent-003, ent-005; заход 1).
  Страницы МД ведут паспорт-таблицу «Назначение / Использование
  сущности / Когда создается запись / Когда изменяется запись» со
  ссылками на функции-создатели. Шаблон data-model про неё молчит →
  агент не перенёс, гейт таблиц требует. Вопросы к волне: куда
  переносится (карточка сущности? связи в функции при их заходе —
  межтиповое?); «Когда создается…» — это готовые связи ENT↔FUN.
- **Э-2. Таблица маппинга БД** (ent-002; заход 1). Источник даёт
  готовый маппинг «Наименование поля ↔ Наименование поля в БД»
  (13 строк); канон: «физическую модель аналитик проектирует сам»,
  но правила про ГОТОВЫЙ маппинг источника нет — агент не перенёс,
  гейт требует.
- **Э-4. Исправление подозреваемой опечатки источника вместо
  дословного переноса + OQ** (prc-002 шаг 14; заход 2). Источник
  (без critic-разметки): «Изменить статус документа на "SIGNED_2"» в
  шаге удаления — очевидная копипаста-опечатка; агент перенёс своё
  предположение `DELETED` и лишь задокументировал спорным местом.
  Канон-прецедент обратный (locks «шаг №1.3»: дословно + OQ), но
  ЯВНОГО правила в create-process/шаблоне нет. Гейт литералов не
  ловит: литерал "SIGNED_2" присутствует в карточке в других шагах
  (сторож ищет по всей карточке, не по месту). Волна-кандидат: правило
  «подозрение на опечатку — переносить дословно + OQ» в create-artifact
  (общее для reverse) + подумать о месте-чувствительности сторожа.
- **Э-5. Сжатие длинного алгоритма невидимо механике** (fun-cl-10;
  заход 4). Источник «Функция подписи документа» — 370 строк, ~100
  шагов с ОДИНОЧНОЙ нумерацией; карточка — 58 строк, агент сам
  задокументировал сжатие спорным местом. Сторож маркеров сознательно
  не собирает одиночные номера (шум счётчиков) — нашлись только
  100.1–100.3; 17 литералов уцелели в сжатом тексте → все гейты ✓.
  Кандидаты волны: сборщик одиночных номеров при длинной
  последовательности (1..N, N≥5, strong/первые колонки); правило
  «алгоритм переносится целиком» уже подразумевается — нужна механика.
  Карточка fun-cl-10 требует пере-заноса при пакете волн.
- **Э-3. ФЛК-колонки и примеры значений** (ent-001; заход 1).
  Литералы примеров и форматов ('000001', '40702810600255278910',
  'Строка: по правилам УФЭБС', 'Копирование') из колонок ФЛК/Примеры
  не переносятся в карточку — шаблон data-model не определяет судьбу
  этих колонок; 6 из 37 литералов.
