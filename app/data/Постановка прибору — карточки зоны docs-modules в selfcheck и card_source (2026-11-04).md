# Постановка прибору — карточки зоны `docs/modules/` в selfcheck и card_source (2026-11-04)

Повод: дозаход формы «Происхождение» мини-комплекта widgets-rtl (КК, exec/tail-0 fa19d483). Исполнитель заметил два расхождения прибора с правленым шаблоном `module-interface.md` (канон a0d9ae4). Причина установлена, ниже — диагноз и целевое поведение; код, тесты и копия в канон — сессии прибора.

## Диагноз

1. **selfcheck не сверяет карточки зоны вообще.** `selfcheck.py` (цикл по `docs`, ветка `in_module_zone`) пропускает `docs/modules/**` целиком по Д-49 п. 4: «перепись, схема типов, реестр ID, сверка с выгрузкой его не касаются», собирает только `zone_cards` для сторожа подсервисов. Шаблон `module-interface.md` (правка 2026-11-04) обещает: «прибор сверяет карточку по первой странице, остальные помечает «вне выгрузки, без сверки» (строка i)». Это поведение есть для карточек комплекта (ветка `len(pids) > 1`, строка i «доп. страницы-источники … вне выгрузки, без сверки»), для зоны его нет. Обещание шаблона сегодня не выполняется — ни ✗, ни i, молчание.

2. **card_source (normalize_tables) не знает зоны.** Карточка зоны с двумя page_id читается как карточка-агрегатор (решение 2026-10-30: больше одной страницы = агрегатор, title дополнительных страниц обязаны быть заголовками разделов) → ✗ «title: карточка-агрегатор 2 страниц — нет заголовков по страницам» (MOD-002, MOD-001). Для зоны вторая и далее страницы — спецификации чужого контура из `sources/external`, не источники тела карточки; агрегаторная логика к ним не относится. Кроме того, сторож «отсылки к страницам источника в теле карточки» ловит слово Confluence, которое шаблон зоны требует в таблице «Происхождение» («Выгрузка Confluence сервиса»). Оба ✗ были и до дозахода (у 002 title «расходится с источником» → «агрегатор»); гейт их не видит, потому что normalize_tables в гейт для зоны не входит. Это не регресс дозахода, а неприменимость утилиты к зоне.

## Целевое поведение

**selfcheck, карточки зоны** (`docs/modules/**/*.md` c frontmatter `confluence_page_ids`, кроме `spec/`):
- первая страница есть в выгрузке → сверка title с наименованием страницы как у карточек комплекта (дословно, с ведущим тегом); расхождение — ⚠, не ✗ (зона вне переносимого состояния, вердикт гейта не меняет — как все сторожа зоны, `zone.py` «только ⚠ и i»);
- первой страницы нет в выгрузке → ⚠ «источник первой страницы не найден в выгрузке» (у README первая — паспорт границы, он в выгрузке);
- остальные page_id: строка i «доп. страницы-источники (N) — спецификации чужого контура; вне выгрузки, без сверки: …» — без ✗;
- сводная строка зоны `_kc_module_zone` считает эти ⚠/i. Перепись, схема типов, реестр ID по-прежнему зону не трогают (Д-49 п. 4 остаётся).

**card_source (normalize_tables), карточки зоны:**
- источник сверки — только первая страница; правило агрегатора к карточке зоны не применяется (условие «больше одной страницы» дополнить «и не зона»);
- раздел «Происхождение» (таблица `Источник | Путь в репозитории | Срез / дата выгрузки`) исключается из сканера «отсылки к страницам источника»; за его пределами сторож работает как прежде (слово Confluence вне этой таблицы в карточке зоны — по-прежнему ✗);
- `--source` для карточки зоны — страница первого page_id; без `--source` поведение прежнее.

## Тесты (обязательны, на НЕсрабатывание тоже)

- selfcheck: карточка зоны с двумя page_id, первая в выгрузке, title совпадает → 0 ✗, 1 i с перечнем «вне выгрузки»; title расходится → ⚠, вердикт не меняется; карточка комплекта с двумя page_id — поведение как было (строка i прежнего текста, агрегаторные сторожа).
- card_source: карточка зоны с двумя page_id и верным title по первой → без ✗ «агрегатор»; таблица «Происхождение» со словом Confluence → без ✗ «отсылки»; слово Confluence в другом разделе → ✗ как прежде; карточка комплекта с двумя page_id → ✗ агрегатора как прежде.
- Эталон: `docs/modules/widgets-rtl/` КК на exec/tail-0 fa19d483 — selfcheck ✗ 0, по пяти файлам по одной строке i; normalize_tables на 001–004 без ✗ «агрегатор» и без ✗ «отсылки» по «Происхождению».
