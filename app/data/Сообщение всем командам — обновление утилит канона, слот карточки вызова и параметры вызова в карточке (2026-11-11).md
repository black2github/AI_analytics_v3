# Обновление утилит канона: слот в идентификаторе карточки вызова и параметры вызова в карточке

Кому: командам, которые ведут комплекты требований по канону docs-o2new.
Срочных действий не требуется: вердикт самопроверки и гейта переноса от этого обновления не ухудшается.

## Что изменилось

**1. Где стоит слот в идентификаторе карточки вызова.** Это касается только комплектов, у которых в
идентификаторах есть слот: сервис из частей или сервис в доменном репозитории. Конвенции говорили «слот
стоит сразу после префикса», но не называли префикс карточки вызова, и команды прочитали правило
по-разному. Теперь записано прямо (конвенции техбука, §5, «Слоты сервиса и части в идентификаторе»;
шаблон канона `contract-call.md`): префиксом карточки вызова считается идентификатор вместе с подтипом —
`CALL-EXT`, `CALL-INT`, `CALL-MOD`. Слот идёт после подтипа:

| Было допустимо | Норма |
|---|---|
| `CALL-USR-EXT-001` | `CALL-EXT-USR-001` |
| `CALL-USR-INT-000` (реестр подтипа) | `CALL-INT-USR-000` |
| `CALL-USR-000` (корневой реестр вызовов) | `CALL-USR-000` — без изменений |

Карточки с прежней формой ошибкой не считаются: самопроверка печатает одно предупреждение на комплект.

**2. Параметры вызова, перенесённые в карточку вызова.** По шаблону значения параметров запроса живут в
карточке вызова, а в шаге функции остаётся вызов со ссылкой на неё. Раньше самопроверка принимала такой
перенос, только если на странице-источнике значения стояли таблицей. Если они записаны списком
«параметр = значение», она давала ошибку «структура тел шагов расходится с источником». Теперь список
присваиваний равноценен таблице: ошибки нет, печатается предупреждение. Остальной текст шага сверяется
с источником как прежде.

## Как получить обновление

1. Обновить клон канона:

   ```powershell
   git -C <клоны>\docs-o2new pull --ff-only
   ```

   Ожидаемый результат: строка `Fast-forward` со списком файлов либо `Already up to date.`

2. Убедиться, что обновление на месте:

   ```powershell
   git -C <клоны>\docs-o2new merge-base --is-ancestor 170d711 HEAD; $?
   ```

   Ожидаемый результат: `True`.

Здесь `<клоны>` — каталог, где у вас лежит клон docs-o2new.

## Что вы увидите в отчёте самопроверки

Если в комплекте есть карточки вызова с прежней позицией слота:

```text
⚠ прежняя позиция слота у карточки вызова — переименовать при ближайшем заходе (слот стоит после подтипа: CALL-EXT-<слот>-…): карточек 10 — CALL-AGR-EXT-000, CALL-AGR-EXT-001, CALL-AGR-INT-000 …
```

Если значения параметров вызова перенесены из шага функции в карточку вызова:

```text
предупреждение: структура тела шага №4 расходится с источником — присваивания шага (8) вынесены в карточки вызова: CALL-INT-020 (один дом у факта: правила заполнения — в карточке вызова; имена параметров есть в группе сверки, значения — проверить приёмкой)
```

Числа и идентификаторы в примерах условные.

## Что сделать

| Строка | Что сделать |
|---|---|
| прежняя позиция слота у карточки вызова | при ближайшем заходе переименовать карточки и файлы (`call-usr-ext-001-…` → `call-ext-usr-001-…`), поправить ссылки на них и реестр идентификаторов в матрице |
| присваивания шага вынесены в карточки вызова | проверить приёмкой, что значения параметров в карточке вызова совпадают с источником |
| ошибка «присваивания шага вынесены в карточку вызова, но параметров нет …» | в карточке вызова нет названных параметров: перенести их из источника в раздел «Правила заполнения исходящего сообщения» |

Когда вносить правки — решает лид аналитиков команды.
