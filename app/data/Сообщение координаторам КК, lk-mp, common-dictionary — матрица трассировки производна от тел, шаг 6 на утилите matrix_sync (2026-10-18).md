# Координаторам КК, lk-mp, common-dictionary (Уполномоченные лица): матрица трассировки производна от тел документов, шаг 6 ведёт её утилитой

Дата: 2026-10-18. От владельца канона. Срез канона: `7cb27ca` (шаблон
матрицы и утилита — с e467758, шаг 6 — с 7cb27ca).

## Что изменилось

1. **Норма.** Матрица трассировки производна от тел документов (стандарт ЭКО, conventions
   §5.3 п.2). Связь между артефактами живёт в теле документа как markdown-ссылка; матрица —
   её отражение. Связь, которая есть только в матрице, — расхождение: её вносят в тело, а не
   в матрицу. Вступление вида «каждая связь зафиксирована только в матрице» больше не
   действует.
2. **Шаблон.** `_meta/templates/traceability-matrix.md`: шесть разделов в фиксированном
   порядке с дословными именами и колонками. Четыре раздела **выводимые** — их собирает
   утилита из тел: «Реестр ID», «Покрытие: функции → артефакты», «Покрытие: процессы →
   артефакты», «Источники миграции». Два **ручные** — их ведёт аналитик, утилита не трогает:
   «Покрытие: API ↔ SRS», «Долги по ссылкам». Ручные строки внутри реестра (снятые и
   плановые ID, файл «—») и текст разделов вне таблиц утилита переносит байт в байт.
   Дополнительные ручные разделы допускаются после шести основных с заголовком,
   начинающимся словом «Приложение» (`## Приложение 1. <имя>`); пустой выводимый раздел
   (например, процессы у справочника) остаётся с заголовком, поясняющей строкой и шапкой
   таблицы — пример в матрице эталона.
3. **Утилита** `_meta/tools/matrix_sync.py`. `--check` печатает расхождения матрицы с
   документами и ничего не пишет; `--write` пересобирает только выводимые разделы. `--write`
   отказывает и не трогает файл, если пересборка потеряла бы факт: структура не по шаблону,
   ID в ячейке без ссылки в документах, строка реестра без документа, текст без ID в
   выводимой ячейке (пометки вида «— (долг …)», «см. OQ-…»).
4. **Самопроверка** (`selfcheck.py`) вызывает `--check` сама. Матрица по шаблону —
   расхождения печатаются как ⚠, вердикт не меняется. Матрица не по шаблону — одна строка
   `i матрица трассировки не по шаблону канона — сверка выводимых разделов (matrix_sync)
   пропущена`, и больше ничего.
5. **Шаг 6 скилла create-artifact** ведёт матрицу по этой строке самопроверки: новый
   комплект — по шаблону, через утилиту; матрица по шаблону — `--check`, затем `--write` в
   том же MR, что и правка документов; матрица не по шаблону — ведётся вручную, как раньше,
   структуру агент не перекраивает.

Долги по ссылкам ничего из этого не затрагивает: раздел ручной, формы строк проверяет
`link_debts.py`, гейт переноса читает его как прежде. Долг — запись об отсутствии связи, из
тел он не выводится и утилитой не трогается.

## Что это значит для действующих комплектов

**Сейчас делать ничего не нужно.** Все три матрицы (КК, lk-mp, common-dictionary — Уполномоченные лица) не по шаблону, поэтому
самопроверка печатает одну строку `i`, агент на шаге 6 ведёт матрицу вручную, как раньше.
Перевод на шаблон — отдельный заход координатора, своим MR, без срока со стороны владельца
канона; рекомендуемый порядок lk-mp → common-dictionary → КК (по объёму правок). После перевода матрица
перестаёт расходиться с телами: утилита пересобирает её при каждой правке документов.

Что показывает утилита по состоянию клонов на 18.10:

## Порядок перевода (для координатора, одним MR)

Клон канона на master не старше среза из шапки. Команды — из корня репозитория комплекта,
`<канон>` — путь к клону `docs-o2new`, `<docs>` — корень комплекта (`docs` у КК и lk-mp,
`output\authorized-person` у common-dictionary).

1. Ветка под заход, матрица в неё. Структуру привести к шаблону вручную: порядок и имена
   разделов, колонки выводимых таблиц дословно по шаблону; разделы вне шаблона — переименовать
   в `## Приложение N. <имя>` и перенести после шести основных; пометки с текстом из ячеек
   покрытия и реестра — в приложение или в «Долги по ссылкам». Содержимое ячеек с ID на этом
   шаге не править: его сверит и дополнит утилита.
2. Сверка структуры и содержимого:

   ```powershell
   python <канон>\_meta\tools\matrix_sync.py --docs <docs>
   ```

   После команды: строк «структура матрицы не по шаблону» быть не должно; оставшиеся ⚠ —
   расхождения содержимого, их закроет следующий шаг. Если есть «ID ячеек, которые
   пересборка потеряет» — это связь, которой нет в телах: вписать ссылку в документ, если
   связь настоящая, иначе снять ячейку; «строка реестра без документа» — документ удалён или
   сменил ID, строку оформить вручную как «снят <дата>: причина, преемник <ID>» (решение
   владельца комплекта, не утилиты).
3. Пересборка выводимых разделов:

   ```powershell
   python <канон>\_meta\tools\matrix_sync.py --docs <docs> --write
   ```

   После команды: ожидается `✓ выводимые разделы пересобраны (ручные разделы и строки не
   тронуты)`. Отказ (`✗ --write отказывает, файл не тронут`) перечисляет причины — вернуться
   к шагу 1 или 2.
4. Ревью диффа матрицы до коммита: ни один ID из прежнего реестра не исчез (снятые — только
   строками «снят …»); связи только добавились или совпали; ручные разделы построчно прежние.
5. Самопроверка комплекта как обычно:

   ```powershell
   python <канон>\_meta\tools\selfcheck.py --docs <docs>
   ```

   После команды: строка `✓ выводимые разделы матрицы … (matrix_sync)` или ⚠ с перечнем
   расхождений; строки `i … сверка … пропущена` быть не должно.
6. MR; в описании — число добавленных связей и число строк, перенесённых в приложение или
   долги.

После перевода правка документов и `--write` идут в одном MR, матрицу руками не правят,
кроме ручных разделов и строк.
