# Сверка base-контрактов file-service: наши черновики vs опубликованные в docs-external-contracts

Дата: 2026-08-12. Контекст: при подготовке переноса черновиков из
`docs-file-storage/sandbox/extint-base-draft/` обнаружено, что каталоги
`cdn/` и `mflash/` во внешнем репо уже заняты опубликованными карточками
(master/trunk, работа владельца комплекта file-service). Наши черновики
создавались в изоляции прогонов и не видели репо. Ссылки «EXTINT-003-01…09»
из захода типа process оказались ссылками на эти реальные карточки.

## Вердикты механического гейта (--check --source, актуальный срез)

- Наши черновики: **9/9 mflash + 1 cdn — OK** (после дозахода).
- Их карточки: **9/9 mflash — БРАК** (4–6 красных позиций каждая).

Разбор их брака по классам:

1. **Потеря дословности §1 (реальная):** паспорт «Общая информация о
   методе» перефразирован и переименован под свой набор полей («Метод»,
   «Синхронность», «Направление»); утеряны лейблы источника («Название
   метода», «Alias», «Тип сервиса», «Тип метода») и в 8 из 9 карточек —
   ссылка «Документация» (swaggerhub). «Краткое описание» — пересказ.
2. **Частично ложный красный (наша сторона):** их шапка колонок
   «Параметр | Название параметра | …» — наш валидатор принимает колонку
   «Параметр» (техимена) за роль «название» и метит техимена как
   подозрительные. ПОПРАВКА (2026-08-12): канон фиксирует только
   «XML-элемент | Название | …» (писан с ЕСК-обменов) — шапки для
   REST/JSON канон НЕ задаёт; «JSON-элемент» в наших черновиках — такая же
   импровизация агентов, как их «Параметр». Дыра канона, требует решения.
   (Побочная находка по валидатору: слово «параметр» в заголовке
   матчится на роль «название» — источник двоения ролей.)

## ПЕРЕКВАЛИФИКАЦИЯ (решение пользователя, 2026-08-12)

Цель пилота — СКИЛЛ, генерящий правильный полный выход из исходников,
а не готовый выход. Слияние с их карточками отменяется; их выход —
diff-подсказка для поиска НАШИХ потерь. Найдено немедленно (пара 004
«Подготовка к загрузке»): источник — HTML-таблица запроса из 22 строк
с секционными строками («Заголовок запроса», «Тело запроса»,
«Блок параметров 1/2 — взаимоисключающие»); в нашей карточке
ОТСУТСТВУЮТ параметры `file_id`, `upload_token` (у них — есть), при
этом наш --check --source давал OK: гейт НЕ сверяет полноту
HTML-таблиц источника (только валидность колонок карточки и значения
готовых markdown-таблиц). Тихая потеря класса П-2 прошла оба гейта.

## Чем их карточки лучше наших

- Сцепка авторизации: «Авторизация: access-токен из EXTINT-003-01» —
  явная связь цепочки методов.
- Поля «Синхронность», «Направление» в §1.
- Examples парами запрос+ответ (у нас — 8 файлов на 10 карточек).
- «Где используется» — привязка к PRC/CTL/FUN расширенного комплекта
  (FUN-SYS-03 и CTL-003/004 существуют в их master-комплекте, вне нашего
  пилотного среза).

## Расхождения схем с каноном _meta

| Ось | У них | Канон _meta |
|---|---|---|
| ID base | `EXTINT-003-NN` (АС=003, метод суб-номером); cdn: `EXTINT-001` | `EXTINT-<AS>-NNN` |
| frontmatter base | `service: file-service` | base — без `service` |
| Имена файлов | `extint-003-01-auth.md` | `extint-<as>-NNN-<slug>.md` |
| Колонки параметров | `Параметр | Название параметра | …` | `JSON-элемент | Название | …` |

## Рекомендация

Вариант «слияние в их ID»: опубликованные карточки первичны (master =
акцепт, стабильность ID), наши черновики — материал обогащения:

1. MR в docs-external-contracts: дословный §1 (лейблы источника +
   «Документация»), выравнивание шапки колонок под канон, перенос нашей
   дословности таблиц (по --check), сохранение их сцепок
   (авторизация, синхронность/направление) и examples; `service:` из
   frontmatter base убрать.
2. Наши usage-карточки: шапки перевести с EXTINT-MFLASH-NNN /
   EXTINT-CDN-001 на их фактические ID и имена файлов.
3. Канон _meta: зафиксировать решение по схеме ID (легализовать
   иерархическую `EXTINT-<AS>-NN` как поколение или планировать
   переименование) — решение с владельцем карточек и руководителем.
4. Перед слиянием — построчная сверка пар 004/006/009 (расходящийся счёт
   параметров).

Наши черновики в sandbox/extint-base-draft/ до решения НЕ удалять — это
проверенный гейтом материал слияния.
