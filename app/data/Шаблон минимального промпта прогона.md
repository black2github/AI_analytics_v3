# Шаблон минимального промпта прогона (рабочий инструмент пилота)

Назначение: постановка захода агенту БЕЗ содержательных подсказок —
всё, что агент должен «знать», живёт в каноне и сторожах; промпт задаёт
только пути, изоляцию и тип захода. Подсказки из сверки эксперта
(«долги там-то», «имена такие-то») в промпт НЕ вписываются — это
маскирует несостоятельность скилла (урок 2026-08-15).

В канон не вносится (решение 2026-08-15: рано) — итерируется здесь.

## Переменные (правятся в одном месте)

| Переменная | Пилот (пример locks) | После пилота |
|---|---|---|
| {КАНОН} | `C:\doc-as-code\EAN\docs-o2new\_meta` | тот же / drcs-ai-toolkit |
| {РЕПО-ВХОДА} | `C:\doc-as-code\EAN\src-locks` | src-репо сервиса |
| {ВХОД} | `confluence\[БлокН2Н]-Сервис-блокировок-доступа-Н2Н\` | каталог выгрузки в src-репо |
| {РЕПО-ВЫХОДА} | тот же, что {РЕПО-ВХОДА} | ОТДЕЛЬНЫЙ рабочий репозиторий AI-aware артефактов |
| {ВЫХОД} | `docs\` | `<service-id>\docs\` целевого репо |
| {ВЕТКА} | `locks-run1` | ветка задачи |
| {SERVICE} | `locks` | service-id |
| {ТИП} | `data-model` / `function` / … | тип захода |

## Шаблон промпта захода

```text
Роль: технический писатель Doc-as-Code. Работаем строго по методологии.

ПУТИ:
- Канон методологии (ТОЛЬКО чтение): {КАНОН} — скиллы, шаблоны, утилиты; читай С ДИСКА.
- Репозиторий входа: {РЕПО-ВХОДА}; сырьё (только чтение): {ВХОД} (каталог raw\ — staging, НЕ источник).
- Репозиторий выхода: {РЕПО-ВЫХОДА}, ветка {ВЕТКА} (уже активна); комплект: {ВЫХОД} (существующие артефакты не перенумеровывать — «Повторный заход» create-artifact). Служебные файлы — только в sandbox\ репозитория выхода.

ИЗОЛЯЦИЯ: ветки не переключать, чужие ветки и trunk/master не смотреть, сеть не использовать, git-коммитов не делать. Прогон с нуля: структуры из прежних диалогов не переиспользуй.

ВВОДНЫЕ: service: {SERVICE}. [Опционально — РЕШЕНИЯ АНАЛИТИКА: тип/трактовка, принятые человеком решения. НЕ находки сверки.]

ЗАДАЧА: заход типа {ТИП} по соответствующему разделу выгрузки — строго по скиллу и шаблону типа (структура, дословность, долги, дозакрытие входящих долгов — всё по канону).

Самопроверка перед сдачей — по скиллу, включая механические гейты:
- python {КАНОН}\tools\normalize_tables.py --check --source <страница> <карточка> — по каждой карточке, вердикты ДОСЛОВНО, пары «карточка ↔ источник» перечисли в сдаче;
- python {КАНОН}\tools\link_debts.py --matrix {ВЫХОД}\traceability-matrix.md --docs {ВЫХОД} — вывод дословно;
- python {КАНОН}\tools\source_coverage.py --sources {ВХОД} --output {ВЫХОД};
- git status --porcelain — скоуп по белому списку типа.
Сдача: резюме до 10 строк + спорные места (вопрос / предположение / что проверить / рекомендация) + версия канона: вывод git -C <репо канона> log -1 --format=%h_%s.
```

## Шаблон промпта дозахода «по сторожам»

Дозаход НЕ перечисляет находки — агент сам читает сторожей:

```text
Роль: технический писатель Doc-as-Code. Дозаход по комплекту {ВЫХОД} (репозиторий {РЕПО-ВЫХОДА}, ветка {ВЕТКА}; канон {КАНОН} — только чтение, читай С ДИСКА; изоляция прежняя: ветки не переключать, сеть не использовать, коммитов не делать, служебное — в sandbox\).

ЗАДАЧА: прогони сторожей и закрой их флаги по правилам канона:
1. python {КАНОН}\tools\link_debts.py --matrix {ВЫХОД}\traceability-matrix.md --docs {ВЫХОД} — каждый флаг (просроченный долг, неисполнимый долг, порядок OQ, параметр без строки в dictionaries) закрой по соответствующему правилу create-artifact / шаблона типа-приёмника;
2. python {КАНОН}\tools\source_coverage.py --sources {ВХОД} --output {ВЫХОД} — непокрытое без документированной судьбы — долг;
3. по правленым карточкам — python {КАНОН}\tools\normalize_tables.py --check --source <страница> <карточка>.
Правки чужих для дозахода типов — только в объёме, санкционированном правилами (замена «имя → ссылка», строки долгов, разделы-приёмники). Сдача: вердикты сторожей ДО и ПОСЛЕ дословно + резюме до 8 строк + спорные места + версия канона.
```

## Хронология применения (пилот)

1. Оставшиеся заходы locks (6б, ПФ, vision+README) — по шаблону захода.
2. Репетиция воспроизводимости: mwqueue «с нуля» минимальным промптом,
   дифф с существующим комплектом.
3. Экзамен: src-inkasso-outgoing минимальными постановками — финальная
   валидация пилота перед тиражом.
