# Шаблон: вызовы чужих контрактов (contract-call)

См. [`conventions.md`](https://gitlab.gboteam.ru/ED/eco-techbook/-/blob/master/standards/analytics/conventions.md) §5.1.1. Карточка вызова (`CALL`) описывает обращение сервиса к ЛЮБОМУ контракту, которым он не владеет; карточка устроена одинаково, различается только владелец базового контракта:

- **внешняя (смежная банковская) АС** — базовый контракт `EXTINT-<AS>-NNN` в общем репозитории (контур A ниже);
- **другой сервис Экосистемы** — базовый контракт `INTC-NNN` в `internal-contract/` его комплекта (контур A не нужен);
- **платформенный метод с опубликованной спецификацией** — базовый контракт в документации платформы (без спецификации — запись `PLT`, не карточка вызова).

Два контура работ: **A. базовый контракт внешней АС** и **B. карточка вызова в сервисе**.

**Репозиторий базовых контрактов внешних АС:** [https://gitlab.gboteam.ru/EAN/docs-external-contracts](https://gitlab.gboteam.ru/EAN/docs-external-contracts)  
Ссылки на базовый контракт: в чужой репозиторий — **только абсолютные** URL GitLab на `master`; на комплект другого сервиса в ЭТОМ ЖЕ репозитории — относительные.

## A. Базовый контракт внешней АС ([docs-external-contracts](https://gitlab.gboteam.ru/EAN/docs-external-contracts))

```
# корень репо https://gitlab.gboteam.ru/EAN/docs-external-contracts
├── README.md                          # сводный реестр EXTINT-<AS>-NNN
└── <as>/                              # knosis | esk | tessa | f1 | bsk | sbp | …
    ├── extint-<as>-NNN-<slug>.md
    └── examples/
        └── extint-<as>-NNN-<сценарий>.<ext>
```

- **ID:** `EXTINT-<AS>-NNN` (нумерация с 001 внутри АС). Frontmatter: `id`, `type: external-integration` — **без** `service`.
- **`title`** — наименование из title главной страницы-источника дословно, **за одним исключением**: ведущий маркер контура-потребителя
  (`[O2+NEW]`, `[ОНБ_2021]`, `[КК_ВК]`, `[ББ_РЕГ]`, `[ГЭП]`, `[РЭП]`) не переносится — базовый контракт общий для всех потребителей и
  префикс одного из них не наследует (решение аналитика 2026-08-25). Имя системы в скобках (`[Файловый сервис] Банк: Функция выгрузки файла`) —
  часть наименования, снятию НЕ подлежит. Гейт знает оба случая: снятый маркер контура он принимает, снятое имя системы — брак.
- **§1–§5:** внешний контракт — без ENT/EXT сервиса, без OQ, без `docs/api/` сервиса.
- **§5:** таблица сценариев → sidecar в `examples/` (относительные пути). Сценарий описывают **в таблице §5 и в имени файла**; внутрь sidecar (JSON/XML/XSD/WSDL) комментарии сценария **не** пишут — только машинный payload/контракт.
- **«Потребители»:** сервис | локальный CALL-EXT-NNN | **абсолютный** URL на карточку вызова.
- **Ссылки источника на другие страницы Confluence** (например, «токен получен в методе …») — живой URL Confluence в карточку НЕ переносится. Текст-название ссылки всегда сохраняется дословно; чем заменить URL — три случая:
  1. целевая страница описана **base-карточкой этого же репо** (соответствие — по `confluence_page_ids` во frontmatter карточек) → относительная ссылка на неё (пример — строка `Authorization` в образце §2);
  2. целевая страница — **артефакт какого-либо сервиса-потребителя** (процесс, функция, сущность — документируемого сервиса или любого другого) → название текстом БЕЗ ссылки: base-контракт общий для ВСЕХ потребителей банка и на артефакты ни одного из них не ссылается (иначе карточка перестаёт быть переиспользуемой); связь с артефактами даёт карточка вызова каждого потребителя у себя;
  3. **карточки нет** (страница ещё не перенесена) → название текстом без URL + долг в open-questions потребителя С УКАЗАНИЕМ `confluence_page_id` целевой страницы (по нему проставление ссылки позже — механический поиск по frontmatter).
  Внешняя документация вне Confluence (swaggerhub и т.п.) переносится дословно.
- **Таблицы параметров (§2–§3) — канонический состав колонок:** `Код параметра | Наименование параметра | Тип | Обяз. | Кратность | Правила заполнения` (решение методолога 2026-08-12; прежние карточки с шапкой «XML-элемент | Название | …» — предыдущее поколение, не переконвертируются). Правила:
  - **«Код параметра» — полный технический путь от корня**: XML-элементы — через `/` (`ObjectBody/Context/…/ProcessGUID`), JSON-элементы — через `.` (`body.file_id`); иерархию не схлопывать до хвоста — по путям читается вложенность;
  - **в «Код параметра» — ТОЛЬКО технические имена источника**; бизнес-название в путь не включается — склейка вида `upload_token/Токен загрузки` разрывает обе колонки и есть брак (инцидент MFlash, 2026-08-12);
  - **узловые элементы-контейнеры и секционные строки источника** («Заголовок запроса», «Тело запроса», «Блок параметров 1 (применяется, если …)») — тоже строки таблицы (тип «контейнер»/«секция», формулировка условия секции — дословно в «Правила заполнения»); без них дерево параметров и взаимоисключающие блоки теряются;
  - **«Наименование параметра» — бизнес-имя из источника дословно**; сокращать («ЛК участника ВЭД» вместо полного) запрещено — литералы переносятся буква в букву (конвенции §4);
  - **«Кратность»** — `[1]` / `[0..1]` / `[0..N]` как в источнике;
  - **каждый параметр источника — строка таблицы**: перед сдачей число строк сверяется с источником; потеря параметра — худший дефект (тихая потеря требования);
  - источник — часто **сырая HTML-таблица с объединёнными ячейками**: разбор по [source-parsing.md](../tools/source-parsing.md) (сетка с раскрытием rowspan/colspan).

### Шаблон базовой карточки

````markdown
---
id: EXTINT-<AS>-NNN
title: '<дословное наименование из title главной страницы-источника>'
type: external-integration
confluence_page_ids: [<ID страниц-источников, главная первой; только reverse>]
---

# EXTINT-<AS>-NNN. <Краткое название точки обмена>

## 1. Краткое описание
| Поле | Значение |
|---|---|
| Внешняя система | … |
| Протокол взаимодействия | … |
| … | … |
| Где используется | Потребители — в разделе «Потребители» и в docs сервисов |

**§1 переносится дословно, не пересказом.** «Протокол взаимодействия» несёт
всё: канал/адаптер, сигнатуру вызова, упаковку (CLOB/XML), формат ответа,
ссылку на общий канал с другой карточкой, если он общий. Сжатие до одной
строки-сигнатуры — потеря (инцидент итерации 5: из описания выпали упаковка
XML в CLOB, формат ответа Receipt и общий канал с ESK-002).

**Состав строк-полей §1 — ДОСЛОВНЫЕ лейблы таблицы-паспорта ИСТОЧНИКА.**
У разных АС макеты паспорта разные («Тип сервиса» / «Тип метода» / «Alias» /
«Название метода» …) — лейблы переносятся как есть, к полям образца НЕ
приводятся. Перечень полей в образце выше — иллюстрация одного типового
макета, а не канонический список (инцидент MFlash 2026-08-12: лейблы
нормализованы под образец — гейт дословности красный при верных значениях).

## 2. Входные параметры

| Код параметра | Наименование параметра | Тип | Обяз. | Кратность | Правила заполнения |
|---|---|---|---|---|---|
| `ObjectBody/Context/CommonSegment/ProcessDetails` | Сведения о процессе | контейнер | Да | [1] | XML-обмен: сегменты пути через `/`; узловой элемент, вложенные — ниже |
| `ObjectBody/Context/CommonSegment/ProcessDetails/ProcessGUID` | Уникальный идентификатор процесса | GUID | Да | [1] | = GUID сессии проверки |
| `Тело запроса` | — | секция | — | — | JSON/REST-обмен: секционная строка источника |
| `Тело запроса.file_id` | Идентификатор файла | Строка (uuid) | Нет | [0..1] | JSON-обмен: сегменты пути через `.` (НЕ `/`) |
| `Authorization` | Заголовок авторизации | Строка | Да | [1] | Токен, полученный в методе [Аутентификация пользователя](extint-<as>-001-….md) — ссылка источника на страницу Confluence заменена относительной ссылкой на карточку этого репо |

### 2.N. <Название справочника из источника — как в источнике>

Каждый справочник кодов/значений источника (готовая markdown-таблица вне
HTML — например «Коды банковских продуктов») переносится подразделом §2
**целиком, со всеми колонками и строками, дословно**:

| Наименование | Код |
|---|---|
| Совершение отдельных видов операций на основании лицензий … | BROKERAGE |
| Корпоративные карты | CORP_CARDS |
| … (все строки источника, без сокращений) | … |

Порядок колонок — **как в источнике** (решение 2026-08-09: дословность,
целевое переформатирование — работа поздних слоёв, не миграции).

Сокращать справочник до одной колонки, до «первых N строк» или до «фрагмента»
запрещено: слова «фрагмент», «и т.д.», «см. источник» в подразделе —
признак потери (инцидент итераций 6-секст/6-септ: таблица «Коды банковских
продуктов» дважды ужималась до колонки кодов без пояснений).
````

## B. Карточка вызова (CALL) в сервисе

```
output/<service>/docs/srs/contract-call/
├── README.md                       # CALL-000: общий реестр вызовов (указатель на оба подкаталога)
├── external/                       # вызовы ВНЕШНИХ (смежных банковских) АС
│   ├── README.md                   # CALL-EXT-000: реестр внешних вызовов
│   └── call-ext-NNN-<slug>.md      # thin: ссылка на базовый контракт EXTINT + использование
├── internal/                       # вызовы ВНУТРИ Экосистемы (чужие сервисы, платформа со спецификацией)
│   ├── README.md                   # CALL-INT-000: реестр внутренних вызовов
│   └── call-int-NNN-<slug>.md      # thin: ссылка на INTC владельца / спецификацию платформы + использование
└── (нет examples/)
```

- **ID:** локальные `CALL-EXT-NNN` (внешняя АС) и `CALL-INT-NNN` (внутри Экосистемы); нумерация
  подтипов независимая, с 001 в каждом подкаталоге. Frontmatter: `type: contract-call`,
  `service: <service-id>`.
- Ссылка на базовый контракт: внешняя АС — **абсолютный** GitLab URL на base и examples;
  другой сервис Экосистемы — его `internal-contract/` (`INTC-NNN`; в этом же репозитории — относительная
  ссылка, в другом — абсолютный URL); платформенный метод — документация платформы. Базового контракта
  ещё нет (комплект владельца не мигрирован) — дословное имя + долг каноническим форматом.
- Раздел «Использование в сервисе …»: процессы, транспорт, маппинг ENT.
- Ссылки из FUN/SCR/PROC — на эту локальную карточку.

### README-реестры (CALL-000, CALL-EXT-000, CALL-INT-000)

Корневой `README.md` (`CALL-000`) — шапка-указатель «что здесь / чего здесь нет»:
здесь — только КАК сервис вызывает чужие контракты; описания самих интерфейсов —
у владельцев (внешняя АС → docs-external-contracts, сервис Экосистемы → его
`internal-contract/`, платформенный метод со спецификацией → документация платформы);
платформенные функции БЕЗ спецификации — `platform-functions.md` (граница —
conventions §5.1.2). Плюс указатель на оба подкаталога.

README подкаталогов (`external/README.md` — `CALL-EXT-000`, `internal/README.md` —
`CALL-INT-000`) — реестры своих карточек, колонки: ID | вызываемый контракт
(владелец) | базовый контракт | процесс/место в сервисе | карточка вызова.

## Приложенные артефакты (при наличии)

Если у страницы-источника есть не-markdown приложения (XSD/JSON-схема
контракта и т.п.) — карточка несёт блок «Приложенные артефакты» по
`attachments-block.md`: файл в `files/` рядом с карточкой, ссылка
обязательна, роль заполнена (дефолт для схемы — «нормативная схема
(структура)» с ограничителем рассинхрона).

## Чек-лист

### Base (внешняя АС)
- [ ] ID `EXTINT-<AS>-NNN`, папка `<as>/`, без `service:` во frontmatter.
- [ ] §1–§5 без ENT/data-model/OQ; examples в `<as>/examples/`.
- [ ] Sidecar (JSON/XML/XSD/WSDL): только payload; нет `# …` / `<!-- EXTINT-… -->` внутри файла; сценарий — §5 + имя файла.
- [ ] «Потребители» с абсолютными URL (или явно пусто до первой карточки вызова).

### Карточка вызова
- [ ] Раздел «Назначение» заполнен: владелец вызываемого, направление обмена, зачем сервису.
- [ ] Ссылка на базовый контракт: чужой репо — абсолютный URL; этот же репо — относительная; базового контракта нет — дословное имя + долг.
- [ ] Нет локального `examples/`.
- [ ] Для внешней АС: во внешнем репо обновлена строка «Потребители».
- [ ] Карточка лежит в своём подкаталоге (внешняя АС → `external/`, внутри Экосистемы → `internal/`) и зарегистрирована в реестре подкаталога.
- [ ] Матрица трассировки сервиса обновлена; FUN/SCR ссылаются на локальный `CALL-EXT-NNN`/`CALL-INT-NNN`.
