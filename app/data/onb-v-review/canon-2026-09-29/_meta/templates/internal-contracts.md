# Шаблон: контракты собственных методов сервиса (internal-contracts)

Постановочный уровень контрактов методов, которыми ВЛАДЕЕТ документируемый
сервис. «Internal» — относительно границы ЭКОСИСТЕМЫ ДБО, не сервиса:
здесь интерфейсы внутреннего контура Экосистемы; интерфейсы систем ВНЕ
Экосистемы — в репозитории
[docs-external-contracts](https://gitlab.gboteam.ru/EAN/docs-external-contracts)
(шаблон [`contract-call.md`](contract-call.md)).

**Два уровня описания контрактов (граница — как у модели данных):**

- `docs/srs/internal-contract/` — **ПОСТАНОВКА** (этот шаблон): что метод
  должен делать, семантика и состав параметров дословно из требований;
  зона аналитика, источник — Confluence.
- `docs/api/` — **РЕАЛИЗАЦИЯ**: OpenAPI/AsyncAPI, авто-выгрузка из кода;
  зона разработки (conventions §1, §5.1). Этот шаблон в `docs/api` ничего
  не пишет. Расхождение уровней — открытый вопрос команде; при переходе
  на api-first карточки — источник description-полей контракта.

## Состав каталога

```
docs/srs/internal-contract/
├── README.md                  # INTC-000: реестр методов сервиса
├── client/                    # контуры — по тем же правилам, что function/
│   └── intc-NNN-<slug>.md     #   Авторизация: Bearer token, роль Клиента
├── bank/
│   └── intc-NNN-<slug>.md     #   Авторизация: Bearer token, роль Банка
├── system/
│   └── intc-NNN-<slug>.md     #   Авторизация: Basic authorization (ТУЗ)
└── examples/
    └── intc-NNN-<сценарий>.<ext>   # sidecar: только машинный payload
```

Контур карточки определяется строкой паспорта «Авторизация:» (см. §1):
`Bearer token` → подкаталог по контуру роли (client/bank),
`Basic authorization` → system. Карточка INTC заводится ТОЛЬКО для
метода с признаками собственного эндпоинта (REST/URL/MQ); «метод» без
эндпоинта — библиотечная процедура (FUN-SYS, см. определитель
create-artifact), контракт ей не заводится.

- **ID:** `INTC-NNN` (по правилу выдачи ID conventions §5, реестр —
  матрица трассировки). Frontmatter: `id`, `type: internal-contract`,
  `service`, `confluence_page_ids`.
- Ссылки артефактов SRS (процессы, функции) НА карточку `INTC-NNN` —
  штатные (метод получает целевой артефакт вместо текстового упоминания).
  Карточка на процессы/функции НЕ ссылается: поведение — их предмет,
  трассировка «метод ↔ SRS» — в матрице (conventions §5.3 п. 7; до
  появления YAML операции в таблице «API ↔ SRS» — карточки INTC).
  Ссылки на сущности и справочники в правилах заполнения — по
  конвенциям §5 (точечная нотация ENT/EXT).

## Правила переноса (общие с базовыми контрактами)

Действуют дословно правила шаблона `contract-call.md` (контур A):
состав колонок таблиц §2/§3, разбор сырых HTML-таблиц нормализатором
(`--sidecar`), дословность §1 (лейблы паспорта ИСТОЧНИКА), секционные
строки, справочники целиком, замена ссылок источника на страницы
Confluence (три случая; целевые карточки ищутся и в этом каталоге, и в
`contract-call/`), сдача с ДОСЛОВНЫМ вердиктом
`--check --source` и эскалацией «НЕ ГОТОВО». Ключевые: «Код параметра» —
полный технический путь (XML — через `/`, JSON — через `.`), ТОЛЬКО
технические имена ИЗ ИСТОЧНИКА (склейка с бизнес-названием — брак);
каждый параметр источника — строка таблицы. **Источник технического
имени не даёт** (только «№» и русские наименования, либо плейсхолдер
вида `<ID "Клиент Банка">`): «Код параметра» остаётся ПУСТЫМ (валидатор
пустое допускает) + спорное место «технические имена появятся из
реализации/делта-захода»; номера строк, транслитерации и синтетические
пути (`1`, `3.1`, `ID.КлиентБанка`) НЕ выдумывать — суррогат хуже
пустоты (инцидент src-locks 2026-08-15); дословный плейсхолдер
источника переносится в «Наименование параметра».

<Таблица-паспорт с ДОСЛОВНЫМИ лейблами источника («Общая информация о
методе»: Название метода / Alias / Тип сервиса / Тип метода / Краткое

Строка **«Авторизация:»** в паспорте ОБЯЗАТЕЛЬНА (решение 2026-08-16):

системный вызов); оба сразу — НИКОГДА (финансовые операции по
логину-паролю недопустимы). Источник значение не даёт — допустимо
вывести по однозначному контексту вызова (метод вызывается клиентской
функцией с фронта → Bearer), но ВСЕГДА с открытым вопросом для ручного
подтверждения; контекст неоднозначен — значение пустым + открытый
вопрос (не выдумывать).
