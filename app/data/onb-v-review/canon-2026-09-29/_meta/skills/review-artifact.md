# Скилл: ревью артефакта

Проверить документ `output/` на соответствие конвенциям и шаблону, выдать вердикт и замечания. Документ **не править** — исправления отдельной задачей после решений аналитика.

Всегда действуют: роль и принципы `AGENTS.md`, конвенции [conventions.md](https://gitlab.gboteam.ru/ED/eco-techbook/-/blob/master/standards/analytics/conventions.md).

Скилл проверяет **соответствие конвенциям репозитория и шаблону**. Смысловое качество требований (критерии Вигерса, неопределённые слова) — скилл [`review-requirements-quality`](review-requirements-quality.md); консистентность набора документов — [`review-requirements-consistency`](review-requirements-consistency.md); интерактивная проверка пакета целиком — агент [`_meta/agents/requirements-reviewer.md`](../agents/requirements-reviewer.md).

## Вход

Путь к документу в `output/`.

## Шаги

1. **Формальные проверки** (conventions §5):
   - frontmatter: `id, type, service` заполнены; у файла-части составного документа (например `control/cards-*.md`) вместо `id` — `partOf` с `id` корневого файла, ровно одно из двух (§5); поле `status` не используется (§5); id по схеме;
   - имя файла — латиница, kebab-case; для нумерованного артефакта — `<id>-<название>.md`;
   - нет ссылок на sources/Confluence/код/классы; нет inline-TODO и черновых пометок;
   - ссылки на модель данных по правилу §5: первое упоминание сущности — полная ссылка `[ENT-NNN <название>](…)`, далее короткая `[ENT-NNN](…)`; голых ID без ссылок нет; атрибуты — точечной нотацией `[ENT-NNN](…).«Атрибут»`, в том числе в плотных формулах и дословных текстах (`«Атрибут»` без идентификатора сущности или идентификатор без ссылки — замечание);
   - язык русский, понятный бизнес-аналитику (жаргон — только с пояснением);
   - ПД в примерах обезличены.
   - **Ссылки на сущности** (conventions §5, forward-стиль): markdown-ссылки на `ENT`/`EXT` — `[ID полное название](path)`; запрещены сокращения вида `[ENT-NNN …]`, голый `ENT-NNN` / `EXT-NNN` без ссылки; атрибут — через `.`field`` после ссылки. Cross-ссылки между карточками `CALL` — текст включает ID и название из H1 целевой карточки.
   - **Трассировка** (conventions §5.3): документ отражён в `docs/traceability-matrix.md` (в корне `docs/`; реестр ID; для функции — заполненная строка покрытия); ID уникален.
2. **Чек-лист шаблона** (`_meta/templates/<тип>.md`, раздел «Чек-лист самопроверки») — пункт за пунктом, с вердиктом по каждому.
3. **Смысловые проверки**:
   - однозначность условий: условия ссылаются на конкретные коды справочников, а не словесные названия;
   - однотипные элементы описаны одинаковыми формулировками;
   - ссылки внутри комплекта живые (файлы существуют; якоря соответствуют заголовкам);
   - утверждения атомарны и проверяемы; нет противоречий между разделами документа.
4. **Отчёт аналитику**:
   - вердикт: `готов к review` / `готов к accepted` (решение — за человеком) / `требует доработки`;
   - замечания списком, каждое: **критичность (блокирует/не блокирует) | место | что не так | предложение**;
   - если замечаний нет — так и скажи, без придумывания мелочей ради объёма.
