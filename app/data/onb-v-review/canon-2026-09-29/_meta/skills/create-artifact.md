# Скилл: создать артефакт

Создать чистовой документ аналитики в `output/` по шаблону из `_meta/templates/`. Результат: чистовой документ, доведённый самопроверкой до готовности к ревью, + список спорных мест для аналитика. Поле `status` во frontmatter не используется (`conventions.md` §5).

Всегда действуют: роль и принципы `AGENTS.md`, конвенции [conventions.md](https://gitlab.gboteam.ru/ED/eco-techbook/-/blob/master/standards/analytics/conventions.md).

## Точка входа и протокол (диспетчеризация — однократная)

- **Если для типа существует специализированный скилл — точка входа всегда он.**
  Таблица: `rbac` → [`create-rbac`](create-rbac.md); `data-model` →
  [`create-data-model`](create-data-model.md); `function` →
  [`create-function`](create-function.md); `screen-form` →
  [`create-screen-form`](create-screen-form.md); `control` →
  [`create-controls`](create-controls.md); `process` →
  [`create-process`](create-process.md); `agent` →
  [`create-agent`](create-agent.md); `notification` →
  [`create-notification`](create-notification.md); `print-form` →
  [`create-print-form`](create-print-form.md); `contract-call` →
  [`create-contract-call`](create-contract-call.md);
  `internal-contract` →
  [`create-internal-contracts`](create-internal-contracts.md);
  `glossary` → [`create-glossary`](create-glossary.md); `vision` →
  [`create-service-vision`](create-service-vision.md) (после vision —
  [`create-docs-readme`](create-docs-readme.md)); `feature` →
  [`create-feature`](create-feature.md); `use-case` →
  [`create-use-case`](create-use-case.md); `business-rules` →
  [`create-business-rules`](create-business-rules.md); навигационный
  `docs/README.md` → [`create-docs-readme`](create-docs-readme.md).
- **Специализированный скилл исполняет шаги режимов A/B этого файла** со своей
  спецификой («Базовый поток — create-artifact» в его шапке означает именно это).
  **Повторный переход по таблице выше из специализации не выполняется** —
  диспетчеризация однократная, цикла нет.
- Типы **без** специализированного скилла (например, `platform-function`) —
  исполняй этот файл целиком.
- **Страница «метода» — определи её природу ДО выбора скилла** (в
  аналитике до-AI «метод» — три разные сущности; решение 2026-08-16):
  1. страница в разделе Интеграций / по формату интеграционного
     шаблона / контракт внешней АС → интеграционный метод: контракт →
     `external-integration` (репо docs-external-contracts), вызов →
     `contract-call/`; асинхронные (MQ) обмены — оба направления
     сообщений (целевая реализация — каталог `asyncapi/` рядом с `api/`);
  2. раздел «Методы» на ВЕРХНЕМ уровне каталога сервиса (рядом с
     Функциями, Контролями, Моделью данных, Процессами, Нотификациями,
     Интеграциями, Агентами) ИЛИ признаки собственного эндпоинта
     (REST/URL/MQ) → метод-как-СИСТЕМНАЯ-функция: поведение →
     `FUN-SYS` (create-function, режим «функция метода»), контракт →
     `internal-contracts` — INTC заводится ТОЛЬКО при признаках
     эндпоинта;
  3. «Методы» как ПОДкаталог функций, вызывается из шагов функций,
     эндпоинта/авторизации нет → БИБЛИОТЕЧНАЯ процедура: `FUN-SYS` с
     пометкой «библиотечная процедура; вызывается только из шагов
     функций комплекта»; параметры — таблицей единого формата, БЕЗ
     строки «Авторизация:»; карточка INTC не заводится;
  4. не подпадает под 1–3 — открытый вопрос (человеческий фактор в
     источниках легален), тип не выдумывать.

## Вход

- Тип артефакта (определяет шаблон: `_meta/templates/<тип>.md`; имена-исключения: `control` → `controls.md`, `feature` → `feature-spec.md`, `vision` → `service-vision.md`, `internal-contract` → `internal-contracts.md`; legacy-тип `external-integration` упразднён моделью CALL 2026-08-20 → `contract-call.md`; если шаблона для типа нет и он не в списке исключений — остановись и скажи об этом).
- Что описываем (сущность, функция, экран…).
- Режим: **reverse** (есть `sources/`) или **forward** (только требования).

## Режим A — reverse (восстановление из источников)

1. Прочитай шаблон типа целиком, включая чек-лист.
2. Собери источники (conventions §1): прочитай **`sources/README.md`**; если профиль не заполнен — создай по `_meta/templates/sources-readme.md` или запроси у аналитика. **Дочерние страницы — неразрывная часть родительской:** в выгрузке дочерние страницы Confluence лежат в каталоге `<имя-страницы>/` рядом с файлом `<имя-страницы>.md` (инвариант экспортёра) — собирая страницу, проверь её каталог. Дочернюю страницу, чей контент не входит в артефакт этого захода (другой тип, вне объёма), не бросай молча: долг в `open-questions.md` с её `confluence_page_id` («дочерняя единица страницы X не покрыта — требуется заход <тип>»). Механическая проверка покрытия — `_meta/tools/source_coverage.py` (миграционный гейт: действует, пока комплект строится из выгрузки; в delta/forward не применяется). Актуальная выгрузка Confluence — каталог из профиля, `<раздел>/` (навигация — через `index.md` в каждой папке). С кодом не сверяем (§5.1, исключения — §1); для экранов дополнительно — `sources/Figma-screen-designs/`.
3. Адаптируй содержимое страниц Confluence под формат шаблона. Фильтр: только новый сервис (§3); версия — актуальная, включая QR/СБП (§2).
4. Собери **список спорных мест** (не решай их молча):
   - противоречия между страницами Confluence;
   - дыры источника: незаполненные разделы, «На усм. арх.», битые включения страниц;
   - семантика, которую не удалось подтвердить (пометь как предположение).
5. Напиши документ **строго по шаблону**. Имя файла — `<id>-<название>.md` (conventions §5); `<название>` в слаге — краткий английский ПЕРЕВОД смысла (латиница, kebab-case), не транслитерация (инцидент mwqueue: `pomeshchenie-modalnogo-okna-v-ochered` против эталонного `enqueue-modal`). В документе запрещены: ссылки на sources/Confluence/код/классы, inline-TODO и пометки, поведение и прикладные контроли (их место — функции и `control/`). Frontmatter: `title` — ДОСЛОВНОЕ наименование из `title` главной страницы-источника, включая сервис-префикс в квадратных скобках (постоянный атрибут: при переименовании файлов в слаги это единственный носитель исходного наименования; для функций оно отражено в ролевой модели; в forward наименование задаёт аналитик); для README-реестров каталогов правило то же: `title` — дословно из страницы-оглавления раздела (она главная в `confluence_page_ids`; реестр несёт её ID плюс прочие страницы, чьим носителем является сам реестр, — покрытие выгрузки считается по этим ID, реестр без них оставляет оглавление «непокрытым»); собственный `title` — ТОЛЬКО у реестра без страницы-оглавления в выгрузке (`page_ids` пусты); расширенное наименование реестра, когда он шире оглавления, — в H1, не в `title`; `confluence_page_ids` — список ID страниц-источников из их frontmatter `confluence_page_id`, главная первой (только reverse; ID не выдумывать). Платформенность сервиса во frontmatter не пишется — она выводится из `service` по справочнику сервисов [`_meta/services.json`](../services.json) (поле `is_platform`; одноимённому полю frontmatter ВЫГРУЗКИ не доверять — оно экспортёрское; место справочника временное, до отдельного решения). Сервиса нет в справочнике — платформенность не выводить, спорное место аналитику.
6. Обнови **матрицу трассировки** `docs/traceability-matrix.md` (в корне `docs/`, conventions §5.3): реестр ID + связи артефакта. ID новых артефактов — по правилу выдачи conventions §5 (по реестру); перед сдачей сверь: дублей номеров нет, авансовых ID чужим типам в текстах не выдано.
7. Прогони чек-лист шаблона пункт за пунктом; исправь найденное. Не более **двух** итераций исправлений; пункты, не закрытые после второй, — в список спорных мест (молча не сдавать и не зацикливаться).
8. Выведи аналитику: резюме **до 10 строк** (какие файлы созданы/изменены, ключевые решения, число спорных мест) + список спорных мест, каждое в формате **вопрос / предположение / что проверить**, с твоей рекомендацией.
9. При коммите (только по просьбе аналитика): тема в **прошедшем времени**; если факты брали из `sources/` — в теле строка **«Откуда взяты факты:»** с перечнем (формат — [git-workflow.md](https://gitlab.gboteam.ru/ED/eco-techbook/-/blob/master/cookbook/analytics/git-workflow.md)).

## Режим B — forward (проектирование по требованиям)

1. Прочитай шаблон типа, включая раздел «Проектирование с нуля (forward-режим)».
2. Собери вход: бизнес-требования, процесс, функции. Пробелы — **списком вопросов аналитику/заказчику до начала проектирования** (перечень обязательных вопросов — в шаблоне).
3. Спроектируй артефакт по нейминг-конвенциям и паттернам шаблона.
4. Далее — шаги 5–9 режима A (коммит-шаг действует и в forward).

## Повторный заход (артефакт/комплект уже существует)

Существующий документ актуализируется, а не создаётся заново рядом:

- приводится к ТЕКУЩЕМУ шаблону типа (шаблон — с диска, якорь свежести);
- выданные ID (реестр в матрице трассировки) сохраняются — не
  перенумеровывать и не переиспользовать; новые артефакты получают ID
  по правилу выдачи `conventions.md` §5 (по реестру матрицы);
- содержимое переносится заново по источнику, а не «сохраняется как было»;
- удаление существующего артефакта — только по явному заданию аналитика.

## Границы скоупа (обязательны для всех типов и специализаций)

- **Свежесть методологии:** шаблон типа и правила читай С ДИСКА в начале КАЖДОГО захода, даже если уже делал такой тип раньше; собственные прежние скрипты и структуры из памяти диалога не переиспользуй без перечитывания шаблона (инцидент: прогон 3 file-storage — агент воспроизвёл старую структуру таблицы из контекста, игнорируя обновлённый шаблон).

- **Создавай ТОЛЬКО артефакты запрошенного типа.** Документы других типов не
  создавать ни полноценными, ни заглушками — даже если на них нужны ссылки
  или этого требуют гейты полноты комплекта.
- **Недостающая цель ссылки** (сущность, процесс, US/UC/фича, справочник…):
  оставь в тексте ДОСЛОВНОЕ имя цели (без выдуманного ID и без файла) и
  зафиксируй долг. Канонический формат строки долга в матрице (по нему
  работает механическое закрытие):
  `| <FROM-ID> | — | нет целевого артефакта <тип> «<дословное имя>» — требуется заход <скилл> |`
  — имя в «ёлочках» ДОСЛОВНО как упомянуто в тексте документа (иначе долг
  неисполним); для однофайловых типов без имени (rbac) имя опускается.
  **Цель принадлежит ДРУГОМУ сервису Экосистемы** (межсервисный долг) —
  владелец указывается в строке долга сразу после имени:
  `нет целевого артефакта <тип> «<дословное имя>» у владельца <service-id> — требуется публикация/миграция владельцем`
  — `<service-id>` по справочнику [`_meta/services.json`](../services.json);
  владелец неизвестен — в долге не угадывать, спорное место аналитику.
  Такие долги локальной просрочкой не сторожатся (цель — в чужом
  репозитории), исполнимость имени проверяется как обычно.
  В `open-questions.md` — запись той же формулой.
  **Все строки долгов живут в ОДНОМ общем разделе матрицы «Долги по
  ссылкам»** (плюс существующие тематические разделы, если они уже есть):
  новых разделов «на карточку» или «на заход» не заводить — раздел
  долгов один, растёт строками (решение аналитика 2026-08-19; прецедент:
  дозаход создал персональный раздел «Долги … (ссылки FUN-SYS-03)»,
  к полному прогону таких разделов стало бы десятки).
- **Закрытие входящих долгов (обязательный шаг каждого захода):** после
  создания артефактов найди в матрице долги, чьи цели — созданные тобой
  артефакты, и закрой каждый: в документе-ожидателе оберни КАЖДОЕ
  вхождение дословного имени ссылкой на карточку-цель, строку долга
  замени строкой связи. **Текст ссылки = ДОСЛОВНЫЙ текст упоминания в
  ЭТОМ документе, включая пунктуацию** — дозакрытие не меняет текст
  ожидателя: ID-префикс не добавляется, а правило «первое упоминание
  полное, далее короткое» действует только в авторских текстах
  шаблонов и на дозакрытия и дословные тексты источника НЕ
  распространяется. Нормализация «по каноническому имени» запрещена,
  даже если текст расходится с `title` карточки-цели (двукратный
  инцидент src-locks: точка «Агент.» из источника снималась при
  дозакрытии); расхождение написаний — вопросом в open-questions.
  Правка чужих для типа документов здесь САНКЦИОНИРОВАНА и ограничена
  заменой «имя → имя-ссылка». Механическая проверка — `_meta/tools/link_debts.py
  --matrix <матрица> --docs <docs>`: долгов с существующей целью — 0,
  имена всех долгов находятся в ожидателях дословно. Внешняя цель (другой
  сервис/репо): карточка у владельца существует — АБСОЛЮТНЫЙ GitLab URL;
  не существует — текст + долг.
- **Гейты достаточности BRD** (`conventions.md` §5.3 п. 8–9) исполняются
  ТОЛЬКО заходом [`create-brd`](create-brd.md) по уже готовому комплекту SRS;
  для остальных скиллов они — не блокер и не команда достроить комплект.
  (Инцидент: file-storage, прогон 1, 2026-08-10 — из задачи «функции» агент
  создал 45 файлов, включая весь BRD из несуществующих источников и модель
  данных под мораторием.)
- **Служебные скрипты и промежуточные файлы** — только в `sandbox/` рабочего
  репозитория; не в корень и не в `output/`.
- **Механическая самопроверка комплекта (обязательна перед сдачей):**
  единой командой `python _meta/tools/selfcheck.py --docs <корень docs>
  --sources <каталог выгрузки> --out sandbox/selfcheck.txt` (в
  forward/delta без `--sources`). Отчёт-файл пишет САМА утилита в
  UTF-8: собственные лаунчеры-обёртки и shell-редиректы вывода
  (`>` в PowerShell даёт UTF-16) не нужны и запрещены.
  Диспетчер САМ находит карточки комплекта, сопоставляет каждой
  страницу-источник по `confluence_page_id` и прогоняет все сторожа:
  связку нормализатора по каждой карточке, долги ссылок, порядок OQ,
  настраиваемые параметры; покрытие выгрузки — информационно. Каждый
  файл комплекта попадает в отчёт (✓/✗/⚠) — молчаливых пропусков нет.
  Строки ✗ и ИТОГО-вердикт (`OK`/`БРАК`) — в сдачу ДОСЛОВНО,
  переименование запрещено; не доведено до `OK` за две итерации —
  статус «НЕ ГОТОВО», дословный вывод в спорные места (приём с `БРАК` —
  только решением аналитика). Точечная отладка одной карточки при
  правках — `python _meta/tools/normalize_tables.py <карточка> --check
  --source <страница>`. Если selfcheck недоступен или падает целиком —
  СТОП и спорное место аналитику; самодельные обходы и собственные
  скрипты-обёртки запрещены.
- **Размещение карточек при подсервисной структуре** (conventions §3.1):
  путь карточки — `docs/srs/[<подсервис>/]<тип>/…`; сегмент подсервиса
  берётся ТОЛЬКО из таблицы «Разметка подсервисов» профиля src (§1.1) —
  без таблицы сегмент не используется, самодеятельные подкаталоги
  запрещены; общая часть сервиса — корень `srs/` без сегмента; зона
  «вне Экосистемы» в `docs/` не размещается (мини-комплект рядом,
  паспорт границы обязателен). Реестры типов — единые на сервис,
  с колонкой «Подсервис».
- **Механическая самопроверка скоупа (обязательна перед сдачей):** выполни
  `git status --porcelain` в рабочем репозитории. Каждый новый/изменённый
  файл обязан лежать в каталоге ЗАПРОШЕННОГО типа (для `function` —
  `docs/srs/function/` либо `docs/srs/<подсервис>/function/` при
  подсервисной структуре — сегмент по таблице разметки профиля,
  для `process` — аналогично, и т.д.), в
  `sandbox/`, либо быть `open-questions.md` / `docs/traceability-matrix.md`.
  Любой другой файл, СОЗДАННЫЙ ИЛИ ИЗМЕНЁННЫЙ ТОБОЙ в этом заходе, — УДАЛИ до сдачи (файлы, существовавшие до захода, не трогать); если содержимое ценно — перенеси
  суть цитатой в `open-questions.md` как долг («нет целевого артефакта…»).
  Сдача с файлами вне этого перечня — брак. (Инцидент: file-storage,
  прогон 2 — при заданном типе `function` созданы data-model, восемь
  процессов-заглушек и rbac; текстовый запрет специализация переиграла.)

## Правила обоих режимов

- Не выдумывай факты; предположения помечай и выноси аналитику.
- **Механический гейт закрывается ПЕРЕНОСОМ данных, а не упоминанием:**
  вписывать имя или значение источника в чужую строку/колонку документа,
  чтобы пройти проверку полноты, запрещено — это маскировка потери
  (инцидент 2026-08-14: имя параметра вписано в «Правила заполнения»
  соседней строки ради гейта полноты имён). Не переносимое по шаблону —
  спорное место / open-questions с честным «НЕ ГОТОВО».
- **Отсылка к источнику НЕ заменяет перенос содержимого** (экзамен
  inkasso, Э-7): строка «см. п. X» / ссылка на другую страницу
  ВЫГРУЗКИ — сигнал перенести содержимое цели (в эту карточку или в
  целевую карточку со штатной ссылкой на неё), а не оставить отсылку
  текстом. Отсылка без переноса легальна ТОЛЬКО когда цель вне выгрузки
  — и тогда обязателен открытый вопрос/долг. Пересказ и компрессия —
  та же потеря: шаги, условия, ветвления и структура переносятся
  дословно, «кратким изложением» раздел не закрывается.
- **CriticMarkup в источнике** (страница не прошла вливание правок —
  брак подготовки входа, но перенос не останавливает): сверка и
  перенос идут по ЦЕЛЕВОМУ тексту — вставки `{++…++}` /
  `<span class="critic-ins">` принимаются, удаления `{--…--}` /
  `critic-del` убираются, у замен `{~~а~>б~~}` берётся правая часть;
  префикс задачи «GBO-NNNNN:» — разметка, не текст. Сомнение в
  применимости правки — спорное место аналитику с идентификатором
  задачи и ОБОИМИ значениями (было/стало). Маркеры разметки в чистовик
  не переносятся (механический сторож).
- **Живое зачёркивание источника (`<s>…</s>`, `~~…~~`) — НЕ
  CriticMarkup:** это содержимое страницы; переносится с сохранением
  зачёркивания и пометкой «(зачёркнуто источником — неактуально)»
  (прецедент контролей inkasso), действующим текстом не считается и
  молча не выбрасывается.
- **Маркер выгрузки `%зачёркнуто%` — постфиксный:** зачёркнут
  ПРЕДЫДУЩИЙ фрагмент текста источника (значит — неактуален,
  аннулирован). В чистовик маркер не переносится — переносится
  семантика: `~~зачёркнутый текст~~` с пометкой «(зачёркнуто источником
  — неактуально)». Зачёркнутое НЕ принимать за действующее, а живой
  текст рядом — за отменённый (инцидент scr-cl-02: «Шаг № 3 исключается
  %зачёркнуто%» прочитано как «шаг исключён», хотя зачёркнуто само
  утверждение об исключении — смысл шага инвертирован). Маркер ищи
  грепом по `%зач` (обе буквы е/ё) — в длинных HTML-строках выгрузки
  глазами он теряется. Образец переноса:
  источник: `<strong>Шаг № 3 исключается %зачёркнуто%</strong>` + живой
  абзац «Вызывается метод …» →
  чистовик: `~~Шаг № 3 исключается~~ (зачёркнуто источником —
  неактуально).` + `**Шаг №3.** Вызывается метод …` (живой текст
  действует). Механический сторож чистовика — нормализатор.
- **Статусы прогонов и вердикты гейтов в чистовые документы не
  вписываются** (README-реестры, карточки, матрица) — их место отчёт
  сдачи и `sandbox/`; акцепт и статусы — вне документов (conventions §5).
- **Отчёты и промежуточные файлы пиши из Python с `encoding="utf-8"`** —
  shell-редиректы (`>`, `Out-File`) дают UTF-16/битую кодировку, отчёт
  сверки становится нечитаемым (повторившийся класс: sidecar, отчёты
  гейтов). Отчёт сверки в `sandbox/` обязан соответствовать ФИНАЛЬНОМУ
  состоянию карточек — после каждой итерации правок перегоняй и
  перезаписывай его.
- **Настраиваемый параметр, упомянутый в любом заходе** (`<сервис>.<ключ>`
  со страницы «Настраиваемые параметры» и т.п.), обязан существовать
  строкой раздела «Настраиваемые параметры» в `data-model/dictionaries.md`
  (conventions §5.2: параметры фиксируются вместе со значениями). Нет
  строки — ОБЯЗАТЕЛЬНЫЙ долг «параметр <ключ> не зафиксирован — требуется
  дозаход create-data-model»; значения вне выгрузки не выдумывать
  (семья «межтиповое содержимое позднего захода»: алгоритм → FUN-SYS,
  каталог статусов → dictionaries, параметры → dictionaries; механический
  сторож — `link_debts.py`).
- **Шаблонные фразы-указатели на другие разделы комплекта** (справочник
  статусов, глоссарий, контроли, статусная модель…) включаются в документ
  только если целевой раздел в комплекте СУЩЕСТВУЕТ или его понятие
  применимо к сервису по источнику. Раздел отсутствует/неприменим
  (например, «зависимость от статуса заявки» у сервиса без заявок) —
  фраза и пункт опускаются ЦЕЛИКОМ (без заглушки и без ссылки в никуда);
  сомнение в применимости — вопрос в open-questions.
- **page_id живёт ровно в двух местах** — frontmatter
  `confluence_page_ids` карточек и матрица трассировки (раздел
  источников, на время миграции). В ТЕКСТАХ open-questions, README и
  карточек page_id не пишется: страница источника именуется `title`
  ДОСЛОВНО + файлом выгрузки (`sources/…/страница.md`), покрытый
  артефакт — ID + название. Отчёт гейта покрытия печатает непокрытые
  страницы сразу в этом формате — копируй его, не добавляя page_id
  (механический софт-сторож в самопроверке).
- Открытые вопросы: сначала попытайся разрулить в диалоге; нерешённое — в `open-questions.md` комплекта (conventions §6). Отсылок к OQ в документах комплекта не делай. **Реестр OQ — append-only:** новая запись — строго В КОНЕЦ файла, номер — следующий свободный; правка существующей записи (решение, статус) — НА МЕСТЕ, записи не перемещать и не перенумеровывать (трёхкратный инцидент; механический сторож — `link_debts.py`).
- Артефакт акцептованным не помечаешь никогда — акцепт делает только человек, вне документа (`conventions.md` §5).
