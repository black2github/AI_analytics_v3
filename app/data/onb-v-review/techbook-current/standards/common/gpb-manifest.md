## Назначение

Файл `gpb-manifest.json`, расположенный в корне репозитория, содержит структурированную информацию о проекте,
его артефактах, контактных ролях и принадлежности команды. Он используется для автоматизации
DevOps‑процессов, каталогизации сервисов и поддержки команд.

---

## Корпоративные требования

При заполнении файла необходимо руководствоваться **общекорпоративными правилами ведения метаданных**,
опубликованными в Confluence.

Ссылка на общий регламент:
[Корпоративный регламент ведения gpb-manifest](https://confluence.int.gazprombank.ru/pages/viewpage.action?spaceKey=devops&title=Application+manifest)

### Стандартизированные значения

Во всех репозиториях должны использоваться следующие значения:

| Поле                  | Значение                                                       |
| --------------------- | -------------------------------------------------------------- |
| `automatedSystemCode` | "ECO"                                                          |
| `projectCodeDevOps`   | "ECO"                                                          |
| `jiraDevProject`      | Код проекта Jira стрима (переменная «Код проекта Jira стрима») |
| `confluenceUrl`       | <https://confluence.int.gazprombank.ru/display/DBOCORPES>      |
| `emailItLeader`       | email техлида команды                                          |
| `emailTechDevLeader`  | техлид или старший разработчик FE/BE                           |
| `emailOperations`     | "<eco_adm@gazprombank.ru>"                                     |
| `emailDevOps`         | "<eco_ops@gazprombank.ru>"                                     |

## Обязательные поля секции teamInfo

| Поле          | Описание                                                                                             |
| ------------- | ---------------------------------------------------------------------------------------------------- |
| `team`        | Ответственная команда                                                                                |
| `projectType` | Тип проекта: `ECO_BE` (backend), `ECO_FE` (frontend), `ECO_QA` (QA), `ECO_AN` (аналитика; docs-репо) |
| `platform`    | Является ли артефакт платформенным (`true` / `false`)                                                |

---

## Поля платформенных backend-микросервисов

Для артефактов с `teamInfo.platform: true`, `teamInfo.projectType: ECO_BE` и **корневым** `type`, не
относящимся к библиотекам (`configuration`, `plugin`, `library`, `generic`, `job`), в секции `teamInfo`
обязательны поля `layer` и `deploymentSegment`. Для уровня `Integration_Adapters` дополнительно обязателен
`externalSystem`.

Корневой `type` — поле `type` в корне `gpb-manifest.json`. В монорепозитории используется `type` первого
элемента массива `monorepository` (при отсутствии — `type` в корне манифеста).

| Поле                | Описание                                                                            |
| ------------------- | ----------------------------------------------------------------------------------- |
| `layer`             | Архитектурный уровень платформенного артефакта                                      |
| `deploymentSegment` | Сегмент размещения: DMZ, LAN или оба                                                |
| `externalSystem`    | Внешняя автоматизированная система (обязательно при `layer = Integration_Adapters`) |

### Допустимые значения `layer`

| Значение               | Описание                                                        |
| ---------------------- | --------------------------------------------------------------- |
| `Transport`            | Сервисы транспорта данных между сетевыми сегментами DMZ и LAN   |
| `Gateway`              | Единая точка входа и маршрутизация запросов                     |
| `Security`             | Аутентификация, авторизация, электронная подпись и криптография |
| `Dictionaries`         | Справочные данные и настройки                                   |
| `Platform_Services`    | Общие сервисы, предоставляемые бизнес-приложениям               |
| `Integration_Adapters` | Адаптеры к внешним автоматизированным системам                  |
| `Infrastructure`       | Инфраструктурные сервисы платформы                              |

### Допустимые значения `deploymentSegment`

| Значение  | Описание                             |
| --------- | ------------------------------------ |
| `DMZ`     | Размещение в демилитаризованной зоне |
| `LAN`     | Размещение во внутренней сети        |
| `DMZ/LAN` | Размещение в обоих сегментах         |

### Классификация корневого `type`

При проверке платформенных полей и формировании отчётов корневой `type` относится к одной из категорий:

| Категория    | Значения `type`                                        |
| ------------ | ------------------------------------------------------ |
| Микросервисы | `application`, `module`, `ui`, `static`                |
| Библиотеки   | `configuration`, `plugin`, `library`, `generic`, `job` |

Для платформенных backend-артефактов с типом из категории библиотек поля `layer` и `deploymentSegment` не
требуются.

## Правила ведения файла

### Расположение

Файл `gpb-manifest.json` находится в корне репозитория.

### Требования

- Валидный JSON
- Кодировка UTF‑8
- Актуальные контактные данные
- **Важно:** подход с монорепозиторием используется только когда сборка приводит к получению нескольких
  артефактов. В случае единственного артефакта избегаем подхода с монорепозиторием.

### Обновление

Файл обновляется при изменении:

- Контактных ролей
- Структуры модулей
- Путей документации
- Типа проекта
- Jira‑компонентов

---

## Ответственность

- За актуальность данных отвечают тех-лиды команды
- Платформенная / DevOps‑команда обеспечивает контроль корректности структуры
