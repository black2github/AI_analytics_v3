# Скилл: создать / обновить docs/README.md (навигация комплекта)

Создать или актуализировать `output/<service>/docs/README.md` — входную навигацию комплекта сервиса: с чего начать (Service Vision), кратко про клиентскую и банковскую части, карта обозначений CL/BNK/SYS и префиксов ID, границы, дерево разделов. Структура и чек-лист — шаблон `_meta/templates/docs-readme.md` (авторитет); живой пример — `docs/README.md` любого готового комплекта. Файл без frontmatter.

Всегда действуют: `AGENTS.md`, `conventions.md` §5 / §5.4. Структура и чек-лист — [`_meta/templates/docs-readme.md`](../templates/docs-readme.md). Коммит и push — [git-workflow.md](https://gitlab.gboteam.ru/ED/eco-techbook/-/blob/master/cookbook/analytics/git-workflow.md).

## Вход

- `service` (путь `output/<service>/docs/`).
- Режим `domain` — корневой README доменного репозитория (шаблон, раздел
  «Корневой README домена»): вход — корень репо; собирается таблица
  сервисов (`service-id`, Слот, Название, Вход) по фактическим каталогам
  комплектов и их README, строка режима глоссария («доменный» либо
  «доменный + указатели» — по факту наличия `glossary.md` в комплектах),
  ссылки на `domain-vision.md` и `glossary.md`; в README каждого
  комплекта домена — абзац «Сервис домена» (шаблон).
- Режим:
  - **create** — README нет или каркас пустой;
  - **sync** — README есть: привести к шаблону и актуальному дереву комплекта (после добавления разделов / переноса vision-glossary).
- Недостающее — спроси до начала.

## Границы

- **Не** переносить сюда полное содержание `service-vision.md` — только абзац «О сервисе» из 1–2 предложений + таблица контуров и ссылка.
- **Не** править комплекты других сервисов без явной просьбы (скилл вызывается для указанного `service`).
- `service-vision.md` и `glossary.md` — в корне `docs/` (не в `brd/` / `srs/`); если их ещё нет — в README **упомяни их словами без ссылки** («концепция сервиса и глоссарий ещё не заведены»), а в «С чего начать» веди в реестр SRS и матрицу; ссылка на несуществующий файл — битая, её ловит сторож относительных ссылок (✗). Отметь аналитику, что vision/glossary нужно завести своими скиллами; ссылки появятся при следующем sync.

## Порядок

1. Просканируй `output/<service>/docs/`: наличие `service-vision.md`, `glossary.md`, `traceability-matrix.md`, `brd/`, `srs/` (подразделы). Отдельно посмотри `output/<service>/nfr/`: ветвь НФТ показывай в «Как читать», «Разделы» и «Дерево» только если каталог есть, ссылкой `../nfr/README.md`. Каталог `api/` в
   комплекте не ожидается: контракты живут в репозитории кода; если он
   есть — это унаследованное состояние, в README его не описывай.
2. Возьми из `service-vision.md` (если есть): название сервиса, 2–4 предложения для «О сервисе», акторов для таблицы CL/BNK/SYS, формулировки границ.
3. Собери `docs/README.md` **строго по шаблону** [`docs-readme.md`](../templates/docs-readme.md): все обязательные разделы, порядок фиксирован.
4. В «Как читать», «Разделы» и «Дерево» — только существующие слои; нумерацию «Как читать» пересобери подряд.
5. «Условные обозначения» — самоописание комплекта для читателей и инструментов вне него; имена подразделов из шаблона не меняй. Собери раздел по факту: (а) префиксы — по `id`/`partOf` из frontmatter всех карточек: каждый встречающийся префикс (в том числе `INTC`, `LIBC`, `SM`, `NTF`, `CHD`, `PLT`) обязан быть в таблице типов, строки отсутствующих типов можно опустить; (б) статусная модель — назови её идентификатор (`SM-000` или `SM-<КОД>-000` на часть); (в) таблица «Подсервисы» — только у сервиса из частей, колонки «Код», «Каталог», «Название» по фактическим каталогам `srs/<часть>/`; (г) таблица «Поля frontmatter» — поля, которые реально встречаются в карточках (`title`, `confluence_page_ids`, у старых комплектов `version`); (д) подраздел «Долги по ссылкам» — только если в матрице есть такой раздел: правило чтения строки долга как поручения (формулировка, основание, адресат, приоритет, область) по шаблону, строки долгов сюда не копируются; (е) абзац о каталоге `tasks/` — только если каталог есть (постановки задач forward, не документы комплекта), текст по шаблону. Легенду контуров CL/BNK/SYS оставляй всегда (контуры не сужай). Проверка — сторож `selfcheck` «условные обозначения README» (⚠).
6. Прогони чек-лист шаблона; исправь найденное.

## Выход аналитику

Краткое резюме (создан / обновлён) + что взято из vision + какие разделы комплекта ещё отсутствуют в дереве + спорные места (**вопрос / предположение / что проверить**).
