# Фича: Регистрация и подтверждение телефона заявителя (F-CL-03)

*Реконструкция по комплекту SRS (reverse-from-SRS); не является требованиями заказчика. Трассировка на этот документ ловит рассинхроны последующих изменений; исходные ошибки SRS она не выявляет — документ выведен из него же.*

Связная способность: пользователь регистрируется в качестве заявителя и подтверждает номер телефона по СМС-коду. Сквозной сценарий — [UC-01](../use-cases/uc-01-open-account.md).

## US-03 — Регистрация и подтверждение телефона заявителя

Как пользователь внешней части сайта, я хочу зарегистрироваться по своим контактным данным и подтвердить номер телефона, чтобы мою заявку можно было связать со мной и продолжить оформление.

### Функциональные требования (EARS)

- FR-03.1 (event): Когда данные организации/ИП проверены и пользователь продолжил оформление, система должна открывать форму данных заявителя (фамилия, имя, отчество, мобильный телефон, email).
- FR-03.2 (event): Когда форма заявителя заполнена, согласие дано ([BR-03](../business-rules.md)) и проверки пройдены, система должна регистрировать пользователя и отправлять код подтверждения по СМС.
- FR-03.3 (event): Когда пользователь вводит код подтверждения, система должна завершать регистрацию пользователя.
- FR-03.4 (event): Когда время ожидания кода истекло, система должна позволять запросить новый код повторно.
- FR-03.5 (unwanted): **Если** код подтверждения введён неверно, **то** система должна показывать сообщение об ошибке и оставлять пользователя на форме подтверждения номера телефона.
- FR-03.6 (ubiquitous): Система должна требовать согласие на обработку персональных данных и принятие условий резервирования счёта до продолжения оформления ([BR-03](../business-rules.md)).
- FR-03.7 (unwanted): **Если** код с картинки введён неверно, **то** система должна показывать сообщение об ошибке у поля ввода кода и оставлять пользователя на форме данных заявителя.

### Критерии приёмки (Gherkin)

```gherkin
@FR-03.1
Сценарий: Переход к данным заявителя
  Дано данные организации/ИП заполнены и прошли проверки
  Когда пользователь подтверждает данные организации
  Тогда открывается форма данных заявителя: фамилия, имя, отчество, мобильный телефон, email

@FR-03.2
Сценарий: Регистрация и отправка кода
  Дано пользователь заполнил данные заявителя и дал согласие
  Когда пользователь подтверждает данные заявителя
  Тогда система регистрирует пользователя и отправляет код подтверждения по СМС на указанный номер

@FR-03.3
Сценарий: Подтверждение номера телефона
  Дано пользователь получил код подтверждения по СМС
  Когда пользователь вводит корректный код
  Тогда регистрация пользователя завершается и оформление продолжается

@FR-03.4
Сценарий: Повторная отправка кода
  Дано время ожидания кода подтверждения истекло
  Когда пользователь запрашивает код повторно
  Тогда новый код отправлен на тот же номер телефона

@FR-03.5
Сценарий: Неверный код подтверждения
  Дано пользователь получил код подтверждения по СМС
  Когда пользователь вводит неверный код
  Тогда отображается сообщение об ошибке, пользователь остаётся на форме подтверждения

@FR-03.6
Сценарий: Согласие не дано
  Дано пользователь заполнил данные заявителя без согласия на обработку персональных данных
  Когда пользователь подтверждает данные заявителя
  Тогда у поля согласия отображается сообщение об ошибке
  И переход к следующему шагу не выполняется

@FR-03.7
Сценарий: Неверный код с картинки
  Дано пользователь заполняет данные заявителя
  Когда код с картинки введён неверно
  Тогда отображается сообщение об ошибке у поля ввода кода, пользователь остаётся на форме
```
