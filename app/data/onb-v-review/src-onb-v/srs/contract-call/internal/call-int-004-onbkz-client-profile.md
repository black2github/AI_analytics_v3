# CALL-INT-004. [ОНБ_КЗ] Метод определения профиля клиента

**Базовый контракт:** [ОНБ_КЗ] Метод определения профиля клиента — постановка владельца (сервис ОНБ_КЗ) вне комплекта.

## Назначение

Сервис вызывает [ОНБ_КЗ] Метод определения профиля клиента (метод сервиса Экосистемы ОНБ_КЗ), чтобы по ОГРН из ответа подсказок определить, соответствует ли профиль клиента требованиям Короткой заявки.

## Использование в сервисе «Открытие 1-го счета и регистрация во внешней части сайта»

### Процессы

[PROC-001 Открытие счета с внешнего сайта](../../process/proc-001-open-account-from-external-site.md), шаг 1.9.1: определяется наличие ОГРН клиента в ответе DaData в поле suggestions.data.ogrn. Ответ метода сохраняется для анализа на шаге 2.12.1 "Исключающий шлюз данных (Профиль клиента соответствует требованиям Короткой заявки?)".

### Транспорт

Синхронный HTTP-запрос.

### Правила заполнения исходящего сообщения

| Параметр контракта | Правило сервиса |
|---|---|
| — | **Если** ОГРН есть,<br>**то** для входящих параметров метода берем ОГРН в ответе DaData из поля suggestions.data.ogrn.<br>**иначе** метод не вызывается, считаем, что профиль клиента не соответствует требованиям Короткой заявки |

### Обработка входящих ответов

| Параметр контракта | Правило сервиса |
|---|---|
| ответ метода | **Шаг 2.12.1:**<br>**Если** на шаге 1.9.1 метод не вызывался,<br>**то** переход на шаг 2.13.<br>**иначе** анализируем ответ метода:<br>&nbsp;&nbsp;&nbsp;&nbsp;**Если** метод вернул ответ "positive" (Профиль клиента соответствует требованиям Короткой заявки),<br>&nbsp;&nbsp;&nbsp;&nbsp;**то** переход на шаг 2.12.2<br>&nbsp;&nbsp;&nbsp;&nbsp;**иначе** (метод вернул ответ != positive или ошибку или сервер выдал ошибку таймаута) переход на шаг 2.13 |
