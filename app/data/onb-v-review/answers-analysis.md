## Разбор по ответам

### 1. ЗК-04 — три вида потерь, которых прибор не видит

- **Таблица из ссылок** («Макеты ЭФ», размерности xl/l/m/s/xs со ссылками): норма есть
  (шаблон ЭФ: «Макеты ЭФ» — README группы, ссылки Figma живыми URL). Прибор ячейки-ссылки на
  Confluence полнотой не считает, таблицу целиком без дословных значений не проверяет вовсе.
  → **Сторож ⚠ «таблица источника целиком не найдена»**: заголовки таблицы (и ключевые ячейки
  первой колонки) не встречаются в карточке и README группы.
- **Картинки** (23 изображения, ни файла, ни описания): норма волны 3 — блок приложений, долг
  «правило на изображении». Прибор отмечает только ячейки со смешанным текстом и картинкой.
  → **Сторож ⚠ «изображения источника ×N без следа в карточке»**: ни блока приложений, ни
  `files/`, ни долга «правило на изображении».
- **Элемент, чей текст есть в карточке в другой роли** (кнопка браузера «Обновить» из таблицы
  в одну строку): механически не ловится — значения на месте. → **Информационный перечень
  таблиц источника** (заголовок, число строк) в отчёте сверки — для приёмки: акцептующий видит
  «Описание кнопок Браузера (1 строка)» и проверяет раздел карточки.
- ПР-10 («опись до элементов») остаётся отклонённым: три сторожа закрывают названные виды без
  параллельной структуры. ПР-31 — без изменений.

### 2. ЗК-25 — дубли среди суб-ID

Пример: `CTL-015` (`cards-org.md`) и `CTL-034` (`cards-applicant.md`), одно название. Контроли —
H3-заголовки `CTL-NNN. <Название>` внутри файлов групп, у них нет title шапки, поэтому сторож
волны 6 (`title_uniqueness`, по frontmatter) их не видит. «Реестр ID» матрицы названия суб-ID
несёт (собирает `matrix_sync` из заголовков) → **сторож ⚠ по «Реестру ID»: одинаковые названия у
разных ID одного типа** (дубль ID остаётся ✗, как сейчас). Шаблон controls.md уже требует
«название уникально в документе» — норма есть, сторожа не было.

### 3. ЗК-40 — два умолчания у одного поля

Случай: «значение с другой ЭФ при переходе» + «Значение по умолчанию: Пусто» у FLD-4…14. Это
одно правило с ветвлением по форме §1 нотации, не два под-ярлыка:
`**По умолчанию:**<br>**Если** переход с [SCR-… «Ввод данных …»](…),<br>**то** = [SCR-…].«Поле»,<br>**иначе** пусто.`
Образец ветвления под «По умолчанию» в нотации §9 уже есть (один счёт в списке). → **В шаблон ЭФ
(§4 п.6) добавить этот образец и фразу: несколько источников умолчания — одно ветвление; новый
под-ярлык не вводится.** Новый ярлык не нужен; ЗК-40 → ИСПРАВЛЕНО.

### 4 и 8. ЗК-10 и ЗК-11 — чужие цели как долг на собственный заход

Факт: в комплекте до ревью не было ни ENT/EXT, ни формулы «у владельца». Чужие данные (ОНБ_2021,
справочники платформы, внешняя АС) — девять долгов «требуется заход create-data-model», чужие
методы — восемь долгов «требуется заход create-internal-contracts» и свободный текст «требуется
комплект сервиса …». Правило разбора адреса (ПР-33) к ЗК-11 не относится — причина в отчёте
переписывается, статус ЗК-11 → «исправлено частично» до волны 9.

Исправление одно на оба класса:

- **канон, `data-model.md:138`** — критерий владения из стандарта (ПР-27 ч.1): «данные, которыми
  владеет другой сервис — платформенный или нет; критерий — владение»;
- **канон, `create-artifact.md` (правило долга)** — перед долгом «требуется заход» исполнитель
  квалифицирует цель: своя → долг на заход; платформа → `EXT` в `dictionaries.md`, не долг;
  другой сервис → формула «у владельца <service-id>»; внешняя АС → карточка вызова, не модель
  данных. Владелец неизвестен — вопрос, не угадывать (это уже есть);
- **канон, `prompt-plan.md` шаг 2** — в «Отдельно выпиши»: данные и методы, которыми сервис не
  владеет, с владельцем (ПР-27 ч.2 — колонка владельца, не отдельный артефакт);
- **прибор, `link_debts` ⚠** — долг «требуется заход create-data-model / create-internal-contracts»,
  в имени цели которого есть код, ключ или название другого сервиса из `services.json` либо слова
  «справочник» / «подразделение» (для data-model): «проверить владение — формула „у владельца“
  или EXT». Только предупреждение: ложные срабатывания возможны, потеря цели — нет.

### 5. ЗК-14 — срез канона нигде не записан

шаблон `sources-readme.md` строки не задаёт, а `check_canon_cut` при её отсутствии молча даёт OK —
комплект без записи среза проходит как свежий. → **канон: строка `| **Срез канона** | … |` в
шаблоне профиля; прибор: ⚠ «в профиле нет строки „Срез канона“ — свежесть канона не
проверяется».** Хвост ЗК-14 закрывается.
