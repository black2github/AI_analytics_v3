## Ось 2. Модель вызовов: эталон уехал дальше конвенции

- **Конвенция** (решение 2026-08-20): плоский `contract-call/` с реестром `CALL-000`,
  карточки `call-NNN-<slug>.md`, ID `CALL-NNN`; базовые контракты внешних АС — только
  в docs-external-contracts (`EXTINT-<AS>-NNN`); свои методы — `internal-contract/`
  (`INTC-NNN`).
- **Эталон**: `contract-call/external/` (`CALL-EXT-NNN`, 14 карточек, реестр
  `CALL-EXT-000`) + `contract-call/internal/` (`CALL-INT-NNN`, 3 карточки: ЭП,
  файловый сервис ×2; реестр `CALL-INT-000`) + общий `CALL-000`. Схема ID и
  подкаталоги в конвенции не описаны.
- **Шаблон** contract-call.md: `docs/srs/contract-call/`, ID CALL + INTC — плоская
  схема конвенции.

## Ось 3. Нотификации: форма упаковки

Конвенция и шаблон — каталог `notification/` с реестром NTF-000 и карточками
`ntf-NN-<slug>.md` (события `NTF-NN.ENN`). Эталон — один файл `ntf-notification.md`
с id NTF-000 (весь состав в нём). У сервисов с богатой нотификацией (прецедент
[КК_ВК]: 3 канала, 14+ событий) один файл не масштабируется.

## Решения, требуемые от держателя канона (Р-1…Р-7)

- **Р-1. Имена 4 каталогов**: единственное (эталон) или множественное (конвенция+шаблоны)?
  Рекомендация: единственное — эталон раздаётся командам первым и уже тиражируется;
  новые типы конвенции и так в единственном; догнать конвенцию и шаблоны дешевле,
  чем переименовывать эталон и переучивать первые команды.
- **Р-2. Схема вызовов**: плоский `CALL-NNN` (конвенция) или `CALL-EXT/CALL-INT` с
  подкаталогами (эталон)? Рекомендация: эталонная — разделение видимо держит границу
  «внешняя АС / внутри Экосистемы» (ровно та классификация, где команды будут путаться);
  конвенцию дописать.
- **Р-3. Нотификации**: применить правило упаковки id/partOf — реестр NTF-000 обязателен,
  упаковка (один файл при малом объёме / каталог с карточками при большом) — вопрос
  физической нарезки. Зафиксировать в шаблоне и конвенции.
- **Р-4. OQ-реестр**: добавить в эталон `open-questions.md` с 1–2 образцовыми записями
  (формат §6) + шаблон-фрагмент. Гигиена должна быть видна в эталоне.
- **Р-5. Шаблон platform-functions**: создать в каноне (форму извлечь из эталонного
  `platform-functions.md` — обратное донорство).
- **Р-6. Донор-образцы** для agent / internal-contract / async — из вычитанных стендов
  (exam-run1, file-storage) в шаблоны (решение A2). После Р-1/Р-2.
- **Р-7. `RestApiTamplate.doc`** — убрать из templates/ или перенести в docs-репозиторий.
