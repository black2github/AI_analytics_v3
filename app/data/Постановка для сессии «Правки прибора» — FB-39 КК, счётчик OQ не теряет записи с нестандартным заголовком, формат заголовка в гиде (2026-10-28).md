# Постановка: selfcheck — счётчик классов OQ не теряет записи с нестандартным заголовком, формат заголовка — норма гида (FB-39 КК)

Дата: 2026-10-28. Для сессии «Правки прибора, акцепт и рутина». Коммит analyzer — по слову владельца; ветка канона —
по его командам. Источник: FB-39 КК (`feedback.md`, 2026-10-28), ответ владельца канона — там же.

## Проблема

`app/scripts/CI/kitcheck/checks/review_guards.py`, сторож B9 `oq_class_counter`: записи реестра `open-questions.md`
перечисляются регуляркой `_OQ_HEAD_RE = ^##\s+OQ-\d+\s*—\s*(\d{4}-\d{2}-\d{2})`. Запись с заголовком не по
формату не попадает ни в «всего», ни в классы статусов — молча. В КК таких 12: OQ-313 (даты нет), OQ-327…OQ-336
(дата «27.10.2026»), OQ-337 (дата «27.10.2026» и разделитель «-» вместо « — »); все открыты. Selfcheck печатает
«i OQ: всего 323, открыт 211», `link_debts` (регулярка `^##\s+OQ-(\d+)\b`) — 335 записей. Координатор на
свёртке 4.1 и классификации 4.5 недооценивает хвост на 12 вопросов. Формат заголовка в каноне не записан
(промпт координатора ссылается на «протокол, §8 п. 12» — такого пункта нет).

## Что сделать

1. **Перечисление записей** — по свободному заголовку `^##\s+OQ-(\d+)\b([^\n]*)$` (та же граница записи, что у
   `link_debts`); каноничность проверяется отдельно: `^##\s+OQ-\d+\s+—\s+\d{4}-\d{2}-\d{2}\s+—\s+\S`.
2. **Счёт статусов** — у всех записей, как сейчас (`OQ_STATUS_RE` по телу до следующего заголовка).
3. **Дата** для «открытых старше 30 дней» — из заголовка в любой из форм: `ГГГГ-ММ-ДД` либо `ДД.ММ.ГГГГ`; даты
   нет — запись в счёт «старше 30 дней» не входит и упоминается в строке ⚠ как «без даты».
4. **Строка ⚠** (рядом со строкой «i OQ: …», тот же сторож): «⚠ заголовки реестра OQ не по формату «## OQ-NNN —
   ГГГГ-ММ-ДД — …»: N — OQ-313 (нет даты), OQ-327…OQ-336 (дата 27.10.2026), OQ-337 (разделитель «-»)» — номера
   сжимаются в диапазоны по одинаковой причине; причина — первая из: нет даты / дата не ISO / разделитель не « — ».
   Нет таких записей — строки нет. ⚠, не i: запись терялась молча, это сигнал приёмке, не справка.
5. **Один дом регулярок:** если гейт переноса (CORE-20) или другие сторожа перечисляют записи OQ своей регуляркой —
   свести к одной функции в `review_guards` (прецедент `OQ_STATUS_RE`, Д-49 п. 3); проверить `transfer_gate.py`.
6. **Канон:** гид `_meta/migration/reference.md`, «Постоянные правила», пункт «Вопросы агентов к источнику — записями
   OQ-NN…» — одна фраза о формате записи: «заголовок `## OQ-NNN — ГГГГ-ММ-ДД — <формулировка>`, строка
   `- Статус: …` в теле; прибор печатает ⚠ по заголовкам не по формату». Промпт координатора, строка «формат —
   протокол, §8 п. 12» — заменить ссылкой на этот пункт гида. README прибора — строка B9.

## Ограничители

- Golden: отличия только у комплектов с нестандартными заголовками (КК: «всего 323 → 335, открыт 211 → 223» и
  новая строка ⚠); стенд, полигон, access-rules — построчно без изменений (проверить).
- Тесты (`tests/`, файл сторожей B-серии): (а) три формы заголовка считаются и попадают в классы; (б) строка ⚠ с
  диапазоном и причинами; (в) дата `ДД.ММ.ГГГГ` входит в «старше 30 дней»; (г) без нестандартных — строки ⚠ нет и
  вывод прежний байт в байт; (д) запись без строки статуса — «прочие», как сейчас.
- Живой прогон на КК (клон владельца, 3be5b4d): строки «i OQ: …» и «⚠ заголовки …» — в сдачу.
