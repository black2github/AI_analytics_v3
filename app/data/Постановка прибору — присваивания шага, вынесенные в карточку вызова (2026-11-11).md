## 1. Что случилось

Постановка 2.17 (второй комплект КК) переносит значения параметров вызова из шага функции в карточку
вызова: в шаге остаётся вызов со ссылкой на карточку, присваивания «параметр = значение» живут в разделе
«Правила заполнения исходящего сообщения» карточки. Это норма шаблона `contract-call.md` и решение
владельца 11.11: список присваиваний равноценен таблице привязки.

На образце прибор (канон 163062a) дал ✗, гейт КК — NOT READY:

```text
fun-sys-13-card-report-view.md, call-int-020-f1-card-operations.md, intc-001-card-view-report.md —
структура тел шагов расходится с источником (уровни/принадлежность): шаги №4 — тело шага переносится
КАК ЕСТЬ с ранговыми уровнями отступов ✗ НИЖЕ ПОРОГА
```

Причина — `kitcheck/checks/card_steps.py`, `check_step_body_structure`. Исключение «вынесено в карточки
вызова» (`_table_moved_to_calls`, решение 02.11) срабатывает только когда в теле шага источника стоит
ТАБЛИЦА. На странице 2166861010 шаг 4 — маркированный список из 8 присваиваний. То же повторится на
каждом методе тиража: функции FUN-SYS-14, 15, 16, 17, 35, FUN-CL-08, 40.

## 2. Принцип правила

Слов источника в признаке нет. Признак по форме: строка-присваивание «имя = значение». Определение
присваивания уже есть в приборе — `kitcheck/checks/call_algorithms.py` (сторож карточек вызова: строка
или пункт списка «<имя> = <значение>», условие значения «**Если** …, **то** = …» — тоже присваивание;
ярлык шага и переход на шаг присваиванием не считаются). Взять то же определение, второго не заводить.

## 3. Что сделать

1. В `check_step_body_structure` исключение «вынесено в карточки вызова» распространить на список
   присваиваний: тело шага источника содержит присваивания, тело того же шага карточки — ссылку на
   карточку вызова. Уровень — предупреждение, как у таблицы; текст строки называет, что вынесены
   присваивания, и карточки вызова по ссылкам.
2. Ограничитель, чтобы исключение не прощало потерю остального текста шага: извиняются только сами
   присваивания. Строки шага источника, которые присваиваниями не являются (условия перехода, обработка
   ошибок, вводная фраза вызова), должны остаться в шаге карточки — сравнение структуры для них остаётся.
   Если так сделать нельзя без большой правки — скажите в плане, какой ограничитель возможен.
3. `_CALL_LINK_RE` сейчас узнаёт только `CALL-EXT-NNN`, `CALL-INT-NNN`, `CALL-MOD-NNN`. Во втором
   комплекте идентификатор несёт слот: `CALL-BC-EXT-001`. Ссылку на такую карточку тоже узнавать (слот из
   2–4 заглавных латинских букв сразу после префикса). Проверьте, нет ли в приборе других мест, где
   идентификатор карточки вызова узнаётся только без слота, и назовите их в плане — чинить по моему слову.
4. Проверка полноты: если это дёшево — убедиться, что каждое присваивание шага источника есть в тексте
   группы сверки (ошибка печатается по группе из трёх файлов, включая карточку вызова). Если дорого —
   оставить, как у таблицы: «полноту правил проверить приёмкой».
