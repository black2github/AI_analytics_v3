# Команде common-dictionary: срез канона `147e7bd`, решения по FB-01 и FB-02

Дата: 2026-10-14. Передаёт владелец канона. Адресат — акцептующая миграции УЛ
(репозиторий `EAS/src-common-dictionary`, комплект `output/authorized-person`).

## Итог

Обе записи `feedback.md` закрыты, решения вписаны в сам файл (строки «Решение владельца канона»).

- **FB-02 — дефект прибора подтверждён и устранён.** Просрочка долга искала имя долга подстрокой
  в заголовке любой карточки любого типа, поэтому долг `data-model «Пользователь»` «находил» карточку
  функции `fun-cl-01-authorized-person-hint.md`. Воспроизведено на копии вашего комплекта: четыре
  ложных ✗ (ENT-003, SCR-BNK-03, SCR-BNK-04, SCR-BNK-08) → OK. Теперь цель долга считается
  существующей только у карточки с тем же заголовком целиком (с тегом `[…]` или без) и, если тип
  карточки известен по реестру матрицы, того же типа. Ваше решение не подставлять владельца и не
  переписывать FUN-CL-01 — верное: это был бы обход сторожа.
- **FB-01 — дефекта исполнения нет.** Нормативный образец карточки internal-contract — раздел
  «Образец заполненной карточки» шаблона `_meta/templates/internal-contracts.md`. Эталон O2+ карточек
  этого типа не содержит по составу своего сервиса; пополнение эталона отложено. Работа от шаблона —
  правильный путь, чужие комплекты образцом не служат.

## Что сделать

### 1. Принять срез канона

Из каталога репозитория сервиса, при клоне канона на `master` после `git pull`:

```powershell
git -C <путь к клону канона docs-o2new> pull --ff-only
```

Ожидается `master` на `147e7bd` (или новее).

```powershell
cd <путь к src-common-dictionary>; python <путь к клону канона docs-o2new>\_meta\tools\accept_canon.py --profile README.md
```

Ожидается строка `✓ срез канона: 811f487 → 147e7bd; профиль закоммичен` и три строки `✓ SF-0N`.
Утилита сама коммитит профиль; push делает команда. Если утилита перечислит замечания к комплекту
по новым сторожам, их нужно разобрать до следующего шага.

### 2. Перепрогнать приёмку FNK-01

Гейт на комплекте УЛ по обычной команде этапа; в отчёте ожидается исчезновение четырёх строк
`ПРОСРОЧЕН долг: цель существует (fun-cl-01-authorized-person-hint.md)`, дельта против baseline
`✗ 1 → 0`. Если это единственное отличие от прежнего прогона — этап принимается, миграция УЛ
продолжается по плану.

### 3. Закрыть записи в журнале

В `coordination-log.md` — запись «решение акцептующего»: срез `147e7bd` принят, FB-01 и FB-02
закрыты решениями владельца канона, FNK-01 перепрогнан (результат дословно: строка ИТОГО и дельта).
