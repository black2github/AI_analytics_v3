Дата: 2026-10-28. Постановка — «Постановка для сессии «Правки прибора» — критик снимает пункт списка, опустевший
после reject или apply, FB-40 КК (2026-10-28)». Исполнитель — сессия «Правки прибора, акцепт и рутина».
Analyzer не закоммичен — коммит по слову владельца. Бандл 1.9.15 — после второй постановки FB-40 (экспортёр),
по слову владельца.

## Итог

- Пункт списка, целиком состоявший из снятого маркера, теперь удаляется:
  - **Markdown:** удаляется строка, где стоял снятый маркер и остался один маркер списка (`*`, `+`, `-`, `1.`, `1)`),
    вместе с переводом строки.
  - **HTML-острова:** удаляется `<li>` без текста, картинки и таблицы, где сняли маркер; затем список, который
    опустел из-за этого.

  Работает и для reject (пункт из вставки), и для apply (пункт из удаления).
- **Живой прогон на КК** (срез 0e32b01 пересобран из raw: apply четырёх введённых задач, затем reject-all):
  - прежний критик воспроизводит срез 0e32b01 байт в байт;
  - новый отличается только снятыми пустыми пунктами: снято **87 строк-пунктов markdown на 18 страницах** и пустые
    `<li>` в HTML-островах на 70 страницах;
  - **все 5 пустых пунктов источника**, которые есть в срезе, сохранены;
  - на странице 2166861010 «ЭКО_Получение отчета по карте из Ф1» сняты те 8 строк, что унаследовала FUN-SYS-13.

## Что изменено (`app/scripts/CI/critic.py`, CRLF сохранён)

| Место | Изменение |
|---|---|
| `_apply_inline(…, hit="")` | на место каждого снятого маркера ставит метку `hit`; по умолчанию метка пустая — текст как прежде |
| `_drop_emptied_items` (новая) | обход снизу вверх. Строка с меткой, у которой после снятия меток остался только маркер списка, удаляется. Пункт остаётся, если следующая непустая оставшаяся строка отступлена глубже: у него есть потомки или продолжение. Метки снимаются все |
| `process_text` | порядок: HTML-острова → inline с меткой `\x00` (если такого символа в тексте нет) → снятие опустевших пунктов → таблицы. Удалённый пункт считается правкой |
| `_transform_html_island` + `_drop_emptied_li` (новая) | ближайший `<li>` каждого снятого span запоминается. После мутаций такой `<li>` удаляется, если в нём нет текста (`get_text().strip()`), `img` и `table`. Затем удаляется его `<ul>/<ol>`, если в нём не осталось пунктов, текста, картинок и таблиц. Пустые списки и пункты выгрузки без снятого маркера не трогаются |

Ограничители постановки:
- строка без маркера до обработки не трогается;
- любой остаток текста (символ, инлайн-код, ссылка) — строка остаётся;
- fenced-код байт в байт: пас по коду не заходит;
- родитель с непустыми детьми остаётся;
- идемпотентность: повторный прогон даёт 0 правок.

`migrate_confluence_tree.py` (сторож ПРОМ при выгрузке) вызывает тот же `process_text` и получает то же поведение.
