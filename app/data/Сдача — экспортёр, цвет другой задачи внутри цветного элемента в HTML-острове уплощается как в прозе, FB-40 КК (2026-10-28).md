# Сдача: экспортёр — цвет другой задачи внутри цветного элемента в HTML-острове уплощается, как в прозе (FB-40 КК)

Дата: 2026-10-28. Постановка — «Постановка для сессии «Правки прибора» — экспортёр, цвет другой задачи внутри цветного
элемента в HTML-острове уплощается как в прозе, FB-40 КК (2026-10-28)». Исполнитель — сессия «Правки прибора,
акцепт и рутина». Analyzer не закоммичен — коммит по слову владельца. Бандл 1.9.15 — вместе со сдачей «критик
снимает пункт списка, опустевший после reject или apply» — по слову владельца.

## Итог

В HTML-островах вложенный цвет другой задачи теперь уплощается по ТЗ п. 4.5 так же, как в прозе:
- один `<span class="critic-ins">` под ВНУТРЕННЕЙ задачей;
- зачёркнутый цветной черновик отброшен, зачёркнутый чёрный текст ПРОМ сохранён;
- запись `{"tasks": […], "confidence": "high"}` в отчёт, раздел «Уплощено: структурная вложенность».

**Живой прогон страницы 2166861010** (HTML с контура, офлайн, прибор `HEAD` против рабочего дерева на одном входе)
отличается одной строкой — ячейкой кратности totalAmount:

```
- <td><span class="critic-ins" data-task="DBOCORPESPLN-104756">[0..1]</span></td>
+ <td><span class="critic-ins" data-task="DBOCORPESPLN-118548">[0..1]</span></td>
```

Отчёт изменился так: «ручной разбор: 0 → 1 (уплощений 1)», в разделе «Уплощено» появилась запись «задачи
['DBOCORPESPLN-104756', 'DBOCORPESPLN-118548'] на «2166861010_ЭКО_Получение-отчета-по-карте-из-Ф1»». Остальной текст
страницы побайтно прежний. В raw КК (выгрузка 1.9.13) эта ячейка совпадает с выводом прибора `HEAD`.

## Что изменено (`app/content_extractor.py`, LF сохранён)

| Место | Изменение |
|---|---|
| `_flatten_nested_parts` (выделено из `_flatten_nested_critic`) | общая часть для обеих нотаций: задачи по глубине, запись в `_critic_report`, задача самого глубокого цвета, выживший текст (`_collect_flattened_text`). Код не дублируется |
| `_flatten_nested_critic` | текстовая нотация `{++внутренняя: текст++}` поверх общей части — вывод прозы прежний |
| `_flatten_nested_critic_html` (новая) | HTML-нотация: `<span class="critic-ins" data-task="внутренняя">текст</span>`, текст через `_escape_stray_tag_openers`, как текстовые узлы острова |
| `_process_nested_table_cell_content` | цветной элемент ячейки острова: `_has_nested_diff_color` → `_flatten_nested_critic_html`, проверка раньше смешанного зачёркивания и частичного перекрытия чёрным — порядок прозы (`_process_element`) |
| `_list_to_html` | то же для цветного потомка пункта и для пункта, цветного целиком (`<li style="color">`) |

**`_process_nested_table_to_html`** отдельной правки не потребовал: содержимое ячеек он рендерит через
`_process_nested_table_cell_content`. Строчные маркеры (`critic-row-*`) ставятся только для ячейки одного цвета
(`_cell_uniform_critic`), поэтому до уплощения такая конструкция не доходит.

**Признак 2** (примыкание зачёркнутого к чужой вставке, `confidence: medium`) в островах по-прежнему не действует:
это отдельное правило прозы, в постановку не входит.

**Видимость цвета** проверяется раньше, как и прежде: её делает `_critic_marker_for`, общий узел обоих путей.

**Огрубление ТЗ п. 4.5 не менялось.** Если пункт, цветной целиком, содержит вложенный цвет другой задачи, он
уплощается в один спан под внутренней задачей. Текст сохраняется, но вложенная разметка пункта (подсписок, жирный)
в маркере не воспроизводится — так же, как в прозе. Это видно в отчёте.

критику, по слову владельца: `build_bundle.py --check` → сборка. Запись «1.9.15» в `CRITICMARKUP_STATUS.md` — при

## Перед сборкой 1.9.15 — расхождение в поставке

`build_bundle --check` (только сверка) показал, кроме двух файлов FB-40, третий — `app/color_map.py`. Это ручная
незакоммиченная правка в самой поставке `confluence-tree-exporter`: синоним `"изменение"` для столбца «Описание»
таблицы «История изменений». В analyzer этой строки нет, и сборка из канона её затрёт. Нужно решение владельца:
перенести синоним в analyzer с тестом (рекомендация — набор синонимов только расширяется) либо отказаться от него.
