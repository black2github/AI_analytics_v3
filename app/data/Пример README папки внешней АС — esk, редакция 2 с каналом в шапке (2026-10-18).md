Здесь — базовые контракты АС ЕСК: точки обмена и форматы сообщений с параметрами, кодами
результата и примерами, одно описание на всю Экосистему.
Чего здесь нет: как сервис вызывает контракт — карточки `CALL-EXT-NNN` в комплекте
сервиса-потребителя (`srs/contract-call/external/`); маппинг на сущности сервисов; открытые
вопросы сервисов. Потребители контракта — в разделе «Потребители» его карточки.

## Как это выглядит в шапке карточки (для сверки)

```yaml
---
id: EXTINT-ESK-002
title: 'Проверка актуальности данных клиента в АС ЕСК'
type: external-integration
kind: operation          # operation | format
channel: online-adapter  # suv | online-adapter | rest | mq | file | kafka | postmessage
confluence_page_ids: [2184432919]
---
```

Отображение значения `channel` в README — по словарю шаблона (`suv` → «СУВ»,
`online-adapter` → «онлайн-адаптер», `rest` → «REST», …), чтобы в шапках был машинный ключ, а
в таблице — читаемое имя. Строки в таблицах сгруппированы по каналу в порядке словаря, внутри
канала — по номеру.

## Что сверить при чтении

1. Достаточно ли таблицы «О системе» из четырёх строк, или нужны ещё строки (владелец АС,
   контакт, ограничения доступа).
2. Группировка строк по каналу против простого порядка по номеру: по номеру проще сверять с
   корнем и с папкой, по каналу — ближе к задуманному «взгляду по каналам».
3. Название таблиц: «Точки обмена» и «Форматы сообщений» против «Реестр» одной таблицей с
   колонкой «Вид».
4. Нужна ли колонка «Синхронность». В примере её нет: это свойство карточки, видно в паспорте;
   если нужна в реестре, её тоже надо выносить в шапку полем, иначе утилите неоткуда брать.
