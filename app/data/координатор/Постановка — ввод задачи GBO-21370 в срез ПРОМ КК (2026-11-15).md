# Постановка — ввод задачи GBO-21370 в срез ПРОМ КК

Дата: 2026-11-15. От: сессия «Точки расширения эталона» (канон, нормы, приёмка).
Кому: сессия «Координатор КК». Слово владельца канона 15.11.2026 (в чате «Точек»): «вводим GBO-21370, отмечай в своем списке, что введена, передавай постановку». Запуск шага у координатора — как обычно, по слову владельца в чате координатора.

## Что не так

В карточке вызова второго комплекта CALL-EXT-BC-004 «Список платёжных систем» после шага 2.26 осталась строка `PAY_SYSTEM` и пункт списка «Расхождения с базовым контрактом»: в базовом контракте EXTINT-F1-027 такого поля нет, там `PAY_SYSTEM_NAME` и `PAY_SYSTEM_CODE`.

Причина — не контракт и не страница сервиса. Поля `PAY_SYSTEM_NAME` и `PAY_SYSTEM_CODE` добавлены задачей GBO-21370, а она в списке ввода (`sandbox/tail-intro-list.md`, строка № 3, первая запись истории 2022-07-04) стоит без отметки акцептующего и без тега `src/`. Слова владельца: задача введена в ПРОМ, её «потеряли и забыли указать, как введённую».

Факты на `origin/master` `8a42c113` (проверено «Точками» и сессией «Привязка API КК», только чтение):

- Страница 2184433383 «[РКО Ф1] DBLINK_Представление со списком платежных систем», `sources/raw`: строка 44 — `PAY_SYSTEM{++GBO-21370: _NAME++}` и `{++GBO-21370: Наименование ++}платежной системы`; строка 45 — новая строка 3 `PAY_SYSTEM_CODE | Код платежной системы | VARCHAR(65) | Да | Нет` с пометкой `+GBO-21370`; строки 51, 53, 54 — колонка `PAY_SYSTEM_CODE` и её значения в примере данных. Других страниц с разметкой GBO-21370 в выгрузке нет (5 вхождений, все здесь).
- В `sources/confluence` (чистый текст) этих вставок нет: задача не применена.
- Страницу 2184433383 несут два файла второго комплекта: карточка `docs-f1-integration/business-cards/srs/contract-call/external/call-ext-bc-004-payment-systems.md` и матрица комплекта.
- 30–31.10 (линия 1 доводки 5.3) содержимое задачи сняли с карточки как текст невведённой задачи; долг OQ-371 по ней закрыт после снятия. С тех пор задача учитывается только строкой списка ввода.
- Базовый контракт EXTINT-F1-027 (`docs-external-contracts`, `origin/trunk` `e18f441`), раздел «3. Исходящие параметры и коды результата»: строка 2 `PAY_SYSTEM_NAME | Наименование платежной системы | VARCHAR(32) | Да | Нет`, строка 3 `PAY_SYSTEM_CODE | Код платежной системы | VARCHAR(65) | Да | Нет`.

## Целевое состояние

1. В списке ввода строка GBO-21370 несёт отметку «введена в ПРОМ» с основанием: слово владельца канона 15.11.2026 (дату ввода владелец не называл — в отметке так и записать, дату не подбирать).
2. Задача применена к источнику штатным порядком итерации ввода (фаза 1 плана довозки хвоста, партия из одной задачи): чистый текст страницы 2184433383 содержит вставки задачи, тег `src/GBO-21370` поставлен.
3. Карточка CALL-EXT-BC-004 соответствует странице после ввода: поля представления и пример данных — по источнику с применённой задачей.
4. Строки карточки, которые после ввода совпали с базовым контрактом EXTINT-F1-027, записаны по норме шаблона карточки вызова (раздел B, свойства контракта живут в базовом контракте) — так же, как остальные строки этой карточки на шаге 2.26. Пункт о `PAY_SYSTEM` в списке «Расхождения с базовым контрактом» уходит, если расхождения больше нет; если после ввода расхождение осталось в другом виде — оно записано дословно.

## Что нужно

1. Отметка в списке ввода и ввод задачи — координатор, штатные шаги итерации ввода.
2. Правка карточки — исполнитель, одной веткой и одним коммитом на комплект; сверку карточки с контрактом повторить тем же способом, что в 2.26 (файл `sandbox/call-cleanup-wave1-call-ext-bc-004.md` дополнить, не переписывать прошлые строки).
3. Приёмка норм карточки вызова — сессия «Привязка API КК» (постановщик шага 2.26). Сверка на потерю содержания и итог прибора — «Точки», до push.

## Границы

- Вводится только GBO-21370. Задача GBO-29398 (страница «Счета клиента для корп. карт», поле `TYPE_CODE_CONTR_ACC`) по слову владельца 15.11 пока НЕ вводится: «после неё было много изменений; будем решать по ситуации». Её строку списка не трогать.
- Остальные строки списка ввода без отметки не трогать: по ним готовится отдельный список акцептующему.
- Базовый контракт EXTINT-F1-027 и его шапку (страница 2184433424 вне выгрузки) в этом шаге не править — отдельное решение владельца.
- Новых записей в журнал вопросов по этому расхождению не заводить: причина установлена.

## Что сдаётся

Одним сообщением «Точкам» до команды push: ветка и хеши; строка списка ввода дословно; что изменилось в чистом тексте страницы; дифф карточки; числа прибора по второму комплекту и по основному до и после (ошибок, долгов, гейт); что сверено чтением. Тег `src/GBO-21370` на сервер отправляет владелец — команду дать ему отдельным блоком.
