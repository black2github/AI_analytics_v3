## 2. Правки класса А (исполнитель)

### 2.1. Все четыре карточки: 011, 036, 037, 038

1. H1 — снять суффикс `[КК_ВК]` / `[КК_БК]` / `[КК_ЛК]`.
2. «Назначение», абзац «Владелец вызываемого контракта…»: «запрос XML в CLOB → ЕСК; ответ ← ЕСК сообщением типа ИО `Receipt` в CLOB» → «запрос — XML в CLOB в ЕСК; ответ — от ЕСК сообщением типа ИО `Receipt` в CLOB».
3. Таблица «Правила заполнения исходящего сообщения»: строку `…/QueryItem/Params/PRODOFF_CREDENTIALS_LIST` снять.
4. Таблица «Сопоставление входящего сообщения» — целиком по примеру v6 (одинакова во всех четырёх):

```markdown
| Параметр контракта | Куда записывается в сервисе |
|---|---|
| `Message/MessageHeader/*`, `Message/MessageBody/ObjectHeader/*` | не обрабатываются |
| `CL_PRIV_ESK_ID` | [EXT-001 Пользователь](../../../bc-component/data-model/dictionaries.md#реестр).«Идентификатор физического лица в ЕСК» |
| `<Is_Success>` | выходной параметр FUN-SYS-10 «Признак наличия у пользователя клиента возможности подписать данный документ (true/false)» |
| `<TopOfficial>` | выходной параметр FUN-SYS-10 «признак «ЕИО»» |
| `<ErrorCode>`, `<ErrorText>`; при ЗОК- без `Segment/Body/Text` — `ObjectBody/Receipt/Information/Description` | «Код ошибки», «Текст исходного сообщения» метода «[СпрОшибок] Метод получения текста ошибки для клиента» (метод `ESK_Authorization_Check`); выходной параметр FUN-SYS-10 «Причина отсутствия возможности подписать» |
| `CL_PRIV_POSITION` | выходной параметр FUN-SYS-10 «Должность пользователя» |
| `AUTORIZING_DOC/DOC_KIND`, `AUTORIZING_DOC/DOC_NUM`, `AUTORIZING_DOC/ISSUE_DT` (блок `AUTORIZING_DOC` — первая запись) | выходной параметр FUN-SYS-10 «Документ полномочий пользователя» |
| `Data/RelPerson/PersonInfo/ContactInfo/Phone` | приводится к формату Экосистемы («[ИО Клиент] Алгоритм приведения номера телефона к формату Экосистемы», внешнее описание в источнике); куда записывается — в постановке не задано |
| `CL_ORG_REJ_499`, `CL_ORG_REJ_115` | выходной параметр FUN-SYS-10 «Приостановления по 499-П и 115-ФЗ» |
```
