# Постановка — КК: переклассификация CALL-EXT-023 в собственный метод сервиса

Дата: 2026-11-18. От: сессия «Точки расширения эталона» (канон, нормы, приёмка).
Кому: сессия «Координатор КК». Запуск — по слову владельца в чате координатора.

Слово владельца 18.11 (в чате «Точек»): «CALL-EXT-023 - согласен на отдельный шаг переклассификации».

## Что не так

CALL-EXT-023 «ЭКО_Получение списка счетов клиента, к которым могут быть выпущены карты» (`docs/srs/bc-issue/contract-call/external/call-ext-023-eko-accounts-for-cards.md`, страница 2184433991) заведена карточкой вызова внешней системы с долгом «нет базового контракта». По содержанию это собственный метод сервиса:

- «Назначение» карточки: «ЭФ Клиента обращается к эндпойнту ЭКО …»; авторизация — Bearer Token (OAuth 2.0); привилегии вызывающего — функции самого сервиса (FUN-CL-45, FUN-CL-46);
- в спецификации сервиса есть операция `getIssuedCardAccounts` — `POST /business-cards/v2/issued-accounts` (`ECO_BE/ms-business-cards`, клиентская спецификация); в матрице, раздел «Покрытие: API ↔ SRS», она привязана к FUN-CL-45, FUN-CL-46;
- метод сам обращается к АБС Ф1: карточка CALL-EXT-021 называет его своим местом вызова («Шаг №4»).

Карточка вызова принадлежит потребителю чужого контракта; у собственного метода её быть не должно, а базового контракта во внешнем репозитории у него не будет никогда.

## Целевое состояние

По шаблонам `internal-contracts.md` и `function.md` и прецеденту шагов 2.28–2.31 (INTC-007…009 и функции FUN-CL-73…75):

- **Внутренний контракт** метода — карточка INTC в `docs/srs/bc-issue/internal-contract/client/` (авторизация по токену пользователя — клиентский контур): паспорт, параметры запроса и ответа, коды ошибок, примеры — дословно со страницы 2184433991. Каталог и README-реестр — по шаблону, если в bc-issue их ещё нет.
- **Функция метода** — клиентская функция (FUN-CL) в `docs/srs/bc-issue/function/client/`: алгоритм обработки запроса дословно; «Доступность» — по привилегиям, которые называет страница; строка «Входные и исходящие параметры — по контракту …»; шаг обращения к АБС Ф1 — ссылкой на CALL-EXT-021.
- **CALL-EXT-023** снимается: в реестре внешних вызовов bc-issue и в «Реестре ID» матрицы — строка «снят» с тем, чем заменён; ID не переиспользуется. Долг «нет базового контракта» по ней закрывается.
- **Ссылки.** SCR-CL-19 (три места), PROC-044, README контролей общей части, CALL-EXT-021 («Процессы» — точка вызова теперь шаг новой функции) ведут на новые карточки: экран и процесс — на функцию метода, текст подписи дословный.
- **Матрица.** `matrix_sync --write`; строка операции `getIssuedCardAccounts` в ручном разделе «Покрытие: API ↔ SRS» — по правилу привязки по коду привилегии; изменение строки согласовать с сессией «Привязка API КК» через координатора.
- **Опись.** Класс страницы 2184433991 — по фактическому дому.

Номера — следующие свободные по всем веткам (на master `22d24263` заняты INTC до 017 и FUN-CL до 75); исполнитель проверяет и называет в сдаче.

## Порядок и границы

- Сначала разбор страницы «Точкам» до правок: что уходит в контракт, что в функцию, что остаётся без дома (если остаётся). Раздел «Транспорт» страницы называет систему «АБС Ф1» — это слова источника; куда их отнести, решается на разборе.
- Текст источника не пересказывать и не дописывать; расхождение страницы со спецификацией (путь, параметры) — запись в журнал вопросов, не правка.
- Содержимое CALL-EXT-021 не менять, кроме раздела «Процессы».
- Шаг пересекается по файлам со срезом 3 шага 2.12 (SCR-CL-19) — ставить после него.
