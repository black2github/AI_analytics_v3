# Постановка PROM-5.3-CI: карточки вызова проверки и установки ЭП — по потребителям (разделение CALL-INT-001 и CALL-INT-002, переезд CALL-INT-003)

От сессии «Точки расширения эталона» (владелец канона), 31.10. Основание — решение владельца Д-53 (принцип: карточка вызова принадлежит потребителю; вызовы одной функции из разных подсервисов — отдельные карточки; общая часть — базовый контракт поставщика). Норма внесена в канон (`contract-call.md` §B, ветка `meta/call-card-per-consumer`, MR владельца). Координатору: оформить постановку исполнителю в `prompts/`, провести как мини-волну после G1/G3 (размер меньше G2); если лимиты недели не позволят до переноса — зарегистрировать как долг с ID карточек и сделать первым заходом после переноса. Матрицу и README-реестр правит координатор, карточки — исполнитель.

## Почему

CALL-INT-001 собрана из трёх страниц по одной на подсервис и лежит в `bc-component` как «общая», хотя содержание карточки вызова — привязка параметров к заявке своего подсервиса (ENT-019 лимитов, заявка на статус, заявка на выпуск). Версии расходятся по потребителям (v2.1 — только ВК и ЛК, v2.2 — только ЛК). Заголовок взял маркер поставщика «[ЭП]», карточка выглядит как базовый контракт сервиса подписи, которого у владельца нет. `page_id` трёх страниц просочился в тело («Вызов из PROC-007; страница-источник 2166859911») — это ошибка чистовика, не временное решение. Решение 30.10 «это вызов, а не функция сервиса» (OQ, FUN-CL-22/24/41/50 сняты) остаётся в силе.

Правила:

1. **Титулы** — дословно по title страницы-источника, маркер контура потребителя сохраняется (это карточка потребителя, не базовый контракт). Соответствие страница ↔ контур исполнитель берёт из строк «страница-источник NNN» прежних подразделов и сверяет по title страницы в `sources/confluence`.
2. **Тело** каждой новой карточки — её прежний подраздел дословно (таблица параметров, шаги) плюс общие разделы по шаблону карточки вызова: «Назначение» (вызов функции сервиса подписи — одна фраза, как в прежней карточке, без фразы «состав трёх вызовов идентичен»), «Использование в сервисе»: «Процессы» — только свой процесс (PROC-007 для ЛК, PROC-016 для БК, PROC-027 для ВК; для v.2.1 — свои функции/процессы из прежней карточки), «Транспорт» — как было («В постановке не задано»), «Правила заполнения исходящего сообщения» — таблица. Строка «**Базовый контракт:** ссылка не ставится — описания метода у владельца нет …» — в каждой карточке, долг прежний. Фраз «Вызов из PROC-NNN; страница-источник NNN» в теле **не остаётся** — `page_id` только во frontmatter.
3. **Frontmatter:** `id`, `title`, `type: contract-call`, `service: business-cards`, `confluence_page_ids: ['<одна страница>']`, прочее как в прежних карточках.
4. **Проверка дословности** каждой новой карточки против своей страницы: `normalize_tables.py --check <карточка> --source "<страница>"` — ✗ 0; затем selfcheck комплекта ✗ 0, `link_debts --strict` rc 0.
5. **Прежние файлы** `call-int-001-uni-server-ep-check.md` и `call-int-002-uni-ep-v21.md` удаляются (`git rm`). ID CALL-INT-001/002 не переиспользуются.
6. **Ссылки на новые карточки** (исполнитель, в тех же коммитах): `bc-limits/process/proc-007-accept-and-verify.md` (:37 диаграмма, :66–67 таблица шагов), `bc-status/process/proc-016-accept-and-verify.md` (:37, :66–67), `bc-issue/process/proc-027-accept-and-verify.md` (:64, :87), `bc-issue/function/client/fun-cl-42-request-ep-check.md` (:42), `fun-cl-56-request-ep-sign.md` (:43), `fun-cl-51-card-issue-spp.md` (:14), `bc-limits/function/client/fun-cl-23-universal-ep-spp.md` (:14, :175 — v.2.1 → CALL-INT-008), `bc-limits/function/README.md` (:44), `bc-issue/process/README.md` (:46), `bc-status/process/README.md` (:41), `call-int-003-uni-ep-v22.md` (:21 — ссылки на FUN-CL-21 и соседей проверить после переезда, относительные пути меняются), `srs/README.md` (:365–366 — строки реестра). ## Что не делать

- Не переписывать содержание таблиц параметров «под единый вид» — дословность по странице важнее единообразия между подсервисами.
- Не заводить базовый контракт сервиса подписи и не добавлять «Временный снимок контракта» — долг «у владельца отсутствует» остаётся.
- Не трогать CALL-MOD и bc-pin.
