## Что не так

Две страницы выгрузки несут требования, а карточек у них нет. В описи обе записаны классом «правила/стандарт ведения документации» (`doc-rules`) — это гипотеза описи, по содержанию она неверна. На страницы ссылаются шесть карточек; ссылка источника в них стоит текстом без цели (вопрос 1 перечня `sandbox/2.12-перечень-В-Г-Д.md`).

| Страница | Что на ней | Кто ссылается |
|---|---|---|
| 2166861161 «[КК] Правила преобразования текста для подсчета хеш по нему» (родитель «[КК] Библиотека модулей Сервиса», 109 строк) | назначение алгоритма; ограничения (4 пункта); преобразование (5 шагов); реализация на PowerShell; пример «входной текст — выходной текст» | SCR-CL-21, SCR-CL-16, SCR-CL-32 — «… и с учетом [КК] Правила преобразования текста для подсчета хеш по нему» |

## Целевое состояние

Тип и дом карточки определяет исполнитель по определителю `create-artifact` и шаблону типа; ниже — моё чтение нормы. Если определитель или скилл дают другое — перечнем «Точкам» до правок.

**Страница 2166861161.** Алгоритм без эндпоинта — библиотечная процедура: системная функция в `docs/srs/bc-component/function/system/` (образцы в комплекте — FUN-SYS-05…09), скилл `create-function`, шаблон `function.md` («Библиотечная процедура … эндпоинта и авторизации у неё нет по определению»). Текст страницы — дословно: назначение, ограничения, шаги преобразования, скрипт (блоком кода), пример. Если по источнику процедуру не вызывают шаги функций комплекта (её применяют при смене текста согласия) — так и записать по источнику, пометку «вызывается только из шагов функций комплекта» не ставить без основания; расхождение с шаблоном — «Точкам».

**Страница 2166861183.** Общее для сервиса правило показа результатов проверок — в документе контролей общей части: `docs/srs/bc-component/control/README.md` (CTL-000), раздел 2, после таблицы групп. Норма — шаблон `controls.md`: «Если источник задаёт общее для группы правило отображения результатов …, оно описывается … после таблицы, а не повторяется в каждой карточке». Таблица страницы переносится дословно под подзаголовком с её названием; страница добавляется в `confluence_page_ids` README. Скилл `create-controls`.

**Ожидатели.** После появления целей шесть карточек получают ссылки, текст дословный:
- SCR-CL-21, SCR-CL-16, SCR-CL-32 — на новую функцию (без ID в подписи: цель — функция);
- три карточки контролей ЭФ — на CTL-000 с ID перед текстом: `[CTL-000 [КК] Правила информирования пользователя Клиента об ошибках](…)` (цель — контроль).

**Реестры.** Строка функции в README функций bc-component и в матрице; опись — класс двух страниц по фактическому дому вместо `doc-rules`; `matrix_sync --write`.

## Порядок и границы

- Ветка от master (`22d24263` или новее), срез `af28475`. Проба — страница 2166861183 (перенос таблицы в README и три ссылки), приёмка «Точек», затем функция.
- Текст источника не дописывать и не пересказывать; дефект источника — вопросом в журнал.
- Номер новой функции — следующий свободный FUN-SYS; место в реестре — по правилам README.
