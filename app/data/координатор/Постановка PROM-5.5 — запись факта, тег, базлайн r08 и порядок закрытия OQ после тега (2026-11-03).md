## Г. Порядок закрытия OQ после тега (решение владельца 03.11)

Принцип: ответ на OQ не закрывает вопрос и не правит карточку; закрывает коммит одного из трёх каналов.

| Канал | Признак | Что делает координатор | Чем закрывается |
|---|---|---|---|
| источник | ответ меняет текст страницы Confluence | ждёт ввода: перевыгрузка страниц задачи → apply → тег → отчёт дельты → дельта-заход → ревью → приёмка (условие 5, шаг 6.2) | тегом ввода |
| комплект | текст источника не меняется, меняется классификация/структура/ссылки/наше решение | режим change: `tasks/<ID>.md` по шаблону канона `task.md` — ответ аналитика дословно строками T-NN, таблица затронутых карточек, умолчания постановки; волна исполнителя с fixlist (строка на OQ: класс, канал, коммит, статус) | коммитом захода |
| без изменений | ответ подтверждает текущее состояние карточек | — | записью «без изменений» со ссылкой на ответ |

Шаги:

1. Приём ответа: в запись OQ дописывается «Ответ: <дословно>, <кто>, <дата>»; статус — «ответ получен, разбор». Статус «закрыт» на этом шаге не ставится.
2. Разбор: координатор относит ответ к каналу и дописывает «канал: источник, задача <ID>» / «канал: комплект, tasks/<ID>» / «без изменений». Решение владельца 03.11 (развилка 2): разбор без приёмки владельца канона допустим только для «без изменений»; каналы «источник» и «комплект» — список на приёмку мне (сессия «Точки расширения эталона») партией, спорное — владельцу.
3. Идентификатор ввода без задачи Jira (решение владельца 03.11, развилка 1): временная норма — ID ввода `OQ-NNN`, тег `src/OQ-NNN`, пока Jira на миграции; при появлении задачи Jira — её ID, в записи OQ обе ссылки.
4. Закрытие: статус «закрыт: <дата>, <коммит/тег>, затронуто: <ID карточек>» (или «без изменений: <ссылка на ответ>»); в строке долга матрицы того же источника — приписка о закрытии (append-only); link_debts --strict и matrix_sync --check — в selfcheck.
