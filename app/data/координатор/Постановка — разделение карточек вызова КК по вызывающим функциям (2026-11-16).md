# Постановка — разделение карточек вызова КК по вызывающим функциям

Дата: 2026-11-16. От: сессия «Точки расширения эталона» (канон, нормы, приёмка).
Кому: сессия «Координатор КК». Слово владельца канона 16.11.2026 (в чате «Точек»): «одна карточка — одна вызывающая функция всегда. одинаковый набор параметров не гарантирует, что завтра ситуация не поменяется, и тогда не будет ясно, что с этим делать. Разделяем четыре карточки. Правим текст канона и сторож». Запуск шага у координатора — по слову владельца в чате координатора.

## Что не так

Четыре карточки вызова подсервиса `bc-component` несут правила нескольких вызывающих функций — отдельными таблицами с подписями «Вызов из …». Так они сложены в волне 2.17 (11–12.11) по правилу «Точек» «вариант б»: перечни параметров из шагов нескольких функций перенесены в одну карточку вызова метода адаптера. Это ошибка постановщика: норма шаблона «Карточка — полная инициализация одного вызова» (решение 02.11) требовала отдельных карточек.

Замер на `origin/master` `124096e5` (скрипт «Точек», только чтение):

| Карточка | Вызываемый метод | Точки вызова в карточке |
|---|---|---|
| CALL-INT-021 | INTC-BC-002 «РКО Ф1_Получение отчета по счету» | FUN-CL-68, FUN-CL-71 — наборы параметров одинаковые, правила свои |
| CALL-INT-022 | INTC-BC-003 «АБС Ф1_Получение списка счетов клиента» | FUN-CL-70; SCR-CL-09 — правил нет («в постановке не задано») |
| CALL-INT-023 | INTC-BC-004 «РКО Ф1_Получение списка карт клиента» | FUN-CL-69 (21 параметр), FUN-CL-72 (3 строки), FUN-CL-73 (2 параметра), FUN-CL-08 — отсылка к таблице «Вызов из FUN-CL-08» карточки CALL-INT-026 |
| CALL-INT-026 | INTC-BC-005 «РКО Ф1_Получение числа карт клиента» | FUN-CL-69, FUN-CL-08, FUN-CL-40 |

Итого одиннадцать точек вызова в четырёх карточках.

## Норма

- Шаблон канона `_meta/templates/contract-call.md`, раздел B, пункт «Карточка — полная инициализация одного вызова» — действует на срезе `68339c6`.
- Решение владельца 16.11 (в канон вносится отдельной веткой, в срезе КК его ещё нет): карточка — одна вызывающая функция. Правила заполнения и сопоставление входящего сообщения в карточке принадлежат одной точке вызова — одной функции (процессу, экранной форме или контролю, если вызов записан в них). У каждой вызывающей функции своя карточка с полным набором параметров, в том числе при одинаковых наборах. Подписи «Вызов из …» над таблицами разных функций и отсылка к таблице другой карточки — признак объединения. Общая функция, которая выполняет вызов с параметрами заявки подсервиса, второй точкой вызова не считается.

## Целевое состояние

1. У каждой из одиннадцати точек вызова своя карточка вызова: в «Процессах» одна вызывающая функция (экранная форма — для SCR-CL-09), в «Правилах заполнения исходящего сообщения» — правила только этой функции, без подписи «Вызов из …», в «Сопоставлении входящего сообщения» — только строки этой функции.
2. Строки правил и сопоставления перенесены из нынешних таблиц дословно, без правки текста ячеек. Ни одна строка нынешних карточек не потеряна: каждая стоит ровно в одной новой карточке.
3. Отсылка FUN-CL-08 в CALL-INT-023 («с заполненными ранее параметрами — таблица … карточки CALL-INT-026») сохраняет смысл источника и указывает на карточку вызова FUN-CL-08 метода «число карт клиента»; текст источника не дописывается.
4. Точка вызова SCR-CL-09 в CALL-INT-022: карточка с формулой «в постановке не задано» там, где источник правил не даёт (conventions §6 п. 5).
5. Шапка, `title`, `confluence_page_ids`, каталог и регистрация каждой карточки — по шаблону `contract-call.md` и скиллу `create-contract-call.md`: страница вызывающей функции — главная; подсервис — потребителя; реестр подкаталога и матрица обновлены.
6. Идентификаторы — по реестру матрицы. Рекомендация «Точек»: прежний идентификатор остаётся за точкой вызова, чья страница сейчас главная в шапке карточки, остальным — новые номера; так меняется меньше ссылок. Если норма conventions требует иначе — по норме, назвать в сдаче.
7. Ссылки на карточки исправлены во всех документах обоих комплектов: шаги функций и экранной формы, «Потребители» базовых контрактов второго комплекта (INTC-BC-…), карточки CALL-EXT-051…055 и прочие отсылки, реестры, матрица.

## Границы

- Текст правил не менять и не «улучшать»: шаг — раскладка существующих строк по карточкам. Дефекты источника (например, две строки `clientId` у FUN-CL-72) остаются как есть.
- Строки-агрегаты «параметры ответа» не раскрывать по параметрам.
- Коды параметров (шаг 2.42) и эти четыре карточки: порядок двух шагов — ваш; один файл с двух сторон одновременно не править.
- Карточки CALL-INT-003, CALL-INT-017, CALL-EXT-BC-003, CALL-EXT-BC-006 (одна страница параметров вызова, которую используют две функции) в этот шаг НЕ входят: по ним владелец решает отдельно.
- Новых исключений в сверку шагов прибора не вводить; если прибор даёт ✗ на новой раскладке — остановиться и написать «Точкам» с дословной строкой.

## Порядок и сдача

1. Сначала проба на одной карточке — CALL-INT-023 (четыре точки вызова): раскладка, идентификаторы, ссылки. Сдача пробы «Точкам» до тиража.
2. Тираж на CALL-INT-021, 022, 026 — после ответа «Точек» по пробе.
3. Сдача одним сообщением до команды push: ветка и хеши; таблица «прежняя карточка → новые карточки → вызывающая функция»; числа «строк правил и сопоставления до / после по каждой карточке»; перечень исправленных ссылок; числа прибора по обоим комплектам до и после (ошибок, долгов, гейт); что сверено чтением.
4. Приёмка норм и сверка на потерю — «Точки». Сессии «Привязка API КК» сообщите о шаге: в этих карточках её строки предупреждения сторожа свойств контракта.
5. Выкладка в целевой `docs-business-cards` — отдельным словом владельца.
