## Срез 2. Сначала перечень, потом правки: части В, Г, Д

Правок до принятого «Точками» перечня нет. Перечень — файл в `sandbox/`, строка на цель (В), на упоминание (Г), на строку прибора (Д): что это, где в источнике, класс, предлагаемое действие.

**В. 84 цели без карточки и без следа в матрице.** Класс на цель:

| Класс | Признак | Действие |
|---|---|---|
| Цель есть в комплекте | страница цели — главная или дополнительная страница существующей карточки (сверять по номеру страницы, не по буквам имени) | упоминание — ссылкой на карточку, текст дословный; у карточки вызова — с ID |
| Обзорная страница раздела | страница — контейнер по описи, её покрывает README-реестр каталога («[КК_БК] Функции Клиента», «[КК_ЛК] Функции Клиента» и подобные) | ссылка на этот README-реестр, текст дословный |
| Цель вне комплекта | чужой сервис, внешняя система, страница вне выгрузки или замороженная | строка долга по правилу долгов канона; если базовый контракт цели есть в `docs-external-contracts` — долг не заводится, решение «Точкам» |
| Не цель | ярлык источника с тегом `[DEV]` и подобные (18 целей: «[DEV] Код колонки», «[DEV] Пример сортировки/множественной сортировки Json» …) — не страница и не артефакт | комплект не правится; места — отдельным списком «Точкам» для сессии прибора |

Самая частая цель — «[ЭП] Сервис по работе с электронной подписью» (14 строк, в том числе строка «Базовый контракт» CALL-INT-003…017): класс «вне комплекта», одна строка долга на все ожидатели — если такой строки ещё нет.

**Г. 54 упоминания источника с тегом, не найденные в карточке.** Класс на упоминание, чтением страницы-источника и карточки:

|---|---|
| Текст зоны в карточке есть, упоминание потеряло тег или изменено | вернуть дословно |
| Зона источника перенесена в другой вид по записанному решению (матрица доступности обзорных страниц — формулой в разделе «Доступность» функции, шаги 2.10–2.11) | не править; в перечне — ссылка на решение |
| Зона в карточку не перенесена | потеря миграции — перенос дословно; объём — «Точкам» до правки |
| Упоминание — ярлык `[DEV]` (12 строк) | как класс «Не цель» части В |

41 строка из 103 — упоминания «Функции Клиента» и «Функции Банка» трёх подсервисов: разобрать на двух-трёх карточках, остальные — по образцу.

**Д. 14 строк «ссылка на ENT-… названием без ID».** Прибор принимает два вида: полная ссылка с ID либо дословное наименование источника с тегом. По каждой строке: что стоит в источнике. Если наименование с тегом — вернуть дословно; если текст авторский (шапка, указатель) — первое упоминание полной ссылкой `[ENT-NNN <название>]`.

## Срез 3. Имя существующей карточки без ссылки: часть Е

Отдельным словом владельца — объём большой: 822 вхождения в 137 карточках.

Норма та же («оберни КАЖДОЕ вхождение дословного имени ссылкой на карточку-цель»). Целевое состояние: каждое вхождение, которое называет прибор, — ссылка на названную прибором карточку; текст подписи — дословный текст вхождения; у цели-карточки вызова перед текстом ID.

Порядок: проба на одной паре с наибольшим числом вхождений («[КК_ВК] Заявка на выпуск карты» → ENT-007, 39 строк прибора) → приёмка «Точек» → тираж. Правка — скриптом исполнителя с сухим прогоном; diff пробы читается целиком.

Границы:
- не трогать `title`, заголовки, блоки кода и текст в обратных апострофах, таблицу «Происхождение», вхождение внутри уже существующей ссылки;
- вхождение, которое является началом более длинного упоминания другой цели, не оборачивать — в перечень «Точкам»;
- пара, где имя ведёт на карточку не того подсервиса или этапа («[КК_ВК] ЖЦ Заявки на выпуск карты и открытие счета» → PROC-045 и «… (Этап 1)» → PROC-022), — сверить с источником, какая страница имеется в виду, до тиража.
