## Пункт 1. Карточка вызова для формы «Отчеты»

Что есть (замер на src КК master `3884bff3`):

- `docs/srs/bc-component/screen-form/client/scr-cl-09-reports.md`, строка 418: «После успешного формирования файла отчета выполняется обращение к сервису «[Внешний файловый сервис] Выгрузка файла» с параметрами: …» — имя метода текстом, без ссылки.
- Карточка вызова этого метода в комплекте одна — CALL-INT-013, вызов с формы SCR-CL-04. Для вызова с SCR-CL-09 карточки нет, строки долга нет. Сторож упоминаний молчит: имя метода стоит в матрице строкой реестра CALL-INT-013.

Что нужно:

1. Сначала перечень «Точкам», без правок: страница-источник SCR-CL-09 (2166860428) — на какую страницу ведёт ссылка «[Внешний файловый сервис] Выгрузка файла» (ожидается 2169862959, как у SCR-CL-04), какие параметры вызова названы для отчёта по карте и для отчёта по счёту, откуда берутся значения.
2. Новая карточка вызова по скиллу и шаблону карточки вызова, правило «одна карточка — одна вызывающая функция»: `title` — название страницы-вызывателя и имя вызова через тире, как у CALL-INT-013. Строка «Базовый контракт» — та же, что в CALL-INT-013 после шага 18.11: спецификация `file-storage-external-openapi.yaml` владельца через `HEAD`, операция `downloadByPost` (`POST /filestorage/external/download`). Правила заполнения — дословно по источнику SCR-CL-09.
3. В SCR-CL-09 имя метода становится ссылкой на новую карточку с её ID в подписи; слова источника не меняются. Реестр внутренних вызовов, навигация `srs/README.md`, матрица — по обычному порядку.
4. Долг не заводится: источник в выгрузке, это незавершённая работа, а не долг.

Ожидание: карточек +1; долгов столько же; ✗ 0.
