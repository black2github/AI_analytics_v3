# Прибор — архитектура подключаемых проверок — подтверждено 2026-10-17

Дата: 2026-10-17. Сессия «Правки прибора, акцепт и рутина». Дополнение к плану «Прибор — анализ
структуры и план рефакторинга без изменения функционала»: требование владельца канона 17.10 —
прибор сразу модульный и гибкий, проверки разных типов и подходов подключаются без структурных
переделок. Кода по проекту нет; этап 0 (эталон отчётов) идёт параллельно.

## Решение

1. **Утверждение.** Прибор состоит из ядра и проверок. Ядро знает только интерфейс проверки:
   контекст на входе, находки на выходе. Какие проверки и в каком порядке запускаются, задаёт реестр
   — список, а не код прогона. Новая проверка — новый модуль и строка в реестре; ядро не меняется.
2. **Маркер.** Требование владельца канона 2026-10-17.
3. **Обоснование.** Замер 17.10: `selfcheck.run` — 513 строк, 25 ручных правок вердикта; уровень
   сигнала определяется по тексту строки; четыре формы ответа проверок; повторное чтение комплекта
   каждым сторожем.
4. **Операционное следствие.** Отчёт до байта тот же (эталон этапа 0); точки входа
   (`python <канон>/_meta/tools/selfcheck.py …`) и имена, которые зовут другие утилиты и тесты,
   сохраняются фасадом.
5. **Согласованность.** План этапов 2–4 переписывается под эту архитектуру; канон получает
   подкаталог пакета рядом с утилитами — в протоколе копирования и в `canon_delta` учесть.

## Устройство

| Часть | Что делает |
| --- | --- |
| `Finding` | Находка: уровень (`fail` / `warn` / `info` / `ok`), единица (файл, группа, комплект, репозиторий), заголовок, строки деталей. Рендер даёт ровно нынешний текст отчёта |
| `KitContext` | Контекст прогона, читается один раз и кэшируется: корень, `docs`, выгрузка, каталог сервисов, профиль (`strict`), перечень файлов, шапки, тексты, индекс источников, ID документов |
| `Check` | Интерфейс проверки: `id`, `scope` (file / group / kit / repo), `affects_verdict`, `profiles`, `applies(ctx, unit)`, `run(ctx, unit) → list[Finding]` |
| Реестр | Упорядоченный список проверок с профилем включения; порядок реестра — порядок отчёта |
| `Runner` | Проходит области по порядку, изолирует сбой проверки (как `_safe`: сбой — брак единицы, прогон продолжается), считает вердикт и счётчики ✓/✗/⚠ в одном месте, рендерит отчёт |
| Примитивы | Один модуль: шапка, блоки кода, ссылки, строки таблиц, обход файлов, якоря GitLab. Варианты поведения, которые сейчас расходятся (`~~~`), — параметром, выбор по месту сохраняется |
| Фасад `selfcheck.py` | Точка входа CLI и прежние имена (`run`, `read_frontmatter`, `page_ids`, `_kit_md`, `gitlab_slug`, регулярки для `transfer_gate` и `passport_sync`, функции `check_*` для тестов) |

Типы проверок, которые подключаются одинаково:
- проверка файла (сверка карточки с источником, колонные валидаторы нормализатора);
- проверка группы файлов (экранная форма из частей, документ контролей);
- проверка комплекта (реестр ID, матрица, обязательные разделы, шаг ↔ вызов);
- проверка репозитория (чистота корня, журнал координации, реестр замечаний);
- внешний инструмент как проверка (`link_debts`, `matrix_sync --check`, валидатор платформы) —
  обёртка, переводящая его вывод в находки.

## Как этапы ложатся на архитектуру

| № | Этап | Что появляется |
| --- | --- | --- |
| 0 | Эталон отчётов | снимок шести комплектов, прогоны, сравнение до байта |
| 1 | Примитивы | модуль примитивов, подключение по одному месту |
| 2 | Ядро | `Finding`, `KitContext`, `Check`, `Runner`, реестр; прежние проверки — через адаптеры, отчёт тот же |
| 3 | Перенос проверок уровня комплекта и репозитория | каждая — модуль с интерфейсом `Check`; `run()` превращается в реестр |
| 4 | Перенос проверок файла | `check_file` нормализатора → набор проверок файла в прежнем порядке |
| 5 | Однократное чтение | все проверки берут данные из `KitContext` |

## Что нужно подтвердить

1. Устройство (таблица выше) и уровни находок `fail` / `warn` / `info` / `ok`.
2. Пакет в каноне: подкаталог рядом с `selfcheck.py` (`_meta/tools/<пакет>/`), точки входа прежние.
3. Профили включения проверок (командный / полный) — в реестре, а не ветвлениями в коде.
