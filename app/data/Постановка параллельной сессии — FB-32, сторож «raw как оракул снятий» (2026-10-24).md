## Что проверяется (одна фраза)

Фрагмент, который в архиве `sources/raw` стоит под маркером **удаления введённой задачи**, не должен
дословно присутствовать в применённой копии той же страницы в `sources/confluence`. Если присутствует —
`⚠ raw-оракул: del-фрагмент <ID> со страницы <page_id> присутствует в применённой копии (<файл>:<строка>)`.

Почему это нужно: команда КК (FB-32) находила недоснятия вслепую, потому что нормализованная копия
теряет зачёркивания; raw несёт истинные пометки. Сторож делает чистоту apply проверяемой машиной.

## Определения

- **Введённая задача** — тег `src/<JIRA-ID>`, достижимый с HEAD репозитория комплекта
  (реестр введённых = теги; так считает `apply_history.py`). Получать `git -C <root> tag --merged HEAD
  "src/*"`; если git/тегов нет — проверка не выполняется, одна строка `i raw-оракул: введённых задач
  не найдено (теги src/*), проверка пропущена`. Ключ `--introduced <файл со списком ID>` — для прогона
  без git (тесты, стенд), по одному ID в строке.
- **del-фрагмент** — текст под маркером удаления задачи в raw-файле страницы, во всех трёх нотациях,
  которые понимает критик (`critic.py`: `_DEL_RE`, старая часть `_SUB_RE`, HTML
  `class="critic-del"`/`critic-row-del` с `data-task`, строки таблиц со столбцом `status` = `-ID`).
  Разбор маркеров — переиспользовать функции критика (`collect_task_occurrences`, `_split_fenced_regions`,
  `_find_table_islands`, табличный путь), не писать параллельный парсер.
- **Применённая копия** — файл `sources/confluence/<тот же относительный путь>` (соответствие по
  `confluence_page_id` во frontmatter, как в `index_sources` selfcheck; путь — запасной способ).
- **Присутствует дословно** — после нормализации обеих сторон: снять HTML-теги и маркеры CriticMarkup,
  раскрыть `&lt;/&gt;/&amp;`, схлопнуть пробелы, убрать пунктуацию по краям; сравнение без учёта
  регистра; фрагмент ищется как подстрока нормализованного текста копии. Порог длины: **не короче
  4 слов и 20 символов** — короче не проверяется (иначе шум на «Да», «Строка (100)» и т. п.); порог —
  константа с комментарием, не ключ.

## Ограничители на НЕсрабатывание (каждый — тест)

1. **Задача не введена** (нет тега) — её del-фрагменты не проверяются: в применённой копии они и должны
   быть (reject-all).
2. **Тот же текст вставлен другой задачей** — если нормализованный фрагмент встречается в raw той же
   страницы внутри `{++OTHER: …++}` / `critic-ins` введённой задачи, сигнала нет (текст законно вернулся).
3. **Внутри блока кода** (`_FENCE_RE` критика, правило трека «блоки кода») — маркеры там не действуют,
   не проверять.
4. **Внутри ячеек вложенных таблиц HTML-островов** — ограничитель из решения владельца (там маркеры были
   ненадёжны до 1.9.8): по умолчанию не проверять; ключ `--include-nested-cells` включает. В отчёте одна
   строка `i raw-оракул: пропущено del-фрагментов в ячейках вложенных таблиц: N`.
5. **Короткие фрагменты** (порог выше) — не проверять; считать в ту же строку `i`.
6. **Страницы без применённой копии** (архивные страницы, которых нет в `sources/confluence`, — напр.
   12 страниц КК, исчезнувших из выгрузки 1.9.13) — пропуск без сигнала, счётчик в `i`.
7. **Повторы** — один и тот же фрагмент на странице несколько раз → одна строка ⚠ с `×N`.

Порог ложных срабатываний для приёмки: на КК при 0e32b01 (четыре введённые задачи: 3716, 3969, 3846,
3633) ожидается **0 ⚠** — применённая копия только что пересобрана критиком из этого же raw. Если ⚠
есть — это либо дефект критика (ценная находка: разобрать и отдать в трек критика), либо дефект
нормализации сторожа (чинить). Каждый ⚠ первого прогона разбирается руками, вердикт — в сдаче.

## Где живёт

В `selfcheck.py`, рядом с проверкой источников (блок `index_sources` / `confluence_page_ids`), новый
блок «raw-оракул». Включается ключом **`--raw <каталог sources/raw>`** (по умолчанию выключен —
legacy-прогоны не меняются; `--sources` остаётся областью сверки, raw по-прежнему пропускается при
индексации — FB-21). Разбор маркеров и нормализация — отдельным модулем `app/scripts/CI/raw_oracle.py`
(функции: `collect_del_fragments(raw_file) -> list[Fragment]`, `normalize(text) -> str`,
`check_page(raw_file, applied_file, introduced) -> list[Finding]`), чтобы тот же модуль позже
использовался для режима карточек (ниже) и в протоколе скана снятия. Формат строк отчёта — как у
остальных проверок selfcheck (`✓/⚠/i`, итог в счётчиках; `--baseline` должен видеть новый класс строк
как обычные).

## Развилка для владельца (НЕ делать до решения)

**Режим карточек**: тот же оракул против `docs/` — del-фрагмент введённой задачи дословно присутствует
в карточке-потребителе страницы (`confluence_page_ids` во frontmatter). Это и есть «реальные недоснятия»
из FB-32 (карточки ISS-03 собирались до ввода 3633). На КК ожидаются десятки сигналов — поэтому не
в selfcheck по умолчанию, а отдельный отчёт `raw_oracle.py --cards <docs> --out <md>` для приёма ввода
задачи и DELTA-заданий. Рекомендация владельца канона — делать вторым срезом после приёмки первого,
тем же модулем; решение владельца пилота ожидается. В первом срезе — только заложить модуль так, чтобы
режим карточек не требовал переписывания.
