# Координатору КК: срез канона `c976739`, 98 строк раздела долгов старой формы, заголовки и протокол сдачи

Дата: 2026-10-15. Передаёт владелец канона. Репозиторий `EAS/src-business-cards`.

## Что изменилось в каноне (срез `c976739`)

Прибор `link_debts.py` теперь читает раздел матрицы «Долги по ссылкам» целиком и сторожит
каждую строку. Раньше строка, записанная не по формуле, молча пропускалась: долг числился в
матрице, но ни просрочка, ни исполнимость по нему не проверялись. Теперь такая строка даёт в
самопроверке предупреждение «строка раздела «Долги по ссылкам» не распознана», а в гейте переноса
в docs-репозиторий — блокер CORE-20. Признаваемые формы строки:

1. `нет целевого артефакта <тип> «<имя>» — требуется заход <скилл>` (при чужой цели — `… у владельца <код сервиса> — требуется публикация/миграция владельцем`);
2. `долг <вид>: «<формулировка>» — причина: …; ответственный: …; ограничение: …; закрытие: …[; источник: OQ-NNN]`;
3. `параметр <ключ> не зафиксирован — требуется дозаход create-data-model`;
4. пробел НФТ `| nfr-<код> | — | «<текст>» |`;
5. закрытый долг: во второй колонке ID появившейся цели вместо «—».

Код владельца в строке «у владельца …» сверяется с каталогом сервисов: кода нет в каталоге —
предупреждение.

## Что ещё в срезе `c976739` (волны 4 и 7)

- **Заголовки документов без названия сервиса.** Шаблоны концепции, глоссария и процессов
  теперь требуют H1 без имени сервиса («Концепция сервиса (Service Vision)», «Глоссарий»,
  «Процессы»); сервис задают поле `service` и путь комплекта. У КК заголовки `service-vision.md`
  и `glossary.md` содержат название сервиса — выровнять ближайшим заходом (правка одной строки
  в каждом файле, прибор пока не сторожит).
- **Протокол сдачи §8, п.14 и п.15.** В сдаче каждая ссылка на правило — с файлом и разделом,
  утверждение без адреса считается предположением исполнителя; в сдаче указывается модель
  захода (первые заходы нового типа — только сильная). Координатору: требовать оба пункта
  при приёмке.
- **Старшинство правил** записано одним разделом в `AGENTS.md` («Порядок чтения и
  старшинство правил»): стандарт ЭКО выше канона, канон выше образца; решение по открытому
  вопросу норм не меняет — отступление оформляется записью в `feedback.md`.
- Скиллы `create-brd` и `create-screen-form` получили шаги сверки (рабочая таблица
  «утверждение → место в SRS», сопоставление реестра полей с текстом) — действуют с
  ближайших заходов этих типов.

## Что это значит для комплекта КК

Прогон на комплекте КК (`docs/traceability-matrix.md`, 209 строк раздела): 98 строк не
распознаны. Это строки ранних заходов, записанные свободным текстом, в основном двух видов:

| Строк | Вид | Пример |
| --- | --- | --- |
| 51 | «нет карточки вызова …» | `нет карточки вызова АБС Ф1 для получения списка счетов клиента — требуется заход create-contract-call` |
| 36 | «нет записи PLT …» | `нет записи PLT «Контроли единых полей» п.1.1 — требуется заход create-platform-functions` |
| 11 | прочие | «нет целевых артефактов screen-form …», «отсутствует карточка вызова …», «параметры … упомянуты без значений …» |

Эти долги прибор не сторожит, и при переносе комплекта в `docs-business-cards` гейт их
заблокирует. Нужно привести строки к форме 1: тип и имя цели в кавычках.

## Что сделать

### 1. Принять срез канона

Из каталога репозитория сервиса, при клоне канона на `master` после `git pull`:

```powershell
git -C <путь к клону канона docs-o2new> pull --ff-only
```

```powershell
cd <путь к src-business-cards>; python <путь к клону канона docs-o2new>\_meta\tools\accept_canon.py --profile README.md
```

Ожидается `✓ срез канона: <прежний> → c976739; профиль закоммичен` и три строки `✓ SF-0N`.

### 2. Заход «нормализация раздела долгов»

Отдельный заход исполнителя без новых карточек: каждую строку раздела «Долги по ссылкам», не
подходящую под формы 1–5, переписать в форму 1 механически, не меняя смысла:

- `нет карточки вызова <имя> — требуется заход create-contract-call` → `нет целевого артефакта contract-call «<имя>» — требуется заход create-contract-call`;
- `нет записи PLT «<имя>» …` → `нет целевого артефакта platform-function «<имя>» — требуется заход create-platform-functions`;
- `нет целевых артефактов <тип> …` с несколькими целями → по одной строке на цель;
- `параметры <что> упомянуты без значений — требуется дозаход create-data-model` → по одной строке `параметр <ключ> не зафиксирован — требуется дозаход create-data-model` на каждый параметр.

Имя цели в кавычках «…» — дословно то, что написано в карточке-ожидателе: прибор проверяет,
что имя находится в документе дословно. Если дословного упоминания нет, строку не придумывать, а
завести вопрос в `open-questions.md`.

Проверка захода: самопроверка комплекта; ожидается отсутствие строк «не распознана» в блоке
«долги ссылок (link_debts)» и прежние счётчики ✗/⚠ по остальным сторожам. Отчёт — файл в
`sandbox/`, в сдаче — путь отчёта, строка ИТОГО и дельта.

### 3. Запись в журнале

В `coordination-log.md` — запись: срез `c976739` принят, заход нормализации долгов выполнен,
число переписанных строк.
