# Пакет волн после экзамена inkasso: нарезка и оценки

Дата: 2026-08-16. Источники: протокол экзамена (Э-1…Э-12, К-10,
Вх-1, наблюдения), NTF-очередь решений, ретро-хвосты. Порядок волн —
по принципу «методология раньше сторожей на неё; волны, отпирающие
контрольные дозаходы экзамена, — первыми». Оценки: S — до часа работы
(правки текстов, мелкая механика), M — 2–4 часа (тексты + сторож +
тесты + синк + перегоны), L — большой инструментальный блок с
калибровочным циклом.

## Волна A — «Методы и авторизация» (Э-12) — M

- create-artifact/диспетчер: дерево-определитель метода (4 ветви:
  интеграционный / системная функция / библиотечная процедура / OQ).
- internal-contracts (шаблон+скилл): строка «Авторизация:» (Bearer
  XOR Basic, оба — никогда; reverse: вывод по контексту + всегда OQ);
  критерий эндпоинта для заведения INTC; контурные подкаталоги
  client/bank/system (контур — из «Авторизации:»).
- function (шаблон+скилл): «Доступность» обязательна — CL/BNK всегда
  с привилегиями/правами, формула SYS «Системная функция; вызов с
  ТУЗ; роли и привилегии не применяются»; пометка «библиотечная
  процедура; вызывается только из шагов функций комплекта»; правило
  контура дополнено сигналом привилегий.
- Сторож-WARNING «FUN-CL/BNK без упоминания привилегий в Доступности»
  (не брак; подсветит старые комплекты — принято как честный долг).
- Проверка: контрольный дозаход экзамена — переклассификация INTC-001
  в FUN-SYS-процедуру (снятие карточки по заданию, долга-390,
  перекладка ссылок) минимальным промптом.

## Волна B — «Единый формат таблиц параметров» (Э-10 + Э-11 + К-10) — M

- Шаблоны function и internal-contracts: канонический состав колонок
  «№ | Код параметра | Название параметра | Тип | Обяз. | Кратность |
  Правила заполнения/Описание»; номерная вложенность уровней (1, 1.1);
  правило разборки сетки нормализатора (лесенка colspan-уровней → одна
  колонка «Название» + номера; протяжку не переносить); «Код
  параметра» ведётся ПУСТЫМ при молчании источника (суррогаты не
  выдумывать); правило-строка для динамических наборов («Все значения
  бизнес-полей…» — правило, не параметр, с явной пометкой).
- К-10: сторож дублей непустых заголовков в шапке таблицы карточки.
- Проверка: дозаход fun-cl-03/18/20 (переформат) — тем же контрольным
  прогоном, что волна A.

## Волна C — «Модель ЭФ, этап 1» (Э-9) — S/M

- Шаблон screen-form: нормированный словарь статик-ярлыков FLD
  (Видимость / Формат-маска / Предзаполнение / Подсказка / Поиск /
  Сортировка / Доступность / Логика установки значения) — голым
  условиям без ярлыка не место (пример FLD-14 «Светофор»); правило
  «Атрибут = элемент данных: поля разных форм с одним атрибутом —
  представления одного элемента; расхождения статики представлений —
  сознательные, предмет ревью».
- Этап 2 (сторож ярлыков, проекция «атрибут→формы», кнопки Д-16) и
  этап 3 (R/V-контроли, DE-реестр Д-10) — ОТЛОЖЕНЫ (решение 2026-08-16).
- ДОПОЛНЕНО 2026-08-17 (стресс-тест: ручное преобразование ЭФ «Документ
  (редактирование)» inkasso, находки Н-1/Н-6/Н-7/Н-8, согласованы):
  словарь выправлен по событийному формату (авторитет Д-16): порядок
  Тип → Формат → Способ заполнения → Обязательность → Видимость →
  Логика установки значения (закрытые под-ярлыки), дополнительные
  Сортировка/Поиск/Подсказка/Действие/Особый случай + «Заголовок:»
  (Н-1); неприменимый атрибут опускается целиком, ярлыки жирным,
  образец в шаблоне. «Экран с вкладками» обобщён до «экрана из частей»
  (Н-6: часть = вкладка UI или дочерняя страница-источник; ложные
  «вкладки» запрещены). Правило `%зачёркнуто%` — постфиксный маркер
  выгрузки, семантика «неактуально»; сторож в нормализаторе (Н-7;
  инцидент scr-cl-02 — инверсия смысла шага 3). «Функции формы» —
  раздел 8 шаблона, FF-N, шаги дословно, вызовы якорями; вынос в FUN
  (суррогатная сигнатура) и дубли в кнопках отклонены (Н-8).
- Проверка: дозаход scr-cl-02.1 (+01) на ярлыки — в контрольном
  прогоне; ТУДА ЖЕ — починка scr-cl-02 (README): инверсия шага 3 EV-1
  (Н-7), перевод «Функций формы» в FF-раздел (Н-8), «Части экрана»
  вместо вкладочной семантики (Н-6), дословный перенос EV-1/кнопок
  (Э-7-класс). Эталон ручного преобразования (с находками Н-1…Н-8) —
  «app/data/Пример преобразования ЭФ Документ (волна C).md».

5. F — после пилота (не блокирует сводный отчёт).
