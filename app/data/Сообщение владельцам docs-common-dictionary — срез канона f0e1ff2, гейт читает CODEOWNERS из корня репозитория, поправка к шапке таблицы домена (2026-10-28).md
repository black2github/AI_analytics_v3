# Владельцам docs-common-dictionary: срез канона f0e1ff2 — гейт переноса читает CODEOWNERS из корня репозитория

Дата: 2026-10-28. От владельца канона. Продолжение сообщения от 28.10 («CODEOWNERS в подкаталогах не нужны,
оформить репозиторий как домен справочников»).

## Что изменилось

Исправление гейта переноса (`_meta/tools/transfer_gate.py`) влито в канон: срез `f0e1ff2`. Ложный ✗ CORE-04 по
справочникам снят. Гейт теперь ищет `CODEOWNERS` там, где его читает GitLab: корень репозитория, `docs/`,
`.gitlab/`; если репозиторий оформлен доменом — в корне домена. Комплект в подкаталоге:

- есть правило на каталог комплекта (`/branches/ …`) — ✓ CORE-04, в строке правило и владельцы;
- комплект покрыт только правилом по умолчанию `*` — ⚠ CORE-04 с просьбой добавить строку для каталога;
- файла нет ни в одном из трёх мест — ✗, как раньше;
- `CODEOWNERS` внутри каталога комплекта при наличии корневого — строка «GitLab не читает, можно удалить»;
  без корневого он не засчитывается;
- `gpb-manifest.json` комплекта печатается справочной строкой без требования, манифест корня — как раньше.

## Что вы увидите на trunk 999325d после обновления канона

| Комплект | CORE-04 | Почему |
| --- | --- | --- |
| `branches` (и остальные 14 с подкаталожным файлом) | ✓ по правилу `/branches/`, плюс строка «branches/CODEOWNERS можно удалить» | строка в корневом файле есть |
| `authorized-person`, `role-template` | ✓ | строка есть, подкаталожного файла нет |
| `currency`, `fatf`, `swift` | ⚠ «назначены только правилом по умолчанию «* @eshefer» [Default]» | строки в корневом файле нет |

Остальные блокеры гейта по справочникам к владельцам не относятся и не менялись (у `currency` — 8 блокеров, у
`branches` — 3; все про состав комплекта, не про владельцев).

   корневого `CODEOWNERS`; пятнадцать подкаталожных `CODEOWNERS` удалить; оформление домена — отдельным заходом.
