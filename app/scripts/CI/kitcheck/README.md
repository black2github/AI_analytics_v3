# kitcheck — ядро прибора самопроверки

Прибор состоит из ядра и проверок. Ядро знает только интерфейс проверки; какие проверки и в каком
порядке выполняются, задают реестры. Точки входа прежние: `selfcheck.py`, `normalize_tables.py`,
`link_debts.py`, `transfer_gate.py` и другие утилиты каталога. Отчёт, ключи и коды возврата
не менялись при переходе на ядро.

## Устройство

| Модуль | Что в нём |
| --- | --- |
| `kitcheck/core.py` | `Check` — проверка; `run_checks` — прогон реестра, вердикт в одном месте; `Finding`, `render` — находки с уровнем для новых проверок; `is_soft_signal` — контракт начала строки (какие строки проверок карточки видны при ✓) |
| `kitcheck/fs.py` | Кэш прогона: файл читается с диска один раз (`read_text`, `read_bytes`); `memoize` — кэш результатов чистых функций разбора. Действует внутри `session()`, её открывает `selfcheck.run` |
| `kitcheck/md.py` | Примитивы markdown: шапка документа, страницы-источники, обход файлов комплекта, якоря GitLab, строки таблиц, границы блоков кода |
| `kitcheck/checks/*.py` | Проверки уровня комплекта по темам: профиль источников, ID и домен, содержание документа, ссылки, артефакты, каталог и API, контроли, НФТ, матрица |

Реестры:

| Реестр | Где | Что проверяет |
| --- | --- | --- |
| `KIT_CHECKS` | `selfcheck.py` | комплект и репозиторий: корень, матрица и долги, реестр вопросов, шапки, разделы, ссылки, каталог… |
| `FILE_CHECKS` | `normalize_tables.py` | одну карточку: разорванные ячейки, маркеры сокращения, гомоглифы, нотация, длинные строки… |
| `SOURCE_CHECKS` | `normalize_tables.py` | карточку против источника: чистовик, полнота ячеек, сверка таблиц и значений… |

## Как добавить проверку

1. Функция `(ctx) -> (строки отчёта, ok)`. Контекст — `_KitCtx` (комплект), `_FileCtx` (карточка)
   или `_SourceCtx` (карточка и источник). Строки — готовый текст отчёта в форме соседних проверок.
   Сбой проверки изолируется обёрткой `_safe`, как у соседних проверок.
2. Строка в нужном реестре: `Check("<id>", <функция>, affects_verdict=<влияет ли на вердикт>)`.
   Порядок реестра — порядок строк отчёта.
3. Проверка уровня комплекта, которой нужны помощники, — в тематический модуль `kitcheck/checks/`;
   `selfcheck` реэкспортирует имя для утилит и тестов.
4. Строка проверки карточки, которая должна быть видна при зелёной карточке, начинается по
   контракту `is_soft_signal` («предупреждение…»).
5. Чтение файлов — через `kitcheck.fs.read_text`; тяжёлый чистый разбор — `@fs.memoize`.
6. Тест на срабатывание и на несрабатывание.

## Проверка эквивалентности

`app/scripts/dev/golden_master.py` — эталон отчётов всех утилит на замороженном снимке комплектов и
сравнение до байта (рефакторинг 2026-10-17, ветка `refactor/tool-structure`).
