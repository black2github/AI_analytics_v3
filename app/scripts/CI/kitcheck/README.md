# kitcheck — ядро прибора самопроверки

Прибор состоит из ядра и проверок. Ядро знает только интерфейс проверки; какие проверки и в каком
порядке выполняются, задают реестры. Точки входа прежние: `selfcheck.py`, `normalize_tables.py`,
`link_debts.py`, `transfer_gate.py` и другие утилиты каталога. Отчёт, ключи и коды возврата
не менялись при переходе на ядро.

## Устройство

| Модуль | Что в нём |
| --- | --- |
| `kitcheck/core.py` | `Check` — проверка; `run_checks` — прогон реестра, вердикт в одном месте; `Finding`, `render` — находки с уровнем для новых проверок; `is_soft_signal` — контракт начала строки (какие строки проверок карточки видны при ✓) |
| `kitcheck/fs.py` | Кэш прогона: файл читается с диска один раз (`read_text`, `read_bytes`); `memoize` — кэш результатов чистых функций разбора. Действует внутри `session()`, её открывает `selfcheck.run` |
| `kitcheck/fence.py` | Границы блоков кода — одно правило прибора и разметки CriticMarkup (`critic.py` бандла): `fence_of` — строка-ограждение, `blocks`/`code_flags` — разметка строк с вложенностью по виду и длине ограждения, `issues` — «закрытие с инфо-строкой» и «блок не закрыт до конца файла». Без зависимостей: едет и в канон, и в бандл |
| `kitcheck/md.py` | Примитивы markdown: шапка документа, страницы-источники, обход файлов комплекта, якоря GitLab, строки таблиц, разметка блоков кода (по `fence.py`) |
| `kitcheck/html.py` | Примитивы разбора HTML и markdown, общие для нормализатора таблиц и проверок карточки: сетка (`cell_text`, `expand_grid`), таблицы верхнего уровня, markdown-таблицы (`parse_md_tables`), шапка документа (`_fm_head`, `_fm_body`), нормализация ячейки (`_norm_cell`); конвертер ячейки паспорта для `--cell-to-md` |
| `kitcheck/columns.py` | Валидаторы колонок (`validate_columns`, `_COLUMN_RULES`): роли «путь», «тип», «обязательность», «кардинальность» — у нормализатора и у сверки карточки |
| `kitcheck/branch_form.py` | Правка формы ветвления (`normalize_branch_form`): по ней работают `normalize_tables.py --branch-form` и сторож формы ветвления |
| `kitcheck/checks/*.py` | Проверки уровня комплекта по темам: профиль источников, ID и домен, содержание документа, ссылки, артефакты, каталог и API, контроли, НФТ, матрица |
| `kitcheck/checks/card_*.py` | Проверки одной карточки по темам — таблица ниже |

Проверки карточки:

| Модуль | Тема |
| --- | --- |
| `card_run.py` | контексты `_FileCtx`/`_SourceCtx`, реестры `FILE_CHECKS`/`SOURCE_CHECKS`, сверка с источником (`_rc_*`), точки входа `check_file` и `run_check`, подготовка источника (`apply_critic`, `strip_history`) |
| `card_source.py` | литералы и источник: кавычечные литералы, сверка таблиц и значений, полнота ячеек, title, имена параметров HTML-таблиц |
| `card_steps.py` | шаги и поведение: маркеры шагов, вложенность, тела шагов, нумерация |
| `card_passport.py` | паспортные и тяжёлые ячейки, лейбл-секции |
| `card_notification.py` | структура уведомления |
| `card_branch_form.py` | сторож формы ветвления |
| `card_controls.py` | сообщения контролей, файл карточек = сущность, приписанные атрибуты |
| `card_clean.py` | чистовик: ссылки, упоминания целей и тегов, OQ и page_id в теле, формула ТУЗ |
| `card_form.py` | форма текста: разорванные ячейки, маркеры сокращения, гомоглифы, невидимые символы, выноски, блоки кода, длинные строки, нотация |
| `card_common.py` | помощники, общие для нескольких тем |

Слой модуля — по строке `Слой:` второй строкой файла (под строкой с путём); перечень и поведение без
выгрузки — README прибора канона, раздел «Слои прибора»; полноту пометок проверяет тест прибора.

Слои без циклов: `html` → `columns`, `branch_form` → `card_common` → `card_<тема>` → `card_run`. Тематические
модули друг друга не импортируют. Внутри пакета модули импортируют друг друга относительно (`from ..html
import …`), поэтому модуль загружается одной копией при любом способе загрузки пакета и его состояние
(кэши) общее.

`normalize_tables.py` — нормализатор таблиц: профиль, сборка плоской таблицы, рендер, `normalize_file` и CLI
(`--sample`, `--cell-to-md`, `--branch-form`, `--check`). Механизмы ядра он импортирует под прежними
именами. `--check` делегирует в `card_run.run_check`. Прежние имена проверок
(`normalize_tables.check_file` и др.) отдаются лениво на переходный релиз; новый код импортирует проверки
из `kitcheck.checks.card_*`.

Реестры:

| Реестр | Где | Что проверяет |
| --- | --- | --- |
| `KIT_CHECKS` | `selfcheck.py` | комплект и репозиторий: корень, матрица и долги, реестр вопросов, шапки, разделы, ссылки, каталог… |
| `FILE_CHECKS` | `kitcheck/checks/card_run.py` | одну карточку: разорванные ячейки, маркеры сокращения, гомоглифы, нотация, длинные строки… |
| `SOURCE_CHECKS` | `kitcheck/checks/card_run.py` | карточку против источника: чистовик, полнота ячеек, сверка таблиц и значений… |

## Как добавить проверку

1. Функция `(ctx) -> (строки отчёта, ok)`. Контекст — `_KitCtx` (комплект), `_FileCtx` (карточка)
   или `_SourceCtx` (карточка и источник). Строки — готовый текст отчёта в форме соседних проверок.
   Сбой проверки изолируется обёрткой `_safe`, как у соседних проверок.
2. Строка в нужном реестре: `Check("<id>", <функция>, affects_verdict=<влияет ли на вердикт>)`.
   Порядок реестра — порядок строк отчёта.
3. Проверка уровня комплекта, которой нужны помощники, — в тематический модуль `kitcheck/checks/`;
   `selfcheck` реэкспортирует имя для утилит и тестов. Проверка карточки — в модуль `card_<тема>.py` по
   таблице выше, строка — в `FILE_CHECKS` или `SOURCE_CHECKS` (`card_run.py`); `normalize_tables.py`
   не трогается. Помощник, нужный двум темам, — в `card_common.py`.
4. Строка проверки карточки, которая должна быть видна при зелёной карточке, начинается по
   контракту `is_soft_signal` («предупреждение…»).
5. Чтение файлов — через `kitcheck.fs.read_text`; тяжёлый чистый разбор — `@fs.memoize`.
6. Тест на срабатывание и на несрабатывание.
7. Укажи, нужен ли проверке источник (выгрузка Confluence). Проверка с источником получает его текст
   через контекст (`_SourceCtx.src_text`) и сама молчит, когда источника нет (`src_text is None`, запуск
   без `--sources`): отсутствие выгрузки она дефектом не считает и строк о нём не печатает. Слой — у
   функции, отдельной пометки модуля нет. Строку `Слой: миграция` несёт только модуль, который целиком
   работает с выгрузкой, — вместе со строкой в таблице «Слои прибора» README прибора канона.
