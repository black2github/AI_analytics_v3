# Тесты: уровни прогона

Три уровня. Настройки pytest этого репозитория: `pytest.ini` начинается с `[tool:pytest]`, и pytest его
секцию не читает (ни `addopts` с покрытием, ни метки). Метка уровня `chain` зарегистрирована в
`tests/conftest.py`; `-o addopts=""` в командах — страховка на случай, если секцию когда-нибудь починят.

| Уровень | Что входит | Когда |
|---|---|---|
| модуль | тестовые файлы затронутого модуля | после каждой правки, по ходу работы |
| быстрый | всё, кроме метки `chain` (тесты утилиты цепочки src-репо, `test_apply_history.py`) | перед сдачей среза прибора |
| полный | всё | перед коммитом правки вне `app/scripts/CI`, при правке утилиты цепочки, перед выпуском бандла |

## Окружение

Локальный `.venv` сломан (ссылается на несуществующий базовый интерпретатор): тесты гоняются системным
Python, `site-packages` venv — в `PYTHONPATH`. `PYTHONIOENCODING=utf-8` обязателен — иначе кириллица в
выводе превращается в мозаику. Параллельный запуск — `pytest-xdist` (`requirements-test.txt`), стоит в
системном Python рядом с pytest. Команды — Git Bash из корня репозитория; путь к интерпретатору зависит
от машины.

```bash
M=$PWD; export PYTHONPATH="$M;$M/.venv/Lib/site-packages" PYTHONIOENCODING=utf-8 PYTHONDONTWRITEBYTECODE=1
```

## Команды

Модуль (секунды; ожидание — падения только из списка полного уровня):

```bash
/c/Python312/python.exe -m pytest tests/test_<модуль>.py -q -o addopts="" -p no:cacheprovider
```

Быстрый (рекомендуемо, `-n 4`):

```bash
/c/Python312/python.exe -m pytest tests -m "not chain" -n 4 -q -o addopts="" -p no:cacheprovider
```

Полный (рекомендуемо, `-n 4`):

```bash
/c/Python312/python.exe -m pytest tests -n 4 -q -o addopts="" -p no:cacheprovider
```

Без `-n 4` — последовательный прогон, исход тот же.

Параллельный и последовательный прогоны дают одинаковые множества упавших, ошибочных и прошедших тестов
поимённо (сверка по junit, оба уровня, оба режима). `-n auto` медленнее `-n 4`: на каждый рабочий процесс
приходится свой запуск и импорт приложения.

Базлайн сверяется на том же уровне, что и прогон, и по именам, а не по счётчикам. Предсуществующие 58
падений и 4 ошибки — тесты приложения (`test_agent`, `test_routes`, разбор таблиц и отступов и др.) и два
в `test_color_map`; ни одного в тестах утилиты цепочки, поэтому на быстром уровне их столько же. Упавший
тест вне этого списка — проверять на чистом `HEAD` (`git worktree add --detach <tmp> HEAD`).
